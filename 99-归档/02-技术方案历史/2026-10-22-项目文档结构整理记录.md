# 2026-10-22 项目文档结构整理记录

用户授权按讨论的目录结构整理整个项目文档，更新 Spec 生成规则、模板与校验，保留内容、稳定 ID 并修正引用；本轮不提交。

## 结构与事实边界

- 技术设计按架构运行、开发规范、业务契约、平台接口与权限分组；开发管理按执行规则、部署、版本、测试、进度与待办组织。
- 版本信息保留原稳定 ID 于总索引，完整每日记录与版本证据拆入 2026-09、2026-10 两个月度页，新月度页独立持有 ID。所有原版本号、日期与显式锚点保留，引用直接指向对应页面。
- 原型的说明、当前入口、备选及共享资源分开。统一目录仍标明当前方案、实施基线与样式评审；小程序版本对照继续由共享控制器切换，不复制方案资源。
- 交付材料的停用测试账号移入内部测试资料，开放接口的执行记录移入部署记录，协议演示稿单列且保持待生效。内部汇报按当前、阶段计划、专题、视觉备选、历史和模板分类。
- Spec 分入六个业务分类，日期文件名保留，实施计划归所属分类，assets/evidence/sql/support 保留共享位置。完成开发不自动归档契约。
- 00 项目资料、01 功能需求、05 业务流程保留原有文件顺序，更新直接引用与阅读边界。历史材料按来源分组，不自动删除。

当前入口见[项目 README](../../README.md)、[技术设计导航](../../02-技术设计/README.md)、[开发管理导航](../../03-开发管理/README.md)与[Spec 生成规则](../../specs/README.md#spec-generation)。读者不依赖本历史记录查找现行页面。
