两端 UI 可以不同，但可见范围、可管理范围、可授予范围、保存结果和后端拒绝规则必须与当前主系统完全一致。子系统权限页可以默认定位售后权限，但必须能正确处理当前操作者在主系统中可管理的完整 Gaia 权限目录，不能只提交售后子树后覆盖其他模块。
子系统可以不打开主系统页面，独立完成登录和管理。子系统权限管理入口可配置关闭，关闭时仍可登录使用业务，用户角色由主系统集中管理。配置开关不能授予权限；后台授权规则保持统一。

四、认证与权限要求
1. 主、子系统登录均使用 Gaia 现有认证契约。当前子系统读取同源 localStorage.token 并使用原始 Authorization 请求头，不要按旧文档误改成仅 Cookie 或 Compass Bearer JWT；实施前再次核对当前源码。
2. 完成当前用户、登录失败、退出、会话过期、安全的站内返回地址及 Gaia 已支持的验证码/多因子流程。不增加未经确认的新登录方式。
3. 同源已有登录态可进入子系统；切换账号或退出时清除旧用户菜单、权限与业务缓存。不得通过 URL、Hash 或 postMessage 传递凭据和授权身份。
4. 登录入口选择、管理入口开关与业务展示模式独立管理。独立模式支持子系统自身登录；已有嵌入模式复用主系统会话，避免 iframe 内套登录页。三模式尚缺的整体集成不自动扩大成本次全部实施范围，明确未验证项。
5. 子系统增加独立的管理菜单和路由注册，按 Gaia 真实管理授权显示；不要把全局管理权限强塞入售后业务子树或增加业务入口统计。
6. 在现有只读页上核对并实现主系统当前真实支持的用户新增、编辑、删除、启停、密码重置、组织／角色关系和数据权限，以及角色新增、编辑、删除和模块／按钮授权。若主系统某动作本身已废弃或后端没有可靠契约，记录证据后不制造空壳；菜单／按钮资源目录定义 CRUD 不是本次默认新增范围。
7. 用户编辑可能是完整聚合保存。必须从最新详情构造显式提交 DTO，保留页面未编辑的头像、组织关系、角色关系、品牌权限、组织数据权限和其他 Gaia 必填字段；不能把当前精简只读模型直接回传，不能把未展示字段写空。新增和重置密码必须复用 Gaia 当前密码规则及服务端校验。
8. 角色授权必须动态读取与主系统相同的 Gaia 分类、模块和按钮目录，处理所有当前操作者可授予范围；可以默认筛选售后，但不能使用静态 manifest 作为授权目录。核对保存是否全量替换；若是，全量加载并保留其他分类、未展示、未加载和不可授予授权，或实现后端受范围约束的增量修改／安全合并。任何情况下不得因编辑售后权限覆盖共享角色的其他模块授权。
9. 管理员可维护的用户、角色、组织、数据范围和可授予权限必须由后端限制，不能仅靠前端过滤。保护当前登录用户、租户管理员、内置／共享角色和最后一个有效管理员，具体规则取自 Gaia，不照搬 Compass 假设。
10. 所有用户／角色／模块／按钮 BIGINT ID 在前端保持字符串，不转 Number。所有写操作使用字段白名单、重复提交保护和明确成功响应；角色基础信息与授权、用户基础信息与关系数据必须原子保存或失败后完整回滚。
11. 主、子系统同时编辑同一用户或角色时不得静默互相覆盖。核对 Gaia 当前版本号／更新时间／锁机制；已有机制直接复用，没有机制则实现最小后端冲突校验，冲突时关闭陈旧编辑器、刷新最新数据并提示用户重新操作。
12. 为列表、详情和每个写操作逐项核对 Gaia 菜单按钮 `code`、`moduleCode`、`api_list` 与 HTTP Method。前端隐藏按钮不等于授权；必须由后端 API 权限拦截器和 AppService 的租户／管理范围校验最终拒绝。尤其检查“接口未配置时默认放行”的路径，管理写接口不得裸露。
13. 验证权限变更后的后端缓存失效和会话生效时点；撤权、禁用、删除或重置密码后，后端按 Gaia 规则立即拒绝旧权限或旧会话，前端重新加载授权，不能只靠菜单隐藏或必须重新登录才生效。
14. 正式接入恢复子系统真实菜单、路由和按钮授权，移除默认全菜单预览状态；管理路由和接口绝不能被开发预览开关绕过。接口失败或未知权限一律拒绝，保留清晰重试体验。

六、实施与验收
从现有“独立登录已闭环、用户／角色只读已完成”的基线开始，按“完整接口/DTO/权限矩阵 → 用户完整聚合写入 → 角色完整权限写入 → 后端范围/并发/事务保护 → 入口与真实按钮/API 权限 → 双端一致性验证”推进。重大且无法从代码推断的权限语义缺口再询问；局部环境阻塞时继续其他可完成项，不用 mock 冒充完成。
运行与改动相关的类型检查、构建和必要测试，并验证：
- 不加载主系统 HTML，子系统能登录并进入已授权业务。
- 在统一同源入口下，两个登录页都使用同一 Gaia 账号：主系统登录可进入子系统，同源已有会话可直接复用；子系统登录也能访问已授权的主系统入口；分别直接访问两个登录页均能完成登录，且不产生第二份身份。内部开发端口或未来独立域名不冒充同源共享，按既定边界单独记录。
- 主系统创建/修改/授权后子系统重新查询即可使用，子系统创建/修改/授权后主系统重新查询即可管理；比对同一记录 ID、租户、用户字段、组织与角色关系、角色模块/按钮授权和数据权限，无复制数据、同步延迟或映射记录。
- 普通用户不能访问管理页面或直调管理接口；管理员仅能操作其授权范围。
- 关闭管理入口后菜单消失、直达被拒绝，普通登录和业务不受影响。
- 任一入口撤权后后端拒绝旧权限操作，两端展示正确更新。
- 跨租户、超范围授权、共享角色隐藏／未加载权限保留、用户未编辑聚合字段保留、并发编辑冲突、账号切换和会话失效。
- 用户创建/编辑/启停/删除/重置密码及组织、角色、数据权限保存；角色创建/编辑/删除及完整模块、按钮授权；危险操作、引用确认、失败回滚和重复提交保护。
- 管理动作的前端按钮允许/拒绝与直接 HTTP 调用允许/拒绝一致；未配置 `api_list` 的管理写接口不得被当作通过。
- 已有商品分类、商品档案及其他当前已实现页面的必要回归；两端请求协议保持兼容。
隔离验证与真实共享环境验证分别记录，缺少账号或环境时明确未验证，不把构建通过当作权限验收。
不要停止用户仍需使用的现有主/子前端或隔离测试服务；只清理本次自行启动且明确不再需要的临时进程，交付时说明保留的服务和访问地址。
