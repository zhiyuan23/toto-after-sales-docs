## 六、进度状态与更新规则

### 状态口径

| 状态 | 使用条件 |
| --- | --- |
| 未开始 | 尚无针对该入口的有效实现 |
| 开发中 | 已开始实现，但尚未达到可验收条件 |
| 待验收 | 开发和研发验证已完成，等待业务或项目验收 |
| 已完成 | 需求范围内的数据、接口、页面、权限和关键场景均验收通过，并有关联证据 |
| 阻塞 | 已开始或计划开始，但被明确外部条件阻断；必须在备注中写原因 |

“菜单已建”只表示菜单/Tab、路由、页面骨架、返回路径和权限可见性已验证；“功能已完成”必须使用真实业务接口和数据完成验收。一个入口含多个动作时，全部适用范围完成后才将该入口计为 1 个已完成；部分完成只在备注中说明，不计入完成数。

### 每次开发完成后的更新动作

1. 在对应功能端明细中更新入口的“菜单状态、功能状态、证据/备注”。
2. 重算该文档的模块合计，再同步本页的模块、功能端和总计。
3. 若范围发生变化，先更新[页面清单](../01-功能需求/08-页面清单.md)和[需求索引](../01-功能需求/09-AI开发需求索引.md)，再调整进度分母。
4. 复杂切片把实现范围、验证记录和遗留项写入对应 [`specs/`](../specs/)；本进度文档只保留状态和证据链接。
5. 在本页更新记录新增一行；不以代码已提交、构建通过或占位页存在替代业务验收。
6. 同步[业务阅读中的开发执行顺序与进度](../04-业务阅读/04-开发执行顺序与进度.md)所涉及模块的状态、阻塞原因和核对日期，保持摘要与本进度体系一致。
