## 六、进度状态与更新规则

### 状态口径

| 状态 | 使用条件 |
| --- | --- |
| 未开始 | 尚无针对该入口的有效实现 |
| 开发中 | 已开始实现，但尚未达到可验收条件 |
| 待验收 | 开发和研发验证已完成，等待业务或项目验收 |
| 已完成 | 需求范围内的数据、接口、页面、权限和关键场景均验收通过，并有关联证据 |
| 阻塞 | 已开始或计划开始，但被明确外部条件阻断；必须在备注中写原因 |

三类数字分开维护：

- **入口进度**：只按当前项目明确采用的入口里程碑计数。页面壳、静态路由或通用 UI 可以作为工程证据保留，但本次复核后不再单独形成进度数，所以消费者端归零。
- **已有真实实现**：入口已接入真实业务数据或 API，并完成相应研发切片验证；只读切片、基础切片和共享联调中的功能均可计入，同时必须写明剩余边界。
- **最终验收完成**：需求范围内的数据、接口、页面、权限和关键场景均已通过真实环境验收。一个入口含多个动作时，全部适用范围完成后才计 1；部分完成不能提前计入。

### 每次开发完成后的更新动作

1. 在对应应用／角色视角明细中更新入口进度、功能状态及证据／备注。
2. 重算“入口进度、已有真实实现、最终验收完成”三类模块合计，再同步本页的模块、应用载体和项目总计；角色视角的入口不能重复计入应用总数。
3. 若范围发生变化，先更新[页面清单](../01-功能需求/08-页面清单.md)和[需求索引](../01-功能需求/09-AI开发需求索引.md)，再调整进度分母。
4. 复杂切片把实现范围、验证记录和遗留项写入对应 [`specs/`](../specs/)；本进度文档只保留状态和证据链接。
5. 在本页更新记录新增一行；不以代码已提交、构建通过或占位页存在替代业务验收。
6. 同步[业务阅读中的开发执行顺序与进度](../04-业务阅读/04-开发执行顺序与进度.md)所涉及模块的状态、阻塞原因和核对日期，保持摘要与本进度体系一致。
