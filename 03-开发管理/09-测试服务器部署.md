`10.1.1.53:8011` 是远程 HTTP 服务入口，不是数据库地址。本机开发、测试库连接及本地后端启动继续按[本地开发与联调](../local-development.md)执行。以上运行路径与端口于 2026-09-20 通过 SSH 只读核对；指纹仅为首次连接记录，未经过独立渠道核验，后续变化须先查明原因。

小程序 profile 只配置服务器根地址，不追加 `/api`；业务模块已经使用以 `/api/...` 开头的相对路径。2026-09-21 从开发机直接请求 `GET http://10.1.1.53:8011/api/afterSales/mobile/consumer/privacy-policy` 得到明确业务响应，确认消费者移动接口已在该路径命中。该入口是私有网络 HTTP 地址，test 微信产物会自动关闭开发者工具的合法域名校验，但运行机器仍须能访问该网段；真机和正式发布仍应改用微信后台允许的 HTTPS 合法域名。

服务人员登录还需宿主为单租户模式配置 `after-sales.mobile.single-tenant-id=1001`；这是服务端数字租户 ID，不是客户端 `x-tenant: TOTO` 租户编码。2026-09-21 通过已记录的 Ed25519 指纹校验后首次核对时，测试机 `/yundata/saas_test/tomcat11/conf/gaia-after-sales.properties` 缺少该项，因此服务人员登录返回 `403 / 缺少有效租户上下文`。外部配置修改后必须重启 Tomcat 才会生效；配置和重启属于测试环境发布操作，不由小程序构建自动执行。当前配置结果见下一段。

2026-09-21 获用户明确授权后，已将外部配置备份到 `/yundata/saas_test/backups/20260921160008-mobile-single-tenant/gaia-after-sales.properties`，再写入 `after-sales.mobile.single-tenant-id=1001`。该 Tomcat 关闭端口未开放，标准 `shutdown.sh` 无法连接；核对精确的 `catalina.base` 与进程命令后，使用 `SIGTERM` 正常终止旧进程 `1512684`，并由 `startup.sh` 启动新进程 `1513093`。新宿主用时约 193 秒完成启动，根入口返回 HTTP 200；服务人员登录接口使用空凭据探测时已从 `403 / 缺少有效租户上下文` 变为 `4001 / 账号或密码错误`，证明请求已越过租户校验并进入账号认证。本次未读取或传输真实账号密码，有效账号的完整登录仍由小程序用户自行验证。

## 后续说“部署”时的执行方式

在本项目任务语境中，用户说“部署”且未指定环境时，目标为上表测试服务器，**默认构建并发布完整的 TOTO Web 前后端，不按当次改动文件缩小发布范围**。两个小程序（消费者端与服务人员端）的构建、上传和发布均不包含在此默认部署中。

| 范围 | 默认处理 |
| --- | --- |
| 售后后端 `backend/gaia-after-sales` | 构建当前售后后端工程；将测试机实际使用的 `core`／`api` 等依赖制品纳入宿主发布。独立 `gaia-after-sales-web` 是否运行，以目标机现状为准。 |
| Gaia 聚合宿主 `backend/gaia-saas-proj` | 构建测试机实际运行的 Web 宿主及其依赖；确认该机使用 WAR 还是可执行 JAR 后，发布完整宿主产物及所需售后依赖。其他未运行的 BI、Job、H5 宿主模块不因位于同一 Maven 仓库而部署。 |
| Web 前端 `frontend/gaia-ui` | 使用项目统一生产构建，生成主站与 `apps/after-sales` 售后子站组成的完整 `dist`，校验后整体发布，而非仅替换 `/after-sales/`。 |

先检查三个代码仓库状态、部署脚本、实际依赖版本和目标机当前运行形态，确定 WAR／JAR、前端资源及实际目录；保留其他人的未提交改动和服务器现有配置。`gaia-ui/push.sh` 当前上传目标是 `192.168.100.180`，**不能直接运行其上传步骤**；可参考其构建流程，但发布目标必须核对为本页的测试服务器。凭据从本地忽略文件读取，终端命令、日志及反馈只展示脱敏信息。

部署时按对应功能 Spec 的顺序准备制品和必要备份，执行目标环境适用的发布与重启，再验证进程、HTTP 入口、相关 API 和本次功能的授权路径；失败时依据备份回退并说明结果。数据库迁移、清库、权限批量变更及生产环境操作依照各自明确的任务授权，不因仅有测试服务器登录信息而自动扩大范围。发布证据写入当次功能 Spec；研发核验与业务验收分别记录。

已有测试环境发布记录可供核对目标形态：[售后 JAR 与子应用替换](../specs/2026-09-18-服务人员三类自动分配策略.md#6-共享测试环境发布与验证2026-09-18)、[WAR 与静态包发布](../specs/2026-09-19-实时工单看板与排班站点默认.md#测试记录)。它们是历史记录，执行时以当前服务器和源码为准。
