## 版本与部署记录怎样分工

| 目录 | 回答的问题 | 维护内容与时机 |
| --- | --- | --- |
| [03-版本记录](03-版本记录/00-版本索引.md) | 代码改了什么，来自哪些提交？ | 功能、修复、优化、项目版本及研发验证边界；随有意义的代码提交维护。 |
| [01-环境部署／部署记录](01-环境部署/00-测试与Demo环境部署.md#release-records) | 哪个环境实际执行了什么，结果如何？ | 发布编号、实际源码快照／制品、备份、配置与数据操作、逐端结果及恢复证据；随实际部署、失败或恢复维护。 |

同一版本可以发布到多个环境或重复发布，一次发布也可以包含多个版本。版本条目链接具体部署章节；部署章节回链能核对的版本，实际发布范围仍以该次源码提交、工作区指纹和制品清单为准。不能仅按日期或最新版本号认定整版已经部署。

功能摘要只在版本记录维护；环境结果和运行证据只在部署记录维护，另一侧保留简短链接。首次集成、重复发布、配置或数据操作若没有新功能提交，不另升项目版本；无法可靠对应版本的历史执行保留原始快照，不强行补号。部署与微信上传也不等于业务验收。
