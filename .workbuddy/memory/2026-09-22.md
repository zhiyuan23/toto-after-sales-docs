## 测试环境外网域名接入方案调研（文档仓库）

- 触发：用户问公司机房测试环境（内网 `10.1.1.53:8011`）能否绑自有域名，目标是**外部客户演示**。
- 2026-09-22 通过 SSH 只读探测（expect + 密码从 `.local/test-server.env` 读取，不落盘不打印）确认：
  单网卡 `ens192=10.1.1.53/24`，默认网关 `10.1.1.1`；**可出公网**，出口 NAT `180.169.137.2`
  （中国电信上海 CHINANET-SH，机房共享）；对外仅监听 `22`、`8011`(Tomcat)、`15050`（另一 java 进程）；
  **未装 Nginx、无 TLS 证书**；`server.xml` 有 8443 但未监听。
  本机无 sshpass，用 `/usr/bin/expect` + base64 传远端命令可用；免密 SSH 不可用（仅密码认证）。
- 结论：`10.1.1.53` 是私网地址，域名不能直接解析到它；必须先补一跳公网入口。
  因出站可用 → 反向隧道类方案（Cloudflare Tunnel、自有云服务器 + frp/autossh）不需要公司网络侧配合。
- 备案红线：国内云厂商拦截未备案域名的 80/443；域名指向公司机房 IP 则备案接入商须与机房线路一致，
  个人在自有云厂商备案的域名指向公司 IP 属「接入信息不符」。中国香港／境外节点免备案但延迟高。
  小程序演示需 HTTPS + 已备案域名 + 标准端口，Cloudflare Tunnel ／境外节点不可用于小程序。
- 产出：新建 `03-开发管理/10-外网访问与域名接入方案.md`（方案 0 内网投屏／1 CF Tunnel／
  2 自有云+隧道／3 公司出口映射／4 临时穿透，含实测现状、对比表、推荐路径、待确认）；
  在 `README.md` 阅读表与 `03-开发管理/09-测试服务器部署.md` 加交叉引用。
- 状态：方案未选定、未实施；用户尚未提供演示形式、域名备案状态、是否有可用云主机等信息。

### 追加：手机端访问内网测试环境

- 用户真实目的修正：不是外部客户演示，而是**自己不在公司时用手机看小程序**（电脑已通过 OpenVPN 进内网）。
- 关键前提：小程序真机网络请求由手机系统发出，**系统级 VPN/NAT 对小程序透明**，只要手机能路由到
  `10.1.1.0/24` 即可；反之 HTTP 系统代理不可靠（微信不一定遵循），不要作为方案基础。
- 三条路：① 手机装 OpenVPN Connect 导入电脑同款 `.ovpn`（需确认公司 VPN 是否限单会话／证书可否共用）；
  ② 电脑当网关共享网络（macOS 互联网共享选 VPN 接口→Wi-Fi/USB；Windows ICS 共享 VPN 适配器 + 移动热点），
  不碰公司配置；③ 挂公网（Cloudflare Tunnel／自有云 + 反向隧道），手机 4G 随时可用。
