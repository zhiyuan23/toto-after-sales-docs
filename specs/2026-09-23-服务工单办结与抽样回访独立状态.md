# 服务工单办结与抽样回访独立状态

- 日期：2026-09-23
- 依据：用户确认从实际售后服务出发，设计并实施工单终态与工单外抽样回访。
- 范围：服务工单主状态、已办结判定、再次服务、报表与派单口径、消费者／服务人员／Web 状态展示，以及人工抽样回访。

## 1. 业务决定

完工审核是本次服务是否已履约的责任确认。审核通过时，工单由 `PENDING_REVIEW` 直接进入唯一正常终态 `CLOSED`，界面名称统一为「已办结」。同一事务写入审核决定、工单状态、状态历史和办结时间；审核退回仍回 `PENDING_COMPLETION`，保留原版本，补充后重提。`CANCELLED` 是未完成服务的终止结果，不计已办结。

回访是工单办结后的质量抽查，不是所有工单的必经阶段，也不决定工单能否办结。客服可在已办结工单中人工抽样，创建与原工单一对一关联的回访任务；未抽中的工单没有「待回访」。回访任务独立经历「待回访 → 已完成／未接通」；联系记录、满意度和问题描述留痕，回访不会写回工单主状态。一次有效结果只能登记一次，重复或过期提交拒绝。未接通为抽样任务的终结结果，不伪造满意度。

消费者自发评价与客服抽样回访是不同事实。抽样回访的满意度用于已有派单评分时，必须以有效已完成回访及明确满意／不满意为样本；无样本继续按现有缺样本规则处理。抽样回访发现未解决问题，应关联投诉或按再次服务规则新建工单；不直接复开已办结工单、不删除原服务及审核证据。费用／结算仍是独立单据或事项，未确认其业务范围前不作为所有工单的关闭前置。

## 2. 主状态与边界

```text
待核验申请（仅服务受理） → 待分站 → 待分配人员 → 待完工 → 待审核
                                                        ↘ 退回待补 → 待审核
待审核 + 审核通过 → 已办结（CLOSED）
处理中 + 合法取消 → 已取消（CANCELLED）
已办结 + 被抽样 → 独立回访任务（不改变工单状态）
```

- `PENDING_DISPATCH` 实际含义是尚待分配承接服务站，`PENDING_ASSIGNMENT` 是已分站、待分配服务人员。已预约、缺件、改期、断联与审核退回是业务事实／任务标签，不额外占用正常主状态终点。
- `PENDING_FOLLOW_UP`、`COMPLETED` 与 `PENDING_HANDOVER` 只作历史兼容，不再由新业务写入。对历史记录保持原值可读；只有核实了有效审核通过记录，才可按受控迁移将历史 `PENDING_FOLLOW_UP` 办结并补状态历史，不能把未知旧单一律改名。
- 已办结／已取消不占用同一商品的活动工单名额。二者都不能经旧异常快照直接复开；再次服务创建新单并关联历史。
- 运营报表中的「已办结」只统计 `CLOSED`，完工审核通过量应以审核事实计；不能再把遗留 `COMPLETED` 与 `CLOSED` 混为当前关闭数量。师傅「今日完工」按审核通过时间统计，不按已取消或当前更新时刻推断。

## 3. 实施与验收

1. 后端将审核通过改为 `CLOSED`，确保并发版本、权限、事务和历史一致；回访使用独立任务与授权接口，抽样只允许已办结工单，单工单至多一条任务。
2. 统一活动工单、已办结报表、服务站／人员满意度、人员今日完工、SLA 与页面过滤口径。历史状态只读兼容，迁移脚本提供预检和回退。
3. Web 在已办结工单提供受权抽样及回访办理入口；消费者和师傅看到「已办结」而非「等待回访」，未抽中时不显示虚构待办。
4. 验证审核通过、退回重提、重复审核、无权／跨范围、重复抽样、未接通、有效回访、再次服务、统计及历史兼容。源码验证、测试数据库迁移和共享环境业务验收分别记录。

本 Spec 是 2026-09-23 新确认业务口径，覆盖此前「审核通过 → 待回访 → 已关闭」的主线设想；不追认历史旧单已被实际回访或结算。
