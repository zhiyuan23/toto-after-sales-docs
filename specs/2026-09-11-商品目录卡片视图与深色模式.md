## 展示规则

| 菜单 | 卡片结构 | 关联入口 |
| --- | --- | --- |
| 商品分类 | 方图、分类名称／编号、维度、状态；筛选时补充所属路径 | 当前层级展示；面包屑和下级分类下钻；关联商品弹窗，包含下级分类商品 |
| 商品系列 | 上图下文、名称／编码、备注、状态 | 关联商品使用已有详情；支持 `seriesId` 精确定位 |
| 商品档案 | 上图下文、名称、编码／型号（相同值合并）、分类、系列、规格、状态 | 分类和系列按字符串 ID 定位；无目标权限时显示文本 |
| 配套品档案 | 上图下文、名称／编码、品牌与型号同行、功能描述、状态 | 关联商品使用既有详情，保留必备数量 |
| 配件档案 | 左图右文的紧凑卡片、名称／编号、品牌与型号同行、功能描述、状态 | 适用商品使用既有详情，保留必备数量 |

- 默认表格；2026-09-12 起按用户及登录信息中可获得的租户标识共用一份表格／卡片偏好，所有支持切换的页面同步使用，不再按菜单保存。共享缓存缺失、损坏或无法识别账号时初始显示表格；存储失败仍可在当前页面会话内切换，不保证下次恢复。旧菜单缓存保留且不猜测迁移，详见 [OPT-20260912-01](#opt-20260912-01)。
- 切换只改变呈现，共用筛选、分页、加载／错误和列表数据，不增加列表请求；分页定位和取消定位继续复用 `useLinkedListPage`。
- 分类不分页。未筛选时展示当前层级；筛选时展示命中的分类并附所属路径，不把服务端保留的祖先重复当成命中项。长 ID 保持字符串。
- 图片只使用档案现有真实图片，以 `object-fit: cover` 居中等比铺满图框；提供预览、缺图占位、加载失败及重试。设计图商品图片不注入业务数据。
- 操作复用 `EsTableActionCell` 的图标、编辑优先、更多菜单、禁用与权限规则；继续隐藏通用“查看”行操作。关联入口按目标读取权限和菜单可达性控制，零数量显示文本。
- 画廊图框固定 3:2，分类与配件图框为 1:1；取消原低窗口 112px 图高压缩，避免真实商品缩成小图。短窗口通过现有卡片滚动区浏览正文与操作，分页仍固定在滚动区外。
- 背景、边框、文字、链接、状态和焦点使用现有 Element Plus 主题变量；支持深色模式与减少动态效果设置。保留现有响应式能力，本次按桌面验收。

## 公共实现与接口

- `EsListViewToggle`：可访问的表格／卡片切换。
- `EsRecordCard`：gallery、compact、category 三种布局，统一图片、字段、状态、关联插槽和操作。
- `EsTable`：增加卡片插槽和滚动区，共用原分页器；保留表格默认行为，支持卡片定位高亮与视图滚动恢复。
- `EsListToolbar`：增加工具插槽。`useListView` 负责视图偏好，不承担业务请求。
- 分类层级与商品封面选择函数放在目录共享模块；分类关联商品弹窗复用 `EsDetailDialog`、`EsTable`、`useListPage`。
- 商品 `ProductRow.imageUrl` 为只读封面：SQL 按图片 `sort_order, id` 取第一张，无图返回空字符串。列表不加载全量 images／faults／manuals，不为每张卡片单独请求详情。不参与商品版本计算，不修改提交白名单。
- OpenAPI 同步新增 `imageUrl`；不改变后端权限、租户范围、写接口或数据库结构。

## 真实图片与信息精简优化（2026-09-11）

来源：用户要求根据真实图片尺寸优化五菜单卡片，等比例撑满图框，新增／编辑时提示建议尺寸，并精简重复信息；归入 OPT-20260911-01。

当前在线商品图实测为 630 × 500 px。以下是展示建议而非上传校验门槛，不重新采样或修改已有图片。

| 使用位置 | 建议尺寸 | 说明 |
| --- | --- | --- |
| 商品、系列、配套品 | 1200 × 800 px（3:2） | 主体居中、减少留白；商品第一张图片作为卡片封面 |
| 分类、配件 | 800 × 800 px（1:1） | 主体居中、减少留白 |

`EsImageUpload.recommendation` 为可选业务提示。提示统一由内部 Hint 在整组图片下方显示；新增空图、编辑已有图片、达到单图数量上限时均可见，允许自然换行；格式和大小限制继续保留。配套品／配件图片改占表单整行。建议尺寸不参与格式／大小／数量校验，未传参数的其他业务表单维持原限制。

| Before | After | Why |
| --- | --- | --- |
| contain 加内边距，低窗口图片仅 112px 高 | cover、无内边距、固定图框比例，点击预览原图 | 提高实物辨识度，避免压扁和小图悬浮 |
| 编码和相同机能型号重复两行 | 相同值合并为“编码 / 型号”，不同时保留独立型号 | 减少重复，同时保持识别信息 |
| 空型号／系列／规格仍占行显示横线 | 商品卡片省略空值，保留非空分类／系列链接 | 缩减无效信息，不影响权限和关联 |
| 品牌、型号各带标签占一行 | 配套品／配件品牌与型号同行，标签保留给辅助技术 | 减少纵向密度，保留型号和适配说明 |
| 当前层级卡片逐张重复所属路径 | 面包屑承载层级，筛选结果才逐张显示所属 | 日常简洁，跨层级搜索仍可辨认来源 |
| 单图已上传后建议说明不可见 | 新增、编辑和数量已满时提示均常驻 | 换图前也能了解尺寸与格式要求 |

## 详情弹窗与卡片阅读入口（2026-09-11）

对应 OPT-20260911-02，来源为用户要求重新设计详情弹窗并比较图片入口与底部图标。

- 选择底部独立 Eye“查看详情”图标；图片继续预览原图，hover／键盘聚焦有明确提示。理由：用户需要同时辨认实物、查阅完整档案，两个入口分别表达看图和看资料，且无图片的档案仍有稳定详情入口。
- 卡片最多额外增加一个只读图标，保留原编辑／更多操作；表格仍隐藏通用 detail 操作并维持两个位置，不改变其他业务表格规则。业务页面显式传入 read 与禁用状态，只读账号可查看，无 read 不展示卡片。前端展示不替代后端读取权限。
- 五类资料均复用 `CatalogDetailDialog`：1040px 上限、最大 88vh，固定标题／关闭按钮，内部滚动；上方为原图、名称、编码、状态和关键字段，下方为分组概览与资料页签。详情图片使用 contain 便于完整辨认，卡片图片继续 cover；多图可切换缩略图并打开原图查看器。
- 抽取 `EsDetailGallery` 和 `EsDetailSection`，沿用 `EsDetailDialog` 壳；公共壳只补充可访问标题和可选“读取期间允许关闭”，其他调用方保留默认行为。
- 分类详情复用已读行和可见分类路径，不增加单条读取；未知父级不显示原始 ID。商品详情按需调用现有读取接口，补充规格、服务属性、完整文本、已有故障与安装手册；无对应记录时不制造空资料页签。
- 系列／配套品／配件详情按需读取，关联数量入口直接选中关联页签。关联表保留商品编码、名称、分类、系列；型号与编码不同时才另列型号，配套品／配件保留必备数量。关联链接继续受目标 read 与菜单可达性控制。
- 包装长／宽／高独立标注，不将缺失维度拼接成含义不明的尺寸串；价格保留 0.00，缺失值为横线，不推断免费、币种或单位。备注完整展示，保留测试资料中的默认价格说明。
- 复用 `useDetailDialog` 处理弹窗内加载、失败重试和过期响应；关闭及组件卸载后旧请求不回填。安装手册链接只接受解析后的 HTTP(S) 或站内路径；无效地址显示“文件地址不可用”。本轮无接口、数据库或业务写入改动。

| Before | After | Why |
| --- | --- | --- |
| 单一字段网格，没有实物图 | 图文摘要与分组概览 | 先确认对象，再查具体资料 |
| 关联表同时展示名称、编码等多组重复列 | 保留识别与关系必要列，型号按内容补充 | 减少横向滚动，保留必备数量 |
| 卡片缺少主动阅读入口 | 底部独立详情图标，图片仍预览 | 语义清楚，缺图档案也可阅读 |
| 请求完成后才弹窗，错误落在列表 | 立即打开，弹窗内加载与重试 | 操作反馈和恢复路径一致 |

## 表格阅读与双向关联优化（2026-09-11）

- 对应事项：OPT-20260911-03。
- 来源：用户确认五菜单表格信息顺序及关联入口评审后，要求按优化执行修改。
- 状态：代码与研发验证完成并已本地提交，完整业务验收待完成；未推送、未发布，无数据库迁移。

### 默认表格结构

| 菜单 | 从左到右的默认列 |
| --- | --- |
| 商品分类 | 分类信息 → 分类维度 → 关联商品数 → 状态 → 更新时间 → 操作 |
| 商品系列 | 系列信息 → 关联商品数 → 系列说明 → 状态 → 更新时间 → 操作 |
| 商品档案 | 商品信息 → 机能型号 → 分类 → 系列 → 规格 → 状态 → 操作 |
| 配套品档案 | 配套品信息 → 型号 → 品牌 → 关联商品数 → 零售价 → 状态 → 操作 |
| 配件档案 | 配件信息 → 型号 → 品牌 → 适用商品数 → 零售价 → 状态 → 操作 |

- 抽取 `EsRecordIdentity`：首列左固定，名称在上、编码在下，编码保留可选择复制的文本；五菜单均附缩略图，分类／系列无图记录保留同宽占位，避免树层级和名称列错位。名称打开当前档案详情，图片打开原图，保持键盘按钮与可见焦点。分类树的展开／收起和缩进跟随名称列。
- 商品机能型号保持稳定列，不按每行数据改变表头；条码、颜色、保修和维护信息放到详情。分类、系列移出的创建／更新人员和时间保留在“档案记录”分组。
- 配套品／配件在表格工具区提供“显示成本价”，默认关闭；金额保留两位小数，真实零值显示 `0.00`，不替换成未设置。
- 四类关联数量入口仅在目标商品可读、菜单可达且数量大于零时可点击；分类包含下级商品，其余直接打开详情的关联商品页签。系列新增的是只读入口，不恢复原已移除的关联编辑动作。
- 关联商品表统一为名称、编码、机能型号、分类、系列、必备数量（仅配套品／配件）；跳转放在名称，编码为普通文本。分类／系列名称用真实 ID 定位，缺 ID 或目标权限／菜单时降级为文本。
- 商品详情增加“关联配套品”“适用配件”按需查询页签，展示名称、编码、型号、品牌、此商品的必备数量和状态。仅进入页签时读取；使用 `useListPage` 处理分页、取消请求、过期响应与重试，切换对象／关闭不串数据。少于等于 15 条时展示数量摘要，超过 15 条显示分页。
- 配套品补齐 `bundleId` 定位，复用 `useLinkedListPage`；支持刷新、取消定位及恢复列表。所有详情中的路由跳转，包括同一菜单内改变定位 ID，均关闭原弹窗，露出目标记录。

### 只读接口增量

### 实现与兼容边界

- 五个页面统一调用无菜单参数的 `useListView()`，读取同一个 Pinia `listView` store；已打开和新打开的支持页均消费同一响应式值，切换不重置筛选、分页、列表数据或业务状态。
- 缓存键为 `${userPreferencesKey}:list-view`，复用已有账号识别和可获得的 `tenantId/tenantCode`；缺少租户标识时沿用账号范围，不宣称这种情况下仍按租户隔离。键不按角色或菜单拆分，也不随会话 token 更新而失效。
- 列表偏好独立存储，导航和配色仍使用原 JSON 键，互不覆盖；退出清理保留偏好前缀，同账号重新登录通过 `loadPreferences()` 重读。缓存仅位于当前浏览器同源 `localStorage`，不跨设备、浏览器或不同源同步。
- `storage` 事件仅重读当前身份对应的偏好，处理身份变化、偏好删除和存储清空；不回写缓存形成循环。监听随 Pinia store 销毁移除，存储受限时仍允许当前应用内共享切换。
- 旧菜单键没有最后更新时间，不能可靠恢复跨菜单的最后一次选择，因此不自动迁移、不删除。新共享键缺失或值非法时默认 `table`，用户下一次明确选择统一生效。
- `EsTable` 默认仍为表格；仅支持表格的页面不消费共享 store，不会因为全局值为卡片而改变展示，也不会反向覆盖偏好。
