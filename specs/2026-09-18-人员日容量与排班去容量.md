## 1. 已确认业务契约

| 项 | 结论 |
| --- | --- |
| 容量归属 | 方案 B：日容量只存在 `afs_service_personnel.daily_capacity`；排班表删除全部容量列 |
| 排班 UI | 新增/编辑日排班、周期生成、批量调整均去掉日/上/下/晚容量；日历与详情只展示排班类型与服务项目 |
| 人员日容量 | 新增/编辑必填，整数 1–999；存量迁移默认 5 |
| 改人员容量 | 不回写历史排班行（排班已无容量列）；分配立即按人员主档新值计算 |
| 当日工单数 | `personnel_id` + `expected_date`（预约日）+ `status IN ('PENDING_COMPLETION','PENDING_REVIEW','COMPLETED')` |
| 饱和度展示 | `floor(assignedCount * 100 / dailyCapacity)%`，超容显示实际值（可 >100%） |
| 智能打分 | 仍用剩余空间 `(1 - assigned/capacity) × 饱和度权重 + 满意度 × 满意度权重`；分子分母与手动一致 |
| AI | 入参饱和度与手动展示同一占用率口径 |
| 客服派站 | 不改；站级饱和度仍用 `afs_service_station.daily_max_orders` |
