## 1. 本次确认范围

总部运营配置消费者首页 Banner，支持维护多张及排序。小程序支持自动轮播和手动滑动切换；用户后续确认自动轮播，覆盖本次对话中先前的“仅手动切换”选择。可使用 TDesign 轮播组件实现。

| 配置项 | 必填规则 | 含义 |
| --- | --- | --- |
| 图片 | 首版按必填设计 | Banner 主图；本次仅明确其他字段可选，图片必填为开发默认 |
| 标题 | 否 | 图片上配套展示的标题，留空不显示 |
| 按钮名称 | 否 | 跳转链接的文案，统一字段名称为“按钮名称”；留空不显示按钮 |
| 跳转方式 | 默认“不跳转” | 不跳转、小程序内部页面、H5 页面三选一 |
| 跳转目标 | 否 | 内部页面目标或 H5 地址；可以不配置跳转 |
| 排序 | 系统提供默认值 | 决定小程序多张 Banner 的展示顺序 |

### 跳转与展示的开发默认

- 不配置链接时按“不跳转”处理；标题和按钮名称均不影响图片展示。
- 选择内部页面或 H5 时，表单要求填写对应目标；若清空目标，则提示切回“不跳转”，不保存“可跳转但无目标”的配置。
- 有有效目标时点击 Banner 可跳转；按钮名称填写后显示同目标按钮，事件只触发一次跳转。按钮名称留空仍允许点击图片。
- 不跳转时图片仅展示，即使保留了按钮名称也不显示动作按钮；后台保留文案以便后续切换，预览按实际显示规则处理。
- 多张自动轮播并支持手动滑动；单张不轮播、不显示切换指示；无可展示内容时收起 Banner 区域。
- 首版轮播间隔采用组件默认或固定值，不额外增加运营配置项；具体值在实现时记录。切换动画与圆角、标题、按钮外观遵循消费者现有 UI 规范。

以上为使选填规则可执行的首版默认，后续用户明确调整时以最新确认覆盖。

## 2. 当前事实与实现方向

2026-10-11 只读核对：正式消费者首页尚未接入运营 Banner；近期首页 Banner 设计存在于 HTML 原型，不能当作正式应用实现。售后后端本轮 Java／SQL 定向检索未发现 Banner 实现；管理配置页面和授权仍需开发时核对。

消费者仓库已使用 `@tdesign/uniapp` **0.10.3**，`src/pages.json` 已配置 `t-*` 按需组件映射。已安装包的 `dist/swiper/swiper.vue` 支持 `autoplay`、`interval`、`loop` 和图片列表；优先复用 `t-swiper`。标题与按钮组合需要核对该版本的内容扩展能力，不能直接照搬原生微信 TDesign 组件 API，也不以新装第二套组件库作为默认方案。

当前包的轮播项主要渲染图片，只提供导航相关插槽；标题／按钮可在轮播容器叠层并跟随当前项更新，实施时重点验证滑动与点击不串项。若需要修改共同基础控件或新增基础 Demo，按双端共同底座规则同步服务人员仓库；单纯消费者 Banner 业务组件不扩展人员业务范围。

总部配置在 `gaia-ui/apps/after-sales` 开发，复用现有列表、编辑弹窗及附件上传能力；Banner 数据由售后独立持有，复用 Gaia 认证、租户、菜单与操作权限。首版建议列表提供图片预览、标题、按钮名称、跳转方式／目标和排序，编辑表单提供消费者效果预览。具体稳定菜单 code、路径、接口和数据字段在开发时按源码核对后补齐，不预造已存在的注册信息。

## 3. 跳转实现与权限边界

- 内部目标由后台选择可运营的消费者页面，使用已注册路由及参数白名单；不能跳到服务人员、后台、开发 Demo 或任意未注册路径。Tab 与普通业务页面分别复用现有导航封装。
- 目标需要消费者身份或本人商品／工单上下文时，沿用目标页面的登录及资格校验；Banner 不授予权限，也不由运营填写其他消费者的私有记录 ID。
- H5 拟通过专用网页承载页打开，目标校验与地址编码由前后端共同处理，不向 URL 附加会话 Token 或消费者隐私信息。允许协议、域名及平台配置须在实施前核实。
- 微信 `web-view` 平台条件核对入口：[微信官方文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html)。本轮官方页面未成功读取，尚未核对本项目业务域名与真机打开能力，不能宣称任意 H5 地址可用。
- 配置只允许已授权的总部运营岗位维护；菜单可见和读写权限分别核对，未经授权岗位必须由接口拒绝。公开首页读取仅返回可展示字段，不暴露后台审计和内部信息。

## 7. 2026-10-11 通用列表高度与刷新入口纠正

用户要求移除刷新按钮，追查首版未撑满原因并补充前端约束。原UI规范第3节及AI执行规范第“Web前端复用约束”已明确连续高度链、空／加载高度和不设独立刷新按钮；本次属于实现未遵守已有规范，不将问题归因为缺少要求。

首版Banner虽复用了FaPageMain、EsTable及flex内容区，但FaPageMain原默认按内容确定高度，页面根未提供可用高度，EsTable的100%缺少可解析的父层高度，导致按内容收缩。上轮仅用业务页私有视口高度公式修补；本轮调查时该补丁已生效，但仍要求每个新页面自行补高度，容易重复遗漏。刷新按钮是业务页主动添加的tools插槽，并非通用组件默认生成。

本轮为FaPageMain增加 `layout="list"`：通用层统一宿主剩余高度、根min-height和内容区flex高度链；Banner切换该模式并移除私有高度公式，继续使用EsTable默认高度和flex父层。普通内容页、仪表盘和折叠行为保持原默认。移除Banner刷新按钮和未使用的中英文键，工具栏仅在有新增权限时渲染；保存／启停后自动更新及错误恢复逻辑保留。UI规范、AI执行规范和工程README补齐具体调用方式、禁止复制视口公式、检查实际表体／分页及无动作不渲染工具栏。

- 新增2项通用组件运行时回归通过，验证列表模式无需业务样式即可获得高度链，普通／折叠模式保持。最终完整check为594项、558通过、36项失败，失败名称集合与正式历史基线完全一致；静态、类型、国际化阶段通过，完整门禁仍失败。
