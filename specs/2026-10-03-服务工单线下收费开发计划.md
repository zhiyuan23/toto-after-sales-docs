## 1. 已确认的核心操作方式

| 角色／场景 | 本期操作 |
| --- | --- |
| 默认全免费 | 系统自动记录本单免费政策；消费者申请、派单预约、师傅三步处理及审核办结保持原样，不增加报价、费用确认或收款必填项 |
| 服务人员 | 收费模式允许时，检测后填写服务／配件费用明细；维修前向客户说明并记录口头同意；执行后核对最终费用、登记线下收款 |
| 消费者 | 现场／电话确认报价；小程序只查看本人费用与收款登记，不新增必点确认、签名或付款步骤 |
| 客服／服务站 | 正常建单、派单和协调不新增收费审批；已知上门／检测费须在发生前告知确认，例外事项由指定授权岗位处理 |
| 原完工审核人员 | 在现有审核页面核对费用依据、客户确认、实际耗用和收款登记；首期收费单走人工审核，无新增日常二次财务审批 |
| 费用异常处理人员 | 按独立授权处理未收、退款、减免或争议；不把例外办理变成所有工单的新增环节 |

收费类型不是可任意修改的工单主状态。师傅操作明细和确认记录，后端据明细得出全免费、部分收费或全收费；总开关关闭且本单采用全免费政策时，师傅不能自行启用收费。

## 2. 范围与实施边界

### 2.1 本期包含

1. 租户级收费总开关，默认全免费；最小收费项目／标准配置，支持免费、固定价格、获授权人工报价。
2. 各建单入口统一保存本单收费模式及政策版本；可信消费者商品仍直接进入现有工单，不恢复服务受理。
3. 本人任务费用明细、不可变报价版本、独立的费用口头确认记录及报价拒绝／增项处理。
4. 线下收款登记，支持实际未收、部分收款、已收；核对及异常处理与现有审核衔接。
5. 完工提交关联费用版本；后台人工与自动审核的费用约束由后端固定门禁执行；退回重提不重复收款或扣库。
6. 消费者本人费用只读展示，以及后台按工单查看费用、处理获授权的收款纠正／退款等异常。
7. 必要迁移、权限、审计、幂等、并发控制、三端及真实接口验证。

### 2.2 本期不包含

线上支付、支付网关／回调、线上退款、消费者必办在线确认或电子签名、师傅佣金、品牌与服务站分账、对公结算、完整开票／税务系统、复杂计价规则引擎。预收款的正式办理在政策确认前不开放。A13 服务项目已退役，不直接恢复旧注册、页面或历史前端调用。

本计划适用于现有安装、维修、现场指导和远程指导；判断位置按服务类型安排。维修通常在现场检测后确定报价；远程收费在提供收费指导前确认，仍不得领料或耗用配件。不得借收费扩展开放远程原单转上门等未确认动作。

## 3. 核心规则与完整交接

### 3.1 从维修建单到办结

1. **建单：**后端保存本单政策。全免费直接记录政策依据；收费启用时初始可为待判定，消费者不自行填写费用或保修责任。
2. **派单／预约：**沿用原操作。已有可靠权益资料可预判；上门／检测本身收费时由联系人员在发生前告知并保存确认，不要求完整维修报价先于派单。
3. **签到／检测：**沿用现有现场或远程开始动作。开始检测不等于已经获准执行全部收费项目，不能要求所有维修在签到前确定最终费用。
4. **报价：**师傅根据故障、实际项目与政策形成明细；政策不清或超出权限交指定授权人员，不直接切换收费标签。
5. **客户口头同意：**师傅在执行收费项目前保存对应报价版本、确认方式、发生时间及说明。该动作独立落库，不能只在完工提交时补勾选“已同意”。记录明确标为“服务人员登记的客户口头确认”，不冒充顾客账号操作。
6. **执行／增项：**只按已同意内容执行；新增项目或增加金额形成新报价并重新确认。重复确认或网络重试不产生重复费用。
7. **完工：**核对最终明细与实际耗用，沿用“服务处理 → 证据与确认 → 核对提交”，关联本次费用版本；收款按实际发生登记，不能把未收写成已收。
8. **审核／办结：**收费单转原授权人工审核。通过仍直接 `CLOSED`；费用确认缺失或争议转人工处置，不能自动通过。用户后续确认未收齐不得办结；完工材料与实际未收／部分收款仍可如实保存，审核通过前必须收齐并核对。
9. **后续：**未收、退款及争议保留独立待办；消费者只读展示。抽样回访、评价和再次服务继续按各自契约办理。

完整流程图见[费用模式逻辑图](../05-业务流程/08-费用确认与线下收款.md#3-收费模式逻辑图)，本计划不复制第二份长期维护的完整图。

### 3.2 收费判断与免费兼容

- 免费权益需结合已核实购买、保修／延保资料、适用政策及检测结果；不能直接以自填日期判定免费或收费。
- 全免费模式对本单允许提供的项目采用免费政策，不绕过服务资格、权限、归属和库存规则；不开费用输入和确认必填。
- 收费模式内，所有最终项目应收为零且依据完整时为全免费；有免费项目又有收费项目为部分收费；实际项目均收费为全收费。人工减免按单独权限留痕，不能用改零价隐藏收费历史。
- 尚待核验、尚未选完项目或价格缺失时为待判定，不因总金额暂为零就写成免费。完工正常提交须完成费用判定；确认异常不得伪造同意，应保留服务事实并走授权人工处置。
- 本单曾有收费版本、人工减免、退款或费用争议，即使当前应收变为零，也保留财务风险并转人工核对；不能靠把金额改零绕过收费审核门禁。全免费政策自动记零不属于人工减免。
- 费用判定不恢复服务受理关卡，也不增加客服、服务站两轮审批。无法自动确认的情况只交指定的授权岗位。

### 3.3 政策和价格版本

- 总开关只影响新工单：旧免费单不能自动变收费；关闭后已有收费单仍能办理原有确认和收退款。
- 本单绑定的政策版本保留其适用收费项目及标准，后续读取须能取得历史版本；检测后具体报价保存名称、单价、数量和依据快照，不只存当前主档 ID。
- 首版收费配件严格使用已有零售价，服务人员不可自行改价／减免；定版保存实际价格快照。成本价不作为对客报价，缺失／默认零价不等于免费；零价收费项须先由授权岗位补齐标准，或明确采用合法免费依据。
- 已确认报价不可原地改写；重报价、减少实际项目、减免和纠正保留新版本与原因。有收费内容变化时重新取得适用确认，不能以新版本覆盖已执行事实。
- 历史无费用数据的单据标为“历史费用未记录”；不批量补零、补同意或补收款。对上线前已存在的未完工单默认不追溯收费，需明确例外才能采用新政策，并保留迁移依据。

### 3.4 线下收退款与库存

- 收款金额、方式、收款主体／人员、发生时间和凭证独立记录，登记与已核对分别展示；现金、转账的凭证要求在阶段 0 确认，不强制所有现金收款提供不存在的转账截图。
- 消费者展示“服务人员登记收款／后台已核对”的实际来源；未核对不伪装为支付平台回执。
- 多次收款合计不能超过有效应收；发生真实超收时进入授权异常纠正，不能静默删除历史。退款关联原收款，累计退款不超过可退金额，不以改小原收款替代退款。
- 应收调整与现金退款分开记账：退掉取消项目时要有对应应收调整及理由，不能仅计算“收款减退款”就把已退款项目重新算作欠款。
- 领料、耗用、费用和收款独立；收费配件关联实际耗用，免费配件照常扣库。完工提交按既有规则扣库，审核、收款、退款及纯补资料重提不得再扣一次。
- 全额实收、未收、部分付款均如实记录；未收齐不得办结，不开放后付例外；未收／部分事实与完工资料仍可保存。

## 4. 数据与接口实施设计

以下为初始设计，第11节已按阶段0源码核查细化接入位置和技术契约，第12节按用户后续授权及官方资料固定人民币、两位小数和对客最终应付价。实际接口、结构和权限以第17／18节为准；下列为阶段0时的设计，历史实施状态不覆盖最终记录。只建设当前能力需要的数据，不预留支付网关或分账配置。

### 4.1 最小数据对象

| 对象 | 主要内容与一致性约束 |
| --- | --- |
| 收费配置及版本 | 模式、收费项目、服务类型、单位、免费／固定价／人工报价、参考价、启停；每次保存保留版本与审计 |
| 工单费用上下文 | 工单、创建时政策版本／快照、当前费用类型、最终费用版本、乐观版本；同工单唯一，旧单识别为无历史费用数据 |
| 费用／报价版本与明细 | 工单、版本、项目、产品／配件、数量、单价、减免、应收、免费或收费依据；确认后不可变，与本次完工版本关联 |
| 费用确认记录 | 报价版本、同意／拒绝、现场或电话口头确认、发生时间、服务端记录时间、人员及说明／附件；与服务结果确认分开 |
| 收退款及纠正记录 | 原报价／最终费用、收款主体、经办人、方式、金额、发生时间、凭证、核对结果；退款或纠正关联原记录，保存不可变办理历史 |

金额由后端用确定精度的十进制计算和校验，前端金额／汇总不是权威值；首版人民币、两位小数，金额SQL类型采用 `DECIMAL(18,2)`，按客户最终应付价记录，不自动额外加税。官方含税属性及收费单位分别核验，具体边界见第12节。普通单据只显示收费类型与收款摘要，不把这些字段写入原工单主状态枚举。

### 4.2 API 与权限分组

| 接口能力 | 必要检查 |
| --- | --- |
| 总部读取／保存收费配置 | 复用 Gaia 租户与服务配置框架，读写分权、版本冲突和配置历史；开关缺省为全免费，不能误启收费 |
| 本人任务读取费用／保存费用草稿 | 从人员会话解析租户、本人任务和当前组织；校验本单政策，不接受客户端自行指定人员或收费模式 |
| 报价定版／口头确认／拒绝 | 工单、草稿和报价版本匹配；当前人员获权，确认记录绑定准确版本；拒绝不自动取消已有有效费用 |
| 本人收款登记／后台纠正退款核对 | 独立操作权限、版本与请求号幂等、金额上限、凭证本租户本单归属；禁止“可看工单即能减免退款” |
| Web 费用查看及异常办理 | 原工单数据范围叠加费用操作授权；不扩大客服全局或服务站跨站范围，已办结单允许获权费用办理但不改服务终态 |
| 消费者本人费用只读 | 复用真实本人单据归属；只返回对客费用、确认及实收信息，隐藏成本价、内部审核说明、敏感收款账号和内部凭证 |
| 完工提交／人工审核／自动审核 | 共用费用校验与快照关联；旧版本拒绝、提交幂等；收费或财务异常强制人工，执行前再次检查当前风险 |

费用草稿可复用现有自动保存，但正式报价确认和收款要有独立受控动作，失败保留输入，超时通过请求号查询已落库结果；不得默认重试写请求。关联工单、费用、完工及库存时复用既有事务和锁顺序，实施前核对并发路径，避免收费新增锁造成死锁。

### 11.5 事务、幂等与审核门禁

1. **政策和建单：**配置写仅锁当前政策、插入不可变政策版本后更新指针，不锁现有工单。建单在原创建事务读取一次有效政策版本并写唯一上下文，工单／上下文任一失败全部回滚。读固定版本，避免后续读取最新政策改写旧单；未初始化或读取失败须明确处理，不把基础设施故障伪装免费。
2. **单据费用写：**先校验身份范围，再按工单锁 → 费用上下文 → 费用草稿／关联事件的顺序处理。同请求号同hash返回原结果，同号异hash409；幂等重放在业务版本拒绝前判定，但始终重新校验当前访问资格。报价确认、收款或争议变化更新费用revision，审核不能复用旧费用版本。
3. **移动完工：**沿用锁单 → 服务草稿的已有顺序，再锁费用上下文并校验最终版本 → 按配件ID排序锁库存 → 同事务写完工与引用。独立费用动作不反向锁服务草稿或库存，收退款、核对、审核不扣库。库存领退料原有锁序保留，阶段1／3用实际Mapper路径复核并发，不能把本次静态核查当死锁已验证。
4. **共用校验：**服务人员首次提交、定向补充、Web代提交、人工审核及自动审核最终执行均调用同一费用规则。首次提交检查判定／确认／配件对应及当前费用版本；纯补资料保留原引用，新费用变化要求新版本和适用确认。免费与历史无记录继续原门禁，不新增必填。
5. **自动审核：**初判及最终锁单事务均检查本单费用版本和累计风险；收费、减免、退款、争议不能经AI建议或智能结果办结，转原人工队列。最终共用办结点验证来源与费用风险，阻断其他调用路径绕过，不把AI识别文本作为金额或收款证据。
6. **人工审核：**免费仍按原审批通过直接 `CLOSED`。收费在原审核页面核对当前提交版与费用版，并记录本次核对结论；“全部收齐／部分／未收”的事实不改变工单枚举。未收齐办结及确认异常的例外授权待确认，未定时拒绝该例外，仍能保存真实未收／部分事实及服务材料；不得增加所有工单的二次财务审批。
