## 1. 当前有效的数据边界

售后子系统独立持有商品、分类、系列、配套关系、配件、代理商、门店、顾客、服务资源、库存、工单、知识和投诉等业务数据。业务主键、关联关系、启停状态、唯一性校验和业务数据范围均以售后自有数据为准，不直接读写、关联、引用或默认同步 Gaia 主系统业务主档。

旧文档中的“复用主档＋售后扩展”“代理商／门店读取 Gaia/DWH 权威主档”不再是开发目标。`md_material`、`md_material_type_category`、`md_customer`、`md_store`、`md_store_type` 等名称仅用于记录旧实现和定位待整改依赖，不能作为新功能的数据来源。建 `afs_*` 关系表但仍引用主系统 ID，也不算业务数据独立。

此前已确认统一使用的 Gaia 登录、用户、角色、菜单、按钮／API 权限和租户平台继续按原方案提供；组织可承担授权能力，但不能继续通过主系统代理商／门店记录解析售后业务归属。复用框架、事务、主键生成器和响应包装不代表复用业务数据；序列命名空间须归属售后表，校验不得查询主系统商品／单位／工厂业务数据。物理数据库是否单独部署不在本次文档修改中假定为已经完成。

原需求中的 DWH、追溯、销售出库核验保留为外部集成需求，不等于直接读取 Gaia 主系统表。接入必须另行明确接口、来源标识、幂等和快照边界；不得将外部系统记录作为售后主档的隐式共享 ID，或默认与主系统同步。

## 3. 初次核查未发现直接业务主档依赖的范围

- 服务项目基础字段（A13）：当前对应 CatalogMapper 语句只读写 `afs_service_item`／审计；共用 `GaiaCatalogPolicy` 类型，但该用例使用主键能力，不调用商品 GTIN 校验。
- 家装公司、服务站、服务区域（A05/A06/A07）、服务人员／按日可用性／质量投影（A26/A27/A28）：相关 Mapper 使用售后自有业务表。通用身份／权限和操作者 ID 属平台能力。
- 配件库存六项（A30～A35）：仓库、配件、归属、余额、流水及单据查询使用 `afs_*`，未发现该库存切片直接查询 `md_*`。配件的适用品番功能仍有上表依赖，库存与工单完工联动也尚未完整验收，不能据此宣称端到端完全独立。
- 标签定义（A14）：当前定义和版本只读写自有表；会员关联／自动打标尚未实现，不计为已经隔离的业务链。
- 消费者小程序：当前 `src/api/index.ts` 仅导出通用请求工具，页面主要为路由／壳，未发现已接入上述主档的真实业务 API；不据此认定消费者功能完成。服务人员／客服助手未有可核验的对应实现。

上述结论来自当前生产 Mapper、跨 Mapper include 及调用服务的核对，范围不包含 Gaia 全系统各业务模块的全面审计，也不证明运行时数据库存在物理隔离。

先落实售后商品／分类、代理商／门店／类型自有主档及授权归属，随后改造全部直接和间接引用、主键序列、校验服务、接口模型与页面说明。已有业务记录的关联和快照须明确迁移／保留策略，不能仅替换表名、让旧 ID 自动指向另一条同号记录，或擅自复制／清空主系统数据。物理表名、列定义和迁移脚本在实施时核对，本次不虚构已建表。

完成标准：以仅含售后业务表及必要平台认证权限表的隔离数据源运行相关真实 SQL 和写路径；覆盖分类／商品写入与唯一性、系列配套／配件关联、代理商门店、登记预约／工单流转、知识／投诉／报表／沟通，并验证跨租户和越权拒绝。主系统商品或门店数据变化不应改变售后业务数据、唯一性和业务归属；同时确认平台授权变化仍正常生效。最后完成已授权目标环境的数据迁移和回归，才可标记“业务数据独立已完成”。

首轮仅进行静态核查和文档检查；旧测试数量及共享环境记录保留原时点。后续代码修改的实测证据见下节，不替代目标环境迁移和业务验收。

### 迁移与数据保护

合并后由 [V3 DDL](../../../backend/gaia-after-sales/database/20260910_catalog_v3_independent_product.sql)创建 7 张商品及关系表，[补充 DDL](../../../backend/gaia-after-sales/database/20260911_independent_business_data.sql)创建 5 张独立配置／渠道表，不再重复建商品和分类表。全新独立模型切换先运行[切换预检](../../../backend/gaia-after-sales/database/20260911_independent_business_data_preflight.sql)，按[切换与恢复说明](../../../backend/gaia-after-sales/database/20260911_independent_business_data_rollback.md)处理。预检对已有目标表及旧售后商品／分类扩展、关系、登记／实例／工单和相关审计中的存量记录拒绝直接切换，防止旧 ID 被错误关联。代码没有复制、同步、清空或自动迁移任何主系统数据。

有旧售后业务数据时，须另外确认售后数据来源、旧新 ID 映射、全部引用及审计保留策略；本次不生成猜测性数据、不自动迁移既有账号业务归属。渠道自有资料及组织归属未初始化前页面为空是预期行为，不回退读取主系统。旧扩展表保留但不再访问。DDL 非事务性，失败恢复及禁止直接退回旧共享主档应用的限制见恢复说明。
