## 1. 本轮目标

为服务站服务人员登录小程序做身份前置：在 Web「服务人员」主档生命周期内，自动维护 Gaia `sys_user` 并与人员档案绑定。

**本轮只做开户与绑定同步，不做小程序登录接口。**

## 2. 已确认规则

| 项 | 结论 |
| --- | --- |
| 账号载体 | Gaia `sys_user`；人员表**不**自建密码字段 |
| 登录名 | = 人员手机号 `mobile` |
| 初始密码 | 固定 `123456` |

| 一人一站 | **已落地**：新增／编辑只能选 1 个站；后端拒绝多站；历史多站清洗脚本见 `20260918_personnel_one_station.sql` |

## 3. 本轮范围（待开发）

### 3.1 数据

- `afs_service_personnel` 增加可空绑定字段 `sys_user_id`（新增成功后必填；历史可空）。
- `sys_user_id` 在有值时应唯一（一账号只绑一人）。
- 不在人员表存 password。

### 3.2 角色

- 迁移或管理脚本／一次性初始化：创建名称为「服务人员」的 `AFS_` 角色。
- 本轮角色**无售后菜单授权**（空权限可接受）。
- 开户按角色名称或稳定配置查找，避免写死环境相关 ID。

### 3.3 新增人员

同一事务内：

1. 既有人员校验（工号／手机唯一、技能、所属站等）。
2. 预检：同登录名（手机号）的 `sys_user` 已存在 → 拒绝。
3. 写入人员主档及关系。
4. 经售后 identity／Gaia 能力创建用户：登录名=手机号，密码=`123456`，角色=「服务人员」，尽量标记首次须改密。
5. 回写 `sys_user_id`。
6. 任一步失败整单回滚。

前端：可不增加密码输入；保存成功后提示已开通账号（手机号）、初始密码 `123456`、首次登录须改密。

### 3.4 编辑／启停／删除（纳入本轮）

| 动作 | 行为 |
| --- | --- |
| 改手机号 | 校验新号未被占用 → 改人员 `mobile` → 改绑定用户登录名 |
| 停用 | 人员 `enabled=0` + 绑定用户禁用 |
| 启用 | 人员启用 + 绑定用户启用 |
| 删除 | 既有删除约束通过后：删人员 → 删绑定用户 |

对**无** `sys_user_id` 的历史记录（本轮不补开户）：

- 改手机号：只改人员字段。
- 启停：只改人员字段。
- 删除：不删除任何 `sys_user`。

### 3.5 本轮验收要点

1. 新增成功 → 存在绑定 `sys_user`（登录名=手机号）且角色为「服务人员」。
2. 手机号已被系统用户占用 → 新增失败，人员未落库。
3. 改手机号成功 → 登录名同步；冲突 → 拒绝且人员手机号不变。
4. 停用人员 → 绑定用户为禁用态。
5. 删除人员 → 绑定用户一并删除。
6. 无绑定历史人员：不自动开户；删除不误删无关账号。

## 4. 业务约束：一人一站（已落地）

### 4.1 「主站／首站」说明（历史实现用语）

历史实现曾允许人员挂多个服务站（`afs_service_personnel_station`），保存时列表第一项写入主表 `station_id`。现已收敛为一人一站。

### 4.2 业务规定

- 一个服务站可有多个服务人员。
- **一个服务人员只能属于一个服务站。**

在一人一站生效后，登录后不再需要「默认站 vs 进端再选站」；当前站即其唯一所属站（登录上下文见 F-09）。

### 4.3 落地内容（F-08）

- 前端：人员新增／编辑所属站单选／更换，不可多选追加。
- 后端：保存时 stations 多于 1 个则拒绝（`服务人员只能归属一个服务站`）。
- 历史数据：`gaia-after-sales/database/20260918_personnel_one_station.sql`（需目标环境授权后执行）。
