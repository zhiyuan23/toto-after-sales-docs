# 防窜货明细与消费者扫码无购买登记建单

2026-10-12 共享测试环境已补充 2026-09-13 至 2026-10-13 的关联演示数据：94 条疑似结果、7 条正常对照，真实登录的明细、趋势及排行榜回读一致；执行、备份与验证边界见[演示数据补充记录](2026-10-12-疑似串货演示数据补充.md)。

## 已确认口径

- 原“防窜货查询”下线；侧栏仅保留“防窜货 / 窜货明细”。该入口只分配给总部运营视角和系统管理员视角。
- 不再使用师傅小程序签到经纬度。服务工单完工审核通过后异步判断，判断不阻塞审核通过。
- 地址来源为服务工单保存的省、市、区县、街道、详细地址。当前销售区域配置的最细粒度为区县，因此范围匹配使用省/市/区县；街道和详细地址用于展示及审计追溯。
- 每个商品唯一码只保留最近一次判断。最近一次的所有校验项均为“否”时，不进入窜货明细。
- 无购买登记消费者工单中：“是否无购买登记”为“是”；“入库门店跟登记门店不一致”和“安装地址不在登记门店销售区域”为“--”；仍继续判断最下级出库经销商销售区域。
- 销售区域未配置或地址行政区不完整时，相应范围校验展示“--”，不单独认定疑似窜货。
- 消费者扫码只关联“我的产品”，不会创建购买登记或产品实例。消费者后续主动发起安装、维修、指导时，才建立无购买登记工单；申请页必须填写省、市、区县和详细地址，售后后台工单创建仍要求购买登记。

## 校验项

1. 无购买登记：消费者扫码关联商品创建工单时为“是”。
2. 入库门店与登记门店：有购买登记且两个门店均存在时比较；不一致为“是”。
3. 登记门店销售区域：有购买登记且登记门店维护销售区域时，以工单行政区判断；不在范围内为“是”。
4. 出库经销商销售区域：以商品实例渠道主档的最下级出库经销商（`selected_dealer_id`）维护的销售区域判断；不在范围内为“是”。

任一项为“是”即为疑似窜货。列表只返回疑似结果。

## 迁移顺序

1. 执行 `gaia-after-sales/database/20260928_consumer_scanned_service_order.sql`。
2. 执行 `gaia-after-sales/database/20260928_anti_diversion_detail.sql`。
3. 执行 `gaia-after-sales/database/20260928_anti_diversion_detail_permissions.sql`。
4. 重新登录后验证总部运营和系统管理员可见“防窜货 / 窜货明细”，其他工作视角不可见。

上述三个脚本已按顺序执行到当前本地联调数据库，并完成表、唯一索引、菜单及角色授权回读；其他环境仍须按此顺序单独执行。
