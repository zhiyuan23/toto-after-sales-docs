# 售后主数据导入导出与下载中心集成

## 范围

售后子系统的以下八个模块增加导入、导出全部、导出当页：

1. 渠道与网点：代理商管理、门店管理、服务站管理、服务区域。
2. 商品管理：商品分类、商品系列、商品档案、配件档案。

仅变更售后子系统；不复用或改变其他子系统的敏感信息、下载中心或菜单行为。

## 导入契约

- 导入以“编码”为业务唯一键：同编码更新，不存在则新增。
- 每行单独校验和调用既有新增/编辑应用服务；成功行立即入库，失败行不影响其他行。
- 有失败行时生成 `错误明细.xlsx`，其中包含 Excel 行号、编码、失败原因和原始列值；任务说明汇总新增、更新、失败数量。
- 错误明细和导出结果均可在下载中心的任务中心下载。失败任务只要有结果文件也允许下载。
- 关联对象统一填编码；多值使用英文分号 `;`。带数量的关联字段格式为 `编码:数量;编码:数量`，未填数量时默认为 1。
- 首期只导入结构化基础字段与关联编码；图片、附件、手册等继续在详情页维护。
- 每种模块创建一个系统管理的 v1 Excel 模板，共 8 个。首次进入模板管理、场景配置或调用该模块导入能力时，若不存在则创建，不覆盖人工已有的模板、版本或场景绑定。

## 模板字段

所有模板的第一张表为“导入数据”，表头 `*` 表示必填；第二张表为“填写说明”。

| 模块 | 必填列 | 关联编码列 |
| --- | --- | --- |
| 代理商 | 编码、名称、级别、所属组织编码、省 | 所属代理商编码 |
| 门店 | 编码、名称、所属代理商编码、所属组织编码、省 | 所属代理商编码 |
| 服务站 | 编码、名称、服务热线、服务项目编码、单日最大工单量、所属组织编码、省 | 服务项目编码、服务区域编码 |
| 服务区域 | 编码、名称、范围层级、省 | 无 |
| 商品分类 | 编码、名称 | 上级分类编码 |
| 商品系列 | 编码、名称 | 无 |
| 商品档案 | 编码、名称、商品分类编码、安装配件编码及数量 | 商品分类编码、商品系列编码、安装配件编码及数量 |
| 配件档案 | 编码、名称、单位成本价、单位零售价 | 关联商品编码及数量 |

网络类模板同时包含已有新增表单的结构化地址、地图坐标、工商及结算字段；不含附件。条件必填（例如非一级代理商的上级编码、服务区域层级的市/区县/街道、商品保修月数）由逐行服务校验返回明确错误。

## 导出契约

- “导出全部”读取当前已生效的筛选条件下全部数据，最多 10,000 行；超过上限提示缩小筛选范围。
- “导出当页”使用页面当前已展示的记录 ID，不会误导出其他页；商品分类在树形视图默认展开，因此导出当前已展示的树节点，在卡片视图导出当前层节点。
- Excel 列与对应列表查询结果列一致，不包含操作列；售后导出保持明文展示。
- 每次导出创建下载中心任务和结果文件。

## 菜单、权限与场景

迁移脚本：`gaia-after-sales/database/20260921_master_data_transfer_permissions.sql`。

- 为八个售后页面分别注册 `import` 与 `export` 操作，并登记 API 权限。
- 页面拥有者获得导出和任务中心（下载中心、任务中心、下载文件）访问；已有同一页面新增和编辑权限的角色获得导入，避免绕过既有写权限。
- 生成模板后，自动将每个页面的 `import` 按钮绑定到相应的 v1 模板。后续在“场景配置”修改绑定后不会被系统覆盖。
- 回退脚本只删除此次新建的操作和动态授权记录，不删除用户已产生的业务数据、模板、版本或任务文件。

## 接口

基础路径：`/api/afterSales/master-data/{moduleCode}`，其中 `moduleCode` 为 `dealer`、`store`、`service-station`、`service-area`、`category`、`series`、`product`、`part`。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/permissions` | 返回当前角色导入、导出能力 |
| GET | `/import-template` | 下载场景绑定的 Excel 模板 |
| POST | `/imports` | multipart `file`，同步逐行处理并创建导入任务 |
| POST | `/exports` | body 为 `{ filters, rowIds? }`，创建导出任务 |

## 导出文件下载修复

2026-09-21 发现任务中心的导出结果在浏览器中显示为约 91 B、无法打开。排查结果如下：

- 服务器实际生成的 `EXP-1`、`EXP-2` 均约 4.2 KB，使用 ZIP 完整性校验通过，文件本身没有损坏。
- 任务下载前端请求错误地沿用了 `Accept: application/json`，而下载接口只协商二进制内容，服务端返回“无可接受表示”的错误 JSON；浏览器将该 JSON 按 `.xlsx` 文件名保存。
- 修复任务下载为请求 Excel 二进制类型，并在保存前验证 ZIP/XLS 文件签名，错误响应将直接提示而不再伪装成 Excel 文件。
- 已通过专用前端回归测试、ESLint、生产构建和包体检查；测试环境仅更新售后前端静态资源，保留可回滚目录，发布后入口 HTTP 200 且新任务模块资源存在。
