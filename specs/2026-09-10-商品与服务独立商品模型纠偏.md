# 商品与服务独立商品模型纠偏 V3

- 日期：2026-09-10
- 状态：V3 已开发；第 5～6 节为团队原环境验证记录。2026-09-11 合并后的完整独立数据方案另需校验配置、渠道主档和目标环境回归，见[独立边界核查](2026-09-11-业务数据独立边界与已开发功能核查.md)。
- 适用范围：售后服务 / 商品与服务中的商品分类、商品档案、商品系列、配套商品、配件适用品番，以及商品图片、故障及维修、安装手册。

## 1. 最终边界

售后商品是独立业务实体，不是 `md_material` 的扩展、镜像或子集。运行时不得读取、写入、复制或以 `md_material.id` 作为售后商品、分类、图片、故障、手册、系列、配套关系或配件适用品番的主键。

Gaia 平台仍只提供登录、账号、菜单/API 权限、租户数据源、主键生成、事务、通用上传和文件访问能力。通用文件服务返回的文件 URL 可以由售后安装手册和图片引用，但文件服务不改变商品领域的独立性。

## 2. 现行数据模型

- `afs_product_category`：售后商品分类。分类编号在本表内唯一，分类图片、启停、路径、版本和审计字段均归本表。
- `afs_product`：售后商品档案。商品编号在本表内唯一；商品分类、营业分类、机能型号、规格、颜色、保修、上/下架、描述和系列归属均归本表。
- `afs_product.series_id`：一个商品至多归属一个系列；一个系列可包含多个商品。
- `afs_product_image_asset`、`afs_product_fault_case`、`afs_product_manual_file`：分别保存商品图片、故障及维修、安装手册；全部通过 `product_id` 关联 `afs_product`。
- `afs_product_bundle_relation`：主商品至配套商品的有向关系；两端均为 `afs_product.id`。
- `afs_part_product_relation`：配件至适用品番关系；适用品番为 `afs_product.id`。
- `afs_product_series`、`afs_part` 继续是售后自有主表。系列编号、配件编号各自在所属表内唯一。

创建人和更新人保存登录账号的主数据 ID；查询时关联 `sys_user.user_name` 展示账号名。历史记录不物理删除。

## 3. 迁移与历史数据

迁移脚本为 [20260910_catalog_v3_independent_product.sql](../../../backend/gaia-after-sales/database/20260910_catalog_v3_independent_product.sql)。它只创建上列 7 张新的 `afs_*` 表，不包含 `md_material`、`md_material_type_category` 或其他 `md_*` 表的 DDL/DML，也不复制、迁移或删除历史共享物料数据。

脚本为一次性迁移，不使用 `IF NOT EXISTS` 掩盖结构漂移。目录事务锁沿用已有售后技术表 `afs_catalog_lock`；该锁表不承载商品数据，也不依赖共享物料。

此前 V1/V2 的 `afs_product_ext`、`afs_category_ext` 及共享物料关联记录仅保留为历史测试留痕。V3 运行代码和售后前端不再查询这些旧表；旧数据不会被自动清理或转换，避免破坏既有留痕。

## 4. 交互与校验

- 新增商品可在同一个弹窗内维护基本信息、故障及维修、安装手册、配件信息和配套商品；提交时作为一个事务保存，任一子项校验失败则商品和全部子项一并回滚。
- 安装手册接受 PDF 与 Office 文档；PDF 使用售后受控内容接口返回 `application/pdf` 和 `inline` 响应头预览，Office 使用同一接口按附件下载。新增商品未提交前也可预览或下载草稿手册。
- 商品与服务统一使用 `/api/sys/commontools/uploadFile`。图片保存其 `access` 地址，通过平台图片接口读取；不再使用旧上传链路的 `/commonUpload/...` 直连 URL，也不将 MinIO 路径拼到前端开发服务器或本地 Tomcat 地址。
- 商品、分类、系列、配件的编号分别在各自业务表中做大小写不敏感唯一校验；机能型号／条码唯一性在合并后由售后自有 `afs_catalog_settings.unique_model`／`unique_barcode` 控制，不再读取平台参数。
- 停用商品不能新增系列、配套或配件关联；历史关联保留，状态变更受本售后表自身状态约束。

## 6. 商品与服务菜单 API 权限（2026-09-11）

Gaia 模块管理采用“菜单读权限 + 操作写权限”的分层模型。叶子菜单的 `sys_module.api_list` 只登记页面进入、列表、详情、关联明细和文件预览等 `GET` 请求；新增、编辑、启停、关联维护和删除仍由该菜单下的 `sys_module_operation.api_list` 承载，并通过 `sys_role_operation` 单独授予角色。

本地测试库已将以下六个售后菜单的读取规则配置为资源前缀匹配，避免单层 `*` 不能覆盖故障、安装手册等多层路径：

| 菜单 | 模块编码 | `sys_module.api_list` |
| --- | --- | --- |
| 商品分类 | `afsProductCategory` | `GET$/api/afterSales/catalog/categories/**` |
| 商品档案 | `afsProduct` | `GET$/api/afterSales/catalog/products/**,GET$/api/afterSales/catalog/manual-preview` |
| 商品系列 | `afsProductSeries` | `GET$/api/afterSales/catalog/series/**` |
| 配套品管理 | `afsProductBundle` | `GET$/api/afterSales/catalog/bundles/**` |
| 服务项目 | `afsServiceItem` | `GET$/api/afterSales/catalog/service-items/**` |
| 配件档案 | `afsPart` | `GET$/api/afterSales/catalog/parts/**` |

其中 `afsProduct` 的规则覆盖商品详情、故障及维修列表、安装手册列表和已保存手册内容；`manual-preview` 供新增商品尚未提交时预览当前账号上传的草稿手册。`AntPathMatcher` 的 `*` 只匹配一个路径段，故不能用 `GET$/api/afterSales/catalog/products/*` 代替上述 `/**` 规则。

本次没有变更任何角色的菜单或按钮授权，也没有将写接口粗放地并入菜单读取权限；管理员和其他角色重新登录后会加载最新模块 API 配置。后续新增商品与服务接口时，先按所属读菜单或写操作登记精确 HTTP 方法和路径，再授权角色。
