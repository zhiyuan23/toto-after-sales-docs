# 两端微信静默登录与会话保持

- 状态：待验收（研发实现完成，正式微信配置与真机待验）；来源：用户 2026-09-29 确认并授权实施。
- 应用：消费者小程序、服务人员小程序；角色视角不适用。
- 范围：CAPP-001、消费者个人中心、服务人员账号登录与 WAPP-022／WAPP-024；负责人待分配。
- 优先级：P0。两端登录底座单列，不增加业务入口或验收计数。

## 已确认契约

首次主动登录后，正常关闭、重开及普通会话到期不要求重复输入手机号或密码。历史手工填写的手机号仍按2026-09-29业务前提视为可信、已验证；2026-10-19起新绑定及换号改为本页末节微信授权方案。数据库仍保留 `MANUAL_TEMP` 来源以区分手工输入与微信验证，新增／变更手工号码写入验证时间；历史该来源号码在业务上下文中也返回 `phoneVerified=true`。`LOCAL_TEST` 不因此被批量升级。首次登录仍须用户主动发起；2026-10-19最终确认取消自建协议勾选，用户直接点击微信原生手机号按钮后才建立登录，不静默创建新账号。

消费者已有 OpenID 对应独立账号；服务人员首次完成账号密码验证且不处于首次强制改密状态时绑定当前微信。服务人员 AppID／AppSecret 使用独立服务端配置，不复用消费者密钥。绑定保持账号与微信双向唯一，不允许密码登录静默覆盖其他绑定。微信 code 获取失败或绑定接口明确返回可用性错误 `503` 时，允许继续账号密码登录并返回未绑定状态；不对密码错误、锁定或绑定冲突执行降级。首次强制改密完成后再次登录建立绑定；旧服务人员客户端的无绑定会话到期后需登录一次。

业务会话默认仍为消费者 24 小时、服务人员 8 小时。到期前 30 秒或服务端明确拒绝会话时，用新的 `wx.login` code 和本机已保存的会话凭证重新认证。后端校验微信身份与原账号匹配、会话未撤销以及账号／人员有效状态，再延长同一随机会话令牌的有效期。保留令牌可避免续登响应丢失后无法重试；数据库仅保存令牌摘要，不保存密码明文、code、OpenID 明文或 session_key。过期会话只能用于有新微信证明的续登，不能直接访问业务。

2026-09-29 用户补充确认：**无本地会话或清空缓存后重新进入，也必须先尝试微信静默登录**。启动时获取新的 `wx.login` code，调用各端 `/auth/silent`，不传旧会话头。后端根据微信绑定定位既有账号，且要求仍存在至少一条未撤销的服务端登录记录（允许普通到期）；消费者校验账号启用，服务人员额外校验独立 AppID 绑定、在职启用及非首次改密状态，再签发新随机会话。未知微信、不存在可恢复登录记录或已撤销时返回 `4001`，端侧回到原登录入口，不创建新账号、隐式接受协议或绕过密码首次核验。已有缓存仍走原会话校验／续登。

主动退出清除本机凭证、缓存和页面身份，写入本机主动退出标记，并撤销该账号当前端的全部服务端会话，避免其他旧记录成为无缓存恢复入口。绑定关系仍保留，下一次主动登录后重新取得恢复资格。`/auth/logout` 与 `/auth/revoke` 使用相同撤销实现，过期凭证也可退出；已撤销凭证重放不影响之后的新登录。无缓存恢复与退出通过账号行锁串行化，退出后迟到的新会话响应会被丢弃并尝试撤销。离线退出靠本机标记阻止恢复；若服务端撤销失败且再清除全部本地存储，服务端无法获知该次离线退出，不承诺仍阻断恢复。

H5 不伪造微信能力，保留现有密码登录／显式本地消费者测试入口。后台停用／离职／改密等既有会话撤销继续有效，静默登录不能绕过。解绑时须同时撤销该账号所有会话并移除绑定；本切片未增加后台解绑 UI。

## 前端恢复与请求规则

- App `onLaunch` 即启动恢复，先于页面鉴权；`onShow` 与并发请求复用进行中的恢复。恢复期间显示加载状态；消费者已按用户最新要求复用 `AppState state="loading"`，只显示转圈图标并沿用统一位置，移除白底“正在恢复登录”文字卡片，无障碍名称保留。成功后消费者读取手机号上下文并加载统一我的商品列表，购买记录进入对应页面时独立加载，服务人员加载企业、服务站和权限上下文；确认未登录后才显示原登录入口。
- 本地持久化包含账号、随机会话令牌和到期时间；消费者同时恢复服务端手机号绑定状态，续登复用原登录时的可信购买同步逻辑。旧消费者缓存无到期时间时先验证服务端上下文。
- 网络超时、临时服务错误保留恢复凭证，不当成用户退出。2026-10-03 按用户确认改为一次轻提示及就近重试，取消公共顶部／登录输入区前的错误卡片；详见下方 OPT-20261003-01。
- 公共认证内核合并同时发生的续登；成功续登不切换账号代次、不清空同账号草稿。账号不匹配、会话已撤销或身份明确不可用时停止恢复。
- 受保护请求发出前检查到期时间；服务端返回 `4001`／HTTP 401 时只尝试一次静默恢复。GET 可恢复后重试一次；写请求不自动重放，提示重试本次操作。
- 恢复、登录和退出使用操作代次隔离；主动退出期间的迟到登录结果不能持久化，已产生的迟到登录会话尝试撤销。
- 消费者“我的”补充主动退出入口；服务人员沿用既有退出入口。

## 接口与配置

| 接口 | 凭证／行为 |
| --- | --- |
| 两端 `POST /auth/silent` | 仅 `{code}`，无需会话头；已有微信绑定和未撤销登录记录才签发新会话 |
| `POST /mobile/consumer/auth/refresh` | `X-AFS-CONSUMER-SESSION`＋`{code}`；校验原消费者与微信身份 |
| `POST /mobile/service-personnel/auth/refresh` | `X-AFS-SESSION-ID`＋`{code}`；校验账号绑定、人员状态及首次改密 |
| 两端 `POST /auth/revoke` | 各自会话头；撤销该账号当前端全部会话，可用过期凭证，重复调用幂等 |
| 服务人员 `POST /auth/login` | 原账号密码＋可选 `wechatCode`；返回服务端确认的 `wechatBound` |

以上完整前缀为 `/api/afterSales`。原 `/auth/logout` 保留路径并统一撤销语义。WAR／Jar 宿主仅将六个新路径精确交给售后独立认证，不放开整个认证目录或后台 API。

服务人员新增 `after-sales.mobile.wechat-app-id`、`after-sales.mobile.wechat-app-secret`；只保存于服务端私有配置，禁止进入小程序产物、日志及提交。消费者沿用现有配置。迁移 `gaia-after-sales/database/20260929_mobile_wechat_session.sql` 只新增 `afs_service_personnel_wechat`，以账号主键和微信摘要唯一索引约束关系，不重写现有账号或会话。

## OPT-20261003-01：自动登录失败轻提示与就近重试

- 类型／优先级／状态：交互优化／P2／待验证（源码及研发验证完成，微信／真机待验）。
- 来源／确认：用户 2026-10-03 反馈关闭调试且未配置域名时两端占位提示干扰页面，并确认本轮轻提示方案。
- 应用／范围：消费者 C01 首页与“我的”、公共页面容器；服务人员独立登录页；共同反馈工具。负责人：待分配。
- 预期结果：自动登录的临时失败不追加公共顶部卡片或表单前错误区，不自动弹 Modal；保留凭证、主动重试和正常首次登录流程。

### 实现规则

1. 两端共用 `sessionRecoveryFeedback.ts`：连续自动失败仅提示一次，主动重试失败可再次提示；成功恢复／主动登录成功清除旧提示记录，取消迟到的网络检测提示。自动取消不弹失败 Toast。
2. 默认文案“暂时无法连接服务，请稍后重试”；只有 `getNetworkType` 明确返回 `none` 才使用“网络未连接，请检查网络后重试”。网络检测失败、域名拦截和超时不得断言用户断网。明确身份错误保留重新登录／联系管理员方向；首次匿名无错误不提醒。
3. 消费者移除 `ConsumerPage` 顶部错误卡片，失败后的重试不卸载公开内容。首页无产品数据时，原内容区提供连接失败态和“重新连接”，不显示尚未绑定或无产品的错误结论；已有数据保留。“我的”保留轻量重试入口及产品未加载提示。成功主动登录清除恢复失败状态。
4. 服务人员登录表单持续挂载，自动恢复与手动重试均不清空手机号／密码；主按钮显示连接进度，输入和操作防重复。登录按钮下方稳定区域显示“重试自动登录”，不在输入区域前增加说明。加载图标和按钮文字水平居中。
5. 认证内核、凭证有效期、首次协议、权限、写请求重放规则不变；本轮不新增强制登录弹窗，不修改域名／调试配置。
