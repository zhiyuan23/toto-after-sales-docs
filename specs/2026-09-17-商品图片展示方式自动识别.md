# 商品图片展示方式自动识别

- 编号：ADM-MD-009-IMG-01
- 应用载体：Web 管理后台、消费者小程序公共数据层
- 模块与入口：A09 商品档案、A11 商品图片（并入商品档案）、C10/C11 的商品图片展示基础
- 状态：待开发（2026-09-17 已按用户要求回退首轮未部署实现）
- 最后更新：2026-09-17

## 1. 已确认范围

计划在商品档案中按商品保存一组封面展示元数据，作用于图片列表的第一张图：

| 字段 | 取值 | 规则 |
| --- | --- | --- |
| `imageBackgroundType` | `solid` / `scene` | `solid` 是商品图，`scene` 是场景图 |
| `imageBackgroundSource` | `auto` / `manual` | 自动识别或后台人工选择 |
| `imageBackgroundConfidence` | `0–1` 或 `null` | 只保留自动结果置信度；人工来源必须为 `null` |

实施后的新增及既有商品安全默认值为 `solid / auto / null`。后端读取到缺失或非法枚举时应封闭回退为 `solid`，不将异常值传给消费端。

## 2. 后台交互与优先级

管理员上传或更换第一张商品图后，前端应调用服务端识别接口。识别采用异步请求，后台显示处理状态，完成后填入类型、`auto` 来源和置信度。

人工点选“商品图”或“场景图”时，立即写为 `manual` 并清空置信度。后到的识别响应只可显示为建议，不得覆盖已有人工值；管理员可显式选择“采用自动建议”恢复 `auto`。连续上传或更换封面时，用请求序号和当前图片地址隔离过期响应。

重新上传必须重新识别，但若当前值已是 `manual`，新识别结果仍只作为建议。识别失败时显示可操作提示；未有人工值时回退 `solid / auto / null`。

## 3. 服务端识别与安全边界

计划提供 `PUT /api/afterSales/catalog/products/image-background-recognition`，接收平台上传返回的 `imageUrl`，返回 `imageBackgroundType` 和 `imageBackgroundConfidence`。该接口复用商品编辑权限，并只允许读取当前租户下可见的平台上传记录，不接受任意外部 URL。

图片读取应在专用有界执行器中完成，异步线程显式传递并清理租户上下文。单文件上限、源图像素上限和读取下采样参数在重新实施时结合真实样本确认。首版可通过边缘颜色一致度与离散度判定 `solid/scene`，但分类器必须可替换，不将算法阈值固化为业务规则。

## 4. 持久化与消费端契约

重新实施时需为 `afs_product` 增加三列及枚举／范围检查约束，并提供独立 rollback 脚本。首轮迁移文件已随功能回退，且从未执行到共享或生产数据库。

计划让消费者商品选项、购买记录实例同时返回封面地址和经后端归一的 `imageBackgroundType`。小程序展示契约：

| 类型 | UniApp `image` mode | 混合模式 |
| --- | --- | --- |
| `solid` | `aspectFit`（等价于 `contain`） | `multiply` |
| `scene` | `aspectFill`（等价于 `cover`） | `normal`（关闭混合） |
| 缺失或异常值 | 按 `solid` | 按 `solid` |

消费者小程序尚未实现公共归一函数、图片组件或消费者选项／记录 API 客户端；文档原型中的展示仅用于说明目标效果，不计真实实现。

## 5. 回退记录

- 2026-09-17 已移除首轮后端字段、识别端点与迁移，Web 配置交互，以及消费者公共组件和 API 客户端。
- 当前源码和数据库基线不包含 `imageBackgroundType`、`imageBackgroundSource`、`imageBackgroundConfidence`，也不包含识别接口；新增商品弹窗不应显示该配置。
- 首轮本地测试结果只说明当时方案可执行，不作为当前版本的完成或验收证据；重新开发后必须重新运行后端、Web、消费者和迁移回滚验证。
- 首轮联调暴露出前端更新而聚合后端仍运行旧 JAR 时，新静态路径会落入旧 `/products/{id}` 路由并返回“无效的记录 ID”。后续部署必须把迁移、模块安装、宿主打包与服务重启作为同一联调检查项。
