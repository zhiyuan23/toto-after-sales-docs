- 应用载体：Web 管理后台（仅独立售后子系统）
- 角色视角：总部运营、客服作业、服务站作业、门店业务
- 关联入口：D03／D04 购买登记、D07 顾客购买记录、A18 服务工单、服务站作业／工单分配
- 关联 Spec：[顾客预约与工单查询全栈首版](./2026-09-10-顾客预约与工单查询全栈首版.md)、[服务站工单分配页面样式确认稿](./2026-09-18-服务站工单分配页面样式确认稿.md)
- 来源：2026-09-20 产品确认

## 1. 已确认范围

1. 区县下的街道选择补齐全国四级行政区划数据；保留可输入、模糊检索和创建输入值的交互，不能因数据补齐限制手工填写。
2. 门店购买登记不再显示“已向顾客展示隐私政策并取得明确授权”选择框，也不生成该登记场景的授权记录。姓名、手机号、地址、门店、商品等原有必填校验仍完整保留。
3. 购买登记弹窗不再显示“* 为必填”提示；字段自身的必填星号和提交校验不变。购买登记列表显示“查看”动作。
4. 仅售后子系统中的所有角色、列表、详情和现有导出读取以明文展示姓名、手机号、详细地址、来源单号等敏感业务字段；不改变主系统及其他子系统。业务库仍以现有 PII 加密列保存，读取层解密后填充既有展示字段，不新增明文落库。
5. 服务工单列表列顺序为：工单号、登记单号、类型、状态、服务站、自动派单，其余既有列顺延。
6. 服务站“工单分配”列表移除联系人和联系电话；分配方式、分配结果、失败原因紧跟工单状态，其他列顺延。

## 2. 异常数据处置

`SO-940918110036` 的库中状态为 `PENDING_VERIFICATION`，前端状态字典没有该值，因而原页面回退显示英文枚举，不是列表渲染顺序造成。经产品确认，该条为异常测试数据，已在共享测试库事务中精确删除其状态历史、工单商品明细和工单主记录；没有关联自动派单、人员分配、沟通、投诉或履约记录，购买登记保留。

## 3. 实现与验证

- 前端：本切片的购买登记 Node 测试 6／6、Vite production build 和 182 个资源包体检查通过；全国街道静态数据共 38,963 条，来源为民政部地名数据快照的 MIT 许可镜像，并提供生成脚本以便后续更新。同步远端后，全量 `vue-tsc -b` 仍在上游新增的派单弹窗、库存筛选、人员提示和排班查询文件报错；本切片相关的登记、工单列表和工单分配类型错误均已修复，不以这些上游错误替代本切片验证。
- 后端：Java 21 下 `mvn -B -pl gaia-after-sales-api -am clean install -DskipTests` 通过；售后宿主 `mvn -B -pl gaia-saas-web -am package -DskipTests` 通过。
- 后端登记集成场景验证了原始 PII 加密存储、登记响应明文展示以及门店登记不写 `afs_consent_record`。完整历史集成套件尚有模板和旧端点等 9 项既有失败，不以其替代本切片验证。
- 独立售后前端的 `pnpm run build` 在既有质量门 `knip` 检测到未使用依赖 `vxe-pc-ui` 后中止；该依赖不在本次改动范围。已单独完成 Vite 产物构建和登录态服务冒烟验证。

## 4. 验收边界

共享测试环境部署后，以真实登录态验证：购买登记新增弹窗的街道下拉与手输、必填校验和无授权框；购买登记列表“查看”；服务工单和工单分配列顺序；以及售后各角色的列表、详情和已提供导出中的明文显示。此记录是研发验证，不代表业务最终验收。
