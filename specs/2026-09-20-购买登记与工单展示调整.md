## 1. 已确认范围

1. 区县下的街道选择补齐全国四级行政区划数据；保留可输入、模糊检索和创建输入值的交互，不能因数据补齐限制手工填写。2026-10-03 购买登记按用户反馈改为省市区与一个详细地址输入框，街道合并展示，既有街道数据仍保留，见第 7 节；其他业务的街道选择不受影响。
2. 门店购买登记不再显示“已向顾客展示隐私政策并取得明确授权”选择框，也不生成该登记场景的授权记录。姓名、手机号、地址、门店、商品等原有必填校验仍完整保留。
3. 购买登记弹窗不再显示“* 为必填”提示；字段自身的必填星号和提交校验不变。购买登记列表显示“查看”动作。
4. 仅售后子系统中的所有角色、列表、详情和现有导出读取以明文展示姓名、手机号、详细地址、来源单号等敏感业务字段；不改变主系统及其他子系统。业务库仍以现有 PII 加密列保存，读取层解密后填充既有展示字段，不新增明文落库。
5. 服务工单列表列顺序为：工单号、登记单号、类型、状态、服务站、自动派单，其余既有列顺延。
6. 服务站“工单分配”列表移除联系人和联系电话；分配方式、分配结果、失败原因紧跟工单状态，其他列顺延。
7. 门店业务的购买登记列表在“顾客姓名”前增加“门店”下拉。选项只返回当前人员组织数据权限内且启用的门店，按代理商编码、门店编码排序并显示“编号 / 名称”；原实现默认选择第一项。列表接口接收门店 ID 后必须再次校验该门店属于当前人员可见范围，不能仅依赖前端筛选。默认值与单门店展示规则已由下文 2026-09-24 调整取代。

### 地图选点加载恢复（2026-09-20）

- 代理商、门店、服务站和创建服务工单共用 `MapLocationPicker`。高德官方加载器在首次地图脚本请求失败后会把失败状态保存在当前页面；原实现仅清理应用层 Promise，用户再次打开任何地图选点弹窗仍会立即失败。

## 6. 2026-09-28 地图地址解析超时与工单定位反馈

- 来源：用户在共享测试环境的门店地图选点与创建服务工单界面反馈。
- 原因：代理商、门店、服务站和创建服务工单共用的 `MapLocationPicker` 对高德 JS SDK 逆地理编码设置了 8 秒保护阈值。该保护用于避免第三方地图回调无响应时弹窗永久加载；测试网络或高德响应超过该阈值时，会显示“地址解析超时”，不是工单创建接口超时。
- 调整：逆地理编码保护阈值改为 20 秒，仍保留超时失败提示和手工填写详细地址的兜底，避免无限等待。创建服务工单在坐标有效时复用门店、代理商和服务站的状态反馈，展示“已完成地图定位”、经纬度和“移除坐标”；移除后恢复地图选点帮助文字。
- 研发验证：`product-instance-detail.test.ts` 与 `work-order-create-dialog.test.ts` 共 10 项通过；变更文件 ESLint 通过。售后子站 Vite production 构建及 237 项 JS／CSS 包体检查通过；主站 `productionSAAS` 构建和主／子入口组合校验通过。全量 Node 测试仍有既有失败（含 `@/utils` 运行时别名解析，以及已变化菜单／页面的旧断言），不以该结果代替本切片定向验证。
- 共享测试环境发布：2026-09-28 已按完整 Web 发布流程替换聚合 WAR 和主／售后静态包。暂存包 `20260928141430` 的 WAR SHA-256 为 `2022e1931f1f94d3970738d87d97708115dcb70365bbfc9571c13d8bf2233a68`，前端包 SHA-256 为 `67a1d90497d85d5fce8faea191783d278feea3b35dc6447a2de7f2c31895f199`；远端回读一致。发布脚本已保留可回退备份 `/yundata/saas_test/backups/20260928141430`，外部运行配置未改动。Tomcat 在 194179ms 内启动完成，服务器内外的根站、`/after-sales/` 和 `/api/` 均返回 HTTP 200；线上售后 bundle 已复核包含 20 秒保护阈值及工单定位状态反馈。
