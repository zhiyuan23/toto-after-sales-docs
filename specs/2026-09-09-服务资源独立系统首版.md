# 服务资源独立系统首版

日期：2026-09-09

范围：A26 服务人员、A27 排班管理、A28 服务质量的可验证首版。

## 已确认实现边界

- 服务人员是售后自有主档，维护编码、姓名、手机号、所属服务站和启停；编码、手机号在租户内按大小写不敏感唯一。人员必须归属一个已启用服务站，停用人员不能新增或修改日可用性。
- 排班采用按“人员 + 日期”唯一的日可用性记录，覆盖工作日（`AVAILABLE`，容量 1～999）、休假（`LEAVE`）和临时停单（`SUSPENDED`，后二者容量固定为 0）。这让后续派单可按日期过滤人员和容量，但本切片不实现派单、工单占用或周期排班模板。
- 服务质量只读读取 `afs_service_quality_daily` 的事实汇总投影，展示服务量、及时率、一次完工率、评价均分和投诉数。该表只能由后续工单完工／评价／投诉闭环的聚合任务写入；当前系统没有这些事实来源时，接口和页面如实返回空数据，绝不生成样例统计或开放人工录入。
- 三项能力均使用 Gaia 登录、租户路由、明确 HTTP 权限、BIGINT 字符串传输、版本冲突保护和审计事务。权限模型与商品分类一致：分组统一提供 `/permissions`，叶子模块登记查询 API，写动作登记模块操作，AppService 对实际接口逐项强校验；服务质量无前端写入接口。

## 明确不在本切片

- 服务技能、服务区域、企业切换、账号绑定、跨站支援和服务站级数据范围。
- 周期性排班规则、任务占用扣减、派单过滤实际接线。
- 工单时效、一次完工、评价、投诉的事实生成、指标口径和区域维度；这些必须随工单闭环确认后实现。

## 验收重点

- 人员的服务站、唯一手机号、启停、权限、租户隔离、版本冲突和审计失败回滚。
- 日可用性的唯一性、容量和状态约束、人员／服务站停用保护、权限、租户隔离与审计。
- 质量页仅能查询已有汇总事实，指标分母为零时显示 0，不将无数据误显示为质量达标。

## 主系统权限配置清单

以下配置与商品分类采用同一结构，主系统保存后才形成完整运行时授权：

| 模块 | `sys_module.api_list`（只读） | `sys_module_operation`（写操作） |
| --- | --- | --- |
| 服务资源分组 `afsServiceResource` | `GET$/api/afterSales/service-resource/permissions` | 无 |
| 服务人员 `afsServicePersonnel` | `GET$/api/afterSales/service-resource/personnel,GET$/api/afterSales/service-resource/personnel/*` | `add`: `POST$/api/afterSales/service-resource/personnel`；`edit`: `PUT$/api/afterSales/service-resource/personnel/*`；`status`: `PUT$/api/afterSales/service-resource/personnel/*/status` |
| 排班管理 `afsSchedule` | `GET$/api/afterSales/service-resource/availability,GET$/api/afterSales/service-resource/availability/*` | `add`: `POST$/api/afterSales/service-resource/availability`；`edit`: `PUT$/api/afterSales/service-resource/availability/*` |
| 服务质量 `afsServiceQuality` | `GET$/api/afterSales/service-resource/quality` | 无 |

- 每项操作的 `code` 与 `action` 保持一致，`enable=1`，并设置稳定顺序。
- 角色同时配置 `sys_role_module` 和所需的 `sys_role_operation`；仅授予菜单不会自动获得新增、编辑或启停接口权限。
- 验收至少覆盖允许角色的菜单／按钮／成功请求，以及拒绝角色直接调用列表或写接口时返回 403。
