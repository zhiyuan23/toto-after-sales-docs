- 类型／优先级／状态：本地联调故障／P1／未关闭；用户要求先保留诊断结果，待网络稳定后复测。
- 来源／范围／负责人：2026-10-10 用户反馈 `127.0.0.1:9010/api/afterSales/authorization?refresh=true` 持续超时；本机售后 Web 与 8080 聚合后端；排查 Codex。用户反馈共享测试服务器连接相同数据库且可正常访问，未据此认定本机链路正常。

## 目标与实施选择

进入售后运行时一次获取当前账号的菜单及按钮快照，保留页面 `permissions()` 调用契约，合并并发初始化并复用结果。Gaia 的 `/api/sys/Module/tree` 和 `/api/sysModuleOperation/getCurrentUserOperationList` 分别返回菜单与按钮，没有覆盖售后按 HTTP 方法／路径投影的全部领域能力，因此新增薄聚合接口。它直接复用 Gaia 服务及 `GaiaAccessContext`／`GaiaPermissionGrantCache`，不请求各业务权限 HTTP 接口，也不建立第二套角色或授权数据。

简短实施顺序：核对原权限规则及基线 → 抽取共同的纯权限投影并提供聚合接口 → 接入统一缓存及兼容适配 → 验证等价性、失效与两种运行模式 → 更新契约和进度。

2026-10-01 [总部服务配置合并](2026-10-01-总部服务配置与两级策略入口合并.md)新增 `stationDispatch` 与 `personnelAssignment` 两个独立 `{ read, editable }` 视图，当前总数 32；客服渠道仍使用 `consumerSupport`，页面复用同一次账号快照。

## 技术契约

`GET /api/afterSales/authorization[?refresh=true]` 返回 Gaia `{ code, errMsg, data }` 响应，`Cache-Control: no-store`。身份从服务端当前登录态取得，租户从 `TenantContextHolder` 取得，不接受请求参数指定其他用户或租户。

| data 字段 | 含义 |
| --- | --- |
| `userId`、`tenantId` | 字符串形式的当前服务端账号、租户；单租户无平台上下文时租户为空字符串 |
| `menus` | Gaia 原当前用户树中售后子树、身份管理三模块及必要祖先；保留显隐属性和原字段，不修改 Gaia 返回对象 |
| `domains` | 32 个权限视图；每项 `{ code, errMsg, data }`，保留原字段名、布尔值及领域元数据 |
| `identityOperations` | `sys_user_list`、`sys_role_list`、`sys_module_list` 的按钮编码数组，沿用 Gaia 原按钮查询的筛选语义 |

权限视图包括目录、渠道网点、服务站、顾客、工单、服务资源、库存、字典、下载中心、两类知识、标签、投诉、回访、工单报表、窜货统计／明细、系统通知，八类 `masterData:{moduleCode}`，以及评价标签、客服渠道、`agreement:TERMS`／`agreement:PRIVACY` 的账号级编辑／发布能力。

原接口与新快照共享 `AccountPermissionViews`。原有领域 `/permissions` 的显式授权门槛保留；某域拒绝以该域 403 视图表示，不阻塞其他域。不可用、数据库或普通服务异常使整个快照失败，不把异常误写成永久拒绝。目录 `uniqueModel` 是配置元数据；下载中心场景管理仍保留原管理员与独立操作权限组合。原主数据权限接口保留其兼容行为，聚合接口不执行模板／场景定义初始化。

WAR 与 JAR 仅将该精确元数据路径排除于菜单 API 权限拦截；Shiro `authc` 和服务端当前用户／租户校验保留。其他业务接口的鉴权、事务、数据范围与记录级规则不变。

## 前端与失效规则

统一入口为 `features/authorization/session.ts` 的 `accountAuthorization`。导航、各领域 API 适配、身份管理按钮、导入导出及配置页嵌入的账号级标志均读取它。配置业务数据继续请求业务接口，编辑／发布标志绑定缓存的响应式 getter；保存成功后不追加权限网络请求，避免成功写入却因权限刷新失败被误报失败。

- 每个运行时只保存内存快照和一个在途初始化 Promise；登录后首次进入、整页重新加载或 iframe 文档重新创建时获取一次，成功后一直复用至显式刷新或会话变化。页面挂载、菜单往返、iframe 内路由切换、等待及同会话恢复焦点均不发起权限请求。父站的全平台导航加载保持原契约，子站自行向后端确认，不信任父窗口传入授权。
- 会话键包括 `token`、`loginDate`、`afterSales:account`、`tenantId`、`tenantCode`。退出及新登录明确清理；同源 storage／focus 检查账号或租户变化。未来租户切换入口须更新租户会话标记或调用 `clearAuthorization()`；当前主站未提供该切换入口，本机 `gaia.multi-tenant=false`。
- 每次清理递增代次；响应完成时同时核对代次与当前会话键。旧成功或失败请求均不能写入或撤销新会话授权。失败不作为成功缓存，可通过导航或明确重试再次加载。同窗口登录完成的受控路由导航会同步会话标记，避免随后 focus 被误判为外部换账号。
- 前端不设置计时有效期、不轮询，也不把快照持久化到浏览器存储。初始化、重新加载、显式刷新及失败重试实际请求均携带 `refresh=true`，仅失效当前账号／租户的 Gaia 授权缓存后重新确认；普通页面调用只读已就绪缓存。Gaia 服务端原 30 秒缓存仍用于业务请求鉴权，不因前端取消轮询而延长。
- 授权变更后的前端展示在下一次整页重新加载、工具栏刷新或重新登录时更新，不承诺固定秒数自动同步；若页面长期不重新加载，展示可能长期维持旧快照。实际操作继续接受后端鉴权：减少权限后旧按钮可能仍显示，但不意味着操作被允许；新增权限需刷新后显示。该时效取舍已由用户确认，不再宣称前端展示有约 60 秒自动更新上限。
- 独立模式工具栏“页面刷新”先 `load(true)`，成功才执行原页面重载；失败保留当前页。失败提示“重试”也强制刷新后端当前账号／租户缓存。每次网络获取均确认最新 Gaia 授权，初始化期间的手动刷新及其他并发命令共用同一个在途请求，不追加第二次请求。
- 刷新开始撤销已有账号级布尔标志／按钮集合，成功原位更新已有响应式对象；普通失败显示中英文友好提示及重试，不清除登录，不卸载页面或丢弃草稿。仅明确的登录失效沿用原登录恢复流程。
- 记录 `actions`、工单状态、归属、业务上下文和数据范围继续由业务接口返回；快照不是业务请求的授权依据。
