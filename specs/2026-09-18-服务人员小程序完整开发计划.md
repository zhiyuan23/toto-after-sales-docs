## 1. 目标、成功标准与范围

### 1.1 总体目标

在已有 `gaia-customer-service-uni` 底座和已确认交互原型上，交付一个由真实售后域服务人员账号、真实服务人员档案、真实企业／服务站归属和服务端权限共同约束的小程序，使服务人员可以完成：

1. 登录并进入当前授权企业与服务站上下文。
2. 查看本人正式下发的任务，联系顾客、记录预约或异常。
3. 签到或开始远程服务，在同一草稿中记录处理、证据、产品码、配件耗用和客户确认。
4. 提交完工版本，查看审核进度；退回后定向补充，通过后不二次交单。
5. 查看个人与服务站配件库存，申请领料、退料，查看和撤销本人处理中单据。
6. 在需求和后端基础具备后使用日程、地图、技术资料、问题反馈和账号操作。

### 1.2 首期必须贯通的业务闭环

```text
真实账号登录
  → 解析当前服务人员／企业／服务站
  → 查看本人任务
  → 联系与预约
  → 签到／远程开始
  → 服务处理／证据／产品码／客户确认
  → 配件耗用与库存流水
  → 完工提交
  → 后台退回后补充重提／通过后进入待回访
```

该闭环通过前，页面数量、原型还原度、路由数量、构建成功均不代表首期交付。

### 1.3 本计划包含

- W01～W10、W13～W16 的分阶段实施。
- W08 作为历史聚合入口的追踪，实际功能按当前原型分配到“配件”和“我的”。
- W11 调拨、W12 延保资料的解阻条件和恢复步骤，但在条件具备前不进入导航或首期开发。
- 移动端专用后端门面、真实身份与数据范围、幂等、版本、事务、审计和拒绝场景。
- H5 快速回归、微信开发者工具、iOS／Android 真机和目标环境验证的分层证据。

### 1.4 暂不纳入首期

- 服务人员抢单、自由接单或混合派单；只实现“已正式分配本人的任务”。
- 小程序内驾车／步行路线计算、多站排序、里程或预计时间。
- 未确认的费用、收款、结算和退款。
- 调拨单 W11、延保资料 W12，直到对应规则、数据源和接口确认。
- 未经确认的离线全功能。首期要求可恢复草稿和媒体失败重试，但不把所有业务操作改造为长时离线队列。
- 上传、提审、发布、共享数据库变更和真实消息通知发送；均需单独授权和环境准备。

## 2. 不可回退的实施基线

1. 服务人员端使用 `mobile/gaia-customer-service-uni`，应用名为“TOTO 客服助手”，不在消费者端实现。
2. 当前交互基线为“任务、配件、我的”三个 Tab；旧“应用”Tab 不恢复。
3. 技术资料放在“我的”，领料／退料记录放在“配件”；直达任务时可带入任务或品番上下文。
4. 师傅首页分为待处理、待补资料、审核中、历史任务；“正在服务”是独立置顶区，不是新增工单主状态。
5. 处理任务为一张页内的“服务处理 → 证据与确认 → 核对提交”三段，共用一份草稿。
6. 审核退回后定向补充指定材料；审核通过后直接待回访，不恢复二次交单。
7. 地图以微信 `<map>`、`MapContext`、`wx.openLocation` 为边界，不增加第三方算路依赖。
8. 服务人员不获得后台派站、派人、库存审批、完工审核等操作；不通过前端隐藏按钮代替后端授权。
9. 路由与 Tab 只在 `src/router/definition.ts` 维护，`src/pages.json` 由 `pnpm routes:generate` 生成，不双写。
10. 涉及路由生成器、请求内核、认证内核、公共组件、主题或质量脚本的底座改动，同步检查 `gaia-after-sales-uni`；业务页、业务路由、AppID 和端侧身份不同步。

### 3.2 移动端专用后端门面

阶段 1 已固定移动端 API 根路径为 `/api/afterSales/mobile/service-personnel`，只开放登录、退出、上下文查询和企业切换四个精确路径；不提供旧建议路径的兼容入口。

该门面应当：

- 从售后域独立服务人员会话解析账号、租户、服务人员档案、当前企业和服务站；普通请求不接受客户端任意指定 `personnelId`。服务人员账号在售后后台新增人员时一并创建，不复用 Gaia 登录。
- 只返回本人办理所需字段和动作，不复用 Web 后台“派站／派人／审核”响应作为移动端授权。
- 内部可复用已有领域查询和事务服务，但移动端读写范围和可执行动作须单独闭合。
- 列表、详情、选项和写入使用同一个本人／企业／服务站数据范围，不允许“列表看不见但猜 ID 可写入”。
- 写操作返回稳定错误语义：未登录、未绑定服务人员、无权、资源不存在或不可见、非法状态、过期版本、重复请求、依赖失败。

| 媒体引用 | 复用已确认文件接口 | 文件归属、类型、大小、数量和访问权限由服务端校验 |
| 产品码校验 | `POST /tasks/{id}/product-code-verifications` | 返回匹配、差异、需要复核或拒绝；不按客户端前缀判真 |
| 完工提交 | `POST /tasks/{id}/completion-submissions` | 幂等请求号＋工单版本＋草稿版本；不可变提交版本 |
| 退回补充 | `GET/POST /tasks/{id}/supplements` | 只允许最新退回意见要求的内容，新建版本而不覆盖旧版 |

新建表或扩展字段前先核对已有签到、工单时间线、完工提交、审核、附件和库存流水表，不重复建模。确有迁移时，须同时提供前置检查、迁移、验证和恢复脚本。

#### 小程序实施

- [ ] 处理任务三段共用同一草稿和自动保存状态，切换其他任务不串草稿。
- [ ] 草稿保留最后成功保存版本；过期响应、页面卸载和切换企业不回写旧状态。
- [ ] 媒体条目独立展示排队、上传中、已就绪、失败和重试，不因一项失败清空整张表单。
- [ ] 扫码失败可手工输入，但两者使用同一个服务端验证契约。
- [ ] 核对提交页从草稿派生摘要，最终提交成功前不切换任务状态或显示已完工。
- [ ] 待补资料页显示退回版本、原因和指定项，不要求重复签到或重填未退回内容。
- [ ] 审核通过后任务进入历史后续进度；不建交单页或交单提交接口。

#### G5 退出条件

- 必填证据缺失、扫码不匹配、媒体失败、定位拒绝、重复提交、过期版本和跨人员均有拒绝或恢复证据。

### 15.1 临界路径


阶段 7 日程／地图已经延期，不与当前阶段并行；重新启动前必须先确认新原型、接口和验收边界。阶段 8 的账号能力可提前，技术资料和反馈需等真实数据源。

### 15.2 可安全并行的工作

- G0 后：后端可设计身份／移动 API 门面；小程序可实施三 Tab 壳和不写入业务数据的原生能力探针；测试可准备身份和数据。
- G1 后：任务查询后端与任务列表／详情前端按已固定合同并行。
- G3 后：任务动作、处理任务草稿、配件自范围查询可由不同工作线并行，但不共享业务文件所有权；日程／地图不在当前并行范围。
- 路由生成器、请求内核、认证内核、主题和通用草稿／媒体机制由固定责任人维护，避免多条工作线同时重写底座。

### 15.3 执行时的停止条件

出现以下情况时，停止直接依赖的动作，记录阻塞并继续其他不依赖工作：

- 无法从真实会话稳定解析服务人员或企业范围。
- 同一工单在后台和小程序显示不同状态或不同执行人。
- 完工必填证据、定位例外、产品码、客户确认或费用范围未确认，实现会产生虚假成功。
- 库存操作无法在事务中保证余额、流水、单据和工单一致。
- 共享数据库、真实文件存储、微信配置、上传或发布需要新授权而当前未获得。
- 无法安全区分当前任务改动与工作树中其他并发改动。
