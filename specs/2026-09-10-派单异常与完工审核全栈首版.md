## 1. 本轮目标

在已有统一工单、服务区域、服务站、服务人员和按日可用性基础上，形成不依赖模拟数据的首个后台工单流转闭环：

1. 按行政服务区域推荐服务站，支持人工分配、转站和原因留痕。
2. 按服务类型技能、日期可用性和当日容量筛选服务人员，支持派单、改派和冲突拦截。
3. 处理取消、拒单、断联、改期、缺件、投诉升级和复开，并保留不可变异常事件。
4. 配置受理、派单、预约、完工和回访阶段 SLA，在列表中给出正常、预警或超时状态。
5. 创建不可变完工提交版本，审核通过或退回；退回后重新提交形成新版本，不覆盖原始材料。

## 2. 前端实现

独立售后子系统新增三个真实页面：

| 菜单码 | 页面 | 当前能力 |
| --- | --- | --- |
| `afsDispatch` | 派单调度 | 工单筛选、详情、服务站推荐与分配、人员候选与冲突说明、派单／改派、完工材料提交 |
| `afsWorkOrderException` | 异常工单 | 异常筛选与详情、七类异常动作、升级标记、复开、五阶段 SLA 配置 |
| `afsCompletionReview` | 完工审核 | 待审工单、最新提交版本与材料核对、通过、退回及原因记录 |

页面继续复用 `FaPageMain`、`EsSearch`、`EsListToolbar`、`EsTable` 和列表／弹窗通用方法。三个列表均采用纵向弹性布局，表格容器占满筛选和工具栏之外的页面剩余高度。

## 3. 后端契约

接口统一位于 `/api/afterSales/work-order`：

- `GET /permissions`：返回三个模块的查询和操作授权。
- `GET /dispatch`、`GET /dispatch/{id}`、`GET /options/{id}`：派单列表、详情和候选项。
- `PUT /dispatch/{id}/station`：自动推荐或人工分配／转站。
- `PUT /dispatch/{id}/personnel`：派单或改派服务人员。
- `POST /dispatch/{id}/completion-submissions`：新增完工材料版本。
- `GET /exceptions`、`GET /exceptions/{id}`、`PUT /exceptions/{id}`：异常查询和动作。
- `GET /sla-policies`、`PUT /sla-policies/{stage}`：SLA 查询和配置。
- `GET /completion-reviews`、`GET /completion-reviews/{id}`、`PUT /completion-reviews/{id}`：完工审核。

写操作使用精确操作权限；列表、详情、状态流转、历史和版本写入遵循 Gaia 租户、数据范围、事务及乐观并发机制。

## 4. 数据与不可变记录

迁移 `20260910_work_order_workflow.sql` 在统一工单增加服务站分配、人员派单、状态变更时间和当前异常摘要字段，并新建：

- `afs_service_personnel_skill`：人员支持的安装、维修或指导技能。

迁移与权限脚本均提供回退文件。本轮已按授权应用到共享测试库：新增 12 个工单字段、6 张业务表、3 个模块查询 API、6 项操作权限和管理员授权；未插入模拟业务数据。

## 5. 关键业务约束

- 自动分站使用当前地址匹配到的已启用行政区域候选站；人工偏离推荐或转站必须填写原因。
- 人员必须启用、属于当前服务站、具备对应工单类型技能，并在期望日期处于可用状态且未超过日容量；不满足时服务端拒绝派单。
- 异常页面只提供已定义动作，不提供任意状态编辑器；拒单时解除当前人员，复开恢复异常前状态。
- 完工提交要求服务结果、与产品实例一致的产品／安装码、1～20 个照片引用和客户签名引用。
- 审核只新增审核记录并迁移工单状态；退回后原提交不可修改，新材料生成下一版本。
- SLA 没有持久化配置时不伪造已生效默认值；保存后才参与真实时限判断。

## 8. 2026-09-13 取消默认二次交单

### 已确认范围

用户确认：完工资料一次提交，审核通过后不再要求师傅交单；同步原型、状态说明与涉及的真实程序。A21 的审核通过从 `PENDING_REVIEW → PENDING_HANDOVER` 改为 `PENDING_REVIEW → PENDING_FOLLOW_UP`，师傅本次处理结束。退回仍为 `PENDING_COMPLETION`，补充新版本再审；不将审核通过直接当作工单关闭。

状态字典、正常／异常流转图、角色和配件单区别统一见[服务工单状态机与单据状态说明](../02-技术设计/13-服务工单状态机与单据状态说明.md)。本段是现有首版 Spec 的已确认变更，不改变其他未确认业务。

### 程序改动

- 后端：审核通过直接待回访，保留权限、版本、锁、事务、审核版本及不可变状态历史；待回访、旧待交单和已关闭阶段不开放旧异常复开动作，也拒绝直接调用绕过。
- Web 独立子系统：待回访／已关闭使用完成服务后的视觉色，旧待交单显示“待交单（历史状态）”；英语同步。审核浏览器夹具改为新目标。未修改 legacy 或受保护 common 子仓。
- 服务人员原型：删除交单页与可提交表单，只保留待处理／审核中／历史；审核通过后查看后续回访进度；旧链接转进度、旧提交拒绝。状态变化不重复扣配件库存，不自动关闭。
- 未发现移动端源码仓库内已有交单业务实现，本轮不为页面壳新建业务模块；后台 HTML 原型未命中该交单状态，不改其并发编辑内容。

### 数据兼容与后续边界

- `PENDING_HANDOVER` 保留为历史查询值，不再由新审核产生；本轮不批量改写数据库或审计，不执行迁移。
- 旧状态治理须核对具体旧单及材料后单独处理；不能用 UI 改名把旧单伪装成已回访／已关闭。
- 回访、评价、结算、关闭的正式接口和条件仍属后续切片。新审核进入已有待回访状态，不表示 A22 或服务人员应用已完成。
- 未安装后端产物、重启聚合宿主或发布 Web；当前修改经本地隔离验证，运行中共享环境需按后续部署验证，不改变原验收统计。
