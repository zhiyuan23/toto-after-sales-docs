## 确认后的筛选布局

默认收起次要条件，复用子系统 `EsSearch` 的展开、重置和查询行为。

| 页面 | 默认条件（按顺序） | 展开条件 |
| --- | --- | --- |
| 代理商 | 所在地、编号／名称、代理商级别、启用状态 | 所属代理商 |
| 门店 | 所在地、编号／名称、所属代理商、启用状态 | 门店类型、营业状态 |
| 服务站 | 服务覆盖地区、编号／名称／服务热线、服务项目、启用状态 | 服务站所在地 |
| 服务区域 | 行政区域、编码／名称／行政区关键词、区域层级、启用状态 | 关联服务站、站点关联状态 |
| 销售区域 | 主体所在地、名称／编码、主体类型、启用状态 | 销售区域配置状态、授权销售地区 |

- 地区使用可搜索的省／市／区县级联，允许只选省或市，清空表示全部。请求使用行政区代码及完整上级路径；非法代码或跨省市路径在服务端拒绝。沿用已有行政区字典，不在本轮扩充行政区数据。
- 地区选择框与其他条件一样填满 `EsSearch` 分配的控件区域，随筛选列自适应，取消实际生效的 200px 默认宽度限制。级联菜单和搜索结果的可见高度由 204px 提高到最高 400px，并以窗口高度减 200px 为上限；仅作用于网络地区筛选控件。
- 代理商关键词占位调整为“代理商编号或名称”；级别沿用 FIRST／SECOND／THIRD，历史空值或 `default` 按既有展示口径匹配一级。
- 门店所属代理商由自由文字改为可搜索的精确 ID 选择；营业状态由自由输入改为当前账号可见门店中的实际值下拉，门店类型也取自可见记录。营业状态与启用状态分别保留，不虚构营业状态枚举。旧 `dealerKeyword` API 参数继续兼容已有调用。
- 服务站覆盖地区按关联且启用的服务区域查询，使用 `EXISTS` 避免同站多个匹配区域造成重复行；省／市级范围可匹配其下级区县。服务站所在地按主档行政区代码精确查询，两个条件可以组合。
- 服务区域的地区路径与区域层级独立：选省不自动加“省级”条件。站点关联按现有关系有／无判断，不等同于服务站启用状态；无服务站读取权限时隐藏站点选择并不请求站点选项。
- 销售区域顶部查询作用于主体树及地图，右侧省／市／区仍用于编辑。配置状态表示主体自身有／无保存的区域记录；授权销售地区匹配主体自身区域，允许省／市级配置覆盖下级。命中子节点时保留并自动展开祖先路径，祖先标为“上级节点”，不能作为命中主体打开编辑或显示地图点。查询清理旧选择；保存后按已应用的查询刷新树，并仅在主体仍匹配时保留详情。

## 接口与实现边界

- 现有列表 API 增加可选条件，不改变原默认查询、分页排序、组织数据范围、租户及操作权限。共用 `NetworkListFilter` 校验代码、字符串 ID 和枚举；代理商／门店／服务站／服务区域的列表和计数使用同一条件，导出复用这些服务调用。
- 地区条件为 `provinceCode/cityCode/districtCode`；服务覆盖加 `coverage` 前缀，销售授权范围加 `sales` 前缀。代理商增加 `agent/parentId`，门店增加 `dealerId/storeTypeCode`，服务站增加 `serviceItem`，服务区域增加 `stationId/associationState`，销售主体增加 `subjectType/configured`。启用状态保留布尔 `false`，ID 保持字符串。
- 新增 `GET /api/afterSales/network/stores/filter-options`，返回 `dealer/storeType/activeState` 三类选项，依照门店原组织范围读取；复用门店列表读取权限。其他选项复用已有接口。
- 没有修改菜单、角色授权、数据库结构、网点数据或业务写入规则；本机后端按正式本地入口重新装配并启动，前端复用原 9010 服务。
