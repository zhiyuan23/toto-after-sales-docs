# 售后子系统统一用户与角色管理阶段

- 日期：2026-09-09
- 范围：售后独立前端的全局用户、角色管理入口
- 状态：只读阶段及可写代码阶段已完成；共享环境真实允许／拒绝账号、双端写入和会话失效仍待验收

## 1. 已交付范围

1. 售后独立前端增加 `/system/user`、`/system/role` 两个全局系统管理路由，不计入售后 49 项业务菜单。
2. `VITE_APP_IDENTITY_MANAGEMENT=true` 仅注册管理入口。路由与顶部入口仍必须命中当前 Gaia Module/tree 中启用、未隐藏且 path 匹配的全局 `user`、`role` 节点；开关本身不赋权。
3. 管理路由不受业务菜单预览开关放行；未登录、未授权、菜单接口失败以及嵌入模式均失败关闭。账号切换或退出继续清理旧菜单与售后缓存。
4. 用户页面复用 Gaia 用户列表和详情，支持用户名、真实姓名、启停状态筛选、分页及详情查看。
5. 角色页面复用 Gaia 角色列表和详情，支持角色名称筛选、分页及详情查看；详情只展示后端返回的授权数量，不在浏览器拼装或修改权限集合。
6. 用户与角色主键在前端统一转成字符串；若后端返回超出 JavaScript 安全整数范围的数字则拒绝使用，防止长整型 ID 静默失真。

## 2. Gaia 接口与安全边界

| 能力 | 复用接口 | 当前范围 |
| --- | --- | --- |
| 用户列表 | `GET /api/sysAuthUser/list` | 查询、分页；沿用 Gaia 后端权限和数据范围 |
| 用户详情 | `GET /api/sysAuthUser/detail?id=` | 只读详情 |
| 角色列表 | `GET /api/sysAuthRole/list` | 查询、分页；沿用主系统的 `conditionItems` 查询格式 |
| 角色详情 | `GET /api/sysAuthRole/detail?id=` | 只读详情及授权数量 |
| 管理入口授权 | `GET /api/sys/Module/tree` | 只接受真实 `user`、`role` 菜单节点，不读取本地角色名推断授权 |

本阶段没有新增认证中心、用户表、角色表、同步任务或售后专用权限模型，也没有修改 Gaia 生产后端。

审计确认以下写操作目前不能安全地从售后子系统局部开放：

- 用户新增/编辑会提交完整组织和角色关系，尚未证明后端会把可管理用户、组织、角色和租户范围限制在当前管理员权限内。
- 角色新增/编辑会提交完整 `moduleIds` 与 `operationIds`；如果子系统只展示售后授权树，保存会有覆盖共享角色其他模块权限的风险。
- 删除、启停、密码重置及撤权缓存生效时点尚未完成允许/拒绝账号和共享环境验证。

因此页面明确标注只读范围，不提供空壳按钮或前端假成功。后续写入应优先由后端提供范围受控的增量修改或安全合并；缺少保障时继续由主系统维护。

- 交互沿用 Compass Admin 工作台结构：搜索、工具栏、身份摘要、编辑弹窗、权限选择器、危险确认、未保存关闭确认、保存互斥、错误重试和并发提示；后端和权限语义仍全部使用 Gaia。
- `SysUserAppServiceImpl`、`SysRoleAppServiceImpl` 的聚合写方法增加事务边界；用户／角色更新使用详情已有 `updateTime` 做秒级后端并发校验。未提交 `updateTime` 的既有客户端保持兼容，主系统详情回填提交路径继续可用。
