# 售后子系统统一用户与角色管理阶段

- 日期：2026-09-09
- 范围：售后独立前端的全局用户、角色管理入口
- 状态：只读阶段及可写代码阶段已完成；共享环境真实允许／拒绝账号、双端写入和会话失效仍待验收

## 1. 已交付范围

1. 售后独立前端增加 `/system/user`、`/system/role` 两个全局系统管理路由，不计入售后 49 项业务菜单。
2. `VITE_APP_IDENTITY_MANAGEMENT=true` 仅注册管理入口。路由与顶部入口仍必须命中当前 Gaia Module/tree 中启用、未隐藏且 path 匹配的全局 `user`、`role` 节点；开关本身不赋权。
3. 管理路由不受业务菜单预览开关放行；未登录、未授权、菜单接口失败以及嵌入模式均失败关闭。账号切换或退出继续清理旧菜单与售后缓存。
4. 用户页面复用 Gaia 用户列表和详情，支持用户名、真实姓名、启停状态筛选、分页及详情查看。
5. 角色页面复用 Gaia 角色列表和详情，支持角色名称筛选、分页及详情查看；详情只展示后端返回的授权数量，不在浏览器拼装或修改权限集合。
6. 用户与角色主键在前端统一转成字符串；若后端返回超出 JavaScript 安全整数范围的数字则拒绝使用，防止长整型 ID 静默失真。

## 2. Gaia 接口与安全边界

| 能力 | 复用接口 | 当前范围 |
| --- | --- | --- |
| 用户列表 | `GET /api/sysAuthUser/list` | 查询、分页；沿用 Gaia 后端权限和数据范围 |
| 用户详情 | `GET /api/sysAuthUser/detail?id=` | 只读详情 |
| 角色列表 | `GET /api/sysAuthRole/list` | 查询、分页；沿用主系统的 `conditionItems` 查询格式 |
| 角色详情 | `GET /api/sysAuthRole/detail?id=` | 只读详情及授权数量 |
| 管理入口授权 | `GET /api/sys/Module/tree` | 只接受真实 `user`、`role` 菜单节点，不读取本地角色名推断授权 |

本阶段没有新增认证中心、用户表、角色表、同步任务或售后专用权限模型，也没有修改 Gaia 生产后端。

审计确认以下写操作目前不能安全地从售后子系统局部开放：

- 用户新增/编辑会提交完整组织和角色关系，尚未证明后端会把可管理用户、组织、角色和租户范围限制在当前管理员权限内。
- 角色新增/编辑会提交完整 `moduleIds` 与 `operationIds`；如果子系统只展示售后授权树，保存会有覆盖共享角色其他模块权限的风险。
- 删除、启停、密码重置及撤权缓存生效时点尚未完成允许/拒绝账号和共享环境验证。

因此页面明确标注只读范围，不提供空壳按钮或前端假成功。后续写入应优先由后端提供范围受控的增量修改或安全合并；缺少保障时继续由主系统维护。

## 5. 后续与阶段暂停

1. 本阶段提交和进度更新完成后暂停，先复盘范围、自动化验证成本和下一大模块边界。
2. 下一阶段恢复主数据优先顺序：先处理需求明确的渠道/服务资源主档；区域重叠、调度优先级、人员技能与账号绑定规则未确认时拆分或跳过。
3. 用户/角色写入作为单独大阶段：先补后端管理范围、共享角色隐藏权限保留与权限缓存失效契约，再实现新增、编辑、启停、删除和角色授权。
4. 浏览器验证调整为阶段收尾抽查，不再逐个基础 CRUD 重复执行；最终联调仍需真实允许/拒绝账号、租户和跨组织边界证据。

## 6. 2026-09-10 可写阶段实施

### 6.1 已实现

- 用户页在既有只读入口上增加新增、编辑、启停、删除和按 Gaia `resetPwd` 操作码条件展示的密码重置；组织、角色选项、当前账号及 `USER_PWD_RULE` 均从 Gaia 动态读取。
- 用户编辑先读取完整最新详情，再显式提交 Gaia 聚合 DTO；保留组织关系、角色关系、品牌数据权限、组织数据权限、主管标记、用户类型、职位、业务类型和 10 个自定义字段。后端同时补充登录信息、最近改密时间、MFA 和邀请审核状态的原值保护，避免精简表单将隐藏字段写空。
- 角色页增加新增、编辑、删除和完整模块／按钮授权；动态读取 `module_category` 的全部分类及每类 Gaia 权限树，保存完整 `moduleIds`、`operationIds`，并保留当前目录中不可见的既有授权。模块和按钮使用 `M_`／`B_` 前端树键隔离同号 BIGINT，提交仍保持原始字符串 ID。
- 用户和角色按钮分别使用 Gaia `moduleCode=user`、`moduleCode=role` 返回的操作码；加载失败时写操作关闭。角色更新与删除完整处理 Gaia `205` 引用确认，不制造角色启停等当前主系统未提供的动作。
- 交互沿用 Compass Admin 工作台结构：搜索、工具栏、身份摘要、编辑弹窗、权限选择器、危险确认、未保存关闭确认、保存互斥、错误重试和并发提示；后端和权限语义仍全部使用 Gaia。
- `SysUserAppServiceImpl`、`SysRoleAppServiceImpl` 的聚合写方法增加事务边界；用户／角色更新使用详情已有 `updateTime` 做秒级后端并发校验。未提交 `updateTime` 的既有客户端保持兼容，主系统详情回填提交路径继续可用。

### 6.2 接口矩阵

| 能力 | Gaia 接口 | Gaia 操作码／保护 |
| --- | --- | --- |
| 用户列表／详情／当前用户 | `GET /api/sysAuthUser/list`、`detail`、`getCurrentLoginUser` | 路由由真实 `user` 模块控制；查看用 `view` |
| 用户新增／编辑 | `POST /api/sysAuthUser/add`、`PUT /api/sysAuthUser/edit` | `add`、`edit`；字段白名单、完整关系和数据范围保留、事务、更新时间冲突检查 |
| 用户启停／删除／重置密码 | `GET /api/sysAuthUser/enable`、`DELETE /api/sysAuthUser/delete`、`GET /api/sysAuthUser/resetPwd` | `enable`、`disable`、`delete`、可选 `resetPwd`；当前账号和超级管理员前端保护，后端继续执行 Gaia 规则 |
| 角色列表／详情 | `GET /api/sysAuthRole/list`、`detail` | 路由由真实 `role` 模块控制；详情保持可读 |
| 角色新增／编辑／删除 | `POST /api/sysAuthRole/add`、`PUT /api/sysAuthRole/updateWithConfirm`、`DELETE /api/sysAuthRole/deleteWithConfirm` | `add`、`edit`、`delete`；完整权限集合、205 引用确认、事务、更新时间冲突检查 |
| 组织／角色／权限目录 | `GET /api/sys/organization/listAll`、`sysAuthRole/list`、`sysDictionaryItem/listEnableByDictionaryCode`、`sys/Module/listEnableModuleAndOperationByCategoryCode` | 使用 Gaia 实时目录，不使用售后静态 manifest 构造授权 |
| 按钮与密码规则 | `GET /api/sysModuleOperation/getCurrentUserOperationList`、`GET /api/sysConfig/getByCode?code=USER_PWD_RULE` | 未知／失败均关闭写操作；密码校验与主系统配置一致 |
