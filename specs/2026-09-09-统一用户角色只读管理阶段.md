# 售后子系统统一用户与角色管理阶段

- 日期：2026-09-09
- 范围：售后独立前端的全局用户、角色及菜单权限管理入口
- 状态：用户／角色可写代码及菜单权限前端已完成；共享环境真实允许／拒绝账号、双端写入和会话失效仍待验收

## 1. 已交付范围

1. 售后独立前端提供 `/system/user`、`/system/role`、`/system/menu` 三个全局系统管理路由，不计入售后业务菜单。
2. `VITE_APP_IDENTITY_MANAGEMENT=true` 仅允许注册管理入口。顶部入口和管理路由只在未携带 `entry=main` 且非 iframe 时开放，并且必须命中当前 Gaia Module/tree 中启用、未隐藏、path 匹配的全局 `sys_user_list`、`sys_role_list`、`sys_module_list` 节点；开关和角色名称本身都不赋权。
3. `entry=main`、iframe、未登录、未授权或菜单接口失败时均失败关闭；管理路由不受业务菜单预览开关放行。账号切换或退出继续清理旧菜单与售后缓存。
4. 用户页面复用 Gaia 用户列表和详情，支持用户名、真实姓名、启停状态筛选、分页及详情查看。
5. 角色页面复用 Gaia 角色列表和详情，支持角色名称筛选、分页及详情查看；详情只展示后端返回的授权数量，不在浏览器拼装或修改权限集合。
6. 用户与角色主键在前端统一转成字符串；若后端返回超出 JavaScript 安全整数范围的数字则拒绝使用，防止长整型 ID 静默失真。

## 2. Gaia 接口与安全边界

| 能力 | 复用接口 | 当前范围 |
| --- | --- | --- |
| 用户列表 | `GET /api/sysAuthUser/list` | 查询、分页；沿用 Gaia 后端权限和数据范围 |
| 用户详情 | `GET /api/sysAuthUser/detail?id=` | 只读详情 |
| 角色列表 | `GET /api/sysAuthRole/list` | 查询、分页；沿用主系统的 `conditionItems` 查询格式 |
| 角色详情 | `GET /api/sysAuthRole/detail?id=` | 只读详情及授权数量 |
| 菜单树／详情 | `GET /api/sys/Module/listAllModule`、`detail?id=` | 读取 Gaia 全局菜单、页面、接口及操作权限聚合 |
| 菜单新增／编辑／删除／排序 | `POST /api/sys/Module/add`、`PUT /api/sys/Module/edit`、`DELETE /api/sys/Module/delete`、`GET moveUp/moveDown` | 沿用 Gaia `SysModuleDTO` 与 `moduleOperationDTOList` 整体保存，不引入 Compass Resource 模型 |
| 管理入口授权 | `GET /api/sys/Module/tree` | 只接受真实 `sys_user_list`、`sys_role_list`、`sys_module_list` 菜单节点，不读取本地角色名推断授权 |

本阶段没有新增认证中心、用户表、角色表、同步任务或售后专用权限模型，也没有修改 Gaia 生产后端。

审计确认以下写操作目前不能安全地从售后子系统局部开放：

- 用户新增/编辑会提交完整组织和角色关系，尚未证明后端会把可管理用户、组织、角色和租户范围限制在当前管理员权限内。
- 角色新增/编辑会提交完整 `moduleIds` 与 `operationIds`；如果子系统只展示售后授权树，保存会有覆盖共享角色其他模块权限的风险。
- 删除、启停、密码重置及撤权缓存生效时点尚未完成允许/拒绝账号和共享环境验证。

因此页面明确标注只读范围，不提供空壳按钮或前端假成功。后续写入应优先由后端提供范围受控的增量修改或安全合并；缺少保障时继续由主系统维护。

### 6.4 2026-09-13 独立入口权限管理收敛

- “系统管理”是子系统独立运行时对 Gaia 全局身份管理能力的入口，不属于售后业务菜单。只有未携带 `entry=main`、非 iframe、`VITE_APP_IDENTITY_MANAGEMENT=true` 且当前账号菜单树实际包含相应全局模块时才显示；无参数是默认独立模式，`entry=standalone` 仅保留兼容。
- `entry=main` 与 iframe 不显示“系统管理”，直接访问 `/system/user`、`/system/role` 也进入无权页；这只调整子系统入口展示与路由保护，不改变根系统原有菜单、角色和接口权限逻辑。
- 根系统真实授权映射固定为 `sys_user_list → /system/user`、`sys_role_list → /system/role`。页面按钮权限查询同步使用这两个真实 `moduleCode`，不再使用不存在的 `user`、`role` 模块编码。
- 是否可见不通过“系统管理员”等角色名称推断。系统管理员只有在具备真实全局模块授权时可见，其他角色若被授予相同模块也可见；未授权账号始终不可见且不可直达。

### 6.7 2026-09-16 菜单树与系统管理导航聚焦

- 菜单与权限页面只投影 Gaia 动态目录中的 `afterSales` 根节点及后代，不再展示其外层“后台网页”分类；首次进入直接选中并展开售后根，其余下级仍由管理员按需展开。菜单编辑上级选择树和角色授权树保持默认收起，测试目录中的主系统同级菜单不会显示。
