# 消费者产品自动同步与智能添加

- 状态：核心流程已确认；用户自报购买后端与 Web 核验首版已开发待环境验收；消费者小程序、手机号自动同步和扫码未实施
- 更新日期：2026-09-14
- 范围：消费者 C03～C06、C10、C11；关联账号、购买、产品实例和服务资格
- 关联方案：[消费者产品自动关联与智能认领方案](../02-技术设计/14-消费者产品自动关联与智能认领方案.md)

## 1. 目标行为

1. 消费者完成微信身份和手机号验证后，系统自动匹配已接入渠道的可信购买明细，并将对应产品展示在“我的产品”；不要求短信链接或逐笔确认。
2. 未自动匹配的产品使用统一“扫一扫添加”。前端不要求用户选择码类型，服务端识别产品码、溯源码、SN、安装码或购买凭证码。
3. 没有码、无法识别或普通商品码只能确认型号时，才允许手动选择产品并填写购买日期，保存为“用户申报、实物待核验”。
4. 三种入口共用一套产品实例和账号产品关系；产品已出现不代表免费安装、保修或延保资格已经通过。

## 2. 用户流程

```text
首次进入 → 授权手机号 → 自动同步 → 我的产品
                                      ↓ 未找到其他产品
                         扫一扫 → 识别并查重 → 添加／提示已有
                                      ↓ 不能定位具体实物
                         手选产品 + 购买日期 → 待核验产品
```

“我的产品”和“购买记录”必须显示来源：手机号同步、扫码添加或用户申报；用户申报同时显示待核验。

## 3. 服务端契约边界

接口名称可按后端规范调整，但职责必须分开：

| 能力 | 输入 | 输出／约束 |
| --- | --- | --- |
| 手机号授权 | 微信一次性授权凭证或验证码结果 | 服务端验证并绑定稳定 `account_id`；客户端明文手机号不能作为可信证明 |
| 购买同步 | 当前登录账号 | 同步结果、增加／已有／冲突数量；只匹配有效、未退货、来源可信的购买明细 |
| 编码解析 | 原始编码、发行方上下文、幂等键 | 码类型、可信级别、候选产品、允许动作；未知／失效／冲突不得返回绑定成功 |
| 确认扫码添加 | 解析结果令牌、幂等键 | 复用或创建的 `product_instance_id`、关系状态、资料来源 |
| 无码添加 | 商品 ID、购买日期、必要使用信息、幂等键 | 待核验产品实例及关系；不得产生已核验权益 |
| 我的产品 | 当前登录账号 | 统一产品关系列表、来源、实物识别和核验状态；服务权益单独返回 |

解析结果应使用短时、一次性服务端令牌承接，不能由客户端回传“这是 SN／已通过”并被直接信任。

## 4. 数据一致性

- 账号产品关系唯一：`account_id + product_instance_id`。
- 可信产品标识唯一：`issuer + identifier_type + identifier_value`。
- 外部购买明细唯一：`source + external_order_no + line_no/unit_no`。
- 所有写操作在事务内执行“查购买—查标识—查关系—能复用则补充—否则创建”，并保存幂等键。
- 普通商品码、型号和购买日期不是实物唯一键；用户可声明另一件同型号产品，但新实例必须保持待核验并关联疑似重复项。
- 合并重复实例时保留原 ID、关系、凭证、工单和审计，不物理删除历史。

## 5. 异常与权限

- 家庭共用手机号、购买人与使用者不同、虚拟号、换号、退货、他人已关联或数据冲突：不得静默改绑，可返回脱敏候选或人工核验入口。
- 手机号换绑不重写历史产品关系；需记录新旧验证信息、时间和操作来源。
- 消费者只能查询当前账号有权查看的产品和购买记录；脱敏在服务端完成。
- 订单同步失败不阻止扫码或无码添加；扫码失败不得自动降级为绑定成功。
- 短信、微信消息只用于提醒或找回，不属于绑定成功条件。

## 6. 验收场景

- 新账号授权手机号后自动出现两件已同步产品；重复同步数量不增加。
- 已同步产品再扫同一可信标识，只补充原实例并提示已存在。
- 扫可信 SN／逐件溯源码可定位具体实例；扫购买凭证码可关联对应购买；扫普通商品码只识别型号。
- 未知、失效、撤销或冲突码不建立关系，并提供手选或人工协助。
- 手选同型号可新增另一件，但显示“待核验”，且不自动获得免费权益。
- 申请服务时独立核验本次资格；待核验产品不可因已加入列表而绕过。
- 并发重试、页面返回和弱网重放不会重复创建关系或产品实例。
- 本人数据隔离、换号、归属冲突、退货撤销和实例合并均有审计记录。

## 7. 本次交付与未完成项

- 已更新文档原型：手机号授权自动同步、扫码优先、无码手选、码类型分流及可信标识防重。
- 已实现首个可运行切片：消费者手选一件商品并提交购买信息后，直接写入统一购买登记、产品实例和消费者关系；来源固定为 `USER_REPORTED`，核验为 `PENDING`，生命周期为 `ACTIVE`，资格为 `NOT_ASSESSED`，且不生成安装码。
- 后台 A15 在同一购买记录列表展示来源与核验状态。有独立“核验购买记录”权限的人员可人工凭证核验、标记冲突、驳回，或从同手机号、同商品、当前数据范围内的正式记录候选中完成关联。关联成功移动消费者关系，原申报登记和实例标为 `MERGED`，不复制正式实例。
- 服务受理和预约只接受 `VERIFIED + ACTIVE` 记录；用户申报进入列表不等于正式购买或服务资格通过。核验轨迹追加写入，不覆盖历史。
- 数据库升级和权限脚本、消费者侧后端 API、Web 核验界面均已形成；隔离后端集成测试及 Web 前端检查通过。消费者小程序本次不实施，尚无添加表单和本人购买记录页面；迁移未应用到共享数据库，真实消费者身份/API 权限尚未验收。
- 未实现消费者小程序、手机号自动同步、扫码解析、可信标识、订单接入、换号和完整权益规则。C03～C06、C10、C11 的小程序入口均不计真实实现或最终验收；后端接口存在不代表小程序功能完成。

## 8. 已实现接口与状态契约

| 接口 | 用途 | 关键约束 |
| --- | --- | --- |
| `GET /api/afterSales/customer/consumer/options` | 加载可选售后商品 | 只返回启用商品 |
| `POST /api/afterSales/customer/consumer/registrations` | 创建用户自报购买 | 当前账号归属；首版每次仅一件；隐私同意和幂等键必填 |
| `GET /api/afterSales/customer/consumer/records[/{id}]` | 查询本人记录 | 只按服务端账号 ID 查询，不接收手机号越权条件 |
| `GET /api/afterSales/customer/records/verification-options` | 加载核验可选门店 | 按核验权限和当前岗位数据范围返回，不依赖购买登记权限 |
| `GET /api/afterSales/customer/records/{id}/verification-candidates` | 生成正式记录候选 | 只返回同手机号、同商品、已核验有效且当前岗位可见的记录 |
| `PUT /api/afterSales/customer/records/{id}/verification` | 后台核验 | 独立按钮权限、乐观版本、动作白名单和不可变历史 |

来源、核验、生命周期和服务资格是四个独立维度。人工核验只改变购买核验状态；`entitlement_status` 仍由后续具体服务资格规则判断，不能因 `VERIFIED` 自动改为免费服务。
