# 顾客预约与工单查询全栈首版

- 日期：2026-09-10
- 对应入口：A15 顾客档案、A16 预约管理、A18 工单管理、D03／D04 顾客登记、D07 门店顾客、D08 门店预约，以及总部／客服共用的安装码查询
- 需求依据：ADM-CU-001～003、DLR-003～005、DLR-009～011、BR-001～006、BR-013、FS-010～017
- 状态：共享迁移与管理员允许侧空数据验收完成，业务写路径、拒绝角色与完整业务规则待验收

## 1. 首版范围

1. 建立售后自有的顾客、购买登记、购买明细、产品实例、隐私同意、统一工单、工单产品及状态历史数据基础，不复用代理商主档 `md_customer` 存消费者。
2. 顾客登记由已授权门店发起，保存购买日期、来源类型、购买人手机号、使用者姓名和地址、VIP、备注及商品数量；门店和商品均从现有权威主档读取并在服务端复核可见性与启用状态。
3. 每个购买商品数量展开为可追踪产品实例，由服务端生成登记号、实例号和安装码；同一安装码唯一。
4. 安装预约从同一购买登记的可预约实例中选择部分商品，保存联系人、结构化地址、期望日期和时间说明，并原子创建 `INSTALLATION / PENDING_ACCEPTANCE` 统一工单及首条状态历史。
5. 顾客档案／门店顾客提供权限范围内的查询、分页和详情；预约管理／门店预约查询同一预约工单；工单管理读取同一统一工单，不复制客服工单表；安装码查询读取同一产品实例。
6. 列表均复用 `FaPageMain → EsSearch → EsTable` 和 `useListPage`；有页面级动作时再使用 `EsListToolbar`，不渲染空工具栏。表格撑满剩余空间，空数据与加载状态分页位置稳定。

## 2. 主动不实现

- 顾客扫码填写、短信验证码、签名图片、隐私撤回与注销仍依赖消费者身份、短信和对象存储，本轮只接受已授权店员确认当前政策版本，不伪造验证码或签名。
- “稍后确认”、确认后再次编辑商品、整单／部分退货、VIP 自动判定、导入导出规则尚未确认，不开放对应写操作。
- 预约只创建待受理工单；服务站自动匹配、人工覆盖、派师傅、改派、缺件、完工、审核、回访、投诉和结算由后续工单切片实现。
- 不把目标状态草案直接做成任意状态编辑；所有后续迁移继续使用专用动作接口并写不可变历史。
- 不向共享测试库写业务样例；本轮仅执行已授权的结构迁移、权限 DML 和本地运行配置。

## 3. 隐私与数据安全

- 手机号、姓名和详细地址不以明文写库。应用使用至少 32 字节的 `gaia.after-sales.pii-key` 进行 AES-GCM 加密，并以派生 HMAC-SHA256 摘要支持手机号／姓名精确检索；数据库另存脱敏展示值。
- 列表和当前首版详情仅返回脱敏值；页面、日志、异常、审计和版本 token 不包含明文或密文。
- 未配置密钥时读空列表仍可用，但登记和预约写入必须明确失败，不回退到明文；已配置但长度不足时宿主拒绝启动。
- 省／市／区县／街道作为路由和统计维度明文保存；详细地址单独加密。

## 4. 数据和并发

- 新表：`afs_customer`、`afs_purchase_registration`、`afs_purchase_item`、`afs_product_instance`、`afs_consent_record`、`afs_service_order`、`afs_service_order_item`、`afs_order_status_history`。
- 所有表使用不可变主键、租户路由数据源、创建／更新时间和创建／更新人；主聚合使用 revision 与版本 token。
- `client_request_id` 在购买登记和预约工单内唯一，用于避免前端重试重复创建；同一产品实例存在活动工单时拒绝再次预约。
- 购买和预约在单事务内保存头、明细、实例／工单关系和历史；任一步失败全部回滚。

## 5. API 与权限

- `GET /api/afterSales/customer/permissions`：按 `customerArchive`、`appointment`、`dealerRegistration`、`dealerCustomer`、`dealerAppointment`、`workOrders`、`installationCodes` 返回读／创建能力。
- `GET /api/afterSales/customer/options`：返回当前用户可登记门店与可选商品，接口自身要求登记权限，不依赖主档管理菜单。
- `POST /api/afterSales/customer/registrations`：创建购买登记。
- `GET /api/afterSales/customer/records`、`GET /records/{id}`：顾客／购买档案分页与详情。
- `POST /api/afterSales/customer/appointments`：对部分实例创建安装预约工单。
- `GET /api/afterSales/customer/appointments`、`GET /appointments/{id}`：预约分页与详情。
- `GET /api/afterSales/customer/work-orders`、`GET /work-orders/{id}`：统一工单分页与详情。
- `GET /api/afterSales/customer/installation-codes`：安装码分页。
- 门店和代理商范围通过 `sys_user_data_permission → sys_organization_relation → md_customer → md_store` 强制过滤；前端选择的门店 ID 不作为授权依据。

## 6. 首版验收

1. 有权限用户可在授权门店登记多个商品，生成一个购买登记和对应数量的实例／安装码；重复请求 ID 不产生第二单。
2. 可只选择部分实例预约；已存在活动工单的实例再次预约返回冲突，未预约实例保持可预约。
3. 顾客、预约、工单和安装码查询只返回当前授权门店范围；跨租户和未授权门店返回空或 404。
4. 明文手机号、姓名和详细地址不出现在业务表、审计、版本 token、API 列表或异常信息中；精确手机号检索可命中脱敏记录。
5. 前端完成筛选／重置／分页／空状态／失败重试／重复提交保护；顾客详情能查看商品实例和预约状态。
6. 后端集成测试、前端测试、类型检查、生产构建及管理员允许侧桌面浏览器关键页面通过；拒绝角色和业务数据验收单独记录。
