# 工单分派职责与菜单权限调整

- 日期：2026-09-16
- 状态：菜单职责已配置；人员三类分配策略研发实现见 [2026-09-18-服务人员三类自动分配策略](./2026-09-18-服务人员三类自动分配策略.md)
- 关联模块：客服作业、服务站作业、服务工单、派单调度

## 1. 已确认职责边界

| 职责 | 菜单 code | 工作视角与分组 | 当前状态 |
| --- | --- | --- | --- |
| 客服将工单分配至服务站 | `afsDispatch` | 客服作业 / 工单处理 | 保留已有服务站推荐和人工服务站分配能力 |
| 服务站将本站工单分配给服务人员 | `afsWorkOrderAssignment` | 服务站作业 / 本站工单 | 手动首次分配、候选硬约束、自动成功/失败留痕已形成研发实现；不支持改派 |

`afsDispatch` 不再投影到服务站作业。服务站不通过客服派单调度入口执行人员分配。

## 2. 菜单与权限实现

- 独立售后前端以 `apps/after-sales/src/features/navigation/manifest.json` 为运行导航来源：客服“工单处理”保留 `afsDispatch`，服务站“本站工单”以 `afsWorkOrderAssignment` 替换它。
- 新菜单路径为 `afterSales/serviceResource/workOrderAssignment`，当前进入通用待接入页面，不调用工单分配写接口。
- `sys_module` 新增 `afsWorkOrderAssignment`，挂在 `afsServiceResource` 下；脚本会向当前拥有服务站视角或售后管理员导航授权的角色授予该菜单。
- 现有站点专属角色如仍保留 `afsDispatch`，脚本会移除该菜单及其操作授权；同时禁用旧 `afsDispatch` 的 `dispatch` 人员分配操作并撤销全部角色操作授权。客服保留 `assignStation` 服务站分配操作。

本地库当前只有共享管理员角色同时具备客服和服务站视角；这些角色保留客服派单菜单，以免误伤客服服务站分配。服务站侧由当前视角导航隐藏旧菜单，未来配置站点专属角色时，迁移脚本会清理该角色的旧派单授权。

## 3. 待开发范围

服务站“工单分配”正式开发时应补齐（业务口径以 2026-09-18 确认稿为准；**本期不支持改派**）：

1. 只查询当前服务站数据：默认 `PENDING_ASSIGNMENT`；条件查询可含已分配行但不提供改派。
2. 候选服务人员按本站归属、启用状态、服务项目技能、排班与容量等策略筛选排序（策略另切）。
3. 提供首次分配与并发版本校验及留痕；不提供改派/撤销（若后续需要另开确认）。
4. 工单冗余写入服务人员工号、姓名、手机；独立操作权限及 `PUT .../personnel` 的服务站范围校验；未完成前不得重新启用旧 `afsDispatch.dispatch` 操作。
