## 1. 当前事实

- 独立子系统位于 `gaia-ui/apps/after-sales`。当前 49 个规划功能中，商品分类、商品档案、商品系列、配套品管理、服务项目和配件基础资料已接入真实接口；其余功能仍使用统一“待接入”页面或按业务边界保持未实现。
- 售后后端当前已具备上述六个目录页面所需的 API、AppService、model、Mapper、迁移和隔离集成测试；目录后端、独立前端及宿主装配已分别提交，未 push。
- 开始时三个仓库均有既存未提交改动：前端独立子系统及双前端编排、售后后端 `database/README.md`、宿主 `.gitignore` 和 POM。本次完整保留。
- 夜间收口时 7004 主前端、9010 内部子前端、18081 隔离 H2 后端和 9013 隔离前端实际保持运行，8080 真实后端未监听。2026-09-09 11:02 最终复核时已恢复并保留 7004、9010、18081、9013 四个入口，均返回 HTTP 200；8080 真实后端当前未监听，7004 仍保持原代理目标且没有自动切换到 H2。普通沙箱进程无法连接本机端口，状态均使用获准的只读本机检查确认。
- 当前系统 Node 是 26.7.0，不符合子系统要求的 `>=22.23.1 <23`；固定 pnpm 10.8.1 可用。受限网络下系统 Corepack 会尝试查询 registry 并失败，因此不下载或替换工具链。

## 3. 实现与修复

- 后端 `GaiaAccessContextTest` 原使用 Mockito mock 两个 Gaia 服务接口；当前 JDK 21 受限环境不允许 Byte Buddy 自附加，标准 `mvn test` 因测试基础设施失败。
- 已改为 JDK 动态代理提供同等的权限返回，保留对真实 Shiro 身份、租户和显式授权逻辑的验证，不改变生产源码或权限行为，也不再依赖 JVM attach 权限。
