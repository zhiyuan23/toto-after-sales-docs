# 渠道与网点独立系统全栈首版

- 日期：2026-09-10
- 对应入口：A03 代理商管理、A04 门店管理、A05 家装公司、A06 服务站管理、A07 服务区域
- 需求依据：ADM-MD-001～ADM-MD-005
- 状态：五个入口均有真实功能；代理商／门店为权威主档只读，家装公司／服务区域完成当前可确认切片，服务站补充负责人联系信息和区域反查；完整业务验收仍受未确认规则限制

## 1. 交付范围

1. 代理商、门店继续读取 Gaia/DWH `md_customer`、`md_store`、`md_store_type`，叠加组织数据范围，支持查询、筛选、分页和详情；不调用 legacy 写入服务，不覆盖权威主档。
2. 家装公司使用售后自有主档，维护编码、名称、外部系统／外部公司编码、联系人、备注和启停。外部系统与外部公司编码成对填写；具体家装订单号属于后续购买记录，不写进公司主档。
3. 服务站保留既有编码、名称、备注和启停，新增负责人姓名、联系电话的独立配置。负责人仅是业务联系人，不等同于 Gaia 登录账号。
4. 服务区域使用省、市、区县、街道四级行政区域表达，维护编码、名称、备注、启停，并可关联最多 100 个候选服务站及 1～999 优先级。停用区域或服务站保留历史关系。
5. 服务站列表反查已关联区域。区域与站点关系由服务区域页面统一维护，前端不复制匹配或派单判断。

## 2. 主动未实现

- 不开放代理商／门店写入、导入或 DWH 同步，不猜测主数据字段责任、同步冲突优先级、门店完整类型／状态或送安一体状态机。
- 不把负责人联系人自动绑定为账号；服务站级数据范围、负责人账号停用联动和服务人员跨站权限仍待确认。
- 不发明技能字典、地图围栏、地址解析、唯一站点自动派单或区域重叠自动决策。当前数据支持维护候选站及显式优先级，后续工单切片再消费。
- 不创建共享业务测试记录，不把空列表、管理员允许侧或隔离测试当作正式角色／业务验收完成。

## 4. API 与权限

- 统一权限：`GET /api/afterSales/network/permissions`，按 dealers、stores、decorationCompanies、serviceStations、serviceAreas 返回能力。
- 家装公司：`/api/afterSales/network/decoration-companies` 的列表、详情、新增、编辑、启停。
- 服务区域：`/api/afterSales/network/service-areas` 的列表、详情、新增、编辑、启停；新增／编辑命令内维护候选服务站优先级。
- 服务站：既有 CRUD／启停外，新增 `PUT /api/afterSales/network/service-stations/{id}/profile`。
- OpenAPI 升级到 1.9.0；BIGINT ID 仍以字符串传输，失败沿用 Gaia `APIResponse` 和 4001／403／404／409／422／503 语义。
