# 售后子系统独立登录基础阶段

- 日期：2026-09-09
- 范围：售后独立前端登录、退出、会话失效与安全回跳
- 状态：基础闭环已完成；用户、角色和角色授权的可写代码阶段已于 2026-09-10 接入同一 Gaia 后端，双端真实账号验收及子系统内 MFA 仍待后续阶段；自助改密前端已接入，真实账号验证待完成

## 1. 已交付范围

1. 售后子系统新增独立 `/after-sales/#/login` 页面，视觉结构沿用 Compass Admin 登录页的双栏卡片形式，并保留“蓝鲸数字售后服务”品牌；不加载主系统 HTML 或运行时。
2. 登录继续调用 Gaia `/api/sys/passport/login`，使用与主系统相同的 multipart 字段、同源服务端会话、前端会话标记及原始 `Authorization` 请求头协议；没有引入 Compass JWT、第二套账号表或同步任务。
3. 接入 `/api/sys/passport/captcha`，支持 Gaia 当前验证码开关及 DES/ECB/PKCS7 密码加密配置；加密实现复用主系统同版本 `crypto-js 4.2.0`。
4. 未登录直达业务页、服务端会话失效和账号切换均失败关闭；独立模式进入子系统登录页，嵌入窗口仍由主系统承接登录，避免 iframe 内出现第二层登录外壳。
5. 登录返回路径只接受子系统站内绝对路径，拒绝协议相对路径、外部 URL 和登录页自身；Hash 查询参数以 `afterSales:` 命名的同页 sessionStorage 记录兜底，不存放凭据。
6. 顶部增加退出入口，调用 Gaia `/api/sys/passport/logout`；成功后清除已知认证键和临时 `afterSales:` 缓存，保留同源其他应用数据及按用户隔离的版本化界面偏好。OIDC/OAuth2 的后端退出地址继续按 Gaia 响应处理。
7. 登录失败保留账号和密码输入、避免重复提交并刷新验证码；退出取消不会产生未处理错误。

## 2. 接口与来源对照

| 前端能力 | Gaia 接口/协议 | 复用和调整 |
| --- | --- | --- |
| 验证码与登录配置 | `GET /api/sys/passport/captcha?userName=` | 复用主系统字段 `verificationCodeRule`、`verificationCode`、`inscriptionEncryption` |
| 账号密码登录 | `POST /api/sys/passport/login` | multipart；按配置加密密码；成功后沿用同源 Gaia 会话和本地会话标记 |
| 菜单授权 | `GET /api/sys/Module/tree` | 沿用已有售后菜单投影，登录成功后重新读取，不从登录结果制造权限 |
| 退出 | `GET /api/sys/passport/logout` | 原始 token 请求头、同源凭据；仅成功后清理本地会话 |

Compass Admin 的注册、找回密码、JWT、Resource RBAC 和 mock 未复制。当前 Gaia 密码重置、多因子特殊状态仍引导到统一主系统账号安全页面，不声称这些异常流程已经在子系统内独立完成。

## 9. 2026-09-12 个人设置未保存确认框交互修复

- 编号／类型：`BUG-20260912-05`／缺陷；标题：改密未保存确认框可见但按钮无法点击。
- 应用／视角／入口：Web 后台／跨视角／统一账号个人设置（登录底座，不新增 A/D 入口）；关联本 Spec。
- 来源／日期：用户反馈，2026-09-12 提出并更新；优先级 P1，严重程度：阻断个人设置退出；负责人待分配；状态：待验证（研发自测通过，待用户复核）。
- 环境与复现：本地 Chrome，`127.0.0.1:9010` 独立入口；已登录后进入个人设置 → 安全设置，输入未保存内容并点击关闭或切换分区。确认框显示在前方，但按钮无法点击，底层输入仍能命中；预期确认框独占点击和键盘焦点。
- 原因与修复：父层 `FaModal` 使用 Radix 模态隔离，追加到 body 的 `ElMessageBox` 继承 `pointer-events: none`，提高 z-index 无法解决。按用户要求保留原 Element Plus 确认框、尺寸、布局和按钮样式，仅为此确认框的遮罩恢复指针事件，并在消息节点使用无视觉样式的 `FocusScope` 暂停父级焦点捕获；确认框关闭后恢复原焦点栈，自动聚焦与键盘循环仍由 Element Plus 管理。只有点击“放弃修改”才清空草稿并执行关闭或分区切换，取消、右上角关闭及 Esc 保留草稿。
- 研发验证：国际化改动完成后，在固定 Node 22.23.1 下最终复验 `profile-module.test.ts` 与 `auth-session.test.ts` 共 7 项通过，`vue-tsc -b` 类型检查和 production build 通过。构建仅保留既有 Vite 配置兼容提示和大包提示。
- 浏览器证据：在 9010 真实登录页面复现原确认框按钮 `pointer-events: none`；最终原样式版本在 `127.0.0.1:9018/after-sales/tests/browser/profile-discard.html` 隔离回归页验证，页面使用实际个人设置和 `FaModal` 组件，规则／验证码为本地桩，禁止改密。确认框两个操作按钮和关闭按钮均为 `auto` 且坐标命中自身，Tab 循环留在确认框；继续编辑、右上角关闭、Esc 保留测试草稿，取消后恢复触发位置焦点；放弃后切换分区清空草稿、放弃后关闭、无修改直接关闭均通过，关闭后 body 恢复 `pointer-events: auto`。主页面最终版本复查受到并行国际化运行错误影响，需相关改动完成后再联调。
- 验证边界：仅在验证码输入框填写非验证码测试字符串以触发未保存状态，未填写新密码、未提交改密请求、未变更账号；不替代真实账号改密与重新登录验收，入口及最终验收计数不变。
