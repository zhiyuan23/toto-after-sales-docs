# 售后子系统独立登录基础阶段

- 日期：2026-09-09
- 范围：售后独立前端登录、退出、会话失效与安全回跳
- 状态：基础闭环已完成；用户、角色、授权管理及子系统内密码重置/多因子仍待后续阶段

## 1. 已交付范围

1. 售后子系统新增独立 `/after-sales/#/login` 页面，视觉结构沿用 Compass Admin 登录页的双栏卡片形式，并保留“蓝鲸数字售后服务”品牌；不加载主系统 HTML 或运行时。
2. 登录继续调用 Gaia `/api/sys/passport/login`，使用与主系统相同的 multipart 字段、同源服务端会话、前端会话标记及原始 `Authorization` 请求头协议；没有引入 Compass JWT、第二套账号表或同步任务。
3. 接入 `/api/sys/passport/captcha`，支持 Gaia 当前验证码开关及 DES/ECB/PKCS7 密码加密配置；加密实现复用主系统同版本 `crypto-js 4.2.0`。
4. 未登录直达业务页、服务端会话失效和账号切换均失败关闭；独立模式进入子系统登录页，嵌入窗口仍由主系统承接登录，避免 iframe 内出现第二层登录外壳。
5. 登录返回路径只接受子系统站内绝对路径，拒绝协议相对路径、外部 URL 和登录页自身；Hash 查询参数以 `afterSales:` 命名的同页 sessionStorage 记录兜底，不存放凭据。
6. 顶部增加退出入口，调用 Gaia `/api/sys/passport/logout`；成功后只清除已知认证键和 `afterSales:` 缓存，保留同源其他应用数据。OIDC/OAuth2 的后端退出地址继续按 Gaia 响应处理。
7. 登录失败保留账号和密码输入、避免重复提交并刷新验证码；退出取消不会产生未处理错误。

## 2. 接口与来源对照

| 前端能力 | Gaia 接口/协议 | 复用和调整 |
| --- | --- | --- |
| 验证码与登录配置 | `GET /api/sys/passport/captcha?userName=` | 复用主系统字段 `verificationCodeRule`、`verificationCode`、`inscriptionEncryption` |
| 账号密码登录 | `POST /api/sys/passport/login` | multipart；按配置加密密码；成功后沿用同源 Gaia 会话和本地会话标记 |
| 菜单授权 | `GET /api/sys/Module/tree` | 沿用已有售后菜单投影，登录成功后重新读取，不从登录结果制造权限 |
| 退出 | `GET /api/sys/passport/logout` | 原始 token 请求头、同源凭据；仅成功后清理本地会话 |

Compass Admin 的注册、找回密码、JWT、Resource RBAC 和 mock 未复制。当前 Gaia 密码重置、多因子特殊状态仍引导到统一主系统账号安全页面，不声称这些异常流程已经在子系统内独立完成。
