## 范围与契约

- 商品、配件、人员照片、消费者头像、申请图片、完工证据及图片类技术资料统一使用公开 HTTP(S) 图片直链。图片读取不要求会话；上传、业务记录读取、修改和删除保持原有认证与权限。
- 售后 API 在 JSON 响应层批量解析 Gaia 文件记录，输出完整图片地址；相同引用去重。商品、库存、领退料、调拨、指南、工单、费用和后台档案复用该能力，不逐页拼接 MinIO 域名。
- 两端小程序直接展示后端地址。服务人员配件缩略图取消会话下载／临时文件转换，保留懒加载、占位、cover 和点击预览；消费者商品图取消专属图片 API 重写。消费者头像使用 `avatarUrl`，申请媒体补充 `imageUrl`；图片资料直接预览，PDF／视频等附件继续原有下载流程。
- 后台售后子系统使用相同直链。图片上传继续 Gaia 通用上传，通过售后 `/catalog/images/url?reference=...` 获取即时预览直链；会员详情取消头像 Blob 下载，直接显示详情返回的 `avatarUrl`。不修改平台公共上传实现、主系统或 `src/views/common`。
- 数据库存储稳定的文件引用和对象路径。JSON 写入前仅还原本环境公开基地址下的图片：公共／上传者文件分别恢复 `picture`／`pictureWithAuth` 引用；外部图片 URL 保持原样。ID、乐观版本及非图片附件不改写。
- 完工证据原始本地文件与审核引用保留；公开副本位于 `afterSales/task-evidence/{tenantId}/{taskId}/{key}`，MIME 类型来自原始校验。已有副本复用；同进程去重并限制缓存规模。提交时直链恢复原审核引用，租户不匹配拒绝。历史原件缺失时保留引用，不因单张图片缺失隐藏整份任务；缺失原件本身不被本次修复。
- 旧商品、配件、头像及证据图片读取路由保留供既有客户端使用。更新顺序为后端先上线，再更新 Web 和两个小程序。

`after-sales.images.public-base-url` 为售后图片公开基地址，未配置时复用 `proj.image.attachment.server`。必须为完整 HTTP(S) 地址并包含桶／代理路径。

当前 HTTPS 入口为 `https://minio.test.ljsz.xyz:1443/file/`；内网 MinIO 入口及该 HTTPS 入口对指定真实配件对象的匿名读取均返回 200。只读回查桶策略确认 `s3:GetObject` 的匿名允许范围包含 `arn:aws:s3:::file/*`，覆盖头像、申请及完工副本目录，无须修改共享桶权限。本次未改变 MinIO 策略。

正式环境应配置正式 HTTPS 图片域名／代理路径，保证匿名 GET 可达，并在两个小程序分别配置所需的微信合法域名。数据库无测试域名迁移；正式域名及真机网络需要在正式配置确定后验证。
