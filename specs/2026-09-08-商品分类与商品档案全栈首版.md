## 1. 架构与数据归属

沿用 Gaia 单体模块和 MyBatis，不增加微服务、通用 CRUD 父类或第二套响应/身份框架。接口层处理 HTTP 和响应；应用服务负责权限、事务及用例；领域规则负责分类关系和商品校验；Mapper 明确列出 SQL。跨域主档操作集中在适配层，禁止前端传实体或任意查询 Map。

- 基础商品：`md_material`，只处理成品 `material_type=3`。编码、名称、GTIN、规格、商品分类继续是共享字段。
- 基础分类：`md_material_type_category`，复用 ID、父子关系、名称、排序、备注和路径。已有未扩展分类按商品分类读取。
- 售后扩展：以主档 ID 为主键建立分类、商品扩展。分类保存维度和售后启停；商品保存机能型号、本体品番、水箱品番、颜色、营业分类和售后启停。共享物料 `enable` 与售后启用共同决定能否用于新售后业务。
- 编辑只更新授权白名单字段，不覆盖共享主档的图片、单位、工厂、品牌、自定义字段等其他能力。禁止物理删除共享主档；停用保留 ID 和历史。
- 商品分类与营业分类作为不同维度，不允许跨维度父子关系；商品引用两种分类时分别校验。商品分类界面展示大/中/小层级。

## 2. 公共契约

- URL：Controller `/api/afterSales/catalog`，宿主 context `/api`；前端继续用 Gaia request 和现有代理。
- 响应复用 `APIResponse<T>`：`code=0` 成功、`errMsg` 为可展示错误、`data` 为 DTO；分页复用 Gaia `PageResponse` 的 `rows/records`，前端适配为 `list/total`。
- 查询统一 `page`（从 1 开始）、`pageSize`（15/30/50/100，服务端上限 100）；搜索有界、参数化，排序固定稳定次序。
- ID 作为字符串传输，数据库继续 BIGINT；版本 token 随详情/列表返回，编辑/状态变更必须带原版本，过期提示刷新。
- 登录和租户使用 Gaia Shiro 与数据源上下文；多租户模式缺上下文时拒绝。不接受客户端 tenantId/userId。
- 权限读取 Gaia 用户菜单/API 和操作授权，售后接口额外采用未授权即拒绝，不依赖宿主“未配置路径放行”。页面通过权限结果和行可执行动作展示按钮。
- 创建、编辑、启停与审计在同一事务。分类结构变更和商品引用校验使用数据库锁；并发失败不部分保存。
