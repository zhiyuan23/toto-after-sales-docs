# 两端小程序简中英日国际化 Spec

- 状态：用户已确认实施范围；本地实现及研发验证完成，微信工具／真机和业务验收待完成。
- 确认记录：2026-10-22，用户要求“按这个方案给两个小程序接入简体中文、英文和日文，先统一国际化底座，再完成现有页面的文案迁移和验证”。
- 载体：消费者小程序与服务人员小程序及其 H5；不修改 Web 后台和后端业务契约。
- 实施及复核日期：2026-10-22～23；研发验证不等于上传、发布或业务验收。

## 1. 目标和范围

两个端侧共同维护国际化底座，为当前正式消费者43页、服务人员23页迁移已有界面文案，支持 `zh-CN`、`en-US`、`ja-JP`。消费者和人员“我的”可切换语言，人员登录页在登录前即可切换。当前语言同步页面、公共控件、导航、Tab、校验、提示、空态、失败态和日期显示。

正式页面关联的业务组件、API前端诊断和辅助展示代码一起迁移。开发 Demo、参考示例、未注册设置页的说明不要求全部翻译，但共同语言控件及基础示例双端等价同步。消费者词典1388键、人员词典1186键，三语言分别保持相同键集和参数集。

商品、型号、客户／企业／地区／字典名称、知识／AI／协议／文件正文、备注等业务原始内容保持其来源语言；不引入机器翻译、后端多语言字段或新权限。微信原生授权及系统权限界面由宿主决定。币种、时区、URL、接口字段、枚举值、提交白名单和现有业务流程保持原契约。

## 2. 运行时契约

| 项目 | 行为 |
| --- | --- |
| 单一状态 | `src/locales/index.ts` 注册三语言及框架映射，复用固定版本 `@dcloudio/uni-i18n`；仅把已有同版本传递依赖声明为直接依赖，未新增依赖版本 |
| 初始语言 | 有效本地手选优先；否则跟随支持的系统语言；不支持或无法读取时回退简体中文 |
| 偏好隔离 | `afs:<tenant>:<environment>:locale:v1`；无效存储值忽略，写存储失败不阻止当前会话切换 |
| 切换行为 | 即时更新展示及 Day.js／H5 lang；保留输入、选择、会话和页面状态，不重建页面、不重发业务请求；进行中请求按原流程完成 |
| 框架文案 | `zh-CN → zh-Hans`、`en-US → en`、`ja-JP → ja-JP`；`src/locale/uni-app.*.json` 覆盖框架选择器、弹窗和媒体控件 |
| 原生导航 | 路由使用稳定 `titleKey`，启动／onShow及语言变化同步标题和Tab；路径、权限与Tab目标保持原值 |
| 静态展示 | `t` 在模板、computed或getter中执行；完整句子参数化；`messageList`仅承载展示数组，提交值不依赖翻译文本 |
| 诊断和未知内容 | `RequestError.originalMessage`、类型和状态保留；已知前端错误展示翻译，原始诊断仍供现有判断使用；未知后端错误和业务内容保留原文 |
| 内置业务标签 | 人员端根据稳定code翻译任务类型／状态／模式及处理标签；日程接口缺code的已知内置名称采用经后端核对的封闭适配，未知自定义名称透传；不改DTO |

`resolveUiMessage`只处理已知前端UI错误快照的展示，不对业务对象、用户输入或DOM做中文替换。消费者服务进度的分支比较改用稳定titleKey；人员步骤计数和密码显示动作使用完整参数句子，避免翻译片段拼接和翻译文本参与业务判断。

## 3. 共同底座和构建约束

两个仓库的运行时、框架词典、语言控件／基础Demo、词典压缩插件、遗漏检查、回归脚本及依赖声明等价同步；各端路由和业务词典保持独立。开发细则见两个仓库的 `docs/i18n.md`，共同范围见 `docs/shared-foundation.md`。

构建只保留一份语义键表和三份值数组，源码仍以可编辑的语义键词典维护，校验严格对齐及逐词条往返一致性。修改词典源码时HMR同时失效共享键表与全部词典并刷新开发页面，保证新增键不造成索引错位；用户操作语言选择时不刷新页面。

微信非watch构建在UniApp及全部输出优化结束后统计最终主包，按 `app.json` 排除实际声明的分包；超过2MiB即失败。不得测量图标裁剪前的中间产物，也不得关闭门禁。所有正式页面继续在主包，默认test无业务分包；development的可选dev分包不计主包。
