# 售后 AI 与高德外部服务配置指南

- 当前方案：默认后端凭证来源，网页管理能力保留待未来显式启用；2026-10-17地图独立配置续轮已完成研发验证，本地提交状态见[整改提交记录](2026-10-17-售后宿主模块级隔离.md#10-本地提交与开发约束)，未部署，既有2026-10-14共享发布状态见[本次发布](../../03-开发管理/01-环境部署/部署记录/测试环境发布记录.md#release-20261014-current)。
- 更新日期：2026-10-17。
- 契约及研发证据：[外部服务配置与密钥集中管理](2026-10-13-外部服务配置与密钥集中管理.md)。

## 当前配置入口与存储

当前默认使用后端私密配置维护凭证，前端保留未来管理能力；最新契约见[后端凭证来源](2026-10-13-外部服务配置与密钥集中管理.md#server-credential-source-20261014)。

2026-10-15 新版源码／本机导航已调整为「系统管理员 → 系统管理 → 系统运维 → 外部服务配置」，共享环境需发布后才显示该分组；[管理员导航与验证](2026-10-15-系统管理视角与全部功能入口.md)。管理员在此查看连接状态、维护服务开关／AI模型和测试连接。默认没有API Key输入或清除操作。分站、人员分配、完工审核和消费者助手共用`gaia.after-sales.ai.api-key`；地图仍分Web服务Key与JS API Key／Security Code，浏览器仅运行时获取JS Key，Security Code只由服务端受限同源代理使用。

## 默认后端私密配置

`gaia.after-sales.external-services.credential-source=SERVER`（未指定时也默认SERVER）。当前四项凭证仅从下列后端配置读取，缺失不会回退到数据库旧值或旧分配／助手／审核专用属性：

```properties
gaia.after-sales.external-services.credential-source=SERVER
gaia.after-sales.ai.api-key=<统一AI Key>
gaia.after-sales.amap.web-service-key=<高德Web服务Key>
gaia.after-sales.amap.js-api-key=<高德Web端JS API Key>
gaia.after-sales.amap.js-security-code=<对应JS安全密钥>
gaia.after-sales.external-services.encryption-key=<32字节随机主密钥的Base64编码>
```

真实值只放运行账号可读的0600私密文件或部署Secret：外部Tomcat为`${CATALINA_BASE}/conf/gaia-after-sales.properties`，可执行Jar为`<启动目录>/conf/gaia-after-sales.properties`；本机统一启动器另加载宿主`.local/application.properties`。无密钥模板在`gaia-after-sales/gaia-after-sales-api/src/main/resources/config/gaia-after-sales.properties.example`。不写入源码、前端环境、WAR/JAR、发布压缩包或验证日志。

数据库仍保存服务开关和四项模型，并沿用原加密配置表、审计及revision。加密主密钥因此仍需保留，供应商Key不等于加密主密钥。原数据库密文中的历史凭证原样保留但不参与当前调用；保存非敏感设置也不自动删除历史Key、不将服务器Key写回数据库。空记录首次保存不保存服务器Key。

修改后端凭证后重启实际运行的宿主；保存页面开关／模型后下一次调用生效，地图已打开时刷新或重新打开。新的部署预检仅返回来源与四项后端凭证就绪布尔值；当前完整发布在SERVER模式下要求四项私密配置齐备、加密主密钥及根路由有效。2026-10-14用户明确授权补齐测试机四项私密凭证后，共享新版已随正式发布完成重启；配置接口确认SERVER、四项配置及主密钥均就绪且不返回私密值。后续目标仍须按新模板准备配置，不通过保留旧WAR内嵌供应商值解决缺失。

## 未来显式启用网页凭证管理

仅由运维在后端设置`gaia.after-sales.external-services.credential-source=DATABASE`并重启，不能由前端切换。启用前须单独确认HTTPS、权限与日志保护，核对数据库凭证是否仍有效；若记录为空或没有Key，不回退到服务器文件。原网页输入、替换／清除、AES-GCM存储、审计与动态读取路径保留。需要输入新Key时按全部启用服务的必需凭证补齐并保存，不把来源切换当作自动迁移或轮换。

2026-10-17用户最终要求主系统地图写法和配置完全保持远端master原样，当前已逐字恢复公共地图库原文件（含原默认Key及覆盖方式），并撤销本机新增`gd.map.key`，不再要求主系统为售后修改配置。售后只读取自己的`gaia.after-sales.amap.*`与开关，删除向公共地图库供Key的桥接。两边代码／配置独立；历史Key值相同，供应商配额及吊销独立仍需另行分配售后专用Key。此前用户授权的一次官方逆地理查询通过（HTTP200、status=1、infocode=10000且返回地址），本轮未增加查询。最新基线、零差异与验证见[master原样契约](2026-10-17-售后宿主模块级隔离.md#8-主系统地图精确保持master原样2026-10-17最终确认)。

售后AI分配endpoint／model默认值由Core持有，宿主重复值已移除，部署仍可覆盖同名属性。未来独立运行宿主继续使用售后自己的配置契约；不因此要求改主系统公共配置。本轮未提交／推送／重启／部署，凭证轮换和正式微信／生产域名验收保持原边界。

## 地图根代理接入

SDK要求站点根路径`/_AMapService`；本机Vite开发／预览已经固定转发到受保护业务API。运行时接口只向根代理窄路径复制现有会话Cookie（HttpOnly、SameSite=Strict；HTTPS应启用Secure），不创建新身份、不在URL传令牌；退出与原会话同步失效。

共享Tomcat直接入口须在Host启用`org.apache.catalina.valves.rewrite.RewriteValve`，并在`conf/<Engine>/<Host>/rewrite.config`加入[固定别名模板](../../scripts/deploy-test/amap-root-rewrite.config)。需保留其他规则，备份、校验及协调必要重启；测试服务器本轮已应用并验证。Nginx生产入口可等价固定转发根别名到应用，保持查询与同源Cookie，不能接受任意目的地。部署门禁会检测售后目标主密钥、固定根别名和公共地图无售后凭证注入；保留主系统master已有默认Key，不因售后发布要求清理主系统配置。

## 替换、验证与恢复

SERVER模式轮换供应商Key时先备份私密文件，在后端更新、重启并逐项测试；DATABASE模式才通过页面填写、保存、测试。供应商侧撤销旧值另行操作，未明确授权时不自动轮换。连接测试只验证已保存配置、官方固定目的地及合成地址，不提交工单或重新执行历史审核。AI测试为认证检查；实际模型可用性与业务效果仍需按各业务Spec验证。

数据库备份必须与主密钥分别保管；遗失主密钥无法解密原凭证。恢复时先恢复同一主密钥，再核对对应密文与配置版本；主密钥轮换需要受控解密／重新加密迁移，不能仅覆盖文件。回退旧包前确认其独立文件凭证，否则旧实例无法读取新加密表。测试库权限回退按本次私密备份恢复原八个地图菜单API清单、移除仅本次新增的菜单／操作绑定；保留表及审计供核验，不清库或覆盖其他并发授权。

Git历史、历史发布备份仍可能保留旧开发凭证；本次已清理TOTO自有源码及前端制品；后端公共依赖副本已清理，Git历史及私密回退备份保留，不重写历史。正式上线前在供应商后台轮换已暴露的AI／高德开发凭证，绑定正式域名并完成共享新版与真实微信验证。

## 历史方案（2026-09-18～2026-10-13，仅适用于未升级实例）

以下旧属性及分配／审核／助手独立Key仅作历史排查依据；新版SERVER模式使用上方统一四项凭证，不能沿用历史的多Key回退。

## 1. 目标与边界

DeepSeek Key 是部署环境密钥，不属于业务数据库、前端构建物、Maven 制品或 Git 内容。宿主会自动从固定的外部应用配置路径导入它，因此部署新的服务器时只需准备一份外部配置文件；更新 WAR、售后 JAR 或前端静态文件不会覆盖该文件。

应用支持以下两种配置方式，外部应用配置文件为标准方案；环境变量仅用于容器、systemd Secret 等平台化部署。

| 配置方式 | 变量/属性 | 适用场景 |
| --- | --- | --- |
| 外部应用配置（标准） | `gaia.after-sales.dispatch.ai.api-key` | 外部 Tomcat、可执行 JAR、人工或脚本发布 |
| 环境变量（可选） | `GAIA_AFTER_SALES_DISPATCH_AI_API_KEY` | Docker、Kubernetes、systemd Secret |

服务站与服务人员分配共用 `gaia.after-sales.dispatch.ai.api-key`。完工审核使用 `gaia.after-sales.completion-audit.ai.api-key`，未单独设置时回退到分配密钥；也可显式设置为 `${gaia.after-sales.dispatch.ai.api-key}`。消费者助手的 `gaia.after-sales.assistant.ai.api-key` 是独立入口，单独配置它不会反向补齐分配或审核凭证。

## 2. 固定加载路径

| 运行形态 | 自动导入的配置文件 |
| --- | --- |
| 外部 Tomcat WAR | `${CATALINA_BASE}/conf/gaia-after-sales.properties` |
| 可执行 JAR | `<启动工作目录>/conf/gaia-after-sales.properties` |

本项目 macOS/Linux 统一启动脚本另通过 `--spring.config.additional-location=file:.local/` 加载宿主 `.local/application.properties`。本机私密配置可在此补齐上述分配和审核属性，保持文件权限 `0600`、备份在忽略目录；配置改变后须重启实际运行的宿主。只修改 WAR 模块资源文件不会更新已运行的可执行 JAR。

宿主的 `spring.config.import` 已设置为 optional import：配置文件不存在时普通功能仍可启动，但 AI 派单/AI 分配会明确记录“未配置 DeepSeek API Key”并转人工；文件存在且属性有效时无需在 Tomcat 环境变量中另配一份 Key。

## 3. 新环境首次部署

1. 安装 Tomcat 或准备可执行 JAR 的启动目录。
2. 创建上表指定的 `conf` 目录和 `gaia-after-sales.properties` 文件。
3. 使用下列模板填写由运维/密钥管理员提供的 Key；不要把真实值提交进代码库或粘贴进发布记录。
4. 将配置文件权限限制给运行服务的账号，例如 Linux 上使用 `chmod 600`，并设置正确属主。
5. 部署 WAR/JAR 和前端资源，重启服务。
6. 按第 5 节执行验证后再开放 AI 策略。

```properties
gaia.after-sales.dispatch.ai.api-key=<由密钥管理员提供>
gaia.after-sales.dispatch.ai.endpoint=https://api.deepseek.com/chat/completions
gaia.after-sales.dispatch.ai.model=deepseek-chat
```

仓库中的无密钥模板：`gaia-after-sales/gaia-after-sales-api/src/main/resources/config/gaia-after-sales.properties.example`。

## 4. 日常升级与换服务器

- 应用升级前备份 `${CATALINA_BASE}/conf/gaia-after-sales.properties`，但不要将其放入发布压缩包或 Git。
- 更新 WAR 时仅替换应用制品；不要删除 `CATALINA_BASE/conf` 下的外部配置文件。
- 新服务器按第 3 节复制或由部署系统生成这一个外部文件即可；无需重复在 Tomcat、数据库、前端和 WAR 内配置 Key。
- Key 轮换时只更新外部文件并重启宿主，失败工单仍遵循“失败转人工、不自动重试”规则；是否重派由业务人员明确发起。

## 5. 发布后验证清单

1. 确认外部配置文件存在、非空且权限正确；日志、截图、终端输出不得展示 Key。
2. 确认 `GET /after-sales/` 返回页面，且售后策略页可正常加载。
3. 使用总部/管理员账号保存 AI 策略，并创建一张满足候选条件的测试工单。
4. 确认工单显示 `AI派单 · 成功`，服务站已关联；若失败，确认仍为待派单且有失败原因和追踪。
5. 测试服务器 DeepSeek 出口需要 HTTP/1.1；售后两个 DeepSeek 客户端已固定 HTTP/1.1，避免 HTTP/2 stream reset。

## 6. 故障排查

| 现象 | 优先检查 |
| --- | --- |
| `AI派单未配置 DeepSeek API Key` | 外部文件固定路径、属性拼写、运行账号的读取权限；不要仅检查已展开 WAR 的 `WEB-INF/classes/application.properties`。 |
| DeepSeek HTTP/2 reset | 确认发布版本含 HTTP/1.1 客户端修复；验证服务器出口防火墙/代理。 |
| AI 失败后工单未继续流转 | 这是预期：工单保留待派单/待分配，查看失败留痕后转人工处理。 |

### 共用测试库的多实例检查

本机与共享测试服务器会竞争领取同一测试库的自动任务。页面访问测试服务器，不代表任务一定由该服务器执行；服务器已配置 Key 时，本机缺少凭证仍可生成“AI分配未配置 DeepSeek API Key”或“AI审核模型或凭证未配置”。应逐个核对活跃实例的实际运行包、启动目录、私密配置及环境变量，不能只看服务器配置。供应商认证失败与本地未配置是两类错误：前者产生 HTTP 401／403，后者在发出请求前被拦截。

2026-10-13 具体排查、修复和验证见[共库实例 AI 凭证缺失](../04-服务履约配件与费用/2026-10-01-完工智能与AI审核.md#ai-credentials-shared-workers-20261013)。历史失败任务不因补齐配置自动重跑，业务接管与新任务验证仍按原契约执行。
