# 售后子系统列表加载性能修复

- 编号／类型／标题：`BUG-20260911-01`／缺陷／本地列表接口因重复权限查询加载缓慢。
- 应用载体／角色视角：Web 管理后台／跨视角。
- 模块与入口：售后独立子系统通用权限链及 `EsTable` 列表；首次复现入口为 A08 商品分类。
- 关联需求／Spec：ADM-MD-006、A08；[商品分类与商品档案全栈首版](2026-09-08-商品分类与商品档案全栈首版.md)。
- 来源与日期：用户本地联调反馈；首次提出及最后更新均为 2026-09-11。
- 优先级／严重程度／状态：P1／中／待验证。
- 负责人：待分配。

## 1. 复现与定位

- 环境：本地售后独立前端 `9010`、Gaia 聚合后端 `8080`，数据库经 VPN 访问 `10.1.1.106`。
- 前置条件：使用已登录且有售后权限的账号打开商品分类列表。
- 复现步骤：进入商品分类，执行筛选或重置并观察列表请求和页面渲染。
- 实际结果：修复前筛选／重置约需 3.1～3.2 秒；本地直连匿名请求仅约 2～7 ms，业务 SQL 约 58～76 ms，但 JDBC 建连约 1.0～1.1 秒，权限查询在线程栈中等待 MySQL TLS。`CategoryAppService` 的一次用例包含一次 `require` 和三次 `allowed`，旧 `GaiaAccessContext.permissionChecker()` 每次均重新查询 Gaia 模块和操作权限，导致一次业务请求重复访问权限服务。前端每行“更多操作”还因下拉触发器把原生 `type="button"` 透传给 Element Plus 按钮的视觉 `type` 属性，产生大量 Vue 警告和组件树日志。
- 预期结果：售后子系统在不修改主系统的前提下消除自身的重复权限读取和列表警告洪泛；权限仍按用户、租户隔离，后端继续作为最终授权边界。

## 2. 修复范围与设计

- 仅修改 `backend/gaia-after-sales` 和 `frontend/gaia-ui/apps/after-sales`；未修改主系统页面、主系统权限拦截器、`gaia-saas-proj`、共享数据库或权限配置。
- `GaiaAccessContext` 改为请求级组件，同一请求内复用已解析的权限集合，避免一次用例的多个 `require／allowed` 重复加载授权。
- 新增 `GaiaPermissionGrantCache`，按 `userId + tenantId` 保存 30 秒只读权限快照，最多保留 1024 个条目；到期后重新读取 Gaia 模块和操作授权。该缓存只减少子系统重复查询，不生成权限、不扩大授权，未登录或缺租户仍按原逻辑拒绝。
- 售后子系统 `FaDropdown` 为 Radix 触发器显式指定 `span` 宿主，保留 `as-child` 和原菜单交互，同时阻止原生按钮类型被解释为 Element Plus 视觉类型。
- 商品分类、商品档案在页面初始化时并行准备表单所需的分类／系列选项，打开新增表单时复用已有数据，不再额外等待远程请求；分类保存、启停和删除后同步维护本地选项集合。分类、商品和系列的状态／删除确认在进入忙碌态前完成，取消确认不触发业务请求。
- 权限变更在售后业务接口上的最长可见延迟由本缓存限定为 30 秒。正式验收撤权场景时需覆盖该时间窗；若后续要求立即撤权，应补充定向失效能力，而不是扩大缓存时长。

## 4. 剩余边界与验收标准

- Gaia 聚合宿主的主系统 `ApiPermissionCheckInterceptor` 仍会在每个请求读取模块和操作权限，在当前 VPN 数据库环境形成约 1.5 秒的剩余下限。按用户要求本次不修改主系统，因此不能把该下限声明为已消除；进一步降低需另行授权优化主系统拦截器或改善本地数据库链路。
- 本缺陷保持“待验证”，不改变 A08 或其他业务入口的完成数。测试人员应在相同本地网络和账号条件下复测冷／热请求、筛选／重置、允许／拒绝及跨租户场景；确认热请求无售后重复权限查询、页面无警告洪泛，且权限在 30 秒内按预期刷新后，方可关闭。
