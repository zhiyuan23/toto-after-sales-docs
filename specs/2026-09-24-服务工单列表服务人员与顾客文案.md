# 服务工单列表服务人员字段与顾客文案

- 状态：源码与共享测试环境发布完成；登录后列表逐列业务验收待人工确认
- 日期：2026-09-24

## 范围

2026-10-09更新：下方“仅待完工”的限制为原实现，已按用户新要求取消。当前所有状态展示已分配师傅姓名／手机号，并补齐分配结果与失败原因悬浮；最新契约、根因与验证见[审核查看与工单人员展示](2026-10-01-完工智能与AI审核.md#completion-list-details-20261009)。

- 客服作业 · 服务工单列表：在「受理渠道」前增加「服务人员姓名」「服务人员手机号」；仅当状态为「待完工」且工单已分配服务人员（师傅）时展示姓名与手机号，否则显示「—」。
- 同列表：「联系人」改为「顾客姓名」，「手机号」改为「顾客手机号」。
- 服务站作业 · 工单分配列表：「人员姓名」改为「服务人员姓名」（共用 `serviceResource.personnelName` 文案）。

## 实现要点

- 后端 `CustomerMapper` 工单列表已返回 `personnelName`／`personnelMobile`／`personnelId`，本轮无 API／DDL 变更。
- 前端 `WorkOrderListPage.vue` 增加列与展示条件；条件逻辑提取为 `assignedPersonnelDisplay`，由 `tests/customer.test.ts` 覆盖。
- 文案：`customer.servicePersonnelName`／`customer.servicePersonnelMobile`；列表联系人列改用既有 `customer.customerName`／`customer.customerMobile`；`serviceResource.personnelName` 中文改为「服务人员姓名」。

- 单元测试：`customer.test.ts` 8 通过。
- 共享测试环境全量 Web 发布记录见 [测试服务器部署](../03-开发管理/09-测试服务器部署.md)「2026-09-24 服务工单列表人员字段与文案全量发布」；`DEPLOY_OK`，入口 HTTP 200，静态文案已命中。
