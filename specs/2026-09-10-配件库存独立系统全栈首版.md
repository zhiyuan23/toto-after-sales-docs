# 配件库存独立系统全栈首版

日期：2026-09-10

最后更新：2026-09-16

范围：A30～A35 / PRT-002～PRT-007 的 Web 管理端首版；A29 继续沿用既有配件基础主档。2026-09-15 的配件管理详细需求是 A30～A32 的最新业务基线，与首版冲突处以该详细需求为准。

## 业务边界与数据模型

- 库存按“配件 + 归属类型 + 归属 ID”唯一。归属类型仅为服务站、服务人员；配件不建立售后仓库主档，也不允许归属到仓库。
- 数量按整数件管理。每次余额变更在同一事务中锁定余额行，扣减后不得小于零，并生成不可编辑、不可删除的库存流水；流水保存单据、明细、归属、变动量和变动后余额。
- 服务站入库单保存为待提交，提交后变为已完成并在同一事务增加服务站库存；待提交可编辑或物理删除，单号和服务站不可编辑，已完成只读。
- 领料由服务站师傅在小程序申请，流向为服务站 → 本站师傅；后台管理员通过后直接完成，并在同一事务扣减服务站库存、增加师傅库存。拒绝必须填写原因且不改库存；处理中可由小程序撤销。
- 退料由服务站师傅在小程序申请，流向为师傅 → 所属服务站；后台管理员通过后直接完成，并在同一事务扣减师傅库存、增加服务站库存。拒绝必须填写原因且不改库存；处理中可由小程序撤销。
- 调拨仅允许服务站与服务人员之间流转，来源和目标必须不同；先出库确认并扣减来源，再入库确认并增加目标，途中状态明确为已出库确认。
- 工单耗用只允许从服务站或人员库存扣减，创建即完成，以“单据类型 + clientRequestId”保证重试幂等，并保存请求内容指纹；同请求号、不同内容会被拒绝。当前工单主域尚未实现，因此本切片不声称已校验工单状态、执行人归属或与完工原子提交。
- 盘点创建时保存实盘数，授权确认时在事务内读取当前账面数、计算差异并形成调整流水；可在确认前撤销。
- 所有单据保存状态历史和乐观版本。单据创建最多 100 行，配件不可重复且必须已启用。

## 实现

- 后端新增 `inventory` 领域的 API / AppService / mapper / model，统一根路径为 `/api/afterSales/inventory`；2026-09-16 已从接口契约、权限能力和归属校验中移除仓库资源及 `WAREHOUSE` 归属类型。
- `database/20260910_part_inventory.sql` 为新环境建立余额、单据、明细、流水和状态历史 5 张库存表，仅允许服务站和服务人员归属。脚本依赖配件、服务站和服务人员迁移；2026-09-10 经用户明确授权执行到共享测试库 `gaia_wh_init_wzy` 的旧版基线仍须通过增量迁移处理。
- `database/20260916_remove_part_warehouse.sql` 用于旧基线环境：先检查是否存在 `WAREHOUSE` 余额、流水或单据，发现即中止；不会擅自删除历史库存或猜测应迁入哪个服务站。由业务方完成历史归属确认后，才可执行该迁移以收紧约束并删除旧仓库表。
- 前端 `apps/after-sales` 已提供真实的配件入库、库存、领料审核、退料审核、调拨、工单耗用和盘点页面。库存页只保留库存余额和库存流水，归属筛选仅为服务站、服务人员：先选类型，再以下拉选择“编号 / 名称”的归属名称；切换类型立即清空原选择并按当前账号的组织权限重新加载。库存筛选可显示并标注已停用的服务站、服务人员，操作单据的归属下拉仍只允许启用数据。入库页实现权限过滤的服务站选择、实时单号、动态明细合计、配件档案选择、待提交保存／编辑／提交／物理删除。页面继续复用 `FaPageMain`、`EsSearch`、`EsListToolbar`、`EsTable`、`EsFormDialog`、`EsDetailDialog`、`useListPage` 和 `useCrudDialog`。
- 后端库存服务已增加 `INBOUND` 类型、`RK/LL/TL + 服务站编号 + YYYYMMDD + 三位流水号`、入库编辑／提交／物理删除、领退料管理员通过／拒绝、服务站与师傅双边库存更新、服务站数据范围、字段查询和详情当前库存；单号和工单号继续由数据库唯一约束／应用校验保护，本期按需求不处理并发取号。
- 服务人员小程序本轮只修改可交互原型：新增领料／退料申请、说明和明细，处理中允许撤销；未修改真实小程序业务代码，也不把原型视为接口联调完成。
- 配件档案 A29 的编号、名称、工厂、启停和适用品番继续使用既有实现。图片依赖对象存储和安全扫描契约，价格依赖币种、精度、生效历史及维护责任，这两项没有足够业务依据，本次未猜字段或伪造上传/价格功能。

## 状态机

| 单据 | 初始状态 | 可执行动作 | 结果 |
| --- | --- | --- | --- |
| 配件入库 | `PENDING` | `SUBMIT` | `COMPLETED` |
| 领料／退料 | `PROCESSING` | `APPROVE` / `REJECT` / `CANCEL` | `COMPLETED` / `REJECTED` / `CANCELLED` |
| 调拨 | `PROCESSING` | `CONFIRM_OUT` / `REJECT` / `CANCEL` | `OUTBOUND_CONFIRMED` / `REJECTED` / `CANCELLED` |
| 调拨 | `OUTBOUND_CONFIRMED` | `CONFIRM_IN` | `COMPLETED` |
| 工单耗用 | 创建即处理 | 无人工状态动作 | `COMPLETED` |
| 盘点 | `PENDING` | `CONFIRM` / `CANCEL` | `COMPLETED` / `CANCELLED` |

非法动作、旧版本重复动作、负库存、停用或不存在的归属和配件均由后端拒绝；前端只展示后端返回的行级 `actions`，不复制状态机。

## 回退与恢复

应用回退时先关闭库存菜单和写接口。新环境迁移未产生业务数据时，可在明确授权后按 `afs_part_inventory_history` → `afs_part_stock_ledger` → `afs_part_inventory_document_line` → `afs_part_inventory_document` → `afs_part_stock_balance` 的顺序删除；一旦产生业务数据，不得直接删表，必须同一时间点备份和恢复单据、明细、余额、流水及历史，并与配件、服务站和人员主档引用一起对账。旧环境如仍存在仓库表或 `WAREHOUSE` 历史记录，不得借由应用回退删除，须按本方案的迁移门禁处理。
