# 配件库存独立系统全栈首版

日期：2026-09-10

范围：A30～A35 / PRT-002～PRT-007 的 Web 管理端首版；A29 继续沿用既有配件基础主档。2026-09-15 的配件管理详细需求是 A30～A32 的最新业务基线，与首版冲突处以该详细需求为准。

## 业务边界与数据模型

- 库存按“配件 + 归属类型 + 归属 ID”唯一。归属类型为仓库、服务站、服务人员；仓库是售后自有主档，服务站和服务人员引用既有售后主档。
- 数量按整数件管理。每次余额变更在同一事务中锁定余额行，扣减后不得小于零，并生成不可编辑、不可删除的库存流水；流水保存单据、明细、归属、变动量和变动后余额。
- 服务站入库单保存为待提交，提交后变为已完成并在同一事务增加服务站库存；待提交可编辑或物理删除，单号和服务站不可编辑，已完成只读。
- 领料由服务站师傅在小程序申请，流向为服务站 → 本站师傅；后台管理员通过后直接完成，并在同一事务扣减服务站库存、增加师傅库存。拒绝必须填写原因且不改库存；处理中可由小程序撤销。
- 退料由服务站师傅在小程序申请，流向为师傅 → 所属服务站；后台管理员通过后直接完成，并在同一事务扣减师傅库存、增加服务站库存。拒绝必须填写原因且不改库存；处理中可由小程序撤销。
- 调拨允许仓库、服务站和人员之间流转，来源和目标必须不同；先出库确认并扣减来源，再入库确认并增加目标，途中状态明确为已出库确认。
- 工单耗用只允许从服务站或人员库存扣减，创建即完成，以“单据类型 + clientRequestId”保证重试幂等，并保存请求内容指纹；同请求号、不同内容会被拒绝。当前工单主域尚未实现，因此本切片不声称已校验工单状态、执行人归属或与完工原子提交。
- 盘点创建时保存实盘数，授权确认时在事务内读取当前账面数、计算差异并形成调整流水；可在确认前撤销。
- 所有单据保存状态历史和乐观版本。单据创建最多 100 行，配件不可重复且必须已启用；仓库存在正库存时不能停用。

## 状态机

| 单据 | 初始状态 | 可执行动作 | 结果 |
| --- | --- | --- | --- |
| 配件入库 | `PENDING` | `SUBMIT` | `COMPLETED` |
| 领料／退料 | `PROCESSING` | `APPROVE` / `REJECT` / `CANCEL` | `COMPLETED` / `REJECTED` / `CANCELLED` |
| 调拨 | `PROCESSING` | `CONFIRM_OUT` / `REJECT` / `CANCEL` | `OUTBOUND_CONFIRMED` / `REJECTED` / `CANCELLED` |
| 调拨 | `OUTBOUND_CONFIRMED` | `CONFIRM_IN` | `COMPLETED` |
| 工单耗用 | 创建即处理 | 无人工状态动作 | `COMPLETED` |
| 盘点 | `PENDING` | `CONFIRM` / `CANCEL` | `COMPLETED` / `CANCELLED` |

非法动作、旧版本重复动作、负库存、停用或不存在的归属和配件均由后端拒绝；前端只展示后端返回的行级 `actions`，不复制状态机。

## 回退与恢复

应用回退时先关闭库存菜单和写接口。迁移未产生业务数据时，可在明确授权后按 `afs_part_inventory_history` → `afs_part_stock_ledger` → `afs_part_inventory_document_line` → `afs_part_inventory_document` → `afs_part_stock_balance` → `afs_part_warehouse_audit` → `afs_part_warehouse` 的顺序删除；一旦产生业务数据，不得直接删表，必须同一时间点备份和恢复单据、明细、余额、流水及历史，并与配件、服务站和人员主档引用一起对账。
