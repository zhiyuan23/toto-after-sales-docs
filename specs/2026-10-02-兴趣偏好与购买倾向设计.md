## 1. 消费者页面

入口放在“我的 → 个人信息 → 兴趣偏好”。入口显示已选产品，优先前两项，超过两项用“等N类”；仅填写购买计划则显示该计划；全部未填写显示“选择您关注的产品”。兴趣信息与关联产品分别展示，不根据已购／扫码关联记录自动勾选。

页面开头：“用于了解您的产品需求，全部选填，可随时修改或清空。”三组轻卡如下：

| 分组 | 选项 | 控件与规则 |
| --- | --- | --- |
| 关注的产品 | 智能一体型座便器、智能座便盖、普通座便器、龙头与淋浴、浴缸、浴室暖风设备、整体卫浴；另有“暂无明确偏好” | 标签多选；“暂无明确偏好”与全部具体产品互斥。默认不选，取消全部产品恢复未填写 |
| 购买计划 | 未填写、暂无购买计划、时间未定、3个月内、3～6个月、6个月以后 | 原生单选选择器；描述“针对您整体的卫浴需求”。时间段按填写时意图解释，不推断每个品类均将购买 |
| 使用场景 | 新房装修、旧房翻新、现有产品换新 | 标签多选；默认不选，取消全部恢复未填写 |

末尾保留文字操作“清空填写”，一并清空三组，不删除头像、联系资料或购买记录。无统一保存按钮，无成功背景提示或反复弹出的“已保存”；选中态承担正常确认反馈。底部说明“选择偏好不会开启营销通知”。本期不新增预算、型号、营销订阅或“希望了解的内容”调查；原型原有内容偏好不作为新的购买倾向数据来源。

沿用消费者胶囊操作、白色无装饰边框卡片、44px最小点击区域及已有主题变量；选项边框仅用于表达可选和选中状态。正式微信选择器按小程序原生能力呈现；HTML 下拉只是本地预览。

## 2. 自动保存与数据语义

资料属于当前消费者账号，微信登录后可编辑，不以绑定手机号为前提。绑定手机号保留本人偏好；不按手机号覆盖或搬移其他账号偏好。登录身份变化时清理该账号的加载状态和草稿。

建议实现以下保存规则，原型当前仅模拟内存成功：

1. 用户选择即更新本地选中态；连续修改合并约500ms后串行提交，每次请求带版本。请求中再次修改，保留最新待提交值，旧响应不得覆盖新选择。
2. 仅发送已改变的字段组；没有修改的姓名、地址、人口资料及其他偏好组不夹带。清空必须显式发送三组空值，省略字段表示保留。
3. 失败保留本次选择，在对应组下方显示“未能保存，点击重试”，点击仅重试该组。返回个人信息也提示有未保存偏好；不能把待保存草稿当作服务端确认结果。沿用按环境／租户／账号隔离的24小时失败草稿规则。
4. 409冲突先重新读取服务端版本，再只重放当前账号本次改变的组；校验失败展示原因，不能无限自动重试。退出页面前发送仍待合并的修改；应用中断后靠失败草稿恢复，不能依赖卸载时网络必达。
5. 偏好与个人资料采用独立版本，避免头像响应或人口资料保存覆盖偏好。品牌侧只读。

建议持久化对象：

| 字段 | 语义与约束 |
| --- | --- |
| `productInterests` | 稳定产品偏好编码数组，去重；具体候选与“暂无偏好”互斥，不把文案当主键 |
| `productInterestsAnswered` | false＋空数组＝未填写；true＋空数组＝主动选择暂无明确偏好；非空数组必须true |
| `purchasePlan` | 空值＝未填写；五个固定编码分别代表无计划、时间未定及三档时间，单值 |
| `usageScenes` | 三个固定编码的去重数组；空数组＝未填写。首版不另设“没有装修需求”答案 |
| `version` | 服务端并发版本，与基本资料独立 |
| 各组更新时间、整体更新时间 | 服务端生成；只更新真正发生变化的组。购买计划时间不被修改产品标签刷新；未填写组的业务填写时间为空 |
| `source` | 服务端固定为消费者主动填写，不接受客户端伪造来源 |

字典编码采用原型的 `smart-toilet/washlet/toilet/faucet-shower/bathtub/bathroom-heater/bathroom-space`；购买计划 `none/undecided/within-3-months/3-to-6-months/after-6-months`；场景 `new-home/renovation/replacement`。正式 API 使用同一份受控白名单，并校验未知值、数组长度及互斥关系。

偏好分类独立于售后实际商品主档；若需关联商品分类，只映射售后自有分类并核实候选，不关联 Gaia 主系统商品类别。一个偏好可映射多个售后类别；“整体卫浴”等需求概念没有实际分类时允许不映射，不制造商品关系。首版统计直接按偏好字典。

设计要求独立本人读取／更新接口（例如 `/api/afterSales/mobile/consumer/preferences`）；档案详情投影增加只读偏好对象，品牌统计扩展专用维度／交叉接口。实际路径、迁移及精确权限注册见第6、7节。审计记录动作、账号及版本，不写完整个人资料或偏好快照。

## 3. 品牌会员档案

2026-10-02后续确认覆盖原同页设计：总部“会员运营”保留会员档案，并新增会员分析；分析内以“基础画像／购买倾向”两个页签展示群体统计。具体实施与验证见第8节。档案详情增加“兴趣偏好”分组：三组内容、信息来源、购买计划填写时间、最近更新时间。未填写与明确暂无偏好分别显示。

## 4. 品牌画像统计

当前会员分析分为“基础画像／购买倾向”两个页签，将购买倾向与实际关联产品统计分开；原2026-10-02首轮为同页区域，后续拆分见第8节。所在省份及年龄段筛选同时作用于各指标、分布、交叉表和档案预览；“未填写”可单独筛选。年龄按当前年减出生年份的近似年龄分段，与现有会员契约一致；演示页同时保留18岁以下选项。

定义当前筛选范围内的启用消费者账号数为 **N**，包括无手机号、无产品、未填写人口或偏好的人，不将其静默排除。账号在每个品类／场景内去重。

| 展示项 | 分子与分母 |
| --- | --- |
| 当前会员 | N；不是已购买或已核验人数 |
| 已填写调查／填写率 | 任意一组有有效答案的不同账号数／N；产品明确无偏好、购买明确无计划均算有效答案 |
| 已填写产品偏好 | `productInterestsAnswered=true`人数；包括暂无明确偏好，占比／N |
| 自报3个月内购买 | 对应计划人数；卡片比例／已填写购买计划人数，明确注明分母 |
| 产品偏好分布 | 每个产品偏好人数／N；同一人可跨类别，各类别比例之和可超过100% |
| 购买计划分布 | 五类答案及“未填写”人数分别／N；单选构成整体，四舍五入可能有误差 |
| 场景分布 | 每种场景人数／N；未填写单列，多选不可相加推算会员总数 |
| 品类×购买计划／省份／年龄／场景 | 同时满足品类和列条件的不同账号数；场景／品类多选，行列合计不等于会员人数 |

产品偏好分布旁单列“未填写／暂无明确偏好”人数，避免把两者塞入实际产品类别。无成员时显示0人、比例“—”，不产生NaN、不用无样本的0%误导。人群筛选后的全部图表使用相同基数，异步响应不得跨筛选混用。

计划是“填写时的整体卫浴意图”：必须保留计划填写时间，不能推算购买截止日、自动移动时间档或把过期答案当实时商机。自愿回答存在偏差，填写人群不能直接代表全部会员；不据此计算销量、成交率或营销触达授权。本稿不加入自动跟进、导出完整号码、兴趣评分或模型推断。

## 5. 原型验证与实施边界

本地消费者原型已验证三组自动回显、返回入口摘要、暂无偏好互斥及清空恢复未填写；资料和已关联产品不随偏好重写。品牌原型以12个虚构会员验证：调查填写10人（83.3%）、产品偏好填写9人、3个月内计划3人／已填计划9人（33.3%）；辽宁筛选3人、年龄组合无成员时比例为“—”、重置、只读详情均已核对。四种交叉维度已核对：智能一体型座便器按辽宁／浙江／广东分别1人；30～39岁1人、40～49岁2人；新房2人、换新1人；3个月内2人、时间未定1人。

消费者原型控制器回归38通过／1失败；失败为服务人员任务地图既有数量断言（期望6，当前7）。扩大到原型4份测试共84项，78通过／6项服务人员既有失败；完整HEAD原型隔离副本83项77通过／同名6项失败，无新增失败。本次新增／更新的3项偏好状态测试、脚本语法检查与差异空白检查通过；未修改服务人员数据或测试基线。

设计阶段尚未验证：真实API持久化、并发／断网／失败重试、真实权限账号、新字段迁移、微信开发者工具／真机。本地原型不等同研发切片完成或业务验收，不调整实现／验收计数；后续实施与未验边界见第7节。

后续真实开发验收应覆盖：未绑号与已绑号的本人保存、其他账号不可读取或写入、字典与互斥校验、空值与省略区别、连续点击与409隔离、失败草稿恢复／清理、头像和基本资料不覆盖偏好、总部允许与其他岗位拒绝、统计分母与去重、未填状态和无样本人群。

## 6. 2026-10-02 已授权实施与跨对话契约

用户已要求“按这个方案执行修改”，并明确选择“创建并启动3个新对话”；设计进入实施，前文原型验证仍仅代表设计阶段。后端、消费者端、品牌后台分工开发，当前协调对话负责实际联调及文档总进度。实施启动时未授权提交、推送或发布；后续用户要求完成剩余操作并提交本次工作区修改，执行结果见第7节。测试库本功能迁移按项目已有持续授权核对、备份后执行。

为避免三端各自定义，下列接口／字段作为本轮共同实施基线：

### 6.1 消费者本人偏好

- `GET /api/afterSales/mobile/consumer/preferences`：当前账号；首次未填返回默认空对象，version=`"0"`。
- `PUT /api/afterSales/mobile/consumer/preferences`：`{version, productInterests?, productInterestsAnswered?, purchasePlan?, usageScenes?}`。只有改变的组进入提交白名单，null／省略保留；清空显式空数组、false、空字符串。产品数组与answered必须成组传入；未知字段不得改变身份或来源。
- 响应统一Gaia外层，data为下列对象。字段和编码与第2节一致，数组去重并按字典稳定排序，时间为服务端ISO日期时间或null；前端必须做运行时结构／字典／账号校验。

```ts
interface ConsumerPreferences {
  accountId: string
  version: string
  productInterests: string[]
  productInterestsAnswered: boolean
  purchasePlan: string
  usageScenes: string[]
  productInterestsUpdatedAt: string | null
  purchasePlanUpdatedAt: string | null
  usageScenesUpdatedAt: string | null
  updatedAt: string | null
  source: 'CONSUMER_DECLARED'
}
```

消费者入口onShow读取服务端偏好及失败状态；新增偏好状态独立于现有profile。新偏好页面逐组自动保存，按账号隔离失败草稿，账号变化清理，不依赖手机号。仅改消费者业务文件，公共底座确需变更才按双端规范同步。

### 6.2 品牌档案与购买倾向

- `GET /api/afterSales/members/accounts/{id}/preferences`：只读ConsumerPreferences，校验现有档案detail权限及精确子接口权限、租户和总部身份。详情增加偏好区，不替换现有资料、产品、服务；列表第一版保留现有字段，避免独立原型六列挤掉当前资料。
- `GET /api/afterSales/members/statistics/preferences`：查询`provinceCode`和`ageGroup`，空值＝全部，`UNKNOWN`＝未填写；年龄白名单`UNDER_18/AGE_18_29/AGE_30_39/AGE_40_49/AGE_50_59/AGE_60_PLUS/UNKNOWN`。省份使用已保存区划编码；不查询定位临时默认值。
- 统计响应一次返回同一筛选人群的各项计数、分布和全部四种交叉数据，避免客户端多请求拼接不同人群。各权限路径显式登记到现有会员只读能力，不新增业务菜单、不扩展其他岗位权限、不覆盖其他任务配置。仅统计账号不能读取偏好详情。

```ts
interface PreferenceBucket { key: string; label: string; count: number }
interface PreferenceCrossTable {
  dimension: 'PLAN' | 'PROVINCE' | 'AGE' | 'SCENE'
  columns: { key: string; label: string }[]
  rows: { key: string; label: string; counts: number[] }[]
}
interface MemberPreferenceStatistics {
  memberCount: number
  answeredCount: number
  productAnsweredCount: number
  productUnknownCount: number
  productNoneCount: number
  planAnsweredCount: number
  withinThreeMonthsCount: number
  sceneUnknownCount: number
  productBuckets: PreferenceBucket[]
  planBuckets: PreferenceBucket[]
  sceneBuckets: PreferenceBucket[]
  provinceOptions: { key: string; label: string }[]
  crossTables: PreferenceCrossTable[]
}
```

省份选项独立于当前省份／年龄筛选，覆盖全部启用消费者已保存省份及UNKNOWN，不能因组合筛选为空消失。交叉省份列可以取当前人群实际省份并附UNKNOWN；AGE／PLAN／SCENE固定字典列含UNKNOWN。产品／场景“未知”用key=`UNKNOWN`；产品暂无偏好单列人数，不当产品bucket。购买计划未知bucket也用UNKNOWN，实际无计划仍编码none。交叉行固定七个产品，counts顺序与columns一致，零值保留。全部计数非负整数，比例由前端按第4节指定分母计算；无样本显示“—”。

后台新增独立购买倾向组件、模型与中英文文案，复用现有会员页面及公共控件。选择筛选后统一应用查询，重置产生一次查询；显示加载、失败重试和空状态，取消过期响应。现有全品牌基础人口／关联产品统计保留原口径，购买倾向明确展示独立筛选人群。
