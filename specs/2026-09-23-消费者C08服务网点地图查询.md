# 消费者 C08 服务网点地图查询

状态：地图、可拖拽列表及本机自动城市逆解析已完成研发验证；当前测试库结构已就绪，两端小程序共用的服务端高德 Web 服务配置及客户端已接入，真机验收待完成。

## 已确认规则

- 范围是消费者端 C08，不是服务人员端 W03 任务地图。
- 用户最新确认：消费者查看所在城市全部已启用且城市、地址、有效坐标齐全的售后自有授权门店或维修服务站，网点可见性不再依赖逐条发布。无对客电话的网点仍显示名称、地址与点位，但隐藏电话及拨号入口；后台人员手机号、服务站原有热线等未单独确认为对客资料的联系方式不自动暴露。
- 消费者可在未登录状态查询网点。小程序服务端须配置唯一租户，并拒绝不匹配的租户上下文。消费者列表按当前城市查询全城网点，不提供省／区县筛选；默认使用定位解析出的城市，只在该城市内按当前位置排序。顶部不再显示城市选择块；只在定位失败或空结果状态提供手选城市兜底。
- 列表自由拖动并在松手位置停留，不做边缘吸附、速度判定、位移阈值或就近自动停靠；点击把手才主动展开／收起。拖动受地图顶部控件与列表最小可见高度边界限制。
- 小程序使用微信原生地图组件展示点位。首次进入且没有已选城市时自动请求一次当前位置，由服务端把该次坐标发给高德 Web 服务解析城市并查询；定位失败或空结果时可通过页内单列城市选择器手选城市，取消不应用；地图右下角“回到当前位置”只取得当前位置并移动地图，不改变已选城市，也不调用城市解析或列表接口。服务端需配置 `gaia.after-sales.amap.web-service-key`，解析失败时明确引导手选，不能用最近网点的城市冒充真实所在城市。点位与列表联动；列表不放详情和大操作按钮，每条只保留“导航图标＋到这里”，直接调用微信 `openLocation` 进入原生位置页。距离是直线估算，位置页内的导航、打车与收藏能力以微信实际提供为准。H5 保留列表与原型预览，不把示意钉子当真实坐标。

## 接口与数据

- 消费者只读接口：`GET /api/afterSales/mobile/consumer/outlets`（消费者端传 `kind`、`city`、`latitude`／`longitude` 与分页；服务端保留可选 `district` 能力，但本页不再传入）、`GET /api/afterSales/mobile/consumer/outlets/regions` 与 `GET /api/afterSales/mobile/consumer/outlets/current-city`。均无需消费者会话；城市解析供首次自动定位识别查询城市使用；地图右下角回位按钮不调用该接口。网点返回字段限定为名称、地区、地址、坐标与单独开启的对客联系资料。
- Web 对客联系资料接口：`GET`／`PUT /api/afterSales/network/consumer-outlets/{STORE|REPAIR}/{id}`。门店和服务站分别使用独立操作权限，沿用既有资源可见范围；开关只决定对客电话及说明是否显示，不决定网点本身是否可见。对客电话可留空，开启后仅公开已填写的资料。保存需提交版本号并留下不可变审计记录。
- 可选对客联系资料的表结构、权限及回滚脚本见 `gaia-after-sales/database/20260923_consumer_outlet_publication*.sql`。当前测试库 `gaia_wh_init_wzy` 已执行；其他环境须按环境核对并迁移。
