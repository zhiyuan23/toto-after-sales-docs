## 2. 导航实现

- `workspace-manifest.mjs`：四视角分组、默认首页、七种角色模板、五个导航授权节点。
- `workspace-navigation.mjs`：对新鲜 Gaia 菜单做功能与视角交集、过滤禁用节点和空分组、投影侧栏、校验直达路径。
- `navigation.ts`：保存当次授权结果与当前视角，sessionStorage 仅保存账号视角偏好；无令牌／重新初始化时清空授权快照。
- `WorkspaceBar.vue`：仅在“运营概览”展示工作视角选择、系统管理员角色提示和离开当前页面提示；其他售后页面不再重复显示这一行。
- Gaia 路由、顶部菜单、侧栏和页面布局：接入售后导航；旧分组及根路径重定向到有效首页，越权功能转 `/401`，菜单加载失败不循环重试。
- 售后页面切换视角或路由时重新挂载，不复用旧视角页面实例；已接入列表 hooks 的清理机制取消旧请求。非售后页面保持原有布局与缓存行为。
- 功能页的分组提示使用当前视角分组，服务结算说明与管理员可查看规则一致。

工作视角不改变后台身份、岗位动作或组织数据范围。D01 门店上下文仍待真实契约；D05/D06 仍是隐藏流程骨架，实际会话及对象校验随登记切片实施。组织切换、上下文标签、待办计数及全局快捷入口不在本次假定已完成。

## 3. Gaia 授权与菜单交付

核对到现有登录页为用户写入固定 `roles: ['admin']`，不能作为真实管理员依据。正式导航使用 `/api/sys/Module/tree?categoryCode=pc_web` 中有效的功能节点和以下隐藏导航授权项：

| code | path | 用途 |
| --- | --- | --- |
| afsNavigationAdministrator | afterSales/access/administrator | 管理员可查看全部视角；功能本身仍须在后端返回 |
| afsWorkspaceHeadquarters | afterSales/access/headquarters | 总部运营 |
| afsWorkspaceServiceDesk | afterSales/access/serviceDesk | 客服作业 |
| afsWorkspaceStation | afterSales/access/station | 服务站作业 |
| afsWorkspaceDealer | afterSales/access/dealer | 门店业务 |

这些项配置为 `type=1`、`isHide=1`，共用售后根节点，承载页只重定向到有效首页。不赋予业务 API、按钮或跨租户权限。禁用父节点会屏蔽整棵子树；code 与 path 不匹配的授权不会接受；无有效视角或功能时拒绝访问。

菜单配置清单从与程序相同的常量按需生成，包括 68 个唯一节点和角色菜单引用。文档归并后不再保存 JSON 副本，保留[生成脚本](../../../frontend/gaia-ui/scripts/after-sales-menu-package.mjs)，分发前生成并核对。生成命令（在 gaia-ui 仓库）：

```sh
node scripts/after-sales-menu-package.mjs /tmp/toto-menu-v2-review.json
```

清单是按 code 复核的配置源，不是批量 API 请求。目标环境需解析实际模块、父节点、租户和角色 ID，合并原授权并走 `gaia-tenant` 既有分发与回执链；不得覆盖无关模块或直接更新运行库 `sys_module`。已核对平台 `TenantModuleDTO`、`TenantSaasModuleSaveDTO`；租户分配接口要求实际 tenantId 和 moduleOperationIdList，不能填本清单的 code 代替。

用户已确认后端菜单功能配置完成；当前前端不再补充 V1/V2 节点。是否可见完全取决于登录账号从菜单接口获得的实际功能节点和导航授权项，仍以本次允许／拒绝账号联调结果作为验收证据。
