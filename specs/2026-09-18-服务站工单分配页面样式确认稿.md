## 1. 目标与范围

服务站在「工单分配」中查询本站待分配人员工单，打开分配弹窗，从候选服务人员中单选一人并分配。本确认稿锁定页面信息架构；后续实现已将列表、候选与人工分配切换到真实接口。三类模式的自动处理与留痕以关联 Spec 为准。

### 本期包含

1. 列表查询区：工单号、联系人手机号、服务人员工号、服务人员姓名、服务人员手机号；**重置**、**筛选**。
2. 工单列表列：工单号、联系人姓名（不脱敏）、联系人手机号、工单状态、服务人员工号、服务人员姓名、服务人员手机号、预约上门时间、预约上门地址（完整）、购买商品型号、购买商品名称、操作「去分配」。
3. 分配弹窗：上方工单只读回显；下方候选服务人员左右布局卡片（左信息、右未来 24h 工单分布折线）；底部「分配」。
4. 工单表扩展设计确认：`personnelCode`、`personnelMobile`（实现写接口时落库）。

### 本期不包含

- 精确预约时段容量和早/中/晚真实负荷统计
- 未来 24h 精确分段工单统计
- 改派、撤销分配
- 投诉率、取消率、职称、「距离最近」气泡

### 成功标准

- 服务站视角可进入「工单分配」并看到完整列表与弹窗样式。
- 「去分配」仅未分配且状态为待分配人员时可用；选中人员后「分配」可点；无人推荐时不预选。
- 折线图横轴从当前时刻向下取整到 2h 边界起连续 12 段，数值全 0。

## 2. 角色、流程与页面

| 应用、角色视角与页面 | 使用者与操作 | 加载、空态、失败处理 | 对应验收项 |
| --- | --- | --- | --- |
| Web / 服务站作业 / 工单分配列表 | 查询本站工单；对待分配行点「去分配」 | 默认空条件下列出本站 `PENDING_ASSIGNMENT`；无数据空态 | A1–A3 |
| Web / 服务站作业 / 分配弹窗 | 查看工单只读信息；单选服务人员；点「分配」 | 候选列表空态；样式阶段分配提示未接写接口 | A4–A7 |

### 列表数据范围（方案 A）

- 默认：当前服务站的 `PENDING_ASSIGNMENT` 与 `PENDING_COMPLETION`，以便查看自动/人工成功和失败留痕；仅未分配的 `PENDING_ASSIGNMENT` 显示「去分配」。
- 按查询条件（尤其服务人员工号/姓名/手机）可查出本站已分配及后续状态工单；这些行不展示「去分配」。
- 不支持改派。

### 当前服务站

只看**当前服务站**数据（登录作业站上下文）；不合并多站。

### 交互规则

1. 「取消」文案为 **重置**（清空条件并回到默认列表）。
2. 预约上门时间展示：`2026-09-17 9:00`（`YYYY-MM-DD H:mm`，小时无前导零）；数据侧已可落到时分，与现网格式化一致。
3. 多商品：型号列、名称列各自换行。
4. 弹窗工单区只读。
5. 人员单选；点卡片「选择」高亮选中后底部「分配」才可点。
6. 有推荐人时默认选中**第一个推荐人**；**无人推荐时不预选**。
7. 折线：当前时刻向下取整到 2h 边界起滚 12 段；现阶全 0，不造假数据点。

### 人员卡片字段

左侧：头像、姓名、手机、推荐（绿）/不推荐（红）、当前距离（占位）、满意度、待处理、今日完工；标签：上班/休息、安装/维修/清洗等技能。
右侧：未来 24H 工单分布标题、总数角标、「选择」、折线图。

## 3. 接口、数据与权限契约

本页面现已接入真实接口；界面布局仍沿用本确认稿，人员推荐和容量约束由后端策略统一计算。

| 能力 | 说明 |
| --- | --- |
| 列表查询 | `GET /api/afterSales/work-order-assignment`；本站范围，默认包含 `PENDING_ASSIGNMENT` 与 `PENDING_COMPLETION`，展示分配结果和失败原因 |
| 候选人员 | `GET /api/afterSales/work-order-assignment/{id}/candidates`；本站在职、预约日期有 `AVAILABLE` 排班且技能匹配的人员；容量满人员只供人工覆盖 |
| 分配写入 | `PUT /api/afterSales/work-order-assignment/{id}/personnel`；首次人工分配写入人员快照、分配方式和留痕，超容量必须附原因 |

权限：沿用菜单 `afsWorkOrderAssignment`；写操作权限与服务站范围校验在写接口切片补齐。禁止改派。

### 数据扩展（确认）

`afs_service_order`（或等价工单表）新增：

- `personnel_code` / API `personnelCode`
- `personnel_mobile` / API `personnelMobile`

分配时从服务人员主档快照写入。
