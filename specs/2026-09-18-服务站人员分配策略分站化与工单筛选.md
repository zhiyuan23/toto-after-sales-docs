# 服务站人员分配策略分站化与工单筛选

- 状态：开发与验证中
- 日期：2026-09-18
- 关联入口：服务站作业 / 本站工单 / 工单分配、人员分配策略
- 前置：服务站、人员、日排班与人员分配策略基础迁移已部署

## 1. 已确认规则

1. 人员分配策略不再全局唯一，而是每个服务站独立维护一条策略；服务站管理人员只能操作数据权限范围内的服务站，总部/管理员也受其数据权限范围约束。
2. 策略页位于服务站作业「本站工单」中，紧跟「工单分配」；总部运营页不再重复展示该入口。总部/管理员需要维护策略时，进入服务站作业视角。
3. 工单分配页新增必填服务站下拉，选项使用服务站数据权限；页面初始化默认选择排序后的第一个可用服务站。列表同样只查询所选服务站，并在工单号之后展示服务站编号和名称。
4. 策略页同样默认选择第一个可用服务站；切换服务站立即读取该站策略，不提供额外查询按钮。
5. 某站从手动切换为智能或 AI、或在智能与 AI 之间切换时，只扫描该站历史 `PENDING_ASSIGNMENT` 且未分配人员的工单。仅改权重或 AI 文本不触发历史重跑。
6. 新建服务站自动创建 `MANUAL`、饱和度权重 60、满意度权重 40 的默认策略。迁移时，将既有全局策略复制给所有现存服务站。
7. 自动分配任务始终按工单当前 `station_id` 读取策略，不能由前端所选服务站绕过工单归属或技能、排班、容量等硬约束。

## 2. 数据与接口变更

| 项目 | 变更 |
| --- | --- |
| `afs_personnel_assignment_policy` | 新增唯一 `station_id`；旧全局行复制到所有服务站后删除。策略主键沿用服务站 ID，避免新增独立映射表。 |
| 服务站新增 | 服务站创建事务内初始化该站手动策略。 |
| 策略读取/保存 | `GET /api/afterSales/personnel-assignment-policy?stationId={id}`；保存请求体包含 `stationId`。后端联合服务站数据权限验证。 |
| 工单分配列表 | `GET /api/afterSales/work-order-assignment?stationId={id}`；服务端再次以数据权限过滤，并返回 `stationCode`、`stationName`。 |
| 服务站选项 | 两个页面使用 `GET /api/afterSales/network/service-stations/options`，只获取当前账号可见且启用的服务站。 |

API 权限仍以菜单和操作权限为准；服务站选项读取权限须同时登记到 `afsWorkOrderAssignment`、`afsPersonnelAssignmentPolicy` 的 `api_list`，不能依赖服务站主档菜单授权。

## 3. 数据库与菜单发布顺序

1. 备份目标库中 `afs_personnel_assignment_policy`、`afs_service_order`、服务站相关菜单授权记录。
2. 确认已执行 `20260918_personnel_assignment_strategy.sql` 后，执行 `gaia-after-sales/database/20260918_personnel_assignment_policy_per_station.sql`。
3. 执行（可重复）`20260918_personnel_assignment_permissions.sql`、`20260918_personnel_assignment_policy_station_menu.sql` 与 `20260918_work_order_station_filter_permissions.sql`，刷新目标角色菜单和接口操作授权。
4. 部署后端、前端，重新登录并强制刷新浏览器缓存。
5. 检查每个有效服务站均有一条策略；新建一个非生产验证服务站时，确认自动生成手动策略。

迁移或发布失败时不得仅回滚前端：旧的全局代码无法正确读取已分站策略。应恢复同一批次的后端制品与数据库备份，或在维护窗口执行已评审的回退脚本。

## 4. 验收清单

| 场景 | 期望 |
| --- | --- |
| 单站账号打开工单分配 | 下拉只返回该站并自动选中；列表只含该站数据，工单号后有站编号、站名称。 |
| 多站授权账号 | 下拉仅含授权站；切换站后，列表按站刷新。 |
| 策略切站 | 无查询按钮；切换后显示该站独立的方式、权重和 AI 文本。 |
| 策略切换为智能/AI | 只创建所选服务站历史待分配工单的任务，其他站不受影响。 |
| 智能/AI 成功与失败 | 成功保留方式和成功结果；失败保持 `PENDING_ASSIGNMENT` 并记录失败原因，供人工分配。 |
| 新建服务站 | 自动拥有手动默认策略。 |
| 总部/管理员 | 在服务站作业视角中，只能维护其数据权限覆盖的服务站。 |
