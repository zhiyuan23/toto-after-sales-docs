# Web 多语言架构底座与遗漏收敛

- 编号／类型：TECH-20261013-I18N-01／横向工程底座与国际化技术优化。
- 应用／视角／入口：Web 独立售后后台／跨视角／工程底座与已有界面，不新增业务入口。
- 来源／日期：用户于 2026-10-13 确认先完成架构、遗漏和检查机制，同步技术文档并验证，日语暂不接入；最后更新 2026-10-14。
- 优先级／状态：P2／待验收（源码、必要研发验证及文档已完成；用户复核与正式环境业务验收待完成）。
- 负责人：本轮研发由 Codex 实施；正式账号、共享环境及业务验收负责人待分配。
- 技术契约：[国际化架构与迁移规范](../02-技术设计/12-售后子系统国际化架构与迁移规范.md)。历史基线见[2026-09-12 首次迁移](2026-09-12-国际化基础与商品分类表单试点.md)。

## 1. 已确认范围与完成标准

保留唯一 Vue I18n 实例、现有中英文资源、稳定业务键、账号／租户偏好和同步切换。完成后，新语言通常只需注册语言元数据、提供同名完整资源、生成装配文件并完成验收；业务页不再为组件库、日期或菜单搜索增加语言二选一分支。

本轮完成语言注册、资源装配、组件库／日期／数字映射、所有注册语言检查、遗漏界面文案与常驻错误收敛、翻译变更导出及技术文档。当前仅 `zh-CN`／`en-US`；日语与其他新增语言没有注册、翻译或上线。

界面翻译不修改权限码、接口、状态机、业务枚举、ID、版本、提交白名单、时区、币种及排序规则；组织、人员、商品、地区、用户输入、现行持久化默认备注与未知后端业务文本保留原值。任务不执行数据库写入、推送或测试环境部署；代码和文档按用户后续明确授权分别本地提交。

## 2. 最终实现

| 能力 | 实现与约束 |
| --- | --- |
| 单一语言注册 | `registry.json` 登记默认语言、自称、Element Plus／Day.js 映射、日期格式和品牌排版；`registry.ts` 派生只读支持列表、类型和校验。语言菜单与授权菜单搜索复用注册表 |
| 资源装配 | `generate:i18n` 根据默认目录和注册表生成 `resources.generated.ts` 与 `adapters.generated.ts`；使用实际导入与类型约束，兼容 Node 回归及 Vite。新增模块不手工修改 `messages.ts` |
| 格式与组件库 | Provider 查表使用组件库语言；Day.js 加载所有已注册包，运行期和日期工具使用同一配置。日期、星期、数字依赖显示语言，接口日期与业务时区保持；全国机器值保留，标题／地图说明按词条显示 |
| 遗漏文案 | 通知、下载任务／模板、主数据导入导出、商品实例表头／筛选、服务站工作台、排班、实时工单、调拨及网络表单校验迁入语义词条；复合确认／数量提示使用完整参数句。未知通知正文与业务名称仍保留原文；任务标题使用动作词条，技能、页签及库存说明自然换行，时间轴列避免英文覆盖编号 |
| 状态保留 | 稳定数组用延迟读取 getter，配置不保存翻译快照；常驻错误区保留错误对象，登录错误通过 cause 保留自有默认词条；既有内联反馈不新增 Toast，语言切换不重复通知已有错误。网络和模板表单只重验已显示错误的字段，不重开表单、不重发业务请求 |
| 通知刷新保护 | 真实页面核对发现无新消息时仍尝试读取空 Toast 的 title，已按实际新增消息保护；回归覆盖重复／空刷新保持铃铛可用、新消息只弹一次且没有已读写入 |
| 稳定错误分类 | 下载／导入导出请求层按 `LocalizedError` 和明确 code 处理，不匹配中文登录提示；二进制 JSON 明确 `code=401` 保留登录失效分类，未知业务错误继续透传；域拒绝的原数值 code 保留，缺省译文放入 cause；写结果未知与只读失败分别处理 |
| 检查门禁 | 所有注册语言校验模块／键／非空值／参数集合和实际编译；校验生成文件是否过期。AST 扫描模板文本、属性、表达式及脚本字符串。源码豁免精确到文件和原文并附理由，失效豁免报错 |
| 翻译维护 | `export:i18n` 输出完整词条或相对 Git 基线的新增、源文案变化、译文变化和删除清单；源文案变化标记人工复核，不将导出视为语义校对完成 |

注册表与门禁设计通过临时三语言资源验证；该测试只在临时目录登记 `fr-FR`，没有把第三种语言加入产品。

## 4. 验收边界与后续接入

自动门禁能阻止资源不一致和未豁免中文源码，不能替代业务术语、图片文字、后端动态正文、其他语种硬编码及所有界面的视觉校对。未知后端中文业务消息仍可能在英文界面原文显示；只有稳定错误码和业务契约明确后才扩展本地展示映射。

正式角色、真实业务数据、共享环境及逐页面业务验收仍待安排。此次没有发布应用，不改变 60 个 Web 业务入口及业务验收计数。

后续日语接入直接按技术规范第 8～9 节进行：注册、完整资源、生成、门禁、术语／桌面／状态验证。代码层普通语言扩展已统一，翻译校对与新语言布局验收仍是实际工作内容。
