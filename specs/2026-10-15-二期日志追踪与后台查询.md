## 实施契约

### 既有记录与新采集

- 工单状态／派单、库存台账／单据历史、费用、配置与主档审计、导入导出任务及 Gaia 操作／登录记录继续查原表，不复制为另一份业务事实。
- 新增 `afs_runtime_log_event` 仅承接既有记录缺少的 REQUEST、SECURITY、EXTERNAL、TASK、ERROR、CLIENT 诊断元数据。分站策略原先没有不可变历史，本次补 `afs_dispatch_policy_audit` 并随原配置事务保存前后版本；其余记录复用原表。显式版本化迁移，不在启动时改表。
- 2026-10-17按[宿主模块级隔离](2026-10-17-售后宿主模块级隔离.md)收窄：新追踪只覆盖售后URL，公共后台登录／退出不再额外写售后运行事件；Gaia既有登录日志继续可查。文件日志通过售后专属logger分流，公共日志格式保持。
- 新请求使用 `X-Trace-Id` 和 MDC 关联；只接收长度及字符合法的关联号，非法值重新生成。记录 MVC 路由模板、HTTP 状态、业务错误码和耗时，避免把 HTTP 200 直接当业务成功。
- 移动登录、换绑、会话撤销、密码变更等记录安全事件；外部适配器只记录供应商分类、方法、耗时及错误类型；后台任务复用原任务结果。
- Web 与双小程序继续使用既有请求／诊断基础设施。客户端错误只发送固定事件和错误分类、追踪号及页面／版本白名单元数据，限频、去重、无重试；页面去查询／片段及动态编号，版本只保留约定构建标识，采集失败不递归上报，也不改变原操作结果。
- 两端移动采集写入通过售后模块提供、宿主装配的专用 Shiro 会话校验过滤器，精确绑定两个 POST 地址；缺失／失效会话及其他地址或方法拒绝，不增加匿名采集入口。Web采集使用原Gaia会话。

### 查询与权限

- 当前导航为系统管理员 → 系统管理 → 系统运维 → 日志查询，分组调整见[管理员导航契约](2026-10-15-系统管理视角与全部功能入口.md)，本轮未共享发布。独立子系统入口仍为 `/system/logs`，沿用现有全局管理入口门禁；仅默认独立模式、非 iframe 且启用身份管理时展示。
- 复用 Gaia 稳定模块 `operation_log`／`login_log`，不创建平行角色或售后日志授权节点。管理员工作视角本身不授予日志读取权。
- 查询要求真实模块授权、精确 API 读取授权、有效服务端租户及全局数据范围。操作／诊断与登录／安全分类分别授权；只有登录日志权限不能查看工单、库存、费用或运行请求。
- `GET /api/afterSales/logs/permissions` 返回实际读取能力及可用来源；`GET /api/afterSales/logs` 提供分页、时间、类别、来源、操作者、对象、结果和关联号筛选；`GET /api/afterSales/logs/{source}/{id}` 单独核验详情。
- 页面初始日期显式填入含今天的最近7个自然日，重置恢复该默认值；清空日期提交时仍沿用后端最近7天的安全默认，不能绕过时间上限。单次时间范围不超过31天，页大小不超过100；来源和排序使用白名单。来源未迁移时明确返回状态，不伪造空数据。未授权角色不查询记录或来源元信息。
- 首版提供筛选、分页、详情及追踪号复制；没有日志导出或删除入口。
- 筛选下不再常驻展示账号权限、脱敏及默认日期说明；日期、分类、来源、操作者／业务对象 ID、结果和追踪编号通过对应字段的占位提示表达输入用途。来源不可用时仍提供明确的异常反馈，权限控制继续由真实菜单、权限快照和接口共同执行。

### 脱敏与可靠性

- 后端查询 DTO 与页面详情均为字段白名单。原始 body、query、输出正文、快照、SQL、错误消息、令牌、密钥、手机号、地址及文件路径不进入统一查看页。
- 历史 Gaia URL 无法可靠还原为路由模板，统一页不展示其原始路径；新请求使用服务端模板。
- Gaia 公共日志采集对售后接口跳过原始输入／输出／错误正文，使用固定省略标记；不因本任务启用通用原始参数采集或日志消费者。
- 未预期异常的技术诊断只保留异常类型和调用位置，移除异常消息及驱动参数；业务端收到可展示的通用错误和请求标识。
- 原业务审计随原业务事务提交；补充诊断在业务事务内先进入有界请求缓冲（最多64条），退出事务后提交独立事务，避免业务持有连接时再等待第二条连接。持久化有超时和失败隔离；日志存储故障不改变业务结果，查询／采集请求避免自我递归。
- 请求追踪过滤器位于租户过滤器内部，在租户上下文清理前持久化；H5同时存在Gaia和移动会话时，以真实移动业务身份为准。UUID日志表不参与整数主键序列校准，避免影响后续业务表启动核对。
- 运行事件保留期限与受控清理由运维配置确认；不自动删除原业务历史，也不在未知租户上下文中批量清理。
