## 1. 已确认范围

首期在全局范围维护一份“派单策略”，创建服务工单时按当前策略处理。自动派单仅把工单关联到**服务站**，不自动指派服务人员；原人工派单与改派能力继续保留。

工单新增及编辑补充地图选点产生的经纬度，沿用现有高德地图选点坐标体系。服务站无有效坐标时不进入自动派单候选；工单无有效坐标时自动派单失败并转人工处理。

满意度仅统计同时满足以下条件的工单：已完成、已有回访结果、评价值为“满意”或“不满意”。

## 2. 策略与处理规则

| 策略 | 创建工单后的处理 | 后续动作 |
| --- | --- | --- |
| 手动派单 | 保持待派单，记录 `NOT_APPLICABLE` | 客服从现有候选服务站中人工选择并关联 |
| 智能派单 | 创建事务内写入待处理任务；后台调度器异步计算并分配服务站 | 成功进入待服务站派单；失败保持待派单并允许人工派单 |
| AI 派单 | 创建事务内写入待处理任务；后台调度器将策略文本和脱敏候选指标交给 DeepSeek | 成功进入待服务站派单；失败保持待派单并允许人工派单 |

自动处理只在“创建工单”后触发；编辑已有工单、策略变更和人工改派均不会重新触发。

### 2.1 智能派单候选与评分

候选服务站必须同时满足：启用、服务类型匹配、服务区域匹配、维护有效坐标、期望日期未满载，且距工单坐标不超过配置的最大距离。首期默认最大距离为 50 公里，可在 1 至 500 公里之间修改。

饱和度沿用派单候选口径：

```text
饱和度 = 当日期望日期、状态为待服务站派单或待完工的本站工单数 / 服务站日容量
```

服务站满意度为该站符合本 Spec 开头筛选条件的满意工单数除以有效回访工单总数。服务站没有有效回访数据时，以全体服务站的有效回访满意度均值补齐，避免新服务站被不合理地固定排末；全局也没有有效回访数据时，回退为 100%。

默认权重为距离 40%、饱和度 35%、满意度 25%，管理员可调整但三项合计必须为 100%。评分公式：

```text
距离分 = max(0, 100 × (最大距离 - 实际距离) / 最大距离)
饱和度分 = max(0, 100 - 饱和度百分比)
满意度分 = 满意度 × 100
综合分 = 距离分 × 距离权重 + 饱和度分 × 饱和度权重 + 满意度分 × 满意度权重
```

综合分相同时，依次选择距离更近、服务站编码更小的候选，确保结果可复现。

### 2.2 AI 派单边界

管理员可配置优先级和策略说明。服务端仅发送候选服务站编码、名称、距离、饱和度、满意度和智能评分；不发送顾客姓名、手机号、详细地址、工单描述或 API Key。提示要求模型严格以 JSON 返回 `selectedStationCode` 和不超过 200 字的理由。

服务端再次校验返回编码必须位于当次候选集内，才执行分站；模型超时、非 2xx 响应、非 JSON、空编码或候选集外编码均视为失败。DeepSeek 参数优先读取宿主 `application.properties` 的 `gaia.after-sales.dispatch.ai.*`，再兼容 JVM 属性和环境变量；Key 不保存到数据库、前端、日志、迁移或 Git。宿主本地配置中的 Key 必须保持为未提交的私有环境改动。

## 3. 状态、任务与留痕

```text
创建工单（智能 / AI）
  └─ 待派单 + 自动任务待处理
       ├─ 成功：关联服务站 → 待服务站派单
       └─ 失败：保持待派单 → 客服人工派单
```

后台每 5 秒获取待处理任务，每张任务通过原子更新获得一次处理权。成功时写入原有工单状态历史与服务站分配历史，并将自动派单状态标为成功。失败时不改变业务状态，记录自动派单方式、失败状态、失败原因、尝试次数和独立任务／决策留痕；工单列表展示结果，客服可据此人工处理。

任务在首期以当前应用数据源中的全局单策略执行。启用多租户的部署需在上线前补齐租户任务枚举或按租户投递，不能假定默认数据源会覆盖全部租户。
