## 1. 目标与范围

本阶段把已确认的信息架构变为可构建、可检查、可继续扩展的页面入口：Web 建立全部售后动态 path 对应页面和隐藏流程架构；消费者小程序建立三 Tab、C01～C17 路由、返回关系、登录拦截插槽和诚实页面壳。

本期不包含：真实业务数据、API、Store、响应包装、角色或权限码、后端数据模型、服务人员 W01～W16、动态菜单数据库直改、生产租户开放、微信上传／提审／发布。页面壳和构建通过均不计业务功能完成。

成功标准：

- Web 具备 1 个顶部入口、10 个分组、49 个功能菜单 path 和 D01/D05/D06 隐藏／上下文页；A46～A53 由蓝鲸数字全局系统能力承接，A01～A55、D01～D08 各追踪一次。
- 消费者端 `pages.json`、集中路径常量、页面文件和返回关系一致；C01～C17 全量追踪，正式 Tab 恰为“首页、服务、我的”。
- A25、C16、C17 保持范围待确认或隐藏语义，不出现猜测数据、号码、外链或渠道。
- 指定 lint、类型检查、覆盖测试和三项构建通过；完成典型页面视觉检查并准确记录未验证边界。

## 3. 动态菜单数据边界

Web 权威菜单数据尚未落地；2026-09-08 增加了严格限定在 development 模式的本地预览菜单。

源码调查确认：

1. `gaia-ui` 调用 `/api/sys/Module/tree?categoryCode=pc_web`，后端按当前用户、角色和 `sys_module.enable=1` 查询菜单；仅存在前端页面文件不会返回菜单。
2. path 由前端动态路由映射到 `src/views/<path>/index.vue`；`isHide` 只影响导航展示，不构成权限隔离。
3. 权威模块及租户分配位于本次写范围之外的 `gaia-tenant`，通过差量包和回执同步到 `gaia-sys` 运行时；`gaia-saas-proj` 没有可遵循的菜单 migration/seed 惯例。
4. 当前缺少目标开发／测试租户、生产租户策略、默认角色 code、角色权限矩阵和稳定模块 ID。直接写 SQL、运行库或把 seed 塞入售后后端会绕过现有分发协议，因此未执行。
5. `.env.development` 的 `VITE_ENABLE_AFTER_SALES_LOCAL_MENU=true` 会在菜单接口响应之后按前端事实清单补入售后树；仅 `import.meta.env.DEV` 时有效，生产构建不注入，后端已返回 `afterSales` 时自动去重，A25 在树中继续保持隐藏。固定菜单使用通用名称“售后服务”、不展示具体租户品牌，并插入顶层“数码中心”之后；若锚点不存在则追加到末尾。该机制只用于本地页面预览，不授予后端接口、按钮或数据权限。

后续需由菜单权威配置负责人确认 60 个售后 `pc_web` 模块的目标租户、默认角色和生产隐藏策略，经既有 `gaia-tenant` → `gaia-sys` 分发／回执链验证 `/tree`、直接访问、刷新、无权限和跨租户场景；A46～A53 在蓝鲸数字全局系统能力中另行配置和验收。在完成前，Web 进度中的“菜单已建”保持 0 / 63；本阶段只认定页面 path 覆盖完成。
