# 后台菜单与工作视角收敛

日期：2026-09-11  
状态：代码完成，真实角色验收待执行

> 第 2～7 节记录 2026-09-11 的收敛基线。2026-09-12 合入新增功能后的导航回归、保留范围和验证结果见第 8～9 节；本日后续恢复 A38 安装码管理的变更见第 10 节。旧数量不代表最新源码快照。

## 1. 目标

解决当前系统菜单与业务文档不一致、系统管理员出现第五套混合菜单、顾客与预约入口重复且名称难以理解的问题。按岗位任务重新组织导航，并将已确认不再需要的独立 Web 功能从当前系统注册、路由和页面实现中删除。

## 2. 已确认口径

- Web 管理后台只有四个业务工作视角：总部运营、客服作业、服务站作业、门店业务。
- 系统管理员不是第五个业务视角。管理员可在系统首页直接选择当前视角，也可在全局页头切换并进入该视角默认功能。
- 视角授权只组织导航；功能页面、操作和数据范围仍分别由 Gaia 功能授权、操作授权和后端数据范围校验决定。
- 当前 Web 系统注册 45 个功能，其中侧栏展示 33 个去重功能；`安装申请查询`只作为客服／服务站上下文功能；其余 11 个功能暂不进入当前导航。
- 四个视角共使用 14 个展示分组：总部 5 个、客服 4 个、服务站 4 个、门店 1 个；不再为单个功能保留独立分组。
- `家装公司`（A05）、`服务项目`（A13）、`安装码管理`（A38）、`安装申请记录`（D08）不是权限隐藏，而是从当前 Web 系统删除；历史需求编号和既有实施记录仅用于变更追溯，不再对应可访问功能。

## 3. 名称与入口调整

| 调整前 | 调整后 | 说明 |
| --- | --- | --- |
| 客户服务／工单管理 | 服务工单 | 强调处理对象，避免“客户服务”同时像部门、流程和菜单域 |
| 顾客与预约 | 顾客与购买 | 以购买记录作为顾客、商品实例和安装申请的业务起点 |
| 顾客档案／门店顾客 | 顾客购买记录 | 复用页面与功能实现，差异由角色数据范围决定 |
| 顾客登记 | 购买登记 | 页面实际创建的是购买、顾客、商品实例、安装码和隐私授权的组合记录 |
| 预约管理 | 安装申请查询 | 不进入侧栏，从服务工单或关联记录进入并保留历史直达 |
| 门店预约 | 删除独立功能 | 门店在“顾客购买记录”内直接申请安装，不再保留独立查询页面 |
| 安装码管理 | 删除独立功能 | 安装码继续作为购买记录、服务受理和工单中的识别／检索字段，不再单独提供只读列表 |
| 商品与服务资料 | 商品资料 | 服务项目已删除，当前分组只包含商品分类、档案、系列和配套品 |

`afsWorkOrder`、`afsCustomerArchive`、`afsAppointment`、`afsDealerRegistration`、`afsDealerCustomer` code 和 path 保持不变；`afsDealerAppointment`、`afsDecorationCompany`、`afsServiceItem`、`afsInstallationCode` 已从当前功能注册和动态路由删除。

## 4. 当前四视角

| 视角 | 默认功能 | 侧栏分组 | 上下文入口 |
| --- | --- | --- | --- |
| 总部运营 | 运营概览 | 运营管理：运营概览、服务质量、运营报表、标签管理；业务查询：服务工单、顾客购买记录；渠道与网点；商品资料：商品分类、商品系列、商品档案、配套品档案；配件管理。去掉预约管理、安装码、家装公司、服务项目 | 无 |
| 客服作业 | 服务受理 | 工单处理：服务受理、服务工单、派单调度、完工审核；异常与投诉；业务查询：顾客购买记录、服务知识库、商品档案；服务分析 | 安装申请查询 |
| 服务站作业 | 服务站工作台 | 本站工单、人员与资料、配件管理、服务分析；服务知识库并入人员与资料，去掉完工审核 | 安装申请查询 |
| 门店业务 | 门店工作台 | 业务办理：门店工作台、购买登记、顾客购买记录；去掉独立预约管理 | 无 |

客服主管和客服专员共用“客服作业”视角，但不是一套完全相同的权限。主管默认可分配派单调度和完工审核，专员默认不分配这两项；最终仍以账号实际功能与操作授权为准。

## 5. 当前隐藏能力与已删除功能

以下 11 个功能保留需求、code、path 和后续开发入口，但不进入当前任何业务视角：

- 回访管理、服务结算；
- 防窜货查询、条码异常、异常复核、防窜货规则；
- 会员档案、消息推送；
- 服务评价、产品问卷；
- 数据任务。

隐藏只影响日常导航，不代替路由、API 和数据权限校验。功能后续完成时须重新判断最合适的工作视角，不自动恢复到 V2 原分组。

家装公司、服务项目、安装码管理、安装申请记录四个独立 Web 功能已删除，不属于上述隐藏能力。删除范围包括功能清单、动态路由、页面实现、图标／页面标识和专用前端 API 类型与调用；既有数据库表和后端 API 未在本次菜单优化中做破坏性删除。其中安装申请后端能力仍被客服／服务站的 A16 上下文查询及门店页面内申请动作复用，安装码生成绑定、业务字段及相关记录检索继续保留。

## 6. 实现边界

- 独立子系统导航清单移除 `administrator` 业务视角，新增独立的 `administratorGrant`。
- 管理员授权返回四个业务视角；没有对应功能授权时，不制造页面权限，也不显示空视角。
- 系统首页和全局页头仅对具有管理员导航授权且存在两个以上有效视角的账号显示切换器；首页切换留在首页，页头切换进入目标视角默认功能。
- 切换视角后进入该视角默认功能；默认功能无权时进入第一个授权功能。
- A16 上下文入口计入客服／服务站路由可达范围，但不生成侧栏菜单；直达时恢复包含该入口的业务视角。D08 和 A38 的独立功能注册、路由和页面已删除。
- 跨视角复用的功能只注册一个 code、path 和页面，由各视角把同一功能引用到适合的展示分组。例如 `afsWorkOrder` 分别出现在总部“业务查询”、客服“工单处理”和服务站“本站工单”，不创建三个权限编码或页面副本。视角、功能、操作和数据范围保持四层独立校验。
- 客服将原“受理与工单”“调度与审核”合并为“工单处理”，并将原“顾客查询”“资料查询”合并为“业务查询”，避免连续工单环节和单功能查询各占一个一级分组。
- 展示顺序按“高频任务优先、查询早于资料维护、维度先于主体、业务单据按发生顺序”组织。总部一级顺序为运营管理、业务查询、渠道与网点、商品资料、配件管理；商品资料按分类、系列、商品、配套品排列；总部与服务站的配件管理统一按档案、库存、领料、工单耗用、退料、调拨、盘点排列。
- 未改后端业务状态枚举、数据库表和 API path；本次删除的是当前 Web 产品功能，不执行历史业务数据清理或共享 API 破坏性下线。

## 9. BUG-20260912-02：深色模式页头标题与工作视角对比度

- 类型／优先级／严重程度／状态：缺陷／P2／一般／待验证（研发修复与本地显示复查完成）。
- 应用／角色／入口：Web 后台／跨视角／全局页头品牌标题、工作视角按钮；关联 Spec 为本文。
- 来源／日期／负责人：用户要求优化深色模式左上角标题和角色信息；首次提出及最后更新 2026-09-12；负责人待分配。
- 复现与实际结果：本机 9010 登录后切换深色模式，黑色页头上的品牌标题仍为深黑色，副标题和视角按钮为深灰色，分隔线反而过亮。
- 根因：本地 Vue 样式编译确认，scoped 样式中的 `:global(.dark) .child` 丢失子选择器并生成根 `.dark` 规则，预期文字覆盖未生效，同时污染根元素颜色与背景。
- 修复：Logo 主标题、副标题和分隔线使用现有 `foreground`、`muted-foreground`、`border` 主题变量；工作视角按钮同步使用主题文字、背景及边框，悬停／展开时提高文字和边界对比，键盘焦点保留清晰主色描边。删除失效的全局深色规则，不调整标题尺寸、角色授权或导航逻辑。
- 验证标准与研发证据：深色页头主标题实测为 `rgb(250,250,250)`，副标题／默认视角为 `rgb(161,161,170)`，展开后视角文字提高至主文字颜色；本机 1470px 桌面侧栏及顶部导航、四项视角下拉、浅色切换均目视复查，无页头横向溢出。两个组件样式编译通过且无泄漏到根元素的 `.dark` 规则；页头接线、主题过渡、导航模式和导航权限相关 21 项测试通过。仅样式变更，未重复运行全量测试或生产构建，不增加业务验收数。
