## 1. 确认契约

| 项目 | 行为 |
| --- | --- |
| 内部人员 ID | 保留原 `personnel_id`，与账号、工单、排班等历史关联不变；不将可见工号作为数据库主键 |
| 工号 | `SP`＋六位流水，如 `SP000001`；同一租户下所有服务站共用一条序列，唯一且创建后不可编辑，删除不回收；超过 `SP999999` 明确拒绝创建 |
| 编号分配 | 后端事务锁定 `afs_service_personnel_code_sequence` 的唯一行；人员、账号、审计失败则一并回滚，避免孤立记录及并发重复 |
| 登录标识 | 人员手机号即售后移动账号 `login_name`，Web 不再提供独立账号输入；保持售后自有账号，不创建 Gaia `sys_user` |
| 修改手机号 | 更新原账号登录名，冲突整单回滚，撤销原账号全部会话；用新手机号＋原密码登录，人员 ID、工号和历史数据保持原关联 |
| 新人员密码 | 服务端用 `SecureRandom` 生成每人独立的 12 位大小写字母和数字组合；不采用统一默认密码、工号或手机号。后台不手填 |
| 初始密码交付 | 仅创建／为缺失账号补开户的成功响应包含 `initialPassword`，前端一次性展示并提示保存；详情、列表和后续编辑不返回明文，数据库只保存加盐摘要 |
| 首次改密 | 新账号 `must_change_password=1`；首次登录只允许改密或退出，业务 API 返回 `4604`；端侧重启恢复会话也强制进入改密页 |
| 修改密码 | 校验当前密码，新密码 8～128 位且非全空白，不能等于当前密码、手机号或工号；确认密码在端侧校验；成功清除首次改密标记并撤销所有会话，重新登录 |
| 密码保护 | 错误验证累计 5 次锁定 15 分钟；只对凭据验证失败保留计数，其余事务错误回滚；不把密码写入日志、本地持久化或审计 |
| 现有人员 | 保留密码摘要、账号 ID、人员 ID，首次改密标记为 0；仍可从“我的→修改密码”主动修改 |

工号序列位于租户数据库，跨站唯一，不承诺其他品牌租户的全平台唯一。手机号码用于登录和联系，不是关联历史数据的主键。已有请求 DTO 的 `code`／`loginAccount`／`initialPassword` 暂留兼容字段，新建时由后端生成／派生，Web 提交白名单不再发送；编辑不能借初始密码字段重置密码。

## 2. 接口与实现

- `POST /api/afterSales/service-resource/personnel`：工号及初始密码由服务端生成；响应只在这次开户时包含初始密码。更新人员同事务同步手机号登录名和账号启停。
- `POST /api/afterSales/mobile/service-personnel/auth/login`：请求保持 `account`／`password`，`account` 内容为手机号；响应增加 `mustChangePassword`。
- 新增 `POST /api/afterSales/mobile/service-personnel/auth/password`：`X-AFS-SESSION-ID`＋`oldPassword`／`newPassword`；不依赖企业上下文，仍验证有效人员和账号；成功使当前及其他会话失效。
- `auth/logout` 允许首次改密会话退出；其他受保护移动接口经统一 `session()` 拦截。客户端标记不能代替服务端校验。
- Jar／WAR 宿主仅放行精确改密路由到售后移动认证，不扩大 Gaia Web 权限。改密审计为 `PASSWORD_CHANGE`，该动作的 `actor_id` 为当前服务人员 ID；后台开户／手机号同步审计仍为 Gaia 操作者 ID。
- Web 人员弹窗工号只读、取消独立账号和密码输入、手机号增加登录用途说明。服务人员端新增真实改密页、登录与路由门禁、修改成功后的本地会话清理。
- 本轮 `auth/password.ts`、权限门禁及密码页属于服务人员身份契约；公共 `auth/session.ts` 未改，消费者微信登录不引入服务人员改密流程。
