## 3. 原始事实与归属设计（待确认）

### 3.1 一条评价，两个统计视图

继续以 afs_service_evaluation 为唯一原始消费者评价。order_id 唯一约束、事务锁、提交资格、内容幂等和不可变性保持。不新增第二条站点评价或人员评价，不允许后台输入主档分数；标签也不折算额外星级。

- 站点评分按 ev.station_id 汇总，不通过人员主表 station_id 求站点历史。
- 人员总部历史分按 ev.personnel_id 汇总；站内人员分按 ev.station_id＋ev.personnel_id 汇总。两个名称分别为“个人历史关联服务评价”和“在本站关联服务评价”，返回范围信息。
- 同一评价在本站统计计一次、在承接人员统计计一次，属于两个观察维度；全项目评价总数从原始评价按 order_id 去重，只计一次。
- 一个工单涉及多件商品仍计一次；后端避免评价 JOIN 商品、附件、区域、标签时放大行数，关联筛选使用 EXISTS 或先按 order_id 去重。
- 评价衡量服务链整体体验，人员关联均分包含联系、协调和等待等因素，不能据此自动归责或计算绩效。若需要个人态度／技能分，另行确认新问卷。

### 3.2 有效样本与边界

有效评价须有唯一工单标识、有效1～5整数和提交时间，并来自正式消费者评价事实或已明确的测试夹具。统计入口共用一个有效性查询片段，非法分数／损坏时间等异常剔除并报告数据质量数量，不能按低分、无意见、无标签、未解决或账号已停用剔除。

| 场景 | 建议处理 |
| --- | --- |
| 工单改派／人员退回 | 当前[两级退回契约](2026-10-03-工单两级退回与重新分配.md)只允许符合门禁的未开工退回；已有服务、完工或配件事实禁止直接退回。评价保存最终有效承接人的工单归属，先前退回的人／站不共享该分 |
| 已评分后数据变化 | 评分以已保存快照为准，不读取当前工单或人员关系重新分摊；现流程不开放已办结单任意改派。未来允许服务中交接／重开时必须另定多参与者规则，不能预先平均拆分 |
| 人员转站 | 旧站保留其历史评价；总部个人历史分仍包含旧站服务，新站仅展示该人员在新站产生的样本。新站无样本即暂无评价，不继承旧站均分作为本站事实 |
| 人员／站点停用 | 历史样本保留；公开列表按既有启用条件隐藏停用站。后台有权限可看历史；不能因离职或停用删除历史低分 |
| 主档删除／关联损坏 | 保留原始评价及ID；历史统计不因 INNER JOIN 主档或 enabled 条件丢样本。名称缺失显示“历史对象（编码）”；无法核验对象的记录单列数据质量项，仅总部可调查，不猜名字或归属 |
| 历史 station_id 空、personnel_id 有 | 可计入该人员总部历史分，不计入任何站点；不能按人员当前站补站点 |
| 历史 station_id 有、personnel_id 空 | 可计入站点，不分配给任何人员 |
| 两项均空 | 保留整单评价，在授权的总体统计中计一次，单列未归属数量；不进入人员／站点榜单，不自动回填 |
| 旧单没有最新审核证明 | 保持原提交资格；不迁移补造评价。已保存的旧评价作为历史事实核查，不因今日重新计算提交资格而全部清除 |
| 未评价／暂不评价 | 不计0分，不按默认5分补齐；邀请收起不影响已有资格和统计 |
| 长期后才评价 | 仍沿用现有无自动过期窗口；按实际提交时间进入当期评分分析，累计分同时更新 |

首期不新增评分撤销／删除、有效性人工开关或归属更正接口。如未来确需纠错，应另定权限、证据、审计及公开口径；不能通过编辑原始评价或主档均分隐式实现。

## 4. 算法、周期与更新（待确认）

对授权范围与周期内的有效集合 E：N=COUNT(*)，S=SUM(score)，均分=N>0时S／N，否则null。计算使用精确整数总分和 BigDecimal，**仅最终返回时 HALF_UP 到2位小数**；比较和再次汇总使用原始S、N，不用已舍入均分。

站点包含没有人员ID的有效本站评价，不按人员名单过滤。例：甲1条5分、乙9条1分，站点评分=(5＋9)／10=1.40，不是(5＋1)／2=3.00。分别取得人员明细时可以核对S、N，但不能从人员显示值反推站点评分。

返回并展示以下口径：

| 指标 | 算法／空态 | 区别 |
| --- | --- | --- |
| 消费者服务均分 | S／N，0样本返回null、显示暂无评价 | 1～5分，包含高低所有有效评价 |
| 评价数 | N | 包含没有意见文字的评价，不能称评论数 |
| 星级分布 | 1／2／3／4／5分各自次数，合计=N | 只反映原始整数，不从均分估计分布 |
| 消费者解决情况 | RESOLVED／PARTIAL／UNRESOLVED各自次数；如展示已解决比例，分母为有有效解决字段的评价数，另列缺失数 | 属于评价人群自述，不是全部工单一次完工率；历史字段异常不伪装未解决 |
| 回访满意率 | 当前回访SATISFIED／(SATISFIED＋UNSATISFIED) | 单独来源、样本数与抽样偏差，不转换为星级 |
| 评价覆盖率 | 首期新评分投影不输出该指标 | 评价提交期间可能包含早期办结单；不能直接除以同期间服务数。若以后做办结队列覆盖率，须明确按办结日选单及截至时点 |

周期建议：

1. 主档和消费者列表统一 ALL_TIME，含全部有可靠归属的历史有效样本，展示“累计评价”。不设新系统上线后的隐含起点。
2. Web评分分析默认最近30个北京时间自然日（含今天），自选含首尾最多93天。转为 submitted_at >= 起日00:00、submitted_at < 结束日次日00:00 的半开区间；拒绝非法日期、缺一端和超过范围。
3. 评价提交日不等于工单创建日、服务结束日或回访日。7月服务、10月评价，在10月评分趋势计一次，不能把它当10月新增服务或混入当前报表创建日队列。
4. 统计默认合并现有服务类型／方式，后台允许白名单按快照 order_type、service_mode 筛选；无历史快照单列未记录，不按当前工单补齐。对客不增加用户未要求的评分筛选器。
5. 0样本：averageScore=null、evaluationCount=0、sampleStatus=NO_EVALUATION。1～9：真实均分＋真实数量＋LOW_SAMPLE；10及以上：AVAILABLE。AVAILABLE只表示未触发提示阈值，不表示代表性或绩效达标。

更新建议：首期直接查询原始表，不引入新汇总写表、定时任务、消息队列或缓存。提交事务成功后，下次查询可见；幂等重试不增加样本。后台办理完成按现有刷新机制更新，消费者返回网点页可刷新；不承诺已打开页面实时推送。

同次汇总、趋势和明细查询使用同一只读一致性快照及 asOf，避免并发新增使分子分母来自不同时间。列表批量查询本页ID的汇总，避免每行一个查询；asOf表达查询时间，lastEvaluationAt表达最新评价时间，二者不混用。查询失败返回明确错误，不把失败转换成“暂无评价”。

主档列表从授权对象集合出发 LEFT JOIN 汇总，没有评价的对象仍返回；历史分析按有历史样本的对象列明细，另提供未归属数量。ALL_TIME分析不默认返回无限时间趋势，趋势通过DATE_RANGE查询。日期区间与累计参数不能混传。

首期不新增评分主表、汇总写表，不回填原始评价。拟交付独立版本迁移及rollback说明：

- 核对评价表12列、主键及实际类型，新增站点／时间、人员／站点／时间、提交时间的查询索引，候选为 `(station_id, submitted_at)`、`(personnel_id, station_id, submitted_at)`、`(submitted_at)`。以真实SQL的EXPLAIN与数据量确认最终索引，已有等价索引不重复建。

## 7. 与智能分站／派人的关系

### 7.1 首期推荐保持

保留 satisfactionRate 为 **回访满意率**，保留当前无样本回退和综合分公式；既有候选样本数／来源及AI输入含义不变。页面清楚区分“消费者服务评分4.35／5（932条）”和“回访满意率94.79%（211条）”；后者抽样覆盖与前者自发评价各有偏差，不能合并样本或认为一个更权威。

当前分站回退到全局／最终1、人员回退到站／全局／最终1，是已实现算法默认值；首期不能把它修成新规则，也不能对客显示为真实满分。候选解释中改善来源提示可作为第二阶段独立优化，需保留已确认语义。

### 7.2 若以后接入消费者星级

应新增明确qualitySource和策略版本，选择替换或独立加权，不能沿用字段名称让旧权重悄然作用在新指标。推荐先离线影子运行，再确认：

1. 使用累计还是近90天、样本阈值、无样本与低样本回退；人员和站点仍按评价快照归属，回退不算其真实评分。
2. 星级映射可选 `(均分-1)/4` 到0～1；若选择4～5星好评率则是另一项指标，不能叫均分。具体映射未确认。
3. 低样本可选收缩估计 `调整均分=(S+k×同类基准均分)/(N+k)`，k须结合真实样本和业务目标确认；对客仍显示原始均分，不能把模型分伪装消费者平均分。本稿不确定k或默认参数。
4. 距离、覆盖、服务技能、启用／在职、排班、容量、返回工单门禁继续作为硬条件，评分不能把不合格候选变成可选；服务类型／方式差异是否分层需证据。
5. 更新SMART、AI输入、策略快照与候选追踪，明确实际来源、周期、S／N、回退来源、映射、综合分及策略版本；仅修改权重不自动重跑既有任务的规则保留，试点和重跑范围另定。
6. 检查新人与低样本站是否长期得不到任务，以及高分集中、选择偏差和站点样本数不均造成的结果。当前测试数据集中一站、三人，无法完成这些业务判断。

**本次推荐不把该阶段并入首期。** 用户若要求同时接入，应先确认D5及上述决策，补专门分配验收范围。
