# 售后宿主模块级隔离

- 日期：2026-10-17。
- 来源：用户明确要求将售后专用认证、日志和配置收敛到售后子项目，宿主只保留必要装配；公共配置先核对，不直接回退他人改动，并验证其他模块不受影响。
- 状态：实现、完整回归、双宿主打包及本地实际运行验证完成。代码已本地提交，归并v0.24.7；未推送、未部署共享环境。

## 1. 架构边界

沿用共享 JVM、Spring 容器、Gaia 认证／权限／租户和数据源的模块化单体；本轮实施业务行为及配置所有权隔离，不建立独立进程、第二套后台认证、独立连接池或通用插件框架。发布／重启、进程资源及公共基础设施仍属于宿主共同运行边界。

| 能力 | 售后模块持有 | 宿主保留 |
| --- | --- | --- |
| Shiro 接入 | `AfterSalesHostIntegration` 中79条有序售后路由、字典与移动采集认证过滤器 | 在公共兜底规则之前合入路由，注册模块提供的过滤器 |
| MVC 边界 | 当前账号授权摘要、待办SSE及两类移动会话的权限／密码拦截例外 | 原公共拦截器及其非售后路径，通过一次模块调用追加售后例外 |
| 日志 | 售后 URL 追踪、专属 logger／滚动文件及售后日志级别属性 | 引用售后日志片段，保持公共 root 日志格式与原输出策略 |
| 外部配置 | 售后 API 中的无密钥配置模板，属性限定为 `gaia.after-sales.*`／`after-sales.*` | 原可选私密文件导入及公共基础配置 |

认证过滤器不是独立注册到所有请求的 Servlet Filter，也不复制 WAR／Jar 两份实现；它们由售后接入类创建，仅交由已匹配的 Shiro 链执行。移动认证服务沿用延迟解析，构造接入类和过滤器不会提前创建移动账号服务。各管理业务 API 继续走原认证及领域权限。

MVC 例外集中维护后，Jar 与 WAR 对消费者和服务人员移动入口统一使用域会话；只追加售后命名空间的例外，移动 API 内的会话／本人／租户校验继续执行，不扩大公共 `/api/**` 例外。字典接口仍使用专用认证链，未改为匿名。

## 2. 公共配置核对

改动前留存两个宿主的公共 Shiro 路由与 MVC 例外快照，以及 `application.properties` 内容摘要；快照不包含凭据。WAR 的48条、Jar的47条非售后 Shiro 规则维持原内容及顺序，公共 MVC 例外也逐项保留。

两个宿主的 `application.properties` 完整内容与改前 SHA-256 一致。包括既有 Druid 校验查询、超时、借出检测、保活，以及 WAR 的统一登录 Cookie 名 `gaia_local_token`，均未修改。审计确认这些设置来自 felixwang 的 `d9e2d4a4`，后经 Snow 的 `467fc74b` 合并带入；合并文件与入站父提交相同，不按“售后隔离”直接回退。

共享 Cookie、连接池参数继续由宿主或部署环境管理；售后模板不能通过移动文件位置或属性名伪装出进程／基础设施隔离。本轮没有修改实际私密配置或凭据，没有执行数据库迁移或业务记录变更，也没有改动 Gaia 系统源码；正常联调仍会产生既有登录和诊断日志。

## 3. 日志隔离及配置位置

- 追踪 Filter 仅注册 `/api/afterSales/*`，内部再次检查去掉 context-path 后的售后前缀；非售后请求、公共登录／退出及近似前缀均直接通过，不包装响应、不增加追踪头、不创建售后日志或修改已有 MDC。
- 删除公共登录／退出专用的响应观察包装器；共享后台登录日志继续读取 Gaia 既有记录，不再向售后运行事件额外采集所有项目的公共登录。
- `afterSales` 和 `com.ehsure.gaia.afterSales` 两个 logger 进入 `${LOG_HOME}/after-sales.log`，包含追踪号，`additivity=false` 防止写入公共 `all.log`。沿用原100MB分卷、60天和20GB上限；develop保留控制台输出。
- 公共 `all.log`／`error.log` 还原本轮隔离所针对的 Snow `00ff53d6` 添加前的无追踪号格式；其他公共日志配置和他人改动保留。原公共日志采集器不需要因售后追踪字段改变解析规则。
- 售后日志片段位于 `gaia-after-sales-api/src/main/resources/com/ehsure/gaia/afterSales/host/logback-after-sales.xml`，级别由 `gaia.after-sales.logging.level` 控制；宿主仅 include 此片段。
- 无密钥模板移至 `gaia-after-sales/gaia-after-sales-api/src/main/resources/config/gaia-after-sales.properties.example`。真实私密文件位置及宿主的可选导入不变，详见[外部配置指南](2026-09-18-售后AI外部配置与部署指南.md)。

完整Core464项／API522项通过，0失败、0错误、0跳过；清理旧class后重新安装售后制品。WAR与Jar编译、宿主全部16项测试通过，包含原BI页面的随机端口真实Spring启动／HTTP200及5项非售后隔离回归；两个宿主最终打包通过。

命令：售后 `mvn -B -pl gaia-after-sales-api -am install`；宿主 `mvn -B -pl gaia-saas-web,gaia-saas-web-jar -am clean test` 及对应 `package -DskipTests`。启动冒烟的测试夹具依赖外部数据库／Redis；本轮只在测试进程环境中注入已有测试库连接参数并复用本地16379 Redis，关闭测试进程的Quartz自动启动，没有修改公共配置文件。日志分流回归使用私有LoggerContext，避免与真实Spring启动测试互相重配置。

本地正式启动器已重建并加载PID9065，运行制品为 `gaia-web-20261017171459-9065.jar`；其中宿主Shiro class及售后接入／认证class逐一与本轮构建相同，旧宿主认证副本及已删除公共响应包装器不存在。WAR也已核对包含售后接入class／日志片段，不含旧认证副本。

真实只读接口复验：公共登录／退出成功且不附加售后追踪头；已登录系统菜单树可读、未登录被4001拒绝；售后门店类型15项、行政区3342项读取及版本unchanged通过，仍返回受控追踪号。字典匿名、两类失效会话、相邻未注册路径及写方法均拒绝。原BI页面HTTP200、112605字节。本机公共Cookie和连接池配置在重启后再次核对内容摘要不变，9010前端保持运行。正常登录及查询可产生既有安全／诊断日志，没有写业务单据。

原始日志与改前摘要留在忽略目录或系统临时目录；仓库只保留路由政策基线及必要回归。此验证不等于其他项目全部业务流程验收、共享环境部署或进程故障隔离。
