# 2026-09-19 实时工单看板与排班站点默认

## 目标

在“服务站作业 → 本站工单”中，将“实时工单”放在“服务站工作台”之后。页面以服务站与日期为范围，按小时展示服务人员已分配工单，供服务站作业人员查看当天工作分布。

同时修复创建服务工单时已填写“期望上门时间”仍提示未填写的问题，并使“排班管理”的服务站条件按数据权限加载且默认选择第一项。

## 已确认口径

| 项目 | 规则 |
| --- | --- |
| 时段 | 固定 24 个整点时段：`00:00-01:00` 至 `23:00-00:00`。 |
| 选择条件 | 页面仅展示当前登录人有数据权限的启用服务站；一项或多项权限均默认选中第一项，切换后立即重新加载。 |
| 日期 | 默认当天，可切换指定日期。 |
| 人员集合 | 该站当天存在已发布或锁定的“工作”排班的启用人员；若人员无排班但当天已有人工分配工单，也保留展示。 |
| 工单集合 | 当前服务站、当前日期、已分配服务人员的安装／维修／清洗工单；排除已取消、已关闭工单。指导／其他仍按既定首期范围不进入看板。 |
| 单元格 | 同一人员同一时段的多张工单纵向展示；文本为“城市区县-服务类型”，悬停显示工单号、完整可用地址、服务类型与预约时间。 |
| 汇总与走势 | 汇总行第一列为人员数，其余列为每小时工单数；走势行使用该 24 个数量绘制折线。 |
| 刷新 | 页面进入后每 5 分钟刷新一次；右上角“搜索”按钮可手动刷新。切到后台标签页时跳过自动请求。 |

## 实现范围

### 前端

- 新页面：`apps/after-sales/src/views/serviceResource/realtimeWorkOrder/index.vue`。
- 新菜单／路由：`afsRealtimeWorkOrder`，路径为 `afterSales/serviceResource/realtimeWorkOrder`，同级归入服务资源；服务站视角顺序为“服务站工作台 → 实时工单 → 服务工单 → 工单分配”。
- 服务站下拉调用现有服务站选项接口，前端不传入任意服务站列表；后端继续执行数据范围校验。
- 排班管理服务站下拉改为编号在前、名称在后，并在入口初始化时校验当前值是否仍在权限选项内；不在时回落至第一项。
- 创建工单时间的正则由错误的双反斜杠字面量改为实际数字格式校验：`YYYY-MM-DD HH:mm`，小时限制为 `00` 至 `23`，分钟限制为 `00` 至 `59`。

### 后端

- `GET /api/afterSales/service-resource/realtime-work-orders?stationId={id}&scheduleDate=YYYY-MM-DD`
  - 首先校验实时工单读取权限。
  - 再用当前用户的数据权限校验服务站。
  - 返回人员行及其工单行；工单开始时刻从单点预约时间（兼容历史区间值时取开始时刻）解析为小时。
- 新增 `RealtimeWorkOrderBoard`、`RealtimeWorkOrderPersonnelRow`、`RealtimeWorkOrderRow` 传输模型与 MyBatis 查询。
- 菜单权限迁移：`gaia-after-sales/database/20260919_realtime_work_order_menu_permissions.sql`；对应回滚：`20260919_realtime_work_order_menu_permissions.rollback.sql`。
