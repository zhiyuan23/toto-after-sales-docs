## 1. 首版范围

1. 服务受理从已有顾客购买记录中按手机号、姓名、登记单号、代理商、门店或安装码识别顾客与商品，复用现有组织数据范围，不借用顾客档案菜单权限。
2. 客服可选择一个购买登记下的 1～100 个产品实例，人工创建安装、维修或指导工单；指导支持远程和上门两种方式。
3. 受理渠道支持电话、微信、消费者、代理商和接口；工单建单来源固定记录为客服代建，来源号／会话号可选并加密保存，只返回脱敏值。
4. 安装工单只允许选择可预约商品并更新产品实例状态；维修和指导拒绝已退回商品。任一商品存在活动工单时拒绝重复建单。
5. 维修和指导必须填写问题描述；联系人、手机号、详细地址继续使用现有加密与脱敏规则。期望日期不得早于当天。
6. 建单在同一事务中保存统一工单、工单商品关系和首条不可变状态历史；使用 `clientRequestId` 保证当前操作人重试幂等，首态为 `PENDING_ACCEPTANCE`。
7. A18 工单列表和详情同步展示受理渠道、脱敏来源编号、服务方式和问题描述，不复制客服专属工单表。
8. Web 继续使用 `FaPageMain → EsSearch → EsTable` 和 `useListPage`；表格撑满筛选、提示和分页之外的剩余空间，空数据时分页位置稳定。

## 2. 主动不实现

- 电话、微信和第三方接口的自动入队、原始会话拉取与回执依赖渠道契约；本轮只建立人工过渡入口和稳定字段，不伪造渠道联调。
- 当前只能对已有购买登记代客建单。未识别顾客的新建、重复顾客合并及合并历史需要确认身份校验、隐私同意和主档归并规则后实现。
- 不返回联系人、手机号、详细地址或来源编号明文；敏感原文仅以 AES-GCM 密文保存。
- 不实现服务站自动分配、师傅派单、任意状态编辑、异常、完工、回访、投诉或结算；这些由后续 A19～A24 专用动作切片完成。

- 页面访问其他代理商、门店和商品详情仍分别检查目标菜单及 API 权限；受理功能不扩大关联主档权限。

## 4. API

- `GET /api/afterSales/customer/intake/records`：权限范围内的顾客／购买记录分页识别。
- `GET /api/afterSales/customer/intake/records/{id}`：读取受理所需的购买记录和产品实例。
- `POST /api/afterSales/customer/intake/orders`：创建安装、维修或指导统一工单。
- 原有 `GET /api/afterSales/customer/work-orders` 与详情接口返回新增受理字段。
