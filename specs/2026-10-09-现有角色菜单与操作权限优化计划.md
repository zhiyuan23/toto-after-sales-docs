## 1. 最终确认范围

本次不增加客服主管或其他新角色，不增加菜单；客服专员日常分站、服务站派人及工单主流程保持。门店现有“服务工单”就是授权范围内的工单查询，保留其入口和既有授权，不新增第二个“工单查询”。

总部需要监督配件库存与工单耗用，保留“库存台账、工单耗用”两个查询入口；库存收发、领退料、调拨和盘点作业继续由服务站视角承接。配件档案仍位于总部商品资料。

先前草案包含隐藏操作授权清理，本次用户进一步明确从可见菜单判断，故那些事项未纳入本次实施：服务站完工审核、客服商品／知识维护、模板写操作及后台领退料创建等仅保留为后续核验线索。本次不撤销或扩大现有数据库角色／操作授权，也不强制拆分客服主管与专员。测试代理商账号缺少工单读取的时点结果不代表所有实际门店缺少入口，不能据此新增菜单或扩大岗位授权。

## 2. 已执行调整

| 对象 | 调整后行为 |

| 总部库存分组 | 只投影 `afsPartStock`、`afsPartConsumption`；收起 `afsPartInbound`、`afsPartRequisition`、`afsPartReturn`、`afsPartTransferOutbound`、`afsPartTransferInbound`、`afsStocktake` |
| 总部工单耗用页 | 查询及详情沿用原权限与接口；隐藏“登记工单耗用”，打开和提交方法也判断当前视角，避免缓存表单继续提交 |
| 服务站库存 | 九个既有入口（含配件档案）保持；耗用登记继续要求原创建权限 |
| 管理员 | 仍按原功能授权切换岗位视角；库存作业路由解析到服务站视角，总部视角显示两个查询入口 |
| 门店／客服 | 视角清单、工单查询和日常办理授权保持 |

唯一导航清单 `apps/after-sales/src/features/navigation/manifest.json` 同时供独立侧栏、搜索、主站投影和菜单交付包使用；只调整总部投影，不修改稳定注册、路径、显隐、操作 ID 或角色绑定，因此无需数据库迁移。主站角色勾选树未扩大为本次验证范围。

当前注册功能59个、去重日常导航47个、上下文2个保持；四视角引用由67减至61（总部29／客服11／服务站18／门店3），普通业务分组17个保持。菜单矩阵、目录规则、当前总部完整侧栏原型及其搜索同步此口径；带日期旧记录保留历史含义。

## 4. 后续与恢复

共享环境更新需按项目正式部署入口另行授权；应用发布后用总部与服务站真实账号复核查询入口、作业按钮和直达路由。若后续决定回收隐藏操作授权，须另核对精确接口和真实岗位责任，验证允许／拒绝及工单主流程，不把前端菜单收起当作后端权限整改。
