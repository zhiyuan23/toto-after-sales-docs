## 1. 目标与操作路径

普通排班只需：**安排本周 → 选择人员并设置七天 → 确认排班**。

选人、星期安排、影响摘要在同一个表单内可见，不拆成多步向导，不再要求用户学习选中格子、应用到格子、全表待保存、保存草稿和发布之间的关系。

明确区分两类操作：

- 整周：在集中表单中安排同一批人员的完整一周。
- 单日：点击周表某个人的某一天，在小表单中确认调整。

本轮只改排班交互和必要支撑，不修改日容量归属、排班状态机、服务站数据权限、技能规则、工单冲突和发布覆盖规则。

## 2. 主页面

### 布局

- 查询区：服务站、人员及现有展开筛选；保留日历／列表切换。
- 周表标题栏：左侧为周日期与上一周／本周／下一周；右侧只突出 **安排本周**。
- 内容区：人员 × 七天完整周表，继续按人员分页，包含未排班人员，保留人员列／表头固定与在岗人数统计。
- 底部：只有分页与统计，不放业务提交按钮。

移除整张周表的编辑模式、人员／日期多选工具、拖选提示、撤销图标、统一设置、快速排班菜单、保存结果分区及保存方式下拉。用户在主页面不会形成一份需要另行提交的全表修改。

### 点击行为

- 有写入及生效权限：点击可编辑班次或未排班日期格，打开单日调整表单。
- 无相应权限，或班次锁定／过期／作废：已有记录打开只读详情，不显示可提交表单；空格不提供写入口。
- 类型／状态筛选生效时，隐藏为“无匹配记录”的格子不能被当作未排班新建；点击仍按实际记录判断。
- 列表保留查询、详情及人员跳转；现有新增日／周、范围批调、独立发布和行编辑入口统一接入新整周／单日表单，避免两套不同的操作方式并存。

## 3. 集中表单：安排本周

使用现有大尺寸 `EsFormDialog`，固定标题与底部，内容内部滚动。标题显示服务站与周日期，当前服务站和周次由页面带入且在表单内只读。

### 3.1 给谁排班

- 人员区域直接显示勾选项：姓名、编码、必要的服务技能摘要；可以按姓名／编码筛选。
- 不默认把空选择解释为全站。至少明确选择 1 人；显示“已选 N 人”。
- 可以选择主周表其他分页的人员，选择跨人员页保留，不受主周表当前显示的人员限制。
- “全选本页”只代表当前人员选择页；搜索后也明确为当前结果页，不能暗中扩大到全站。
- 保持现有精确提交上限：一次最多 100 人、700 个日期格；达到上限有说明，不悄悄拆为多个非原子请求。
- 若主页面已精确筛选一人，打开时预选该人；其他情况不预选所有人。

### 3.2 这一周怎么上班

七天横向排列，每天显示星期、具体日期和直接可见的 **工作／休息** 两项选择，不使用七个下拉框。

- 默认预设为周一至周五工作、周末休息；可直接调整每一天，也可以使用“全周工作”预设。
- 工作项目按每位人员本人技能安排，不把某个人的技能套给整批人员；无可服务技能时提示具体人员并阻止确认。
- 请假、临时停单作为单日例外处理，不在默认整周规则中堆叠更多选项。
- 对同一批人使用同一星期安排；不同轮休安排分批办理，不额外引入轮班模板管理。

### 3.3 摘要与已有安排

人员及规则变化时，在当前表单下部生成预览，不额外弹出第二个确认窗口。

- 明确显示人员数、周日期、工作日／休息日，以及新增／修改／不变数量。
- 默认仅补未排班日期，已有安排保留。存在已有安排时才出现一个明确复选项：**同时调整已有排班**。
- 勾选后列出实际修改的人员、日期、原班次和新班次；未改变的已发布记录不重复提交。
- 已发布记录被改变时显示必填“调整原因”；锁定、过期、作废或无编辑权限的记录始终不可覆盖，并说明保留数量及具体记录。
- 草稿属于已有安排；只有明确纳入本次确认范围的草稿随本次立即生效，不自动发布同页其他人员的草稿。
- 如果没有任何可提交的新建／修改／明确纳入的草稿，按钮禁用并显示“所选日期已有安排，无需重复排班”。

### 3.4 底部操作

始终只有 **取消** 与 **确认排班**。旁边用一句说明明确“确认后立即生效”。不提供页面级保存草稿、发布、应用或撤销入口。

点击确认前，用户已能在同一个表单中看见本次影响；确认后只提交预览中的精确日期格。请求期间防止重复提交和关闭，成功关闭表单、刷新当前周并反馈结果；失败在原表单中显示原因，保留所有输入可修正或重试。

## 4. 单日调整表单

使用小尺寸 `EsFormDialog`，标题为“调整排班”，固定展示人员、服务站和日期。

- 直接显示工作／休息／请假／临时停单四个选项；回显原班次。
- 工作时显示服务项目：已有班次保留原项目，新班次默认本人技能；只能选本人可服务项目。
- 调整已发布安排、请假或临时停单时必须填写原因；备注保留现有能力。
- 当前值与原值相同时不提交重复修改；草稿明确确认后可生效。
- 底部只有 **取消** 与 **确认调整**。成功立即生效并刷新周表，失败保留内容。
- 已有记录可在表单内通过次级文字入口查看完整详情；只读用户直接查看详情。

## 5. 必须保留的业务约束

### 覆盖与工单

复用已有版本、权限、本站归属、启用状态、技能、审计和事务校验。已安排未完成工单的日期不能改成非工作，不能移除其所需服务项目；预览显示人员、日期和工单编号，并提示先改派／改期。

**现有发布规则要求本周每天都有已发布在岗人员。** 默认周末休息只是所选人员的规则，不代表全站可以无人值班。如果本次确认后周末全站无人，表单直接提示缺少在岗的具体日期，允许改规则或换一批人员；不能为了使默认预设通过而自动放宽后端规则。

整周确认和单日立即生效都使用既有发布校验。因此一个完全没有排班的新周，仅安排一天可能仍因其他日期缺少在岗人员而被拒绝；提示引导到“安排本周”。本轮不私自把整周覆盖规则改成单日规则。

### 权限

“确认后立即生效”仍需要发布权限；新建格需要新增权限，修改已有格需要编辑权限，批量请求需要批量权限。没有生效权限的账号保留查看能力，不能把确认操作悄悄降级成草稿保存。按权限矩阵是否补充岗位授权需另行核对，本轮不自动扩大授权。

### 未保存、网络与并发

- 只有表单内存在未确认输入。取消／路由离开时有改动则提示放弃，未改动直接关闭。
- 不自动重放超时／502 的写请求；保留输入并允许用户核对、重试，继续由唯一约束和版本校验防止覆盖。
- 版本冲突不覆盖他人修改；允许重新加载最新记录并重新查看影响，不静默丢弃用户选人和规则。
- 请求加载失败提供原位重试；异步响应按当前服务站、周次及请求代次隔离。

## 6. 实现边界与组件职责

- 周表组件收敛为读取、周次／人员分页、展示、打开整周／单日表单；删除现有页面级编辑、选择、撤销和保存状态。
- 整周表单独立组件负责人员选择、七天规则、影响预览、覆盖选择及一次确认。
- 单日表单独立组件负责回显、单日校验及一次确认；共用已验证的班次／服务项目转换方法。
- 纯模型负责从人员、已有排班及规则生成精确日期格，区分新增／修改／保留、工单影响、预计在岗人数，不在 UI 层推断权限。
- 复用 `GET availability/week` 读取完整人员页及相关班次／工单。弹窗用自己的请求及选择状态获取所需人员页，不能只使用主周表已载入的一页，也不直接使用可能截断的人员选项列表充当全站。
- 复用 `PUT availability/batch` 精确 `cells` 分支，确认时 `publish: true`，保留 `id/version`。一次事务，不逐人循环发布，不增加页面自动写入。
- 无新增菜单、数据表和前端依赖；使用已有 `EsFormDialog`、`EsDialogTablePanel`、Element Plus 和国际化体系。保留现有 API 兼容性，不在此任务删除历史接口。
- 复制上周及可复用轮班模板不是本轮主要交互；本轮不扩展这些能力，不再把复制／生成工具作为周表顶层主按钮。

## 7. 验收场景

1. 首次使用者无需进入编辑模式，即可通过“安排本周”完成选人、设置星期、查看摘要和一次确认。
2. 主周表第二页人员可以在表单内选中；跨人员页选择不丢失，全选本页不扩大范围，超过 100 人明确阻止。
3. 默认补空格不覆盖现有安排；明确覆盖后预览与提交一致，锁定记录保留、已发布调整必填原因。
4. 确认后即时已发布，只提交本次选定记录，不顺带发布其他人员草稿；失败全部回滚且表单输入保留。
5. 默认周末休息遇到全站无人时显示具体日期并阻止确认；安排其他人在岗后可正常通过。
6. 直接点一天可调整，变更原因、技能与工单冲突校验有效；只读／无发布／无新增／无编辑等权限分别符合契约。
7. 取消无写入，有改动提示放弃；重复点击、网络失败、版本变化和快速切换周次不造成重复保存或过期响应覆盖。
8. 桌面端表头、人员列、分页、弹窗固定头尾和内部滚动正常；中英文操作文案与权限显示验证。
9. 运行必要模型行为测试、现有前后端相关回归、前端完整检查与构建；既有失败单独标明，不当作通过。
