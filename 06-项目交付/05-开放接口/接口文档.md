# 售后基础数据开放接口 v1.0

更新日期：2026-10-19。目标：[测试环境](http://10.1.1.53:8011/)。本文件与本目录 OpenAPI JSON、模拟数据及 SQL 共同交付。运行验证结果见对应 Spec，文档生成不代表已经部署。

## 认证与调用

基址：`http://10.1.1.53:8011/api/openapi/v1.0/afterSales`，所有业务接口使用 POST。复用现有平台 OAuth2 Token，后续请求携带 `Authorization: Bearer <access_token>`；不使用后台登录Cookie替代开放账号。Token地址与参数见下方认证示例，密钥从“开放接口→账号管理”查看，禁止写入日志和Git。

测试账号appId：`afs_openapi_test_20261019`，说明“售后接口测试用户”；初始化时授予当前全部开放接口权限，后续新增接口需重跑授权SQL。业务操作人是该开放账号在平台登记的创建人，售后范围仍执行该操作人的组织可见规则。禁用账号／操作人或撤销接口授权后拒绝调用。多租户模式必须有平台可信租户上下文，不能传tenantId/userId切换身份。

认证示例（表单提交，不把密钥拼入URL）：

```text
POST http://10.1.1.53:8011/api/openapi/v1.0/oauth2/token
Content-Type: application/x-www-form-urlencoded

client_id=afs_openapi_test_20261019&client_secret=<从账号管理取得的密钥>
```

取响应中的access_token；有效期和刷新方式沿平台v1.0现有行为。不要在模拟数据中保存密钥或Token。

## 保存与批量结果

可以提交单个对象，或`{"items":[对象1,对象2]}`；每批1～100条，按提交顺序逐条处理、独立事务。相同唯一编号存在则更新，不存在则新增。普通档案使用code，实物使用uniqueCode，销售区域使用subjectType+subjectCode。编号按目标库现有比较规则判重；编号本身不可用本接口改号。

更新未传字段保留，显式空值按页面校验决定能否清空。嵌套businessInfo/profile按字段合并；传入关系数组整体替换，空数组表示清空但仍受业务必选规则限制。关联填写编号，禁止提交内部ID、操作人、审计及租户字段。关联不存在／停用、层级循环、非法字典、已登记实物变更等仍按页面业务规则拒绝。重复推送不重复新增，但可产生正常更新审计；requestId用于追踪，不代表跨请求幂等缓存。

version可选：传入时必须匹配当前详情版本；未传时服务端锁定现有记录并读取当前版本，保证本次部分更新不覆盖未传字段。并发新增或唯一字段冲突返回409，可核对后重试。

返回示例：

```json
{"code":0,"errMsg":"","requestId":"UUID","data":{"total":1,"successCount":1,"failureCount":0,"results":[{"index":1,"code":"OA26_CAT","success":true,"data":{"id":"字符串ID","code":"OA26_CAT","version":"版本令牌"}}]}}
```

部分或全部失败外层code=422，成功项已经提交，不得整批盲目回滚；逐条results返回success、errorCode、errMsg。修复后可重试失败项，或按编号安全重推。新增缺必填值／类型错误为422，未授权403，缺记录404，冲突409，基础设施失败503。平台认证错误保留既有400xx码和HTTP行为，不能只看HTTP 200判断成功。

## 查询与启停

查询请求：`{"page":1,"pageSize":15,"keyword":""}`；page≥1，pageSize 1～100。也可用code精确查询，实物用uniqueCode；销售区域用subjectType+subjectCode精确查询。返回data.rows和data.records，详情含version及字符串ID；业务关联／审计展示字段以当前售后详情模型为准，不应回填为保存参数。

启停请求：`{"code":"OA26_PART","enabled":false,"version":"可选"}`，返回更新详情。新增默认启用；保存不隐式启停。已有引用、父子层级及状态限制继续生效。首期没有开放删除接口。

## 图片规则

JPG/JPEG、PNG、WebP，单张≤5×1024×1024字节，商品最多10张；分类、系列、配件各1张。商品及系列建议1200×800（3:2），分类／配件建议800×800（1:1）；尺寸为建议，不强制裁剪／缩放或有损压缩。上传校验扩展名和真实文件头，JPG统一以.jpeg入平台；存储与现有SysCommonUploadAppService一致。

先上传，保存返回的access（`/api/sys/commontools/picture?id=...`），再放入imageUrl/imageUrls；不接收任意远程URL代抓取。保存时核对上传记录、文件大小和格式。附件回显沿现有鉴权方式，不重复拼接/api或文件域名。二进制内容和认证头不写入开放日志。

## 监控与配置

“开放接口→接口管理→售后服务”查看接口，“开放接口→监控日志”按接口地址、账号和时间定位调用；requestId关联响应与日志，成功、业务失败及批量部分失败均可核对。复用平台OpenApiInvokeLogHandler及sys_open_api_invoke_log，不另建售后专用调用日志。认证在平台拦截器阶段被拒绝的请求沿平台既有监控行为，不保证生成业务Controller日志。

SQL单独位于sql目录：01分类／23接口／日志配置，02测试账号／全接口授权，03停用回退。执行前检查目标库和ID／路径冲突，备份涉及配置；脚本不自动迁移或删除业务表。密钥数据库随机生成，重复初始化不重置密钥。测试数据不要用于正式订单或真实客户业务。
