# 项目交付

交付材料按三项正式产物组织：**角色手册、项目说明、交付清单**。以网页为主要阅读与展示形式，配套可打印文档；简明业务指南和协议参考仍作为支撑资料保留。本轮先整理结构，不展开手册正文、不制作新的手册／清单网页或打印文档。

## 内容与维护边界

- 角色手册按操作场景组织步骤、权限、交接与异常；项目说明提炼总体关系与价值；交付清单引用实际材料入口和核对依据，三项不重复维护相同正文。
- 各项内容源为本目录 Markdown 与正式网页资源。后续网页及可打印文档从同一内容源组织，避免形成两套独立业务口径；本轮不创建空网页或空打印目录。
- 内容覆盖完整项目与完整需求；具体步骤仍以对应需求、Spec 和实际程序为依据。讨论稿、规划、材料骨架不因结构整理成为已实现或已交付内容。
- 项目按 Web 管理后台、消费者小程序、服务人员小程序三个应用组织。总部、客服、服务站、门店属于同一 Web 后台的工作视角，系统管理员另有平台管理手册。
- [业务指南](01-业务指南/00-项目概览.md)与[岗位导读](01-业务指南/01-角色与操作指南.md)保持简明，通过链接进入详细手册，不复制完整权限或实时进度台账。
- [协议参考文稿](01-业务指南/协议文稿/README.md)保持未正式生效的说明；[测试账号手册](01-业务指南/售后数据权限测试账号手册.md)仅供内部测试，不进入对外材料包。凭据和测试账号不写入正式交付正文。
- 后续正式交付包按实际交付范围核对，不将网页存在、研发验证或 Git 提交等同于业务验收与签收。
