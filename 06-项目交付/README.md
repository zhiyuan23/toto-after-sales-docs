## 内容及格式维护

正文源是本目录相应 Markdown，共用模板在 [生成脚本](../scripts/build-delivery-docs.mjs)，样式及交互在 [assets](assets/)。修改源后生成 HTML，不直接修改生成正文。内部汇报在独立目录维护，不进入客户交付首页或清单；客户汇报版本待准备后再加入项目说明目录。

```sh
node scripts/build-delivery-docs.mjs
```

脚本使用 `marked`（本次已捆绑版本 17.0.5），本地已安装时直接使用；否则设置 `MARKED_MODULE` 指向已有 `marked/lib/marked.esm.js`。本次桌面环境生成命令：

```sh
MARKED_MODULE=/Users/snow/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/marked/lib/marked.esm.js node scripts/build-delivery-docs.mjs
```

阅读无需 Node、联网、外部字体或脚本库，可直接打开 HTML。搜索筛选仅影响当前阅读，打印按钮输出全文并展开常见问题，清单实际交接结果不在浏览器持久保存。内部依据折叠显示且不进入打印；独立对外包按清单筛选，不依赖仓库外部路径。

版式采用白底品牌蓝、左侧章节目录、正文任务步骤与右侧快捷链接；清单保留类别／状态／关键词筛选。首版不使用模拟截图替代真实程序；后续业务复核后可补最有帮助的真实截图，不要求每个操作配图。

设计方法参考 [Microsoft Field Service 入门](https://learn.microsoft.com/dynamics365/field-service/field-service-get-started)的角色配置与端到端任务组织、[Salesforce Field Service 入门](https://trailhead.salesforce.com/content/learn/modules/field_service_basics/field_service_basics_intro)的管理员／调度／现场协同，以及 [Diátaxis](https://www.diataxis.fr/start-here/)对操作指南、解释与参考资料的分工。仅借鉴组织方法，业务与权限以本项目契约为准。

## 范围与复核

三应用为 Web 管理后台、消费者小程序、TOTO客服助手；Web 有总部、客服、服务站、门店四视角，系统管理员另有平台手册。完整需求、技术契约和实时进度继续在原目录维护，不在交付目录另建验收台账。

手册据当前确认规则编写，最新程序与目标环境须在交付时核对。费用首版链路已有但正式细则待确认、当前免费；延保活动未开发；消息须核对接入和送达。阅读、打印与本地验证不证明业务验收。

项目组继续负责持续运维，资料接收不转移运维责任。[演示协议](01-业务指南/协议文稿/README.md)不等于正式生效文本。内部测试账号手册、密码、密钥与本地配置不进入对外包。

后续业务复核重点：实际菜单与按钮、专项权限、异常交接、有效费用和权益政策；正式交付时再填写批次、环境版本、接收人、培训结果和验收／签收依据。
