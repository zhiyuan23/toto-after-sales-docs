## 修改入口

- `content.js`：标题、画面关键词、讲解备注及 HTML。第二版中的详细内容已保留在对应备注中。
- `brand-logo.png`：复用售后 Web 后台的品牌图标，作为页面运行资源随本版保存。
- `presentation.css`：第三版的字号、留白、卡片布局与双端知识图形。底层 `styles.css` 沿用第二版主题和视觉规则。
- `platform-puzzle.js`：根据拼图实际可用宽高重新排布六块拼图，管理连续拼接轮廓、整体阴影及图标／文字比例；页面显隐、窗口缩放与全屏变化由尺寸观察自动更新。
- `icons.js`、`business-diagrams.js`、`graph-layout.js`：现有 Tabler 图标与扁平场景插画，不引入第二套视觉体系。
- `display-motion.js`、`cover-motion.js`：入场动画与首页工单循环。双端知识辅助页按知识库、两端卡片、能力示意与价值说明依次呈现。

初版精简时，内容区非 SVG 文本去除空白后由第二版 1847 字符减少到第三版 899 字符，双端辅助由 209 减至 89。该统计是合并亮点页前的记录，用于说明精简幅度，不是当前字数或业务效率数据。

## 业务口径

平台页采用“补齐售后服务环节，让蓝鲸数字全链路延伸至产品使用与服务”。依据知识库《蓝鲸数字》《蓝鲸数字-仓库与能力导航》《蓝鲸数字-业务域、接口与数据归属索引》，将已有能力概括为生产仓储、渠道分销、门店销售、会员营销、防伪追溯五块，与蓝色售后拼块相互拼合。“最后一环”作为价值比喻有依据，但正式文案避免暗示全平台已全部打通或验收。拼图为能力关系示意，不是完整模块清单或严格流转顺序；跨系统集成与多客户适配保持实际边界，详细依据及限定放入讲解备注。

首页总部与门店位于流转区域外的上方，保留各自主题色与细线边框，以较小卡片与图标、轻字重保持辅助视觉层级；总部以无箭头虚线连接门店和服务站，表达授权范围内的基础资料维护关系，并提供规则／运营支撑。首页动画固定展示消费者自主申请、客服分站、服务站派人、人员预约履约、提交、审核与办结的简单主线，循环后仍从消费者开始。门店保留购买登记与代客申请的能力说明及总部管理连线，不参与本页工单动画。消费者可信商品申请进入服务工单及分站策略，预约服务对象为消费者。减少动态效果时展示六角色与消费者申请主线总览。

全稿按完整项目需求组织，不增加实现率或验收台账。商品档案知识分别支持消费者智能助手提供处理建议，以及服务人员查询解决方案和获取备件建议；未解决仍可申请服务，实际用料由人员确认。未来规划页区分已有预留与扩展建议：消费者品牌产品中心与商城接入为用户提出的方向，延保活动仍属预留，主动养护、会员运营与品质洞察为扩展建议；不据此新增正式需求、开发排期或交付承诺。智能审核发生于提交完工后，疑点转人工。

后台实时待办依据[客服与服务站 SSE 契约](../../../../specs/2026-10-07-客服与服务站待办SSE实时更新.md)；微信订阅依据当前两端小程序订阅消息设计稿（`specs/2026-10-07-两端小程序订阅消息设计.md`，该业务设计稿尚未提交，另行维护），保留用户授权与本单发送机会的边界。服务站派人后向对应服务人员发送新任务短信，按用户确认的完整方案展示；接入及送达状态以对应业务契约和运行证据为准。本 HTML 不连接业务接口或实际发送消息。真实演示按实际可用能力组织。
