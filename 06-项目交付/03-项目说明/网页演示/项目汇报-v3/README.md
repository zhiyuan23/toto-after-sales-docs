## 修改入口

- `content.js`：标题、画面关键词、讲解备注及 HTML。第二版中的详细内容已保留在对应备注中。
- `brand-logo.png`：复用售后 Web 后台的品牌图标，作为页面运行资源随本版保存。
- `presentation.css`：第三版的字号、留白、卡片布局与双端知识图形。底层 `styles.css` 沿用第二版主题和视觉规则。
- `platform-puzzle.js`：根据拼图实际可用宽高重新排布六块拼图，管理连续拼接轮廓、整体阴影及图标／文字比例；页面显隐、窗口缩放与全屏变化由尺寸观察自动更新。
- `icons.js`、`business-diagrams.js`、`graph-layout.js`：现有 Tabler 图标与扁平场景插画，不引入第二套视觉体系。
- `display-motion.js`、`cover-motion.js`：入场动画与首页工单循环。双端知识辅助页按知识库、两端卡片、能力示意与价值说明依次呈现。

初版精简时，内容区非 SVG 文本去除空白后由第二版 1847 字符减少到第三版 899 字符，双端辅助由 209 减至 89。该统计是合并亮点页前的记录，用于说明精简幅度，不是当前字数或业务效率数据。

## 卡片视觉规则

同页主要信息使用完整浅彩卡面，次要信息使用完整白色卡面；颜色补充表达角色或类别，卡面、文字与底部厚度分别承担不同职责。规则集中在 `presentation.css` 末尾，沿用原有主题色、卡片圆角、5 单位主卡厚度与 3 单位小卡厚度，不逐页另配颜色。

| 信息类别 | 卡片处理 | 本版示例 |
| --- | --- | --- |
| 角色、应用身份 | 固定角色色的浅彩卡面，彩色标题／图标与同色底部厚度 | 系统全景、消费者与服务人员知识辅助 |
| 能力、建设方向、交付事项 | 组内分类色的浅彩卡面，统一色彩强度；同组卡片保持同一视觉层级 | 背景方向、配套业务、智能协同、演示路线、未来规划、交付安排 |
| 单据、具体处理步骤、记录与核验依据 | 白色卡面与中性底部厚度；用标题／图标点缀主题色 | 首页工单、变化处理中的具体步骤、全过程留痕与防窜货核验的记录卡 |
| 阶段、变化类型 | 作为主要信息，整张卡片使用同一种浅彩色；具体处理步骤可作为独立白色小卡 | 服务主线六节点、变化类型、防窜货四节点 |
| 次要说明、记录分组 | 白色卡面，与主要浅彩卡片形成层级 | 服务主线下方说明、全过程留痕、四项核验依据 |
| 视觉、交互与通知 | 保留已恢复的白色外卡及内部示意配色，字号与间距遵循下方文字规则 | 亮点一三张卡片 |
| 状态 | 只着色小标签／图标，配明确状态文字；状态改变不染整张单据 | 首页待处理用金黄，处理中用蓝，通过／办结用青绿；工作台示意按恢复后的原样式 |
| 页面承载框、共用资料 | 中性卡面，内容层次由留白、细线与小卡厚度区分 | Web 外框、平台外框、商品知识库、配套材料 |

六角色跨页保持：总部灰蓝、客服蓝、服务站紫、门店珊瑚、消费者青绿、服务人员金黄。角色色用于识别参与者，不代表处理状态；能力分类色只用于当前有文字标明的分组，不建立跨业务的状态含义。首页当前处理角色可使用实色强调，平台售后拼块保留实色强调。

服务主线按阶段区分：产品准备灰蓝、申请建单青绿、资源调度紫、预约履约金黄、完工审核蓝、工单办结靛蓝。产品准备与申请建单采用不同浅彩色，明确前后阶段；下方“复用产品资料”的图标同步使用灰蓝，说明卡片保持白色。

浅彩卡面统一为主题浅色与中性表面按 65%／35% 混合，配同色细边框；正文与说明沿用统一的正文色和次要文字色。同一张卡片使用完整、单一的卡面，不使用一半彩色一半白色的分区样式。同页通过主要浅彩卡片与次要白色卡片建立层级，单据和具体记录保持白色。亮点一页面保留按用户要求恢复的配色与示意构成，文字与留白按统一规则优化。深色主题使用现有深色中性表面及对应浅色文字，保留相同的信息层级和厚度层级。颜色始终与文字、图标共同表达，不单独承担信息识别。

## 文字与占屏规则

保留中文系统字体和横向展示构图，以 1280×720 窗口的 1178×575 主内容区为基准。主画面沿用 `responsive-layout.js` 根据可用宽高取较小比例整体放大；字号与间距变量在具体页面中解析，继承主内容区的缩放单位，避免大屏卡片放大、文字仍停留在基准尺寸。1920×1080 下实际主内容缩放约为 1.504 倍，页面仍占满屏幕主要区域，顶部工具与页脚保留紧凑操作尺度。

| 文字角色 | 基准字号 | 字重与行高 |
| --- | --- | --- |
| 首页主标题 | 60 | 600 / 1.2 |
| 页面主标题 | 46 | 600 / 1.25 |
| 重点能力标题 | 30 | 600 / 1.4 |
| 普通卡片标题 | 26 | 600 / 1.4 |
| 流程节点、次级分组标题 | 22 | 600 / 1.4 |
| 正文、具体处理步骤 | 18 | 正文 400、步骤 500 / 1.5–1.6 |
| 次要说明、记录内容 | 16 | 400 / 1.5–1.6 |
| 章节、身份标签与辅助标识 | 14 | 400–500 / 1.5 |

字号随主内容同比放大；较小桌面调整主标题和重点标题档位，具体说明允许换行，不用隐藏或截断压缩信息。间距以 8、12、16、24 为主要档位，密集页面适当收紧卡内留白，保留足够的标题与正文距离。界面缩略图和 SVG 按自身几何比例使用独立小字号：通知示意标题 16、说明 12，并同步放大；平台拼图说明由 12 调整为 13。目录与讲解备注沿用统一字重，备注正文使用 16 / 1.75。

背景与建设方向页的三组短句对照采用居中轴线：插图、问题、箭头与建设方向居中对应，问题保留次要色与常规字重，建设方向保留主题色与加重；页面大标题保持左对齐。

十四页展示区使用固定画布，主内容区及页面采用 `overflow: clip`，入场动画的临时位移不会触发横向或纵向滚动条，也不会挤占内容宽高。正常内容通过布局与整体缩放完整呈现；目录与讲解备注保留各自面板内的滚动能力。

## 业务口径

平台页采用“补齐售后服务环节，让蓝鲸数字全链路延伸至产品使用与服务”。依据知识库《蓝鲸数字》《蓝鲸数字-仓库与能力导航》《蓝鲸数字-业务域、接口与数据归属索引》，将已有能力概括为生产仓储、渠道分销、门店销售、会员营销、防伪追溯五块，与蓝色售后拼块相互拼合。“最后一环”作为价值比喻有依据，但正式文案避免暗示全平台已全部打通或验收。拼图为能力关系示意，不是完整模块清单或严格流转顺序；跨系统集成与多客户适配保持实际边界，详细依据及限定放入讲解备注。

首页总部与门店位于流转区域外的上方，保留各自主题色与细线边框，以较小卡片与图标、轻字重保持辅助视觉层级；总部以无箭头虚线连接门店和服务站，表达授权范围内的基础资料维护关系，并提供规则／运营支撑。首页动画固定展示消费者自主申请、客服分站、服务站派人、人员预约履约、提交、审核与办结的简单主线，循环后仍从消费者开始。门店保留购买登记与代客申请的能力说明及总部管理连线，不参与本页工单动画。消费者可信商品申请进入服务工单及分站策略，预约服务对象为消费者。减少动态效果时展示六角色与消费者申请主线总览。

全稿按完整项目需求组织，不增加实现率或验收台账。商品档案知识分别支持消费者智能助手提供处理建议，以及服务人员查询解决方案和获取备件建议；未解决仍可申请服务，实际用料由人员确认。未来规划页区分已有预留与扩展建议：消费者品牌产品中心与商城接入为用户提出的方向，延保活动仍属预留，主动养护、会员运营与品质洞察为扩展建议；不据此新增正式需求、开发排期或交付承诺。智能审核发生于提交完工后，疑点转人工。

后台实时待办依据[客服与服务站 SSE 契约](../../../../specs/2026-10-07-客服与服务站待办SSE实时更新.md)；微信订阅依据当前两端小程序订阅消息设计稿（`specs/2026-10-07-两端小程序订阅消息设计.md`，该业务设计稿尚未提交，另行维护），保留用户授权与本单发送机会的边界。服务站派人后向对应服务人员发送新任务短信，按用户确认的完整方案展示；接入及送达状态以对应业务契约和运行证据为准。本 HTML 不连接业务接口或实际发送消息。真实演示按实际可用能力组织。
