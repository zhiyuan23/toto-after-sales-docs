# TOTO 售后服务｜后台菜单与角色权限手册

核对日期：2026-09-08 · 按当前已创建的后台菜单结构整理

[阅读指南](00-阅读指南.md) · [完整菜单树](#menu-tree) · [逐菜单权限表](#menu-matrix) · [按角色查功能](#role-functions) · [隐藏流程与全局能力](#other-entries)

后台共用 **“售后服务”一个顶部入口，下面是 10 个业务分组、49 个功能菜单**。总部、客服、服务站、代理商及门店人员按角色使用同一套后台；代理商／门店的日常入口集中为 **门店工作台、顾客登记、门店顾客、门店预约** 4 个菜单。

**菜单结构已创建；下面的角色分配是现有菜单设计中的建议使用范围，尚不是正式账号的实际授权清单。** 本地预览尚未按角色过滤菜单，正式菜单、操作和数据范围仍须通过 Gaia 权限体系配置并联调。服务结算虽保留在 49 项清单中，仍是范围待确认的隐藏入口。

本文覆盖售后后台及其关联的全局系统能力，不展开 Gaia 其他业务系统菜单。阅读顺序建议：先看下方角色说明，再看菜单树；需要判断具体菜单给谁用时看权限表，需要只看某一角色时看角色清单。

## 1. 角色怎样理解

| 表中简称 | 对应人员 | 数据范围与使用边界 |
| --- | --- | --- |
| 总部 | TOTO 业务管理员、总部管理／运营人员 | 授权区域或全部业务数据；具体维护、审核、发布动作按岗位再分配 |
| 客服 | 客服主管、客服专员 | 主管按授权队列／区域管理；专员处理本人或队列工单。菜单设计尚未逐项拆分两者的按钮权限 |
| 站点 | 服务站管理员 | 本服务站及授权资源；不是服务人员个人账号 |
| 门店 | 代理商管理员、门店店员 | 代理商管理员管理本代理商及下属授权门店；店员处理当前门店 |
| 系统 | 承担系统管理职责的 TOTO 超级管理员／系统管理员 | 承担全局配置、权限、审计与治理；本表列明设计中的业务菜单使用范围，不把管理员身份解释为默认拥有每项业务操作 |

服务人员主要使用服务人员小程序，消费者主要使用消费者小程序，不因存在“服务人员”“顾客档案”菜单就成为这些后台菜单的使用角色。审计／只读用户按单独授权查询数据，导出也须单独授权；当前设计没有其固定菜单包，因此不默认复制总部权限。

同一菜单分给多个角色，表示这些角色可能使用该功能，**不代表看到相同数据，也不代表都有新增、修改、删除、审核或导出权限**。

## 6. 分配权限时还要看什么

| 判断的问题 | 当前使用原则 |
| --- | --- |
| 有菜单就能新增、修改、删除吗？ | 不能。页面访问与按钮／接口权限分别配置，表中的 ● 仅表示建议菜单范围 |
| 同一个菜单能看到哪些数据？ | 总部按授权区域或全部；客服按本人／队列／区域；站点按本站；代理商按本代理商及下属授权门店；店员按当前门店 |
| 能查列表就能看完整手机、地址或导出吗？ | 不能。敏感字段展示与导出权限单独控制 |
| 谁可以派单、改派、取消恢复和审核？ | 菜单已列使用角色，具体动作分工与状态条件仍待相应业务 Spec 确认，不能由菜单表替代 |
| 超级管理员是否天然拥有所有业务操作？ | 角色需求具有全局治理职责；具体业务菜单、操作与审计范围以实际授权为准，本手册不补写“所有按钮默认开放” |
| 生产环境是否已按这张表开放？ | 尚无完成正式菜单和真实角色联调的证据；开发预览用于查看结构，不能用来验收角色权限 |
