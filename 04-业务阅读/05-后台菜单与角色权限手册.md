# TOTO 售后服务｜后台菜单与角色权限手册

版本：V3 四视角首页版 · 更新日期：2026-09-12

[阅读指南](00-阅读指南.md) · [当前菜单目录](#full-catalog) · [48 项功能分配基线](#visibility-matrix) · [工作视角与默认首页](#role-functions) · [操作权限](#permissions) · [多角色与数据范围](#data-scope) · [隐藏入口与全局能力](#additional-entries)

本手册统一维护最新后台菜单、可查看角色、岗位操作分工和多角色权限规则，是菜单与角色权限的唯一业务阅读入口。项目只有一个 Web 管理后台，采用 **一个“售后服务”顶部入口、四个岗位工作视角**；当前系统注册 48 个售后功能。

2026-09-12 四视角均以工作台作为首页，总首页直接呈现当前视角，管理员通过全局页头切换。当前源码注册 48 个功能，16 个展示分组包含 41 个去重侧栏注册，另有 1 个安装申请查询上下文功能和 6 个导航外功能；这些数字包含前次已合入的字典、总部会员运营与数据结算分组，不表示相关占位业务已开放或通过验收。首页改造与边界见[四视角首页工作台](../specs/2026-09-12-四视角首页工作台.md)。家装公司、服务项目和门店独立安装申请记录仍不在当前 Web 范围；安装码管理于本日按用户要求恢复至总部／客服“业务查询”组，复用真实查询切片，详见[恢复与标识关系核查](../specs/2026-09-12-安装码管理恢复与标识关系核查.md)。视角授权只决定其余功能怎样组织，页面与动作仍由功能权限、操作权限和数据范围共同决定。详见[本次收敛记录](../specs/2026-09-11-后台菜单与工作视角收敛.md)。

## 1. 角色标记

| 目录标记 | 对应角色 | 查看范围说明 |
| --- | --- | --- |
| 管理员 | 系统管理员／TOTO 超级管理员 | 可切换全部四个工作视角，并使用另行授权的全局系统入口；未完成能力不进入当前导航 |
| 总部 | TOTO 业务管理员、总部管理／运营人员 | 总部运营视角中的岗位菜单；查看授权区域或业务范围 |
| 客服主管 | 客服中心主管 | 客服作业视角；查看授权队列和区域 |
| 客服专员 | 客服中心专员 | 客服受理、跟进和必要查询；派单调度、完工审核不默认显示 |
| 站点 | 服务站管理员 | 服务站作业视角；查看本站与授权资源 |
| 代理商 | 代理商管理员 | 门店业务视角；查看本代理商及下属授权门店 |
| 店员 | 门店店员 | 门店业务视角；查看当前门店 |

“站点／代理商管理员”不属于上表“系统管理员”。审计／只读用户按单独授权使用相应目录子集，不默认获得全部菜单；消费者、服务人员继续使用小程序，不默认获得后台菜单。

| 角色／视角 | 当前导航口径 |
| --- | --- |
| 管理员 | 四个视角；共 41 个去重侧栏注册和 1 个上下文功能，业务内容仍须对应功能权限 |
| 总部运营 | 当前目录 28 个去重注册（29 处引用）；服务结算仅管理员待启用查看，其余按真实功能授权收窄 |
| 客服主管 | 最多 13 个侧栏功能，另有 1 个安装申请查询上下文入口 |
| 客服专员 | 默认不授派单调度、完工审核，可在客服视角按实际功能授权收窄 |
| 服务站作业 | 16 个侧栏功能，另有 1 个安装申请查询上下文入口；不提供完工审核 |
| 代理商／店员 | 3 个侧栏功能；可在顾客购买记录内申请安装，不提供独立预约管理 |

以上是视角目录上限，不是当前生产账号授权验收结果。实际账号按功能权限继续收窄；空分组不展示。普通业务账号不显示管理员专属视角切换器，浏览器直达上下文入口仍须同时通过功能与数据权限校验。

相同功能出现在不同视角或不同分组时，只引用同一个功能 code、路由和页面。例如“服务工单”在总部的“业务查询”、客服的“工单处理”和服务站的“本站工单”中各有一个展示位置，但系统只注册一个 `afsWorkOrder`。是否可见由视角权限与功能权限共同决定，可执行动作和可见数据再由操作权限与后端数据范围决定；不会为不同分组复制第二套功能入口。

### 查看与操作的区别

| 例子 | 菜单查看 | 操作权限 |
| --- | --- | --- |
| 管理员查看完工审核 | 可查看，无需兼任客服或站点角色 | 审核、退回等动作仍按业务授权及规则执行 |
| 总部查看服务工单 | 可查看授权范围工单 | 不自动取得派单、取消、恢复、审核等权限 |
| 客服主管查看完工审核 | 可查看授权范围的审核列表和记录 | 执行审核仍需审核动作授权 |
| 客服专员查看商品档案 | 可查询办理所需资料 | 不自动取得主档新增、修改、删除权限 |
| 代理商、店员登记时选择商品 | 从登记表单查看必要商品选项 | 不因选择商品而获得商品档案菜单 |
| 管理员检查未完成能力 | 不进入日常导航，可按开发或验收路径核对 | 范围未定版，不开放业务办理 |

## 4. 隐藏流程、合并入口和全局系统能力

### 4.1 业务上下文入口（4 项）

| 入口 | 编号 | 可查看角色／参与者 | 进入方式 |
| --- | --- | --- | --- |
| 授权门店上下文 | D01 | 管理员、代理商、店员 | 门店视角页头选择与切换；管理员可查看，办理前仍要确定有效门店 |
| 扫码或店员填写 | D05 | 管理员、代理商、店员；顾客通过有效扫码会话参与 | 购买登记中的流程页；需要有效的登记对象或会话 |
| 隐私条款与签名 | D06 | 管理员、代理商、店员；实际签署人通过有效流程参与 | 购买登记中的授权流程；查看不表示可代签 |
| 安装申请查询 | A16 | 管理员、客服主管、客服专员、站点 | 从服务工单或关联记录进入；保留历史直达兼容，不在侧栏重复展示 |

隐藏入口不是侧栏菜单，管理员全菜单查看也不取消流程对象和会话校验。表中“进入方式”为目标业务方式：当前 D01 门店选择及切换、D05／D06 的真实流程会话仍待对应业务切片接入。

## 8. 多角色与数据范围：避免权限串用

以下为业务切片必须遵守的权限规则；导航代码已落地不代表组织切换、业务动作与范围校验已全部实现。

1. **角色授权与岗位视角分开。** 角色决定允许哪些动作及对象范围；工作视角决定怎样组织这些已授权入口。隐藏菜单不能替代权限校验，切换视角也不能授予新权限。
2. **每项授权保留动作与范围的对应关系。** 一个人是总部只读用户、同时是某门店店员，不得把“总部能读所有门店”和“店员能编辑当前门店”拼成“可编辑所有门店”。后端应判断同一有效授权是否同时允许该动作和该对象，并应用租户隔离及当前组织约束。
3. **当前岗位与组织要明确。** 管理员页头显示当前工作视角；门店、服务站或授权区域仍由业务上下文单独确定。购买登记必须确定一个授权门店后才能写入；代理商跨门店汇总查询与单门店办理分开。每张单据的门店、站点归属由服务端校验，不能直接信任前端传值。
4. **切换时刷新上下文。** 先处理未保存内容，再重新验证视角与组织授权；清除旧范围的列表、选择项和缓存，取消或丢弃旧请求结果，刷新按钮与数据。多个标签页必须各自绑定并校验上下文，不能把旧门店的编辑单据提交到新门店。
5. **同一页面保留一个身份。** 服务工单、库存台账等跨视角复用原功能 code、页面与领域接口。工作视角切换只改变导航位置，不扩大既有授权；业务组织切换时另行核对有效范围；查询条件、页面缓存须包含上下文，浏览器直达和刷新也要重验权限。
6. **普通业务角色进入岗位视角，管理员切换全部视角。** 总部业务人员可以通过授权查询看服务结果；需要实际派单、审核时按相应功能与操作权限另授。系统管理员无需兼任业务岗位即可切换四个视角，但仍不因视角可选自动取得全部业务功能或日常操作权限。
7. **操作仍受业务条件约束。** 同时具备提交与审核权限的账号也不能绕过业务规定的职责分离；可审核范围、退回和取消恢复规则由对应业务 Spec 定义，不由本菜单设计新增流程。

实现时要核对 Gaia 现有的角色、组织与租户机制对“动作与范围绑定”的支持方式；不假设新增一个前端角色切换控件就已经满足以上要求。

| 客服主管 | 在授权队列／区域调度；未取得审核岗位授权时，主管身份不自动允许完工审核 |
| 服务站管理员 | 从本站工作台处理工单、人员和配件，不显示完工审核；直接访问其他站点单据时被拒绝，跨站调拨或改派按独立规则校验 |
| 总部运营人员 | 能在授权范围查询分析、维护职责内资料；没有客服或站点作业授权时不能实际派单、审核 |
| 总部只读＋某门店店员的兼任账号 | 可以按总部范围读、仅按门店授权写；两个角色的范围与动作不发生交叉放大 |
| 管理员切换视角、多标签页和切换组织 | 页头只列四个业务视角，无第五套混合菜单；选择后进入该视角工作台；未保存确认取消后保留原页面。组织切换独立校验，旧请求不覆盖新组织数据 |
| 审计／系统管理员 | 管理员可切换四个售后工作视角；业务功能和全局系统入口仍分别授权。审计只读且导出单独控制 |
| 刷新、直达 URL 与权限撤销 | 有效授权才能恢复页面；撤销角色／组织后不可继续操作旧页面或缓存数据 |
| 隐藏能力与完整性 | 6 个当前导航外功能及已引用的待验收占位入口均不据此宣称开放；3 个已删除功能无注册、路由和页面；48 个注册功能及 63 个历史 Web 编号可追溯 |
