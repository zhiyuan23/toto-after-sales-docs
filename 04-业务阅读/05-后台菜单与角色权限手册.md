# TOTO 售后服务｜后台菜单与角色权限手册

版本：V2 统一版 · 更新日期：2026-09-08

[阅读指南](00-阅读指南.md) · [完整菜单目录](#full-catalog) · [49 项角色总表](#visibility-matrix) · [工作视角与默认首页](#role-functions) · [操作权限](#permissions) · [多角色与数据范围](#data-scope) · [隐藏入口与全局能力](#additional-entries)

本手册统一维护最新后台菜单、可查看角色、岗位操作分工和多角色权限规则，是菜单与角色权限的唯一业务阅读入口。采用 **一个“售后服务”顶部入口、四个岗位工作视角、49 个共享功能**，管理员可查看全部菜单，无需兼任业务岗位。

前端已实现四视角导航，正式租户分发与账号授权仍待联调，详见[实施记录](../specs/2026-09-08-多角色菜单V2实施.md)。管理员全菜单查看是已确认规则；其他角色按现有岗位分工维护默认目录和操作建议。查看不自动授予修改、删除、审批、库存调整、导出或跨租户读取数据的权限，待确认业务规则仍由各切片定版。

## 1. 角色标记

| 目录标记 | 对应角色 | 查看范围说明 |
| --- | --- | --- |
| 管理员 | 系统管理员／TOTO 超级管理员 | 全部菜单，包含全部工作视角和全局系统入口 |
| 总部 | TOTO 业务管理员、总部管理／运营人员 | 总部运营视角中的岗位菜单；查看授权区域或业务范围 |
| 客服主管 | 客服中心主管 | 客服作业视角；查看授权队列和区域 |
| 客服专员 | 客服中心专员 | 客服受理、跟进和必要查询；派单调度、完工审核不默认显示 |
| 站点 | 服务站管理员 | 服务站作业视角；查看本站与授权资源 |
| 代理商 | 代理商管理员 | 门店业务视角；查看本代理商及下属授权门店 |
| 店员 | 门店店员 | 门店业务视角；查看当前门店 |

“站点／代理商管理员”不属于上表“管理员”的全菜单角色。审计／只读用户按单独授权使用相应目录子集，不默认获得全部菜单；消费者、服务人员继续使用小程序，不默认获得后台菜单。

| 角色 | 默认可查看的售后功能数量（去重） |
| --- | --- |
| 管理员 | **49 项全部可见**；其中服务结算标注待启用 |
| 总部 | 34 项；另有服务结算 1 项规划占位，待启用后按岗位开放 |
| 客服主管 | 17 项 |
| 客服专员 | 15 项；派单调度、完工审核如需只读查看再单独授权 |
| 站点 | 19 项 |
| 代理商 | 4 项 |
| 店员 | 4 项 |

以上数量是规划的角色目录，不是当前生产账号授权验收结果。除管理员外，实际账号还可按具体岗位收窄可见项。管理员默认可进入全部视角；普通多角色用户切换自己获授权的视角。空分组不展示。

### 查看与操作的区别

| 例子 | 菜单查看 | 操作权限 |
| --- | --- | --- |
| 管理员查看完工审核 | 可查看，无需兼任客服或站点角色 | 审核、退回等动作仍按业务授权及规则执行 |
| 总部查看工单管理 | 可查看授权范围工单 | 不自动取得派单、取消、恢复、审核等权限 |
| 客服主管、站点查看完工审核 | 可查看相应范围的审核列表和记录 | 执行审核仍需审核动作授权 |
| 客服专员查看商品档案／服务项目 | 可查询办理所需资料 | 不自动取得主档新增、修改、删除权限 |
| 代理商、店员登记时选择商品 | 从登记表单查看必要商品选项 | 不因选择商品而获得商品档案菜单 |
| 管理员查看服务结算 | 菜单可见，标注待启用 | 范围未定版，不开放费用结算办理 |

## 4. 隐藏流程、合并入口和全局系统能力

### 4.1 隐藏／上下文入口（3 项）

| 入口 | 编号 | 可查看角色／参与者 | 进入方式 |
| --- | --- | --- | --- |
| 授权门店上下文 | D01 | 管理员、代理商、店员 | 门店视角页头选择与切换；管理员可查看，办理前仍要确定有效门店 |
| 扫码或店员填写 | D05 | 管理员、代理商、店员；顾客通过有效扫码会话参与 | 顾客登记中的流程页；需要有效的登记对象或会话 |
| 隐私条款与签名 | D06 | 管理员、代理商、店员；实际签署人通过有效流程参与 | 顾客登记中的授权流程；查看不表示可代签 |

隐藏入口不是侧栏菜单，管理员全菜单查看也不取消流程对象和会话校验。表中“进入方式”为目标业务方式：当前 D01 门店选择及切换、D05／D06 的真实流程会话仍待对应业务切片接入。

### 4.2 已合并入口（2 项）

| 原入口 | 编号 | 所在菜单 | 可查看角色 |
| --- | --- | --- | --- |
| 商品图片 | A11 | 商品档案 | 管理员、总部、客服主管、客服专员 |
| 推送结果 | A43 | 消息推送 | 管理员、总部 |

### 4.3 蓝鲸数字全局系统入口（4 类）

| 入口 | 承接编号 | 管理员 | 其他角色的查看安排 |
| --- | --- | :---: | --- |
| 角色与权限 | A46、A47 | ● | 默认不开放；确有角色治理职责时单独授权 |
| 用户管理 | A48、A49、A50 | ● | 代理商管理员的组织内用户管理按委派授权开放；其他业务角色不默认开放全局用户入口 |
| 业务配置 | A51 | ● | 特定业务参数维护岗位另授对应入口／配置项 |
| 日志审计 | A52、A53 | ● | 审计／只读用户按授权查看；导出单独授权 |

这 4 类继续复用蓝鲸数字现有全局能力，页头快捷入口待核对全局路径后接入，不在售后重复建立一套系统管理。管理员全部可查看，但本目录不虚构尚未核对的全局菜单路径。

| 总部运营 | 管理员、总部业务岗位 | 运营概览 | 运营分析、渠道与服务网络、商品与服务、顾客与服务、防窜货、配件管理、会员运营、数据与结算 |
| 客服作业 | 管理员、客服主管、客服专员 | 服务受理 | 服务办理、顾客查询、资料参考、服务分析 |
| 服务站作业 | 管理员、服务站管理员 | 服务站工作台 | 本站服务、人员安排、配件管理、资料参考、服务分析 |
| 门店业务 | 管理员、代理商管理员、门店店员 | 门店工作台 | 门店服务：门店工作台、顾客登记、门店顾客、门店预约 |

每个角色的完整可查看功能见第 3 节对应列，操作分工见第 7 节。代理商管理员与店员共用菜单，分别受授权下属门店集合和当前门店限制；不复制登记、预约页面。

单视角用户直接进入其视角；多视角恢复本账号上次仍有效的视角，首次按总部→客服→服务站→门店顺序选择第一个有效视角。管理员默认进入总部运营，可切换全部四个视角。默认首页无权时进入该视角第一个授权功能，无可用功能时隐藏整个视角。浏览器直达功能链接时恢复适用的授权视角；切换视角不会增加权限。

选择岗位视角的原因是让门店登记与预约集中、客服和服务站各自沿工作顺序处理业务，同时保持同一工单、商品或库存功能只实现一次。原 10 个业务域继续用于代码目录和唯一功能注册，不再直接决定用户侧栏；旧菜单 code/path 对应关系保留在[技术菜单设计](../02-技术设计/03-gaia-ui目录与菜单设计.md)。

当前页头选择器仅切换导航，不改变后端身份或组织。切换前提示未保存内容，页面重新挂载。门店／服务站／授权区域上下文、全局快捷入口和待办数量尚待相关切片实施，不能将导航切换视为完整业务上下文已接入。

## 8. 多角色与数据范围：避免权限串用

以下为业务切片必须遵守的权限规则；导航代码已落地不代表组织切换、业务动作与范围校验已全部实现。

1. **角色授权与岗位视角分开。** 角色决定允许哪些动作及对象范围；工作视角决定怎样组织这些已授权入口。隐藏菜单不能替代权限校验，切换视角也不能授予新权限。
2. **每项授权保留动作与范围的对应关系。** 一个人是总部只读用户、同时是某门店店员，不得把“总部能读所有门店”和“店员能编辑当前门店”拼成“可编辑所有门店”。后端应判断同一有效授权是否同时允许该动作和该对象，并应用租户隔离及当前组织约束。
3. **当前岗位与组织要明确。** 页头显示“工作视角＋当前门店／服务站／授权区域”。门店登记必须确定一个授权门店后才能写入；代理商跨门店汇总查询与单门店办理分开。每张单据的门店、站点归属由服务端校验，不能直接信任前端传值。
4. **切换时刷新上下文。** 先处理未保存内容，再重新验证视角与组织授权；清除旧范围的列表、选择项和缓存，取消或丢弃旧请求结果，刷新按钮与数据。多个标签页必须各自绑定并校验上下文，不能把旧门店的编辑单据提交到新门店。
5. **同一页面保留一个身份。** 工单管理、库存台账等跨视角复用原功能 code、页面与领域接口。工作视角切换只改变导航位置，不扩大既有授权；业务组织切换时另行核对有效范围；查询条件、页面缓存须包含上下文，浏览器直达和刷新也要重验权限。
6. **普通业务角色按职责跨视角，管理员可查看全部视角。** 总部业务人员可以通过授权查询看服务结果；需要实际派单、审核时取得客服或站点作业权限。系统管理员无需兼任业务岗位即可查看全部菜单，但仍不因菜单可见自动取得全部日常操作权限。
7. **操作仍受业务条件约束。** 同时具备提交与审核权限的账号也不能绕过业务规定的职责分离；可审核范围、退回和取消恢复规则由对应业务 Spec 定义，不由本菜单设计新增流程。

实现时要核对 Gaia 现有的角色、组织与租户机制对“动作与范围绑定”的支持方式；不假设新增一个前端角色切换控件就已经满足以上要求。

## 9. 数量与版本口径

- **49 个独立售后功能**：管理员全部可查看；同一功能出现在多个工作视角时只算一次。
- **4 个工作视角、18 个展示分组、75 处岗位导航引用**：总部 35、客服 17、服务站 19、门店 4。客服视角中的部分功能不默认给专员，服务结算对总部业务角色仍待启用；引用数量不等于每个角色实际可见数量。
- **63 个 Web 需求入口**：49 个功能菜单承载 52 个入口编号（顾客登记合并 D03／D04、商品档案合并 A09／A11、消息推送合并 A42／A43），再加 3 个隐藏／上下文入口和 8 个全局系统能力入口。
- 119 个功能需求编号、96 个四端入口的总体需求分母不变；本次归并文档，未增加业务需求或业务完成数。

## 10. 权限与使用场景验收

以下是后续真实账号和业务切片的验收要求，不是本次文档归并的完成声明。

| 验收角色／场景 | 必须达到的结果 |

| 客服主管 | 在授权队列／区域调度；未取得审核岗位授权时，主管身份不自动允许完工审核 |
| 服务站管理员 | 从本站工作台一路处理工单、人员和配件；直接访问其他站点单据时被拒绝，跨站调拨或改派按独立规则校验 |
| 总部运营人员 | 能在授权范围查询分析、维护职责内资料；没有客服或站点作业授权时不能实际派单、审核 |
| 总部只读＋某门店店员的兼任账号 | 可以按总部范围读、仅按门店授权写；两个角色的范围与动作不发生交叉放大 |
| 多视角、多标签页和切换组织 | 无重复菜单及路由；未保存内容有处理提示；旧请求不覆盖新组织数据，旧标签页不能在错误上下文中提交 |
| 审计／系统管理员 | 管理员可查看全部 49 个售后菜单和全部全局系统入口，不要求兼任业务角色；操作与数据范围仍分别验证。审计只读且导出单独控制 |
| 刷新、直达 URL 与权限撤销 | 有效授权才能恢复页面；撤销角色／组织后不可继续操作旧页面或缓存数据 |
| 隐藏能力与完整性 | 服务结算对管理员显示待启用，对业务角色保持隐藏，不开放办理；49 项功能、63 个 Web 入口可追溯，无遗漏、重复授权身份或新增业务范围 |
