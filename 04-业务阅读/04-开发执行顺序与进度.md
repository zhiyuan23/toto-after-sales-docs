## 现在应从哪里开始

**业务开发从“权限与账号”开始，再做“主数据”，然后建立“客户、产品和工单”，最后贯通派单、履约、审核回访及运营管理。**

当前已有工程和页面基础，但真实业务功能尚未验收完成。下一步应把 Web 权威动态菜单与权限配置接起来，完成角色、系统用户和数据范围基础；随后进入代理商、门店、服务站、商品等主数据开发。

| 当前成果 | 已有进度 | 还缺什么 |
| --- | --- | --- |
| 需求和工程基础 | 已有需求基线、页面规划、任务依赖和售后后端三模块骨架 | 真实业务接口、数据、运行宿主接入及局部业务规则确认 |
| 管理后台、代理商工作台 | 页面架构及本地开发菜单预览已具备；正式入口 **0 / 63** | 权威动态菜单、真实角色权限和业务接口 |
| 消费者小程序 | 入口 **17 / 17**，已有页面和样式优化；业务功能 **0 / 17** | 微信真实身份、产品登记、预约等业务接入 |

页面能打开、工程能构建，只代表有了开发基础。下面的进度指业务功能；每一步可能跨多个端，不另行计算一套完成率。

## 外部能力在什么时候穿插

这些能力当前缺少完整真实业务联调证据，应在首次使用前核对契约和环境，不能统一等到最后才接。

| 外部能力 | 最早需要它的步骤 | 支撑哪些业务 |
| --- | --- | --- |
| DWH | 第 2 步前明确主数据责任，第 3 步前联调登记所需数据 | 代理商/门店、销售、出库；第 8 步复用于防窜货 |
| 微信身份 | 第 1 步，第 3 步扫码填写和自主登记的前置 | 登录、手机号和身份关联、二维码场景 |
| 短信 | 第 3 步手机验证前 | 验证码；后续补预约、派单、回访通知及回执 |
| 追溯与 RFID / QR | 第 3 步产品登记前，第 6 步补现场回传联调 | 码校验、绑定、扫码、流向和防窜货 |
| 地图 | 第 2 步区域方案时准备，第 5 步分配前联调适用能力 | 地址、经纬度、区域匹配、签到和距离 |
| 对象存储 | 最早的图片、签名或导入导出功能之前 | 登记凭证、故障媒体、完工资料和文件访问 |
| 现有客服渠道 | 第 4 步受理前结合调研明确 | 电话/微信来源、会话或人工代客建单衔接 |

服务入口类型、派单责任、完工标准等在相关步骤实施前确认；历史迁移范围提前盘点。详细问题继续维护在[风险与待确认事项](../03-开发管理/02-风险与待确认事项.md)。
