# TOTO 售后服务技术架构与技术栈

## 当前技术基线

| 层 | 技术或机制 | 当前结论 |
| --- | --- | --- |
| Web 管理端 | `gaia-ui`：Vue 3、Vite、后端动态菜单、按钮权限 | 统一管理后台与代理商工作台共用“TOTO 售后服务”顶部菜单；页面进入 `src/views/afterSales` |
| 售后后端 | Java 21、Maven 3.9.x、Gaia 父 POM `3.5.0-SNAPSHOT`、Spring Boot 3.5.3 | 根制品 `com.ehsure.gaia:gaia-after-sales:3.0-SNAPSHOT` |
| 运行宿主 | `gaia-saas-proj` 多业务聚合 | 售后模块不单独启动；首个接口后接入宿主 |
| 原售后小程序 | UniApp `3.0.0-5020420260813003`、Vue `3.4.21`、Vite `5.2.8`、TypeScript `5.9.3` | 主交付微信小程序，兼容 H5 |
| 小程序状态与 UI | Pinia `2.2.4`、TDesign UniApp `0.10.3`、UnoCSS `66.7.5` | 已形成通用 UI 基线，不等于业务功能 |
| 小程序工具链 | Node `24.19.x`、pnpm `10.34.5`、ESLint、Stylelint、vue-tsc、Node tests | `pnpm verify` 覆盖检查及微信/H5 构建 |
| 客服助手 | `gaia-customer-service-uni` | 仓库尚未创建，不能默认继承原售后小程序技术结论 |

小程序的 DCloud/Vue/Vite 版本存在兼容关系，不应单独追随最新版本；升级时必须同步兼容包组和锁文件并运行完整验证。当前依赖审计历史结果为 0 critical、17 high、24 moderate、9 low，未通过且没有风险豁免；构建通过不能替代安全审计。

消费者端的主包、业务分包、Tab 和 C01～C17 路由以[小程序目录与页面路由设计](../02-技术设计/04-小程序目录与页面路由设计.md)为准。服务人员部分目前只作为逻辑目录，不能据此认定其已归属 `gaia-customer-service-uni`。

## 后端模块和职责

```text
gaia-after-sales
├── gaia-after-sales-core      # 领域模型、数据访问、业务规则
├── gaia-after-sales-api       # 管理后台接口
└── gaia-after-sales-xcx-api   # 小程序接口
```

三个模块目前都是普通 JAR，没有启动类。Java 包根为 `com.ehsure.gaia.aftersales`，业务类前缀为 `AfterSales`，数据库表前缀为 `afs_`。当前只有工程骨架，尚无业务实体、数据库迁移、接口或业务测试。

首个真实接口的装配顺序：

1. 在 `gaia-after-sales` 完成领域逻辑和对应 API，执行必要 Maven 验证并按团队流程本地 install 或发布制品。
2. 在 `gaia-saas-proj` 根 POM 增加版本/依赖管理，在运行模块聚合需要的 `api` 或 `xcx-api`。
3. 验证 `com.ehsure` 包扫描、接口路径、权限拦截、租户上下文、配置和健康检查。
4. 再由 `gaia-ui` 或小程序调用真实接口，完成权限、异常和端到端验收。

仅重启宿主不会自动使用未安装的新业务源码制品。

## 请求、会话、租户与权限

| 主题 | 已知机制 | 当前必须确认的内容 |
| --- | --- | --- |
| Web 请求 | 统一进入 `/api/**` | 总部、客服、服务站、代理商/门店共用 Web 请求体系；仍需确认售后接口命名空间和数据范围 |
| 小程序请求 | 统一进入 `/wxapi/**`，请求携带 `thirdSessionKey` | 消费者、服务人员、客服分别使用什么身份和登录方案 |
| 会话失效 | 现有业务码 `50040` 触发重新登录 | 售后是否完全沿用，及各应用的失效交互 |
| 租户 | `x-tenant`、域名识别和动态数据源机制 | TOTO 各端如何传递租户、测试数据源位置 |
| 菜单 | `gaia-ui` 从 `/api/sys/Module/tree` 获取动态菜单 | 顶部菜单、分组、名称、代码和目录见[菜单设计](../02-技术设计/03-gaia-ui目录与菜单设计.md)；初始化、租户同步和角色授权仍需实施 |
| 权限 | 按钮权限加后端 HTTP 方法/路径权限检查 | 角色矩阵、按钮编码、接口权限和数据权限 |
| 数据库 | 租户数据源，售后表前缀 `afs_` | DDL 发布/回滚、索引、并发与幂等规则 |
| 文件与缓存 | 复用现有对象存储、Redis 和安全组件 | 附件规格、会话键、锁和缓存是否需要 |

前端隐藏按钮不能替代后端授权；菜单、按钮、接口和数据范围必须作为同一切片验收。

## 现有 TOTO 数据基础

- `gaia-dms` 已有 TOTO 销售出库导入逻辑。
- `gaia-fulllink` 已有出库、订单/参考单、项目、产品、颜色、RFID/制造编号和扫描时间等追溯信息。
- `gaia-dms-uni` 已存在 TOTO 相关租户配置。

这些事实只表示应优先联调，不证明接口契约满足售后需求。进入顾客产品、安装码和防窜货切片前，必须确认每个字段的权威来源、接口负责人、可用环境和业务快照规则。

## 开发与验证入口

### 后端

```bash
cd backend/gaia-after-sales
mvn -B verify
git diff --check
```

父 POM 属于内部制品，开发机需要可用的 Maven 本地缓存或私服配置；个人 `settings.xml` 和凭据不得进入仓库或文档。

### 原售后小程序

```bash
cd mobile/gaia-after-sales-uni
pnpm tenant:check TOTO
pnpm verify
pnpm run audit
```

`pnpm verify` 包含类型、lint、测试、租户总览检查及微信/H5 正式构建；微信开发者工具、真机、真实接口、上传和发布要分别记录。上传、提审、发布都不是普通验证的一部分。

跨仓启动、环境和联调细节见[本地开发与联调](../local-development.md)，单切片的数据、接口和验收契约见 [`specs/`](../specs/)。
