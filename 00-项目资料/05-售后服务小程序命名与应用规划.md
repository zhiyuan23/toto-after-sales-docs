# 蓝鲸数字售后服务小程序命名与应用规划

## 1. 规划定位

售后服务是蓝鲸数字平台内的业务模块，TOTO 是当前承载的品牌业务，通用产品命名应能继续用于其他品牌。

移动端按使用者及工作职责规划为六类：消费者申请服务，渠道协助办理，客服受理跟进，服务站组织调度，服务人员现场履约，总部统筹运营。六类产品定位不等于六个应用已经开发，也不预先决定 AppID、代码仓库、部署方式或一人多身份的切换机制。

本次范围是保存命名、简要介绍、业务边界和推进方向，不执行源码、微信后台或现有应用名称变更。现有需求、权限、数据范围、状态机和验收口径继续有效。

## 2. 六端名称与简要介绍

| 规划产品名称 | 文档简称 | 面向用户 | 简要介绍 |
| --- | --- | --- | --- |
| **蓝鲸数字产品服务** | 消费者端／产品服务端 | 消费者、产品使用者 | 管理本人产品，办理产品注册、安装预约和维修申请，查询服务进度与历史记录，进行评价和反馈。 |
| **蓝鲸数字渠道服务助手** | 渠道端 | 经销商、代理商、门店店员 | 办理顾客及购买登记，帮助客户发起安装、维修等服务申请，查询授权范围内的服务进度。 |
| **蓝鲸数字现场服务助手** | 服务人员端／现场服务端 | 安装、维修、上门指导等服务人员 | 查看本人任务和日程，联系客户，执行现场服务，记录作业过程、配件使用及完工情况。 |
| **蓝鲸数字服务站助手** | 服务站端 | 服务站负责人、调度及管理人员 | 管理本站工单，安排人员和排班，办理配件领退审批与库存作业，协调服务异常。 |
| **蓝鲸数字客服工作助手** | 客服端 | 客服专员、客服主管 | 受理客户诉求、代客建单、分配服务站，跟进工单、协调异常并开展回访。 |
| **蓝鲸数字总部运营助手** | 总部端 | 品牌总部管理、运营人员 | 查看授权范围内的服务概览、业务数据、质量及关键异常，统筹服务运营与资源；具体移动办理范围待细化。 |

以上为大模块定位，不能据此推断具体页面、接口或操作权限已开放。现有业务依据见[角色权限与总体架构](../01-功能需求/02-角色权限与总体架构.md)、[代理商与门店需求](../01-功能需求/05-代理商工作台需求.md)、[消费者需求](../01-功能需求/06-消费者小程序需求.md)和[服务人员需求](../01-功能需求/07-服务人员小程序需求.md)。

## 3. 命名与品牌展示规则

- 平台产品全称采用“蓝鲸数字＋业务定位”，工作人员端使用“助手”后缀；消费者端直接使用“产品服务”。
- 品牌作为应用内业务上下文展示，例如“TOTO · 产品服务”“TOTO · 现场服务”，其他品牌沿用相同产品定位。这里约定的是展示方向，不代表多品牌身份、数据或切换机制已实现。
- 经销商与门店共用“渠道服务助手”这一产品定位；应用内部按授权显示经销商工作台、门店工作台及各自数据范围，不按名称自动扩大权限。
- “消费者端”“服务人员端”等职责简称继续用于需求、进度和验收文档；产品名称与职责简称建立映射，不批量替换已有编号和历史证据。
- 现有服务人员应用名“TOTO客服助手”规划对应“蓝鲸数字现场服务助手”。后续“客服工作助手”面向客服专员和主管，避免将现场履约人员与客服人员混称。

## 4. 与其他业务及角色的边界

### 4.1 渠道服务与渠道经营

渠道服务端聚焦顾客／购买登记、代客服务申请及进度查询，**不包含销售下单、订货和销售库存业务**。购买登记记录已发生的购买，不等同于创建销售订单；代客建单指服务申请或服务工单，具体受理路径仍按已有契约。

蓝鲸数字原有经销商端、门店／终端端承担的渠道关系、收发货、库存、核销、返利等能力，属于渠道／终端经营。本规划不合并或更名这些现有应用，也不默认共享其门店主档；售后业务数据边界继续遵循[独立业务数据契约](../specs/2026-09-11-业务数据独立边界与已开发功能核查.md)。

### 4.2 产品服务与会员权益

原会员小程序在本次讨论中的通用命名方案为“蓝鲸数字会员权益”，定位消费者营销，主要包括活动、扫码奖励、积分、奖券和兑换。它不计入本规划的六个售后服务端，其现有名称和代码不在本次变更范围。

“蓝鲸数字产品服务”定位产品注册和安装维修等服务。同一个人可以同时参与会员活动和办理产品服务；产品定位的划分不自动建立或合并会员身份、账号及数据。

### 4.3 客服、服务站与现场人员

客服负责受理与跟进、按授权分配服务站；服务站负责本站组织与人员调度；现场人员负责本人任务履约。既有审核责任和允许／拒绝规则仍以[岗位权限矩阵](../02-技术设计/09-后台菜单与岗位权限矩阵.md)及对应 Spec 为准，应用名称不授予额外审批或调度能力。

渠道端不含销售库存，不影响服务站、服务人员已有的配件库存与领退料业务。

### 4.4 总部运营与岗位作业

总部移动端定位服务概览与运营统筹，具体首版功能根据总部的移动使用场景选择；不因名称自动开放全部品牌或组织的数据，也不默认获得客服分站、服务站派人或完工审核权限。权限与数据范围沿用岗位契约，管理配置和详细业务办理按实际场景确认，不将整个 Web 后台直接复制到移动端。

## 5. 现有应用与规划对应关系

| 规划端 | 当前载体或代码映射 | 规划动作及状态 |
| --- | --- | --- |
| 产品服务端 | 已有消费者小程序／H5，`gaia-after-sales-uni` | 保留现有工程，记录通用产品名称；实际更名和多品牌接入另行实施。 |
| 现场服务端 | 已有服务人员小程序／H5，`gaia-customer-service-uni`，现名“TOTO客服助手” | 保留现有工程，规划调整产品名称；仓库名、AppID 与发布配置本次不变。 |
| 渠道端 | 当前通过同一 Web 后台的门店业务视角办理代理商／门店业务 | 新增移动入口的规划；详细范围、身份、页面、仓库与 AppID 待确认。 |
| 服务站端 | 当前通过同一 Web 后台的服务站作业视角办理 | 后续移动端规划；详细范围和实施条件待确认。 |
| 客服端 | 当前通过同一 Web 后台的客服作业视角办理 | 后续移动端规划；详细范围和实施条件待确认。 |
| 总部端 | 当前通过同一 Web 后台的总部运营视角办理 | 新增总部移动入口规划；通用产品名为“蓝鲸数字总部运营助手”，首版功能、身份、数据范围及实施条件待确认。 |

当前项目继续按 **Web 管理后台、消费者小程序、服务人员小程序三个应用载体**维护进度。已有两个小程序不因通用名称规划而另计应用；渠道、服务站、客服、总部规划端不加入当前入口或验收分母。

具体实现及验收状态仍只在[开发进度总览](../03-开发管理/00-开发进度与下一步.md)及其应用明细维护；当前工程关系见[仓库与系统关系](02-仓库与系统关系.md)。

## 6. 后续推进方向

以下为规划步骤，不承诺开发先后、工期或新增功能上线：

| 步骤 | 需要完成的工作 | 完成条件 |
| --- | --- | --- |
| 命名落地 | 核对已有消费者、服务人员端的产品名称、应用内品牌展示、微信名称及发布配置 | 明确实施范围，形成一致的名称映射并完成对应验证；历史证据保留原名。 |
| 多品牌接入 | 明确品牌与租户、账号、组织归属、授权及数据范围的关系 | 有可执行的接入契约，跨品牌业务和数据边界清晰；不凭名称复用数据或扩大授权。 |
| 渠道移动入口 | 从现有代理商／门店需求确定首版登记、代客申请和查询范围 | 明确用户身份、门店上下文、页面与接口契约、允许／拒绝及重复提交验证标准。 |
| 总部、服务站与客服入口 | 根据实际移动工作场景选择首版功能，确认是否分别建应用及其工程边界 | 各端职责、权限、数据范围、实施优先级和验收标准明确。 |

涉及实际更名、新增端或多品牌功能时，按[团队文档协作规范](../03-开发管理/08-团队文档协作与提交同步规范.md)细化对应需求与 Spec，再同步页面清单、架构和应用进度。本文件保留产品定位和命名，具体功能状态不在此重复维护。
