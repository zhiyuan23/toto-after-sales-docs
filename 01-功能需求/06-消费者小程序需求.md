# TOTO售后服务消费者小程序需求

2026-09-29 已确认两端首次主动登录后保持会话，并在普通到期时微信静默续登；无本地会话／清空缓存后重新进入也先用新的微信 code 识别已有登录，恢复成功后获取身份信息，未登录才显示登录入口；主动退出、账号停用和会话撤销停止恢复。消费者当前手工填写手机号按业务前提视为可信、已验证，保留手工来源记录，后续可替换为微信授权手机号。详见[登录保持与微信绑定契约](../specs/2026-09-29-两端微信静默登录与会话保持.md)。

本文件定义消费者的产品注册、售后预约、网点、客服、记录、隐私和评价功能。

2026-09-08 已补入全部 4 张消费者截图的可见信息，见[截图补充](#screenshot-details)。截图仅证明旧系统现状，未展示的校验、跳转和后台规则不视为已验证。

菜单采用原始截图的“首页、服务、我的”3 个 Tab，“我的产品/购买记录/服务记录”从“我的”进入。见[页面清单](08-页面清单.md) C01～C19，具体主包、业务分包和路由见[小程序目录与页面路由设计](../02-技术设计/04-小程序目录与页面路由设计.md)。2026-09-09 依据[脑图导出](../00-项目资料/原始摘录/TOTO售后服务系统调研.md)将误读的“家装热线”纠正为“客服热线”：C16 保留“我的”入口并纳入 CAPP-009 的电话客服能力；C09 仍为“服务”中的电话／微信客服入口，具体号码是否共用见 [Q-MM-06](../03-开发管理/02-风险与待确认事项.md#mindmap-questions)。C17“了解更多咨询”的内容和需求编号仍待确认，不自动归入轮播或客服；C18 为 2026-09-17 新增的 AI 智能售后助手原型入口；C19 为 2026-09-25 新增的本人服务投诉与进度入口。

## 10.3 消费者小程序

| 编号 | 功能 | 优先级 | 需求说明 | 核心验收点 |
| --- | --- | --- | --- | --- |
| CAPP-001 | 微信登录与手机号授权 | P0 | 建立消费者账号；手机号验证成功后自动匹配已接入的可信购买记录 | 未授权不匹配购买数据；正式关系使用稳定账号 ID，不直接以手机号作为外键 |
| CAPP-002 | 首页轮播 | P1 | 后台配置广告轮播和跳转 | 按有效期和状态展示 |
| CAPP-003 | 添加 TOTO 产品 | P0 | 默认同步手机号匹配的购买产品；其他产品统一扫码，无码时手动选择 | 识别码类型并先查后建；可信标识重复提交不得产生重复实例 |
| CAPP-004 | 无码产品信息 | P0 | 扫码无法完成时，手动选择产品并填写购买日期及必要使用信息 | 直接进入统一购买记录，标记为用户申报／待核验；不自动授予服务权益 |
| CAPP-005 | 添加结果与关联码 | P0 | 展示添加来源、产品关系和核验状态；有真实关联码时才展示 | 仅本人可见；产品已添加与免费安装、保修资格分开表达 |
| CAPP-006 | 售后预约 | P0 | 发起安装、维修或指导申请 | 手机号同步购买及有效唯一码扫码绑定商品均直接进入服务工单和既有派单流程，不经来源审核；保修及费用资格另判，当前安装每次申请一件产品 |
| CAPP-007 | 故障描述和媒体 | P0 | 描述故障并上传图片或视频 | 支持压缩、断点重试和内容安全检查 |
| CAPP-008 | 网点查询 | P1 | 查找消费者所在城市内已启用且城市、地址、地图坐标完整的售后自有授权门店和维修网点；未登录可查询 | 支持手动选城及点击定位后解析所在城市、列表、微信小程序地图和打开位置；仅单独配置的对客电话与说明可公开，未配置电话时不展示拨号；停用或资料不完整网点不可见，距离仅作直线参考 |
| CAPP-009 | 客户服务 | P0 | “服务”提供电话客服与微信在线客服选择页（C09），“我的”保留客服热线（C16）；AI 助手、活动服务和编码查询可直接进入 C09 | 号码和渠道后台可配置；电话使用有效配置调用小程序拨号能力，未配置时不得用占位号码开放拨号；微信在线客服使用小程序原生客服能力，需完成平台配置及真机验证；进入渠道页不等于已经接通或转接 |
| CAPP-010 | 个人信息及偏好 | P1 | 维护头像、姓名、手机号、常用地址、选填性别／出生日期和通知偏好 | 本人资料按独立消费者账号保存，未绑号可编辑、绑定后保留；性别可修改或清空、出生日期可修改，逐项自动保存；变更手机号需二次验证 |
| CAPP-011 | 我的产品 | P0 | 统一接口按登录消费者账号汇总手机号匹配、扫码添加和用户申报的产品 | 由后端去重、按实物分页并显示来源与核验状态；手机号作为自动匹配入口，同账号换号保留已有归属；支持按产品进入售后预约 |
| CAPP-012 | 我的购买记录 | P0 | 统一查看正式购买和自行填写记录的日期、门店、产品、数量、来源、核验状态和适用关联码 | 仅展示本人或已授权记录；自行填写明确标为待核验，不按姓名、型号或日期模糊认领 |
| CAPP-013 | 我的问卷 | P1 | 查看待填写和已填写问卷 | 防止重复提交 |
| CAPP-014 | 隐私权条款 | P0 | 查看当前及历史同意条款 | 支持撤回授权和账户注销流程 |
| CAPP-015 | 服务评价 | P0 | 对整次售后服务评分，记录问题解决情况、按评分出现的可选感受标签及意见；1～3星为改进、4～5星为满意，每组最多四项，解决情况独立；标签动态维护、独立多选 | 审核通过后本人评价，每单一次；详情见[服务评价 Spec](../specs/2026-09-24-消费者服务评价与工单展示.md) |
| CAPP-016 | AI 智能售后助手 | P1 | 首页以不遮挡 TabBar 的悬浮入口带入本人已关联产品，根据后台维护的适用品番、维修与故障知识进行一轮智能回答；无产品时引导同步／添加但保留人工客服入口；解决则结束，未解决则生成可修改摘要并带入 C07 维修申请，或复制摘要后直接进入 C09 选择人工渠道；首屏、回答和失败状态均可直接联系人工 | 只使用已启用、已生效且适用当前品番的知识，未命中时不得生成维修步骤；漏水、异常发热等风险不引导拆机；维修申请仍由用户核对问题、联系人、地址和期望时间后提交，并防止重复活动工单；摘要发送给客服前由用户确认，没有在线客服会话接口时不得显示已转人工；AI 不自动承诺保修、费用、派单或上门时间 |
| CAPP-017 | 消费者投诉 | P0 | 对本人一条服务记录发起正式投诉，选择问题类型、填写情况和联系偏好；在投诉记录查看“处理中／已办结”和办结结果 | 投诉对象是本次服务体验，由 TOTO 客服统一受理，具体责任方核实后认定；同一工单同时只允许一条未结案投诉；投诉不自动改变原工单或评价、不自动承诺赔偿；消费者可见明确填写的办结结果，不可见后台内部跟进与责任分析；首版不含附件 |

2026-10-01 用户再次确认：省市区默认使用消费者当前位置经纬度逆解析结果，三级选择器默认落在相应省／市／区；移除“使用当前位置”按钮和结果确认弹层。定位默认本身不写资料，选择确认继续自动保存，详细地址保留，失败手动兜底。此规则覆盖下方此前主动定位交互，详见[省市区自动默认](../specs/2026-10-01-消费者个人资料持久化.md#2026-10-01-省市区自动定位默认)。

## CAPP-014 首版范围（2026-09-27 已确认）

首版提供用户协议与隐私政策两份在线文本。后台配置并发布，消费者可在未登录状态、登录页面及“我的”阅读；手机号登录按钮下方主动勾选，两份名称可查看全文；仅前端控制未勾选不能登录。登录接口不校验协议版本、不写登录同意记录，新版发布不触发会话失效。首次不再静默创建账号，产品申报隐私政策来源统一。本版不含撤回、注销及消费者历史同意查询，完整 CAPP-014 目标保留，详见[协议首版 Spec](../specs/2026-09-27-消费者用户协议与隐私政策首版.md)。


2026-10-03 用户确认：个人信息“出生年份”改为“出生日期”，选择年月日、选填且可修改；后续明确移除出生日期清空按钮。安装和维修联系表单恢复姓名、联系人手机号、省市区等资料自动带入，保留手动修改。完整日期持久化、历史年份处理及回填规则见[个人资料 Spec](../specs/2026-10-01-消费者个人资料持久化.md#2026-10-03-出生日期与安装维修回填修复)。

## 2026-10-04 已确认产品保修展示

用户确认在产品资料展示标准保修时长、预计剩余天数和预计到期日。当前只按登记购买日期估算并标记待核实；期限保存购买明细快照，主档后续调整不回写历史。缺少购买日期提示暂无法计算剩余保修时间，期限缺失提示待完善；保修区不提供联系客服按钮，已退回不显示剩余时间。核定起保日、部件差异和延保需要可信数据，不从自填日期授予保修或免费维修资格。实现及验证见[保修展示Spec](../specs/2026-10-04-消费者产品保修时间展示.md)。

2026-10-05 用户确认断网／服务重启时首页重连区增加说明与按钮间距，助手备用人工入口使用完整留白的胶囊并区分主次操作；“我的”页不单独显示重试自动登录提示，产品卡重新连接入口保留。见[断网状态布局](../specs/2026-09-19-消费者-v013-UI-逐屏对照.md#consumer-offline-layout-20261005)。
