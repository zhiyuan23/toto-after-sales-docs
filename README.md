# TOTO 售后服务开发工作区

本目录是 TOTO 售后服务的跨仓开发入口，集中维护项目背景、完整需求、技术约束、开发进度、功能 Spec 和验收证据。`Gaia/` 不是 Git 仓库，因此这里的文档不会随任一业务仓库自动提交或分发。

## 现在先看什么

1. 先看[开发进度与下一步](03-开发管理/00-开发进度与下一步.md)：这是唯一的进度文档，集中展示各系统的功能模块、菜单建设、业务完成情况和开发顺序。
2. 需要理解项目边界时，读[项目概览与范围](00-项目资料/01-项目概览与范围.md)、[仓库与系统关系](00-项目资料/02-仓库与系统关系.md)和[技术架构与技术栈](00-项目资料/03-技术架构与技术栈.md)。
3. AI 开发前，通过[页面清单](01-功能需求/08-页面清单.md)定位菜单，通过[需求索引](01-功能需求/09-AI开发需求索引.md)定位需求原文、任务依赖、业务规则和验收。原始材料取用见[资料索引与核对](00-项目资料/04-原始资料索引与需求核对.md)。
4. 先批量建立归属明确的已知菜单入口，再按依赖逐个开发全栈切片；复杂切片的范围、接口、权限和验收写入 [`specs/`](specs/)，状态回写进度文档。

进度按 4 个系统、26 个功能模块展示。需求目录保留 119 个功能编号、96 个入口组及开发任务依赖；其中 2 个原脑图入口的详细需求待补编号。菜单定义和需求索引不再维护另一份进度，当前状态统一查看进度文档。来源草案与未确认规则不因已编目而自动定版。

## AI 开发闭环

1. 从唯一进度文档确定下一模块和工作范围，在需求索引中检查依赖和局部阻塞；先菜单入口，后业务功能。
2. 阅读对应需求、技术设计、相关仓库说明与 `AGENTS.md`，核对 Git 现场。
3. 复杂跨仓切片用 [`specs/_template.md`](specs/_template.md)固化角色、菜单、数据、接口、权限、验收和禁止假设；普通任务直接按明确需求与项目惯例实施，仅重大业务缺口需要确认。
4. 在一个任务中贯通必要的数据模型、后端逻辑、接口、宿主接入、前端页面和权限，不拆成互相失联的前后端任务。
5. 按风险完成 lint、类型检查、测试、构建和关键路径验收，记录未验证项。
6. 只回写进度文档的模块完成情况、合计和下一步；具体实现、验证及遗留事项写入对应 Spec 并关联证据，不新增平行进度台账。提交、推送、上传、发布仍需用户明确授权。

环境启动、租户构建和联调步骤见[本地开发与联调](local-development.md)。
