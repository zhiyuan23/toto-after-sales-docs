# TOTO 售后服务开发工作区

本目录是 TOTO 售后服务的独立项目文档 Git 仓库，也是跨仓任务入口。集中维护完整需求、技术规则、开发进度、页面原型、业务流程、Spec 与验收证据。

本仓库的 LLM Wiki 主节点为[项目概览与范围](00-项目资料/01-项目概览与范围.md)，稳定 ID 为 `kb:project:toto-after-sales-docs`。现有目录与开发入口保持；格式、索引范围、校验及交付网页生成见[知识维护规范](03-开发管理/00-开发与文档规范/03-LLM-Wiki文档维护规范.md)。

团队成员独立使用本仓库即可获得完整项目文档。AI 开发从 AGENTS、进度和对应需求／Spec 进入，根据任务检出关联源码仓库。只拿到文档时，未检出的跨仓源码引用会在校验中提示；完整工作区可加 `--strict-workspace-links` 严格核对。

## 文档目录

```text
docs/toto/
├── 00-项目资料/       项目背景、仓库关系、原始资料
├── 01-功能需求/       完整需求、入口与需求编号索引
├── 02-技术设计/       架构、接口、完整业务规则与权限矩阵
├── 03-开发管理/       进度、验收、执行规范与待办
├── 04-页面原型/       可查看和修改的页面原型及配套说明
├── 05-业务流程/       总流程、七个阶段与线下收费跨阶段专题
├── 06-项目交付/       业务指南、角色手册、项目说明与交付材料
├── 07-内部汇报/       项目内部汇报网页及配套资源
├── specs/            功能契约、实施记录与 evidence 验证材料
└── 99-归档/           历史材料与设计探索
```

流程文档在同一目录平铺，不再增加阶段子目录。原型按后台、小程序组织，脚本和资源保留在对应原型旁。

内部汇报单独维护在 `07-内部汇报/`，不作为客户交付材料；后续客户汇报版本准备后放入 `06-项目交付/03-项目说明/`。

项目交付目录统一按“业务指南 → 角色手册 → 项目说明 → 交付材料”组织；简明导读与详细手册分别维护，完整需求、业务流程、技术契约及开发进度仍在各自原目录维护。

## 整理后的阅读边界

[技术设计导航](02-技术设计/README.md)按架构运行、开发规范、业务契约、平台接口与权限组织；[开发管理导航](03-开发管理/README.md)集中执行规则、部署、版本、测试、进度和待办。版本信息按月记录，日常进度仍只有总览及三个应用明细。

`00-项目资料/` 说明背景、范围与仓库关系；`01-功能需求/` 保留完整需求基线和依赖索引；`05-业务流程/` 保留按阶段阅读的流程摘要，不代替技术契约。以上三处保持原有文件顺序，避免为分层额外增加入口。

原型的说明、当前入口、备选方案和共享资源分别归位；统一预览继续作为入口。交付材料中的测试账号已归内部测试资料，协议演示稿单列并保持待生效状态。内部汇报按当前、阶段计划、专题、视觉备选、历史和模板分类，历史文件仍可追溯。

[Spec 分类与生成规则](specs/README.md#spec-generation)约束后续 AI 写入；[历史归档导航](99-归档/README.md)仅用于追溯。目录整理不改变任何业务确认、部署或验收状态。
