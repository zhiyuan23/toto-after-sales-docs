# 两端小程序 UI 样式与验收规范

- 生效日期：2026-09-27。
- 适用：消费者 `gaia-after-sales-uni`、服务人员 `gaia-customer-service-uni` 的新页面、已有页面修改和公共 UI 能力。
- 来源：用户要求将多轮已调整的胶囊按钮、文字位置与大小、卡片和输入框规则固化，避免技术资料等新页面反复出现旧问题。
- 状态：开发规范已建立；同日已完成技术资料三页及必要公共样式修复，两端完整校验与 H5 隔离验证通过，微信实际显示待用户验证；其他既有页面不据此宣称全部对齐。实现与验收状态见 [OPT-20260927-01](../03-开发管理/07-后续开发与交互优化待办.md#opt-20260927-01)，不得据本规范声明页面已修复或视觉验收通过。

## 1. 依据与复用入口

本文件统一两端基础控件的视觉规则。用户最新确认的视觉调整优先于旧原型及历史样式；已确认原型继续决定页面信息层级、区块顺序和交互。功能 Spec、权限和服务端状态不因视觉统一而改变。现有源码说明当前实现，不证明其符合最新规范；旧页面不能整页照搬为范例。

| 内容 | 实现入口与使用方式 |
| --- | --- |
| 两端共同尺寸、按钮与卡片 | 两仓 `src/static/styles/common.scss`；复用 `.app-page*`、`.app-action*`、`.app-card*`、`.app-segmented*` |
| 颜色与 TDesign 适配 | 两仓 `src/theme.json`、`build/theme.ts`、`src/static/styles/tdesign-theme.scss`；沿用 `--app-*` 语义变量 |
| 消费者端既有页面 | [端侧说明](../../../mobile/gaia-after-sales-uni/docs/design-system.md)、`src/consumer/style.scss`；`.consumer-ui .primary/.secondary` 是已有兼容入口，不能复制成新页面私有按钮规则 |
| 服务人员端既有页面 | [端侧说明](../../../mobile/gaia-customer-service-uni/docs/design-system.md)；`TaskCard.vue` 的无边框与内容裁切、配件页的按钮对齐可作局部参考，业务规则与局部尺寸不整体复制 |
| 加载、空态和失败 | 复用 `AppState`；按钮加载复用 `.app-button--loading`、`.app-button__spinner` 或 TDesign 自带加载态 |
| 自定义导航与顶部占位 | 两仓 `CustomNavigation.vue`、`useNavigationMetrics.ts`；无背景返回箭头、状态栏／胶囊高度、普通占位及透明覆盖模式，详见各端 `docs/design-system.md` |
| 公共变更同步 | 两仓 `docs/shared-foundation.md`；同一任务同步公共样式、组件、相应说明和必要回归 |

消费者亮蓝、服务人员深蓝和消费者 AI 功能域已确认的紫色语义继续独立。统一控件结构，不强行合并品牌色或业务布局。TDesign 仍是唯一 UI 组件库，不恢复旧 Demo、不创建第二套设计系统。

**自定义导航（2026-09-29）：** 返回统一使用无背景、无阴影的原生样式折角箭头（12px 几何框、2px 线宽，可见轮廓约 10×17px，距屏幕左侧约 10px），保留 44×44px 触控区；不使用白色圆形底。普通页面由 `CustomNavigation` 自动撑开状态栏与导航总高度，地图等沉浸页面传 `overlay` 使用透明零占位模式，并通过 `@metrics-change` 取得尺寸安排内容避让。返回兜底入口由业务页传入。高度统一由 `useNavigationMetrics` 读取并监听窗口变化，现有 `RootNavigation` 同样复用；不在页面复制胶囊计算或写死顶部高度。需同时配置页面 `navigationStyle: 'custom'`；同步组件能力不等于批量改造所有页面。

## 2. 尺寸与文字基线

以下是没有更具体已确认设计时的默认值；同层控件必须一致，不能每页自行选一套字号。已有消费者 px 原型保持原单位及同视口效果，不机械按 `1px = 2rpx` 替换：该换算只在 375px 视口成立。

| 对象 | 默认规格 | 约束 |
| --- | --- | --- |
| 主／次操作按钮 | `28rpx`、字重 `600`、行高 `1.35`，最小高度 `88rpx` | 沿用 `.app-action`；消费者已确认的 `48px / 14px` 按钮允许保留 |
| 正文、字段标签 | `28rpx`、字重 `400`、正文行高 `1.5` | 紧凑列表允许已确认的 `26rpx`，同层一致 |
| 公共单行输入、选择、多行输入的内容与占位 | `26rpx`、字重 `400` | 三类控件同字号，placeholder与输入／选择值同字号；底部提示及字数计数仍为24rpx |
| 全宽上传动作、表单类型选项 | `26rpx`，上传字重 `400` | AppChoiceTabs的segmented／outline／soft默认26rpx，显式font-size优先；状态胶囊／列表导航保留各自规格，方形上传文案及数量24rpx |
| 辅助说明、错误提示、计数 | `24rpx`、行高 `1.5`，次级文字色 | 关键说明不得靠继续缩小字号容纳 |
| 卡片／区块标题 | `32rpx`、字重 `600`、行高 `1.4` | 不随意引入 `29rpx`、`34rpx` 等同层新规格 |
| 根页展开标题 | 沿用 `RootNavigation` 与端侧原型 | 不在普通内容卡重复制造页面大标题 |
| 页面边距、区块间距 | `--app-page-gutter`、`--app-section-gap`，当前均为 `32rpx` | 已确认原型局部布局可有差异 |
| 普通独立卡片之间 | `--app-card-gap`，当前 `24rpx` | 375px 视口为 12px；资料列表、同层独立信息卡默认使用 |
| 卡内字段／紧凑同组间距 | `--app-space-2`／既有 `--app-list-gap`，当前 `16rpx` | 不作为独立大卡之间的默认间距；标题紧邻说明可用 `8–12rpx` |
| 普通控件、卡片、大卡／弹层圆角 | `--app-radius-control: 24rpx`、`--app-radius-card: 32rpx`、`--app-radius-overlay: 40rpx` | 形状由用途决定 |
| 操作按钮圆角 | `--app-radius-button: 999rpx` | 主次操作都使用胶囊形 |

**控件迁移保留排版（2026-10-06）：** 统一公共皮肤时先对照原字号与字重，不让普通文字入口、紧凑分类因默认28rpx/600而放大、变粗。AppButton通过font-size／font-weight参数保留已确认排版，AppChoiceTabs通过font-size统一调整各变体（包括TDesign导航），不在页面复制控件皮肤。字号调整不缩小触控区。人员任务首页分类24rpx；详情资料入口23rpx、地图入口24rpx，普通400字重。

**卡片与业务预览（2026-10-06）：** 自带卡片的业务组件在Demo中直接平铺，组标题／说明使用无背景容器；无卡片表面的明细只包一层公共卡片。AppCard默认stack提供24rpx内部gap，复杂原业务排布使用layout="block"，避免和旧margin叠加。卡间距由父布局统一管理。微信AppCard使用virtualHost并同步开启mergeVirtualHostAttributes，让调用方class/style落在真实根节点，卡片padding计算一次；两端共同同步，不能用页面额外padding补偿。AppButton同样使用virtualHost；跨列宽度和外间距由业务原生容器承担。消费者原生button重置不得覆盖业务卡片／返回按钮的margin、padding和border；见[第一轮样式修复](../specs/2026-10-06-消费者基础组件全页面迁移.md#consumer-style-round1-20261006)。

正文使用系统字体，展示数字按下方[数字字体规则](#numeric-font)显式接入。长标题、品番、文件名必须换行或有可获取完整值的截断策略；不能把文字缩小到不可读。不要新造未定义的 CSS 变量；技术资料首次核对使用的 `--app-background-color` 不在主题定义中（同日修复已移除），应按用途选 `--app-bg-color`、`--app-bg-secondary` 或 `--app-surface-color`。

<a id="rounded-icons"></a>
### 2.1 图标：默认圆润风格（2026-10-05）

用户已确认两个小程序使用图标／icon时以圆润风格为主。新建及调整现有图标优先采用圆头线条、圆角转折和圆润外轮廓，同组统一画布、线宽、留白、描边／填充语言与视觉大小；品牌标识、平台专用图标和明确语义需要的特殊轮廓可保留。既有图标随实际修改范围逐步对齐，本轮不据规范建立宣称全量整改完成。

- 优先复用精简本地SVG及既有TDesign渲染入口；线性SVG显式使用`stroke-linecap="round"`与`stroke-linejoin="round"`，矩形轮廓使用适当`rx`或曲线。TDesign／MDI图标仅在符合圆润轮廓时复用，不另引入图标／UI组件库，不以emoji或字体字符模拟图标。
- 默认24×24画布、1.5～2线宽；常规菜单40rpx，独立资料入口48rpx；通用进入箭头保留32rpx尺寸；右向入口按最新确认使用TDesign，作为圆润风格优先规则的明确例外。独立纯图标操作仍保留至少44px点击区和可访问名称，装饰图标设为无障碍隐藏；操作含义由文字或无障碍名称表达。背景方块仅在已确认设计或状态语义需要时使用。
- 简单SVG目标每个不超过1KB；去掉无用元数据，不携带脚本、外链、字体或内嵌位图。颜色按本端品牌／状态语义，核对明暗、按下和禁用；作为图片载入的外部SVG不继承父元素`color`／`currentColor`，按需提供明暗语义色资源。共同能力和资产按两仓`docs/shared-foundation.md`同步，业务资产与品牌颜色保持端侧独立。
- 两仓`AGENTS.md`和`docs/design-system.md`已增加上述开发与验收约束。首个实例为人员“我的”文档搜索、反馈、密码与退出SVG，实施、实际字节数及平台边界见[OPT-20261005-06](../specs/2026-10-03-服务人员产品服务指南与配件建议.md#mine-resource-icon-20261005)。

<a id="reading-typography"></a>
### 2.2 通用文字层级与阅读间距（2026-10-08）

共同入口：`src/static/styles/typography.scss`（由`common.scss`加载），两端等价同步。仅显式接入的内容生效，既有页面和表单控件默认值不批量改写；基础Demo“文字阅读层级”展示标题、正文、紧凑正文、辅助信息及长地址。

| 角色 | 字号令牌 | 字重／行高 | 用途 |
| --- | --- | --- | --- |
| 辅助信息 | `--app-font-caption: 24rpx` | 400／1.5，多行说明1.6 | 日期、结束时间、字段说明、记录时间；状态标签可600／1.4 |
| 紧凑正文 | `--app-font-compact: 26rpx` | 400／1.5，地址1.6 | 列表地址、紧凑字段值；不再把地址降为辅助小字 |
| 正文 | `--app-font-body: 28rpx` | 400／1.5 | 产品名称、常规正文；名称可500或600 |
| 客户／区块标题 | `--app-font-title: 32rpx` | 600／1.4 | 列表客户名、详情区块标题 |
| 抽屉标题 | `--app-font-sheet-title: 36rpx` | 600／1.4 | 已有底部表单抽屉 |
| 状态主标题／窄列时间 | `--app-font-display: 40rpx` | 600／标题1.4、数字1.3 | 详情状态、日程既有116rpx时间列 |
| 标准时间数字 | `--app-font-time: 44rpx` | 600／1.3 | 首页、地图既有130rpx时间列；数字等宽，非时间文字回退24或26rpx |

行高复用`--app-leading-title/body/reading/number`；字重复用`--app-weight-regular/medium/semibold`（400/500/600）。普通内容可使用`.app-text-title/body/compact/caption`和`.app-text-reading`，业务已有class直接引用令牌。正文使用系统字体；展示数字采用下节已确认的Inter Bold子集，不调整正文的字重基线。不得通过650/700或20–23rpx小字制造正文同层差异。375px视口24rpx=12px，换算随视口变化，不声称rpx等同固定px或系统大字体适配。

间距优先复用8/16/24/32/48rpx的`--app-space-*`；标题紧邻说明8rpx，同组字段16rpx，独立卡24rpx，区块32rpx。既有布局的12/20/28rpx局部内距可保留；首页和地图卡头、正文、地址水平28rpx对齐，提示使用16rpx内距。卡间距由既有唯一一处管理，末卡与安全区不重复叠加。字号变更保留触控最小高度、列宽、节点顺序、定位、网格及换行／截断策略；长字段不靠缩小文字容纳。

本轮人员任务列表／详情（含记录与表单抽屉）、日程任务列表、地图任务列表已接入，详情资料及审核文字入口由22/23rpx收敛为24rpx，覆盖此前这些入口的保留规格。安装／维修语义色、按钮、状态与权限不变；消费者只同步公共令牌和Demo，不批量改其业务页面。规范建立不等于所有历史页面、微信深色或真机验收通过。实施与验证见[TOTO任务阅读规范记录](../specs/2026-09-18-服务人员小程序完整开发计划.md#task-reading-type-20261008)。

**消费者追加接入（2026-10-08）：** 用户已授权将上述标准实际应用到消费者正式页面及业务组件。首页／欢迎的展示主标题与结果／状态标题使用40rpx，区块标题32rpx／600，抽屉标题36rpx／600；产品名和常规正文28rpx，字段值26rpx，标签／日期／辅助说明24rpx，表单标签28rpx／400。AI回答正文28rpx／1.6，回答标题32rpx／600／1.4；地址与多行字段1.6。品牌字标、图标／选择符号、既有输入控件的垂直对齐和按钮专用规格保留。消费者卡间距引用既有公共变量，不新增公共皮肤；业务脚本和布局声明保持。此追加覆盖前段“消费者只同步公共能力”的阶段范围；平台验证与剩余边界见[消费者阅读规范记录](../specs/2026-09-19-消费者-v013-UI-逐屏对照.md#consumer-reading-20261008)。

<a id="numeric-font"></a>
### 2.3 展示数字字体（2026-10-08）

用户确认采用Inter Bold（700）的数字与常用符号WOFF2子集，两端共同入口为`src/static/styles/number-font.scss`（由`common.scss`加载），数字片段显式使用`.app-number`，不得设置在页面／卡片根节点。

- 使用：人员首页待处理／今日预约／本月完成统计及服务进度数字；配件库存、种类、参考价格、列表／单据／详情中的展示数量；两端服务费用和消费者购买记录数量、服务进度节点。
- 保留系统字体：中文及单位、日期时间、手机号、工单／单据编号、产品型号、输入内容与占位；免费／价格待维护等文字状态、完成勾号及停止符号不接入。数量步进控件的只读数字可接入，原生输入仍用系统字体。
- 仅引入一个Bold字形，保留业务字号、CSS字重、行高、颜色和原布局；字体匹配使用该Bold字形，不将中文一并加粗。新增嵌套`text`时，原标签／单位选择器须约束到直接子节点或排除`.app-number`，防止大数字继承单位小字。
- 资产`src/assets/fonts/afs-numbers.woff2`实测2092字节，保留`0–9`、空格及`.,+-%/:¥`。遵循SIL OFL 1.1；固定`wght=700`与`opsz=14`，保留等宽数字`tnum`；内部字体名沿用`Afs Numbers`，源码来源、原许可证和重建方式在两仓`licenses/inter/`及`scripts/subset-number-font.py`留存。
- 微信构建将本地字体转换为内嵌base64；本轮实测base64为2792字符，各端`app.wxss`仅一个字体声明且未重复输出字体文件。不依赖外部CDN；字体无法加载或缺字时回退系统字体。遵循[uni-app本地字体说明](https://uniapp.dcloud.net.cn/tutorial/syntax-css.html)。
- 共同资产、样式、基础“数字展示字体”示例和一致性检查同一任务双端同步；验收须核对实际字体加载、中文／单位字号、浅深色及0／多位数字，微信编译成功不能替代真机字体兼容验证。

本轮实施与平台验证边界见[OPT-20261008-NUMBER-FONT-01](../specs/2026-10-05-服务人员公共控件Demo.md#inter-numeric-font-20261008)。

## 3. 按钮：形状、文字居中与原生重置

### 3.1 按用途选样式

| 用途 | 必须使用 | 不得出现 |
| --- | --- | --- |
| 多条件表单查询、保存、提交、继续等主操作 | `.app-action.app-action--primary` 或经同规格验证的 TDesign 按钮 | 裸原生按钮、局部小圆角矩形 |
| 重置、取消等次操作 | `.app-action.app-action--secondary`；轻操作可用 `--soft` | 主按钮胶囊、次按钮方形的混搭 |
| 关闭视频、重试、加载更多等操作 | 按上下文选胶囊次／轻按钮；纯文字操作使用已验证的文字按钮规则 | 遗漏这些条件渲染按钮的样式和禁用态 |
| 整卡／列表行点击 | 卡片／列表外观，保留可访问名称和真实点击语义 | 为套胶囊把整张资料卡变成长药丸 |
| 文字链接、纯图标、数量步进、状态导航 | 对应专用控件，保留足够触控区 | 把一切 `button` 全局强制变成胶囊 |

2026-10-07 服务人员处理任务首步的“开始远程指导”与“定位签到”均复用AppButton secondary白底主题描边胶囊，页面底部流程推进按钮保留primary填充样式，避免两个区域同时使用相同主操作外观。仅调整按钮层级，开始服务条件、loading／disabled、远程不定位及服务事实契约保持。

多条件表单的操作区这样接入已有样式，布局类只控制排列和宽度；单关键词检索采用第 5 节通用搜索框，不额外放置大查询／重置按钮：

```vue
<view class="filter-actions">
  <button class="app-action app-action--secondary" @click="reset">重置</button>
  <button class="app-action app-action--primary" @click="search">查询</button>
</view>
```

### 3.2 必须检查最终样式

- 内容由 `display: flex; align-items: center; justify-content: center` 居中；显式设置字号、字重、行高、`box-sizing: border-box`、对称上下内边距和 `margin: 0`。不得依赖原生按钮默认行高，或用负 margin、`top`、`translateY` 补偿文字偏移。
- `.app-action` 当前默认 `padding: 20rpx 28rpx`、`min-height: 88rpx`。不要叠加较小固定高度造成文字挤压；长文案应调整布局或允许合理增高，加载图标和文字作为一组居中。
- 检查 CSS 加载顺序和选择器覆盖，包括公共 `font: inherit`、页面 `button` 规则及 TDesign 内部内容层。只看到 class 名或 `align-items: center` 不能证明最终字号、行高正确。
- UniApp 原生按钮本体边框与 `button::after` 分别处理；胶囊操作沿用公共伪元素重置，整卡按钮也必须清除原生伪元素边框。仅设置 `border: 0` 不够。
- 加载期间保留宽高、圆角与语义色，使用真实 `disabled` 或组件加载保护阻止重复操作；通用 `.app-action` 当前加载和禁用透明度均为 `0.82`，紧凑控件按已确认规则处理。不要用颜色变化代替交互禁用。
- TDesign 按钮需核对微信实际节点的圆角和内容居中，不能认为仅配置主题圆角就完成适配。

## 4. 卡片：无装饰边框与圆角裁切

普通信息卡默认使用表面色、卡片圆角、**无外边框、无逐卡阴影**。独立信息以背景和间距分组，卡内可保留有必要的弱分隔线。选中项、错误提示、焦点环和次操作按钮的语义描边允许保留，不用“所有 border 清零”破坏状态表达。

**间距分级（2026-09-27 用户复核后补充）：** 卡内字段／紧凑行之间 `16rpx`，普通独立卡片之间 `24rpx`，筛选区与结果区等不同区块之间 `32rpx`。资料列表不再使用仅约 8px 的紧凑间距。`24rpx` 是结合消费者既有 `--c-card-gap: 12px`、服务人员任务卡 `26rpx` 及 UI UX Pro Max 的 4／8 步进和分组层次原则作出的项目选择；该技能没有规定所有卡片必须为 12px。375px 视口下约 12px，390px 下约 12.48px。

间距由父列表 `gap` 或条目单侧 margin 统一管理，两者不得累加；`.app-card` 本体不设外间距，以免卡内嵌套或网格布局额外留白。同层卡片使用同一变量，文字换行、加载、禁用或分页追加后间距不变。两端技术资料和服务人员任务资料已应用；其他已有明确原型的页面按后续实际变更范围对齐，不因新增变量自动改写原布局。

有图片、彩色头部、底部条或按下背景的卡片，内容必须沿卡片圆角裁切。优先由卡片内容容器设置 `overflow: hidden`；需要外部焦点环、角标或浮层时，使用外层交互容器与内层裁切容器，避免一刀切隐藏它们。图片／视频应核对目标微信渲染模式的实际效果，不以 H5 圆角截图代替。

可点击卡片使用原生 `button` 时，除卡片规则外还需显式处理 `::after`、默认内边距、外边距、对齐、文字行高和禁用态；卡片中的正文不继承操作按钮字号或垂直居中布局。避免整卡按钮再嵌套独立操作按钮。

可点击资料卡使用右侧垂直居中的 TDesign `chevron-right`，放入公共 `.app-entry-arrow` 容器并设置图标 `size="inherit"`；共同尺寸 `--app-entry-arrow-size: 32rpx`（375px视口为16px），固定宽度且不压缩；正文与箭头间隔24rpx。右留白由父容器提供一次 `--app-entry-inset: 32rpx`，不叠加margin；人员“我的”及两端资料列表、消费者“我的”同类入口沿用此规格。独立列表／卡片箭头使用次级灰，个人信息、全部产品、单据记录等文字操作中的箭头通过 `.app-entry-arrow--text` 继承文字颜色；文字操作不套卡片内边距。已有局部箭头保留原size与位置，不统一放大；旧字符入口由共同 `AppInlineChevron` 渲染TDesign图标，不可见占位仅保留原字宽／行高。辅助文字与箭头保留对齐、原加载反馈和禁用行为；不得可见地使用字符模拟图标，不在卡底重复“查看资料”或“打开”。整卡可点击且保留含文件名的无障碍名称，打开过程中原位显示加载图标，避免布局跳动。

**2026-09-27 收敛记录：** 首次核对两仓 `.app-card` 仍为 `2rpx` 浅边框且无内容裁切，服务人员另在 `App.vue` 覆盖边框。同日已将两仓共同 `.app-card` 改为无边框、裁切内容并清除原生伪元素，保留选中态内描边和 H5 焦点规则；旧 `.app-surface` 的用途未批量改动。技术资料三页已接入，详见[验证记录](../specs/evidence/2026-09-27-material-ui/verification.md)。其他页面的全面视觉迁移未在本轮宣称完成。

## 5. 输入框与表单

**第二种浅灰搜索（2026-10-08）：** 无独立提交／扫码的页内搜索复用共同 `AppSearchSimple`，浅灰 `--app-bg-secondary` 胶囊、左侧40rpx搜索图标、28rpx输入及有值清除；高度至少88rpx且不低于44px，清除区同样至少44px。不在业务页复制皮肤，是否输入即查或键盘确认由页面绑定事件决定。原带右侧搜索／扫码的 `AppSearch` 保留；两端基础Demo、控件源码、样式与文档同步。C08已应用，详见[实施与验证](../specs/2026-09-23-消费者C08服务网点地图查询.md#outlet-refinement-20261008)。

- 普通独立输入、picker 入口和多行文本统一使用 `24rpx` 控件圆角、`--app-field-bg` 输入面（浅色 `#FBFCFE`／深色 `#1D2024`）和 `--app-field-border` 细浅边界（复用主题浅边框），输入值及占位文字 `28rpx`。单行明确 `88rpx` 高度、水平 `24rpx` 内边距且无上下 padding；选择入口至少 `88rpx`、上下 `20rpx`，长值允许换行；多行默认 `176rpx` 高度、上下 `20rpx` 和 `1.5` 行高，不套单行垂直居中。焦点沿用焦点色，错误保留错误语义，禁用／只读使用主题禁用面和次文字，避免降低可读性。已有经确认的行内表单、搜索组合框保留自身结构。
- 原生单行 `input` 明确高度、字号及占位文字样式，上下避免不对称 padding；文字垂直位置按原生控件实际渲染检查，不照搬按钮的超大行高，也不把 flex 属性当成输入文字已居中的证据。
- 字段有可见标签，placeholder 仅提供填写示例。普通输入、picker 入口、日期及只读值在同组中对齐；长文本用 textarea，允许内容增高，不能套单行垂直居中规则。
- 确需多条件的表单保留 `min-width: 0`、合理比例及间距；检查输入值、placeholder、清空控件、错误提示、禁用与键盘弹起状态。能通过单关键词覆盖的列表检索，不拆成多个输入条件。
- 两端已提供 `.app-field`、`.app-field__label`、`.app-input`、`.app-textarea`、`.app-picker` 和 `.app-input-placeholder` 公共样式，局部布局通过 `src/static/styles/form-controls.scss` 的 `input`／`textarea`／`picker` 混入复用同一皮肤，TDesign 使用 `tdesign` 适配；这是原生输入样式约定，不是新的表单组件库。优先复用这些样式或端内已验证控件，不能把局部输入框皮肤反复复制到新页面。

## 6. 新开发与修改页面的执行要求
