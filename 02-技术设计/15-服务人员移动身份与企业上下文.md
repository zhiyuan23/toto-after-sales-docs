# 服务人员移动身份与企业上下文

更新时间：2026-09-19。本文记录服务人员小程序身份、会话、企业上下文和移动能力边界；配件阶段 6 的实施与未验边界见完整开发计划第 9.1 节。

## 1. 调查结论

- 服务人员小程序不使用蓝鲸/Gaia 的用户登录。售后后台新增服务人员时同时创建售后域登录账号和初始密码；账号通过不可变 `personnel_id` 绑定 `afs_service_personnel`，禁止按姓名、手机号、昵称或客户端人员 ID 猜测。
- Web 新增表单必填 `loginAccount` 和 `initialPassword`，初始密码只在创建请求中传输，不回显；编辑人员允许修改登录账号，不允许借初始密码字段重置密码。人员与账号在同一后端事务内创建，任一步失败均不留下孤立记录。
- Gaia Web 后台仍使用 `UserRealm.getCurrentLoginUserId()`、请求 `x-tenant` 和现有菜单/API 权限。Gaia 会话只有用户标识，租户由 `TenantUntil` 从请求解析，现有模型没有 Gaia 用户与 `afs_service_personnel` 的稳定绑定字段。
- `afs_service_personnel_station` 表达一名人员的多服务站关系；有效服务站的 `org_id` 指向 `sys_organization`，作为移动端企业候选。一名人员可以拥有多个站，也可以因不同站获得多个企业候选；旧 `afs_service_personnel.station_id` 只保留第一站兼容值。
- `gaia-after-sales-api` 同时被 `gaia-saas-web` 和 `gaia-saas-web-jar` 依赖，Controller 通过宿主组件扫描挂载。宿主只将移动身份、任务及配件专用路径设为 Shiro `anon`，其认证和权限仍由售后移动会话逐请求校验；未列出的 `/api/**` 继续走 Gaia `authc`。

## 2. 数据与会话

迁移为 `gaia-after-sales/database/20260918_service_personnel_mobile_identity.sql`，回滚文件同目录。该迁移已于 2026-09-18 经明确授权执行到共享测试库 `gaia_wh_init_wzy`；其他租户库和环境仍须单独授权。迁移只新增售后自有表，不引用或读写 Gaia 业务主档：

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `afs_service_personnel_account` | 登录账号与稳定人员绑定 | `personnel_id`、大小写不敏感业务校验后的 `login_name` 均唯一；密码使用带随机盐的 PBKDF2-SHA256 摘要 |
| `afs_service_personnel_account_permission` | 移动端精确能力 | 阶段 1 为 `MOBILE_CONTEXT_READ`、`MOBILE_ENTERPRISE_SWITCH`；任务阶段增加 `MOBILE_TASK_READ`／`MOBILE_TASK_WRITE`；配件阶段源码增加独立 `MOBILE_INVENTORY_READ`／`MOBILE_INVENTORY_WRITE`，目标库仍待授权执行增量迁移 |
| `afs_service_personnel_session` | 服务端会话与当前企业/站点 | 只保存随机令牌的 SHA-256 摘要；保存选择结果、上下文版本、到期和撤销时间 |
| `afs_service_personnel_account_audit` | 账号创建、改名、启停审计 | 记录账号、人员、动作和后台操作者 |

租户继续由 `x-tenant` 进入 Gaia 租户路由，但服务人员令牌只在该租户数据库内查询；同一令牌换租户查询不到即拒绝。移动认证头固定为 `X-AFS-SESSION-ID`，不使用 Gaia 的 `X-SESSION-ID`。默认会话 8 小时，服务人员或账号停用时撤销已有会话。退出接口先使本地状态失效，再调用服务端撤销；调用失败不得恢复本地旧会话。

多租户宿主必须由 Gaia 路由设置 `TenantContextHolder`；单租户本地宿主可显式配置 `after-sales.mobile.single-tenant-id`，作为服务端受控的租户 ID。该配置没有默认值，未配置且会话中也没有 Gaia 租户上下文时仍返回 `403`；客户端 `x-tenant` 不能覆盖此单租户配置。

企业上下文存于服务端会话，不接受客户端人员 ID、服务站 ID 或自造候选列表。切换请求只提交候选企业 ID 和 `contextVersion`；服务端重新从人员有效站点计算候选并以版本条件更新，过期请求返回冲突。当前服务站是所选企业下人员关系顺序最前的有效站点。

## 3. 阶段 1 API

根路径固定为 `/api/afterSales/mobile/service-personnel`：

| 方法与路径 | 输入 | 输出／行为 | 权限 |
| --- | --- | --- | --- |
| `POST /auth/login` | `account`、`password`，并携带 `x-tenant` | 返回不透明 `sessionId`、稳定 `accountId`、`expiresAt`；连续失败锁定 | 匿名 |
| `POST /auth/logout` | `X-AFS-SESSION-ID` | 撤销当前服务端会话 | 有效移动会话 |
| `GET /context` | `X-AFS-SESSION-ID` | 最小人员、当前企业、当前站点、企业/站点候选、能力、版本 | `MOBILE_CONTEXT_READ` |
| `POST /context/switch` | `enterpriseId`、`contextVersion` | 校验候选归属并原子切换，返回新上下文 | `MOBILE_ENTERPRISE_SWITCH` |

错误码 `4601` 表示账号未绑定人员，`4602` 表示账号或人员停用，`4603` 表示没有有效服务站；`4001` 表示凭据错误或会话失效，`403` 表示无移动能力或跨范围，`409` 表示上下文版本过期。登录错误不透露账号是否存在。

## 4. 权限与端侧隔离

移动账号不是 Gaia Web 用户，不分配后台角色、菜单或 Web API 集合。上下文能力明确返回 `dispatchStation=false`、`dispatchPersonnel=false`、`completionReview=false`、`inventoryApproval=false`。使用移动令牌直接访问派站、派人、完工审核、库存审批或其他 `/api/**` 时，Gaia Shiro 不将该令牌视为后台会话，因此被拒绝。

2026-09-19 配件切片新增 `inventoryRead`、`inventoryWrite` 两项上下文能力，对应 `MOBILE_INVENTORY_READ`／`MOBILE_INVENTORY_WRITE`；`inventoryApproval` 固定为 `false`。独立移动 API 根路径 `/api/afterSales/mobile/service-personnel/parts` 只接收移动会话，查询按服务端当前人员、当前站点与企业重新定范围，创建与撤销还要求移动写能力；W04 含实际配件耗用的首次完工提交同时要求任务写与库存写能力。宿主 WAR 和 Jar 仅为该根路径及其子路径增加窄放行，不能用移动会话调用 `/api/afterSales/inventory` 的后台审批动作。新增权限脚本 `gaia-after-sales/database/20260919_service_personnel_parts.sql` 尚未在共享库执行；本段只描述当前源码目标，不是共享环境权限已生效的证据。

小程序登录或恢复会话后必须先解析上下文。上下文缓存通过 `accountStorage(accountId)` 按账号隔离，键再包含企业 ID，版本为 1、TTL 为 5 分钟，读取执行完整运行时结构校验。企业切换先运行草稿守卫并让用户确认，再清除旧企业注册的列表、选项、草稿、缓存和请求结果；账号/操作代次不一致的迟到响应不能写回。

阶段 3 的 W01／W02 只读切片新增 `MOBILE_TASK_READ`，由迁移 `gaia-after-sales/database/20260918_service_personnel_task_read.sql` 为现有有效移动账号补齐，并由人员账号创建逻辑为新账号授予。该权限只允许读取当前会话人员在当前服务站下正式分配给本人的任务列表、分类计数和详情，不包含预约修改、异常提交、签到、处理、完工或审核等写能力。列表和详情必须使用同一服务端范围条件，越权直查返回 `404`；客户端人员 ID、服务站 ID 和企业 ID 均不能扩大范围。该迁移已于 2026-09-18 经明确授权执行到共享测试库 `gaia_wh_init_wzy`，影响 2 个既有移动账号；数据库复核 `accountId=2` 已持有该权限。其他租户库和环境仍须单独授权。

宿主 `gaia-saas-web` 与 `gaia-saas-web-jar` 仅额外放行 `/api/afterSales/mobile/service-personnel/tasks` 和其详情子路径，使请求可以到达售后域移动会话校验；这里的 Shiro `anon` 不等于匿名可读，缺少有效 `X-AFS-SESSION-ID`、`MOBILE_TASK_READ` 或本人当前服务站数据范围时仍由业务门面拒绝。

## 5. 共享测试库与 G1 验证记录

2026-09-18 经明确授权在共享测试库 `gaia_wh_init_wzy` 执行迁移。执行前 4 张目标表均不存在；执行后 4 张表和 10 个主键／唯一／检查约束完整。随后通过 Gaia 后台真实 `POST /api/afterSales/service-resource/personnel` 创建专用测试人员 `SP-G1-20260918-01`，在同一事务内生成移动账号、PBKDF2-SHA256 密码摘要、两项精确移动权限，并绑定分别属于企业 `-2`、`161` 的服务站 `3`、`5`。未复用已有服务人员姓名、手机号或客户端人员 ID。

本机宿主使用根 context path、显式单租户 ID 和独立本地 Redis，微信开发者工具请求指向 `http://127.0.0.1:18080`。真实验证结果：

- 登录、上下文查询及会话恢复成功；上下文返回稳定 `accountId=1`、`personnelId=4` 和服务端计算的两个企业候选。
- 企业从 `-2` 切换到 `161` 后，当前服务站从 `3` 变为 `5`，再次恢复仍为新上下文；旧 `contextVersion` 请求返回 `409`，列表外企业返回 `403`。
- 移动令牌访问 Web 派单查询返回 Gaia 未登录 `4001`；数据库权限只有 `MOBILE_CONTEXT_READ`、`MOBILE_ENTERPRISE_SWITCH`，能力明确关闭派站、派人、完工审核和库存审批。

阶段 1 的 G1 已达到，但该结论仅覆盖身份、上下文和移动 API 门面，不增加 W01～W16 实现计数，也不代表其他环境已迁移、阶段 2 已开始或业务 UAT 已完成。其他租户库部署仍须单独审批；专用测试账号应在不再使用时由环境负责人停用或删除。
