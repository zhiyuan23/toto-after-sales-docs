# 售后子系统国际化架构与迁移规范

- 日期：2026-09-12
- 范围：`frontend/gaia-ui/apps/after-sales`，Web 后台、跨工作视角。
- 来源：用户要求增加中英文切换，并先完成技术准备和小范围验证，再由新对话继续迁移。
- 关联：[国际化试点与交接 Spec](../specs/2026-09-12-国际化基础与商品分类表单试点.md)、[Web UI 规范](05-gaia-ui售后服务UI样式规范.md)。
- 本文规定技术实现方式；哪些页面已经完成及验证边界以 Spec 为准。现阶段不代表整个子系统已双语化。

## 1. 架构与边界

使用 `vue-i18n` Composition API，在子系统内持有唯一全局实例。首版语言为 `zh-CN`、`en-US`；缺省及非法存储值回退中文。两套词条静态打包，不增加远程翻译服务、后端配置接口或新的状态库。

```text
工具栏 LanguageSwitch / 用户偏好恢复
                 ↓
          setAppLocale / reloadAppLocale
                 ↓
          唯一 i18n.global.locale
          ├─ t() → 页面、配置工厂、提示
          ├─ ElConfigProvider → Element Plus
          ├─ VxeUI.setLanguage → VXE
          ├─ dayjs.locale → 日期语言
          └─ document.documentElement.lang
```

- 只翻译界面展示；接口 URL、字段名、枚举值、功能 code、权限码、ID、版本、路由、查询参数、幂等键及提交白名单保持原契约。
- 商品名称、型号、客户名称、组织名称、知识正文、备注等业务原始内容保留原值。切换语言不修改数据库，不翻译用户输入，不生成另一份主数据。
- 显示语言与时区、币种、税率、单位和接口日期格式相互独立；选择英文不改人民币、不换业务时区、不改变排序和查询范围。
- 未实现业务入口只翻译其现有占位说明，不能因为国际化而开放菜单或增加业务实现。主工程、legacy 售后入口、`src/views/common`、后端及小程序不在本轮范围。

## 2. 入口与偏好

- 顶栏右侧主题按钮后使用 `Languages` 图标，复用 `FaButton` 及现有下拉菜单组件，使用原生 title 提供悬停提示（避免嵌套提示浮层抢占菜单点击）。按钮名称随当前语言变化；列表项始终使用语言自身名称 `简体中文`、`English`，提供当前项选中状态、键盘操作和可见焦点。
- 点击语言项即时生效，不调用刷新、不重新挂载页面、不重置页签、不重新获取业务列表或权限。
- `src/features/preferences/language.ts` 使用现有 `userPreferencesKey`，在其后添加 `:locale`，与菜单、主题、列表视图偏好分别存储。租户和用户隔离方式与既有逻辑一致；退出清理沿用已有偏好保留规则。
- `setAppLocale` 是用户切换入口，校验值并尝试持久化。未登录或存储不可用时仍支持当前页面内切换，使用者不会因无法保存偏好失去操作能力；跨刷新持久化仅在可识别账号且存储可写时保证。
- `reloadAppLocale` 用于启动及登录后恢复，不反向写存储。其他标签页相同账号偏好变化由 `storage` 事件同步，避免形成互相写回循环。账号变化仍由现有会话机制处理。
- 当前未在登录页增加语言按钮；登录页本身及访客偏好属于后续迁移范围，不能宣称已完成。

## 3. 词条与开发接口

代码入口：

| 文件 | 职责 |
| --- | --- |
| `src/locales/index.ts` | 全局实例、只读语言 ref、`useAppI18n`、`translate`、语言切换与恢复 |
| `src/locales/runtime.ts` | Vue 插件安装、组件库／日期／HTML 语言联动、跨标签页事件及卸载清理 |
| `src/locales/messages.ts` | 词条注册、`MessageSchema`、`MessageKey`、`Translate` 类型 |
| `src/locales/{zh-CN,en-US}/*.json` | 按用途成对维护的平铺词条模块 |
| `src/locales/errors.ts` | 前端自有 `LocalizedError` 及显示函数；原始后端错误回退 |

当前已有 `common`、`layout`、`navigation`、`profile`、`appSettings`、`category`、`upload` 模块。后续按 `catalog`、`network`、`customer`、`workOrder`、`inventory`、`dashboard`、`system` 等稳定业务域新增，不按日期或开发批次命名。

- 使用语义键，例如 `category.enterName`；模块 JSON 内保持平铺，便于检查与交接。不要用完整中文作 key，不创建中文→英文全局替换表。
- 增加一个模块必须同时新增中英文文件并在 `messages.ts` 注册；两种语言相同 key、相同参数名、非空值。`enUS satisfies MessageSchema`、词条检查和测试共同验证。
- 在 Vue 中使用 `const { t, locale } = useAppI18n()`。本项目入口统一使用全局 scope，不在各模块再次 `createI18n`，不为已有组件增加仅用于注入翻译的包装页。
- 模板直接 `t('common.save')`；动态状态使用明确的稳定值映射到 key。固定枚举写 `Record<State, MessageKey>`，不要通过拼接任意字符串或类型强转绕过键检查。
- 文案中的名称、数量用参数传递，例如 `t('upload.limit', { count })`。需要英语单复数时写完整语句或分别定义单数、复数键，由数量选择；不拼接中文量词，不直接插入 HTML。
- 同一业务术语保持一致：分类 Category，商品 Product，商品系列 Product series，配件 Part，代理商 Dealer，门店 Store，服务站 Service station，服务人员 Technician，工单 Work order，派单 Dispatch，购买登记 Purchase registration，安装码 Installation code，工作视角 Workspace。品牌、产品型号及正式组织名称保留原文。

## 4. 响应式配置与状态保留

采用已有商品分类范例：

```ts
// schemas/index.ts：配置工厂只返回展示配置，不请求数据。
export const createFields = (t: Translate): SearchField[] => [
  { key: 'keyword', label: t('category.name'), type: 'input' },
]

// index.vue
const { t } = useAppI18n()
const fields = computed(() => createFields(t))
```

- 不在模块加载时调用 `t()` 并将结果存成永久数组。筛选、表头、卡片、详情、按钮、选项、规则都应在 `computed`、渲染或动作执行时生成。
- `EsSearch` 只有字段 key 结构变化时才协调字段模型，保留仍存在字段的本地草稿；文案、选项标签变化不重置草稿、不发出查询。父组件显式修改 `modelValue` 仍按既有逻辑同步。
- 字段 key、选项 value、表格 prop、row key、操作 key 稳定；不得给页面、表格、弹窗或 KeepAlive 加语言 key 强制重建。
- 新增／编辑表单只在原来的打开动作中创建或回填 model。语言变化不触发 `openEdit`、`openCreate`、数据请求、关闭确认、dirty 更新或提交。
- 校验规则为 `computed`；关闭 `validate-on-rule-change` 自动全表校验。语言变化时只对已经显示错误的字段重新校验，避免对未触碰字段突然报错。试点覆盖基础必填校验；异步规则按本模块原契约补充防重复校验验证。
- 通用组件默认文案在渲染时 `props.xxx ?? t(...)`，调用方传入的自定义文案原样展示，由调用方负责翻译。不要在 `withDefaults` 宏中调用依赖运行期 scope 的 `t()`。
- `EsSearch` 标签最多占字段列宽的 40%，长文本自然换行，不能用省略号或仅 title 代替完整标签；输入框保留其余空间。该规则对中英文共用，不改变查询或布局断点。
- 英文长标签按现有表单和表格约束调整 label-width／minWidth／换行／Tooltip；保留桌面高度链、分页位置和按钮可用性，不随意放大所有列或复制一套英文布局。

## 5. 菜单、页签与页面标题

已实施：`locales/navigation.ts` 用固定功能 code、分组 ID、视角 ID 映射词条；菜单／路由／面包屑／页签附带 `titleKey`，统一通过 `displayTitle` 渲染。原始 title 保留为自定义名称的回退，权限及图标映射继续使用原始标识。

统一实现约束：

1. 在菜单／路由／页签类型中添加可选 `titleKey: MessageKey`，保留原 `title` 用于动态业务名称及未知节点回退。标题解析函数优先按 titleKey 翻译，其次读取原字符串／函数 title。
2. 售后功能以稳定 `feature.code` 对应 `navigation.<code>`；分组使用稳定 group ID，视角使用稳定 view ID。所有映射只定义显示名称，不参与权限过滤或路由匹配。图标仍按已有原始映射取值，不能用翻译后的名称做 key。
3. 导航投影只附带翻译 key，不因语言变化重复调用 `setMenus`／`selectView`，保留手动展开、收起状态和活动路由。
4. 菜单、面包屑、Tabbar、NavSearch、工作视角切换统一在渲染／计算时解析标题；业务首页内部快捷卡片仍由后续模块迁移。菜单搜索只检索已授权项，支持中英文名称和既有 path，英文忽略大小写；不要把未授权完整词条当作可搜索菜单。
5. 已打开页签保存 titleKey，渲染即时解析；页签身份仍由原 pageIdentity 决定，不能用翻译结果区分页签。
6. `App.vue` 的 document.title 更新显式依赖 locale；内置系统名称使用 layout 词条，普通页面标题按 key 翻译；英文品牌使用两行排版，避免挤占菜单。语言不进入 URL。

顶部／单侧栏两种模式、多个页签、手动收起分组、双语菜单搜索和未授权节点隐藏已完成隔离验证，证据见 Spec 第 3.2 节。菜单搜索随授权菜单变化更新候选，不随语言切换重新投影菜单。

个人设置复用同一词条和表单状态。内置工作视角名称可按稳定 ID 翻译；当前用户详情只提供角色名称及角色 ID，没有可确认的内置角色代码与英文名，因此个人资料中的角色／组织／姓名原文保留，不做中文名称猜译，也不追加角色列表请求。

## 6. 错误、校验和业务逻辑

本轮已清除 API 透传与登录链接消费方对中文认证提示的匹配，改用稳定 `LOGIN_REQUIRED`／`SESSION_CHANGED`。后续错误迁移遵循：

1. 先定位匹配方及生产方，将前端可确认的认证／网络错误分类为稳定 code；只根据现有 HTTP 状态、会话事件、明确后端错误码建立分类，不从中文文案猜测业务状态。
2. 同一分类的生产、透传和消费位置一起迁移；登录链接／重试按钮按 code 显示。尚未成套迁移前保留原错误文本及判断，不只翻译生产方。
3. 前端自有错误使用 `LocalizedError(code, messageKey, params)`；错误 code 不随语言变化。展示时 `formatUiError`，未知后端错误保留原始 message，缺少有效 message 时显示本地通用失败提示。
4. 异步状态保留原始错误对象，到渲染时解析。`useCrudDialog` 已提供可选 `formatError`，错误 getter 可响应 locale；兼容已有调用方显式设置或清空 `error.value`。直接设置文本的旧调用方仍是文本快照，后续需分别迁移。
5. `useUiErrorState` 保留错误对象并返回响应式 error／loginRequired；列表、关联列表、详情与个人设置已接入，共享请求层及 API 透传链已使用稳定认证码。其余业务页面直接保存 message 的位置仍需逐页迁移。后续按同样原则扩展，保留只读／写入超时差异、写入结果未知提示、取消请求和过期响应隔离；不得让语言变化重发请求。
6. 消息弹窗和 Toast 在动作发生时翻译。已弹出的阻塞确认框／短期 Toast 不强制原地切换，下一次打开使用当前语言；可见表单字段、长驻错误区必须即时更新。

图片格式校验已将返回结果改为 `format`／`size`／空字符串，规则不变，由 UI 选择文案。这个范例用于说明“结果码与展示分离”，不是让其他模块照搬图片规则。

## 7. 完成判定与检查

每个模块必须覆盖入口页、列表／卡片、筛选、表头、选项、空态／错误态、详情、表单、Tooltip、aria-label、确认提示和前端操作结果。函数返回的详情数据、列配置和 API 本地错误文本也要检查，不能只扫描 Vue 模板。

在子系统目录使用项目固定 Node 22.23.1、pnpm 10.8.1：

```sh
pnpm --ignore-workspace check:i18n
pnpm --ignore-workspace test:i18n
pnpm --ignore-workspace typecheck
pnpm --ignore-workspace build
node scripts/check-i18n.mjs --inventory
pnpm --ignore-workspace test:i18n:browser
```

- 独立试点入口：`http://127.0.0.1:9017/after-sales/tests/browser/i18n.html`。该专用启动配置拦截 `/api/`，保存操作只写内存；不要改用主工程业务代理来运行该隔离验收。
- 公共框架隔离入口：`http://127.0.0.1:9017/after-sales/tests/browser/shared-i18n.html`，真实布局／菜单／个人设置，资料和改密请求仅为内存模拟；Alt+L 仅用于弹窗内验证语言切换，Alt+S 仅打开测试用应用设置面板。
- 分类整页隔离入口：`http://127.0.0.1:9017/after-sales/tests/browser/category-i18n.html`，使用相同的专用启动配置，验证列表／卡片、操作提示／菜单及筛选标签。
- `--inventory` 只输出中文候选（脚本字符串及模板行），不是覆盖率；注释、业务值、机器判定字符串和第三方资源需人工分类。不要为使候选数变零而删除业务值或弱化检查。
- 词条检查覆盖文件、键和插值参数；类型检查覆盖语义 key。既有源码结构断言若因翻译调整，应保留对应行为检查，不删掉权限、白名单、事务／请求、ID 和版本断言。
- 浏览器验证必须看实际布局与交互，至少包含中文→英文→中文、草稿、已显示校验错误、一次筛选／保存对应一次请求、失败保留与重试、英文长文本。涉及通用组件时回归试点与该组件另一个既有使用方。
- 无关既有失败按证据单列；新增失败必须解决。研发验证不能代替正式账号、数据和共享环境验收。

官方依据：[Vue I18n Composition API](https://vue-i18n.intlify.dev/guide/advanced/composition)、[Element Plus 国际化](https://element-plus.org/en-US/guide/i18n.html)。当前依赖已锁定版本；后续迁移不顺带升级工具链和组件库。
