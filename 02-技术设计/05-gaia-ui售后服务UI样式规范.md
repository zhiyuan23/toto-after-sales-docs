# gaia-ui 售后独立子系统 UI 与前端复用规范

- 更新日期：2026-09-15
- 适用范围：`gaia-ui/apps/after-sales`
- 当前基线：已开发的独立子系统“商品分类”功能

## 1. 开发位置与适用边界

后续 Web 售后功能默认在 `gaia-ui/apps/after-sales` 开发，使用子系统自身的路由、页面、通用组件、composables 和 API 适配层。除非用户明确要求维护旧入口，不再把新功能实现到主系统 `src/views/afterSales` 或 `src/components/commonV2` 中。

主系统旧售后页面及 `commonV2` 仅作 legacy 实现保留，不再是子系统新页面的开发基线。子系统不复制 `commonV2`，不运行时导入主系统源码，不修改受保护的 `src/views/common`。

## 2. 标准功能范例

标准列表和表单功能以以下已实现代码为首要参考：

- 页面：`apps/after-sales/src/views/catalog/category/index.vue`
- 表单弹窗：`apps/after-sales/src/views/catalog/category/components/CategoryFormDialog.vue`
- 模型和映射：`apps/after-sales/src/views/catalog/category/model/`
- 筛选与表格配置：`apps/after-sales/src/views/catalog/category/schemas/`
- 列表方法：`apps/after-sales/src/composables/useListPage.ts`
- 弹窗方法：`apps/after-sales/src/composables/useCrudDialog.ts`

范例用于复用页面结构、状态处理和交互模式，不表示可复制商品分类的字段、校验、接口、权限码、引用规则或启停规则。

## 3. 通用页面结构

标准列表页默认使用：

```text
FaPageMain
├── EsSearch
├── EsListToolbar（存在已授权页面操作时）
├── 错误／业务提示及重试入口
└── EsTable（包含表格、行操作和可选分页）
```

- 页面使用 `FaPageMain` 填满子系统宿主剩余高度。
- 标准列表页必须建立连续高度链：页面根容器使用宿主可用视口高度并设置 `min-height: 0`，`FaPageMain` 内容区及 `EsTable` 直接父层使用 `flex: 1` 和 `min-height: 0`。表格在剩余空间内撑满并内部滚动，分页固定在底部；即使列表为空或加载中也不能按内容高度收缩，业务页不得写死像素表格高度。
- 筛选使用 `EsSearch`，不在功能页重新实现同类筛选容器、展开收起或重置逻辑。
- 页面操作使用 `EsListToolbar`；无已授权操作且没有按需帮助入口时不渲染空工具栏。
- 列表、树表、行操作和分页优先使用 `EsTable`，页面只提供列配置、业务数据和已授权操作。
- 列表页默认不使用不可关闭的信息 Alert 常驻展示架构边界、数据归属、研发阶段、一期范围、后续规划或页面功能复述；这些内容写入项目文档、操作指南或按需帮助，不占用每次进入页面的主要空间。只有当前状态确实需要用户处理的错误、权限、合规或风险信息才在列表上下文显示。
- 仅对某条记录、某个字段或某次动作生效的限制必须就近提示：字段因业务规则不可编辑时，在对应表单内说明原因和解除条件；停用、删除、发布等动作的影响放入操作前确认；提交范围和不可变数据规则放入当前弹窗。后台仍执行相同校验，提示不替代服务端约束。
- 会影响数据理解但不需要每次阅读的稳定口径（例如报表统计范围和不可跨组合计规则）使用工具栏“统计口径”等按需入口；隐私授权、敏感信息处理和不可逆后果等高影响内容仍可保持显式可见。
- 当前阶段统一隐藏表格的“查看／预览”行操作（`detail`），包括“更多操作”内的入口；有权限显示的 `edit` 操作排在第一位，其余操作保持原顺序。隐藏项不占列宽，整列无可见操作时隐藏操作列。详情组件与关联链接直达保留。
- 列表页不设独立刷新按钮；保存、启停等操作成功后刷新，失败时保留明确重试入口。
- 未接真实接口时显示未接入状态，不伪造列表、总数、分页或可执行操作。

## 4. 通用组件与方法复用

| 层级 | 默认职责 |
| --- | --- |
| `components/common/EsSearch` | 筛选字段配置、默认值、展开/收起、筛选和重置事件 |
| `components/common/EsListToolbar` | 页面级新增、批量等操作容器 |
| `components/common/EsTable` | 列表/树表展示、加载、空状态、行操作、分页 |
| `composables/useListPage` | 筛选草稿与已应用快照、页码、列表、loading/error、刷新、请求取消与过期响应隔离、删除后页码修正 |
| `composables/useCrudDialog` | 新增/编辑模式、独立表单模型、dirty、互斥提交、失败保留和成功关闭 |
| 功能 `index.vue` | 页面装配、权限初始化、业务事件协调及操作后刷新 |
| 功能 `components/` | 专属表单弹窗和复杂业务交互 |
| 功能 `model/` | 类型、默认值、详情回填、查询归一化和提交字段白名单 |
| 功能 `schemas/` | 筛选项和表格列配置 |
| `api/<domain>/` | 按真实契约处理请求、业务错误、响应适配和 `AbortSignal` |

- 已有通用能力能满足时必须直接复用，不在业务页复制查询、分页、弹窗状态或行操作框架。
- 确有多功能可复用的缺失能力时，最小扩展子系统现有通用组件或 composable，并补充针对性测试；业务专属逻辑保留在功能目录。
- `useListPage` 不自动请求、不推断 API 或权限；`useCrudDialog` 不承担业务校验和传输。
- 表单使用默认值工厂和 mapper 创建副本，不直接编辑列表行。校验与保存在业务功能内完成；提交失败保留输入，提交中禁止重复提交和关闭。

## 5. 查询、权限与业务边界

- 筛选和重置回到第 1 页，分页使用已应用的筛选快照；一次用户操作只发起一次查询。
- 请求取消和过期响应隔离用于防止旧数据回写，不能替代后端权限和数据隔离。
- 页面先获取真实领域权限；`read=false` 时不请求业务列表。页面操作按权限显示，行操作以后端返回的 `actions` 为准。
- 前端不推断角色、不复制数据范围或状态机，不把隐藏按钮当作授权。
- 租户、组织、门店、服务站或用户上下文变化时，先清理旧列表、选择、详情和表单，再在新权限确认后加载。
- 状态迁移、引用限制、并发版本和提交字段白名单仍按各功能契约实现，不因复用通用 CRUD 能力而放宽。

### 5.1 表格关联项跳转

- 已验证的实现基线为“门店管理的所属代理商 → 代理商详情”：使用字符串 `dealerId`、命名路由 `afsDealer` 和 `dealerId` query 直达详情，关闭弹窗后清理 query。后续页面复用该技术模式，不复制其业务字段。
- 只将具有明确关联语义的编号、名称、单号或关联数量渲染为链接；不把整行、状态或无关字段全部链接化。
- 实现前必须明确源列、目标资源、已注册路由、详情／带条件列表语义、稳定关联 ID 和目标 `read` 权限；不以显示名称或行号代替 ID，长整型 ID 按字符串传递。
- 只有目标资源可读、关联 ID 有效且目标页可达时显示链接，否则降级为原文本或 `—`；前端隐藏不替代目标页和 API 的权限校验。
- 系统内导航默认使用 Vue Router 真实链接并在当前页签打开，保留键盘、右键和 Ctrl/Cmd 新页签能力；不使用 `window.location`、强制新页签或在路由中携带敏感数据。
- 通过 `TableColumn.link` 配置 `to`、`visible` 和 `ariaLabel`，由 `EsTableLinkCell` 统一解析目标并渲染 `RouterLink + ElLink`；业务页不在单元格插槽中重复拼接路由、散落 `router.push` 或自建链接样式。
- 链接沿用主色并在 hover/focus 时有明确反馈，具备语义化链接、可见焦点和可理解的无障碍名称；截断文本可查看完整值，点击链接不误触发行选择或其他行交互。
- 目标页支持路由直达和刷新，弹窗型详情关闭后使用 `router.replace` 清理定位 query；需保留源列表完整筛选、页码和滚动现场时，必须在对应 Spec 明确并通过页面缓存或路由状态单独实现。完整实施规则见[AI 开发执行规范—表格关联项跳转约束](../03-开发管理/03-AI开发执行规范.md#表格关联项跳转约束)。

### 5.2 关联跳转落地与加载规则（2026-09-10 调整）

- 按用户到达后的任务选择展示形式。分类等字段少、需要查看层级并继续管理的主档，优先进入目标列表，定位并高亮目标行、展示完整层级；不默认“切换列表后再自动弹出详情”。商品档案 → 商品分类首先按此实施。
- 分类列表顶部显示“已定位分类：名称”和“取消定位”，保留正常筛选和行操作。目标行滚动到表格可视区域；取消定位仅清除定位参数与高亮，不重新查询、不重建页面。用户主动筛选时退出定位，再执行一次筛选查询。
- 分类列表响应已包含展示所需字段，进入只请求一次列表，不追加单条详情请求。参数无效或当前可见列表中找不到目标时明确提示，不猜测数据被删除还是无权限，不自动扩大权限或用名称模糊匹配。
- 其他分页主档和业务列表统一使用 `useLinkedListPage + EsListFocus`：商品、配件、代理商、门店、服务站、服务区域、服务人员、顾客购买记录、工单。定位期间只展示目标记录并高亮，隐藏普通分页；取消定位恢复原列表、已应用筛选、页码和总数，不重新请求。主动筛选退出定位并仅查询一次。
- 分页列表不能将“当前页未命中”当作资源不存在。先复用已加载的目标行；未命中时用对应业务已有的按 ID 读取接口精确加载，仍由该接口校验权限。首次进入最多一次列表请求和一次必要的精确读取，保持一段连续 loading；不遍历全部分页、不按名称模糊检索、不自行添加后端未支持的 ID 筛选。
- 顾客购买记录和工单定位后可通过“查看完整详情”手动阅读明细，关闭手动详情不取消定位或刷新列表。知识库正文、标签版本和投诉处理记录的同页阅读入口保留原详情语义，不属于跨页关联定位。
- 定位状态不改变业务操作键、权限或提交契约。快速切换 ID、取消定位、组件销毁及权限失效后忽略旧响应；返回记录 ID 不一致时拒绝展示。读取失败显示错误与重试，取消后可恢复原列表。
- 已登记的定位／详情 query 是同页展示状态，不作为页面实例或页签的新身份；添加、切换或清除该参数不重建列表、不新增同名页签，也不触发全局导航进度或滚动复位。其他业务筛选参数保留既有路由语义，菜单与 API 权限守卫继续执行。
- 原 5.1 节的“门店 → 代理商弹窗”仅作为历史实现记录；当前已改为列表定位，新场景按本节执行。刷新／复制链接仍以稳定字符串 ID 恢复定位，独立打开不能依赖来源页内存。

## 6. 视觉与样式维护

- 子系统页面沿用已有 `FaPageMain`、`EsSearch`、`EsListToolbar`、`EsTable`、Element Plus 和子系统现有主题，不引入第二套 UI 体系。
- “渠道与网点”下的代理商、门店、服务站和服务区域共享主档卡片外壳：标题区使用对应业务图标、名称、编码和状态徽标，卡片网格最小宽度为 520px，默认不使用阴影，鼠标悬停时仅以主题蓝色边框反馈；各页面保留已有字段、关联链接、备注和操作，不为视觉统一删减业务信息。代理商、门店和服务区域统一使用通用无图片卡片，正文为固定三行两列、单元格高度 50px 的标签—值网格；奇数个字段时最后一项自动占满整行。信息网格不使用内部横线或竖线，依靠固定行高、24px 列间距和留白对齐；仅保留标题、信息和操作三个区域之间的外层分隔。卡片名称使用主文字色和较高字重，字段标签使用次要文字色，字段值使用常规文字色和 500 字重，可点击值保留主题链接色；标题和值均以单行省略保证同页卡片严格对齐，完整内容通过原有标题提示和详情入口读取。窄屏时双列网格回落为单列。
- 无主导航的侧边栏模式切换不同一级分组下的二级页面时，必须复用当前菜单实例，并保留用户手动展开或收起的分组状态；路由变化只更新当前项及展开其所属分组，不得重复写入相同菜单树、重建整棵菜单，或把用户已收起的旧分组再次展开。含主导航的侧边栏切换一级主导航时，仍可按新的投影菜单重建次导航。
- 工具栏全屏入口使用浏览器标准 Fullscreen API，并兼容现有前缀接口；进入、退出及用户按 Esc 退出时同步按钮状态。按钮须提供“进入全屏／退出全屏”的可访问名称，浏览器不支持或拒绝全屏时显示明确反馈，不得静默无响应。
- 独立登录页与顶栏个人信息模块复用 gaoge-compass Admin 的视觉结构和交互分组；登录页不展示验证码，售后品牌与 Gaia 认证契约保持独立。个人信息下拉提供首页、个人设置、快捷键介绍和退出登录，个人设置中的基本资料只读展示当前账号，安全设置仅调用 Gaia 自助改密接口；不得复用管理员用户编辑接口修改当前账号，也不得把管理员用户／角色管理入口合并到个人设置。
- 通用视觉问题在现有通用组件中修复，不在多个页面重复覆盖；业务专属样式保留在对应功能目录。
- 表格单元格内展示多个并列分类或能力时，统一使用 `es-table-tag-list` 标签组：采用紧凑、中性的 `small`／`plain` 标签和 6px 横纵间距，移除标签各自的外边距。列宽应保证当前语言下的常见短值优先在一行完整展示；空间确实不足时允许整枚标签自然换行并保留纵向间距，不压缩、截断或用 `+N` 隐藏影响判断的信息。标签颜色只表达已有业务语义，不为装饰给不同分类任意分色。
- `EsSearch` 筛选项保持等宽，按钮组占一个等宽网格列；按容器宽度切换默认展示数量，不逐项测量控件或按钮。默认列宽下，904／1216／1528px 起分别展示 2／3／4 项，较窄时展示 1 项；全部条件可见时不显示展开入口，展开后的各行仍等宽。按钮组收起时在第一行最右列，展开时在最后一行最右列；条件恰好填满整行时，按钮另起一行靠右。页面不再指定固定展示数量。
- 不修改主系统全局主题或无关业务模块，不为单页视觉差异复制整套组件。
- 当前以桌面管理后台为验收目标，保留现有响应式能力，不做移动端/窄屏专项验收。

### 6.1 表格操作列规范（2026-09-10 确认）

- 统一使用 Lucide 简洁线性图标。编辑使用单支铅笔 `lucide:pencil`，不随业务模块改成纸笔、画笔或资源图标；图标 16px、按钮 32px、间距 8px，使用子系统主题色。
- 每行最多显示两个图标按钮，包含“更多操作”：一个可见操作直接显示；两个直接显示；三个及以上显示首要操作 + 省略号 `lucide:ellipsis`，其余进入菜单。编辑优先，其余保留页面配置顺序；页面不可将上限提高到三个。
- 行内纯图标按钮保留随当前语言显示的 Tooltip，悬停延迟 300ms；“更多操作”同样保留提示。按钮提供与操作名称一致的 `aria-label` 和可见键盘焦点。
- 更多菜单只显示随当前语言显示的操作名称，不显示图标、不预留图标占位、不重复添加 Tooltip。名称应准确描述动作；处理中允许附加对应语言的处理中提示。
- 普通操作使用统一中性色；删除等被业务明确标记为 `danger` 的操作使用红色，菜单内同样标红。启用、停用不自动推断为危险操作；确认弹窗、权限、显隐、禁用、加载和重复提交保护沿用业务契约。
- 通用映射集中维护在 `EsTable/action.ts`；已定义的标准动作按 `key` 选择图标，页面不重复覆盖。一个业务键承载不同动作时（如 `status` 同时表示启用／停用），由页面明确提供对应 Lucide 图标，通用组件不根据文案或行状态推断业务动作。新增业务动作优先补充中央映射，并同步 `EsTable/icons.json` 本地图标集合，避免依赖外部图标服务。

| 操作 | Lucide 图标名（统一 `lucide:` 前缀） |
| --- | --- |
| 编辑／启用／停用／删除 | `pencil`／`circle-check`／`ban`／`trash-2` |
| 确认／取消／重试／同步 | `check`／`undo-2`／`rotate-cw`／`refresh-cw` |
| 关联商品／配置／授权／更多 | `link`／`settings-2`／`shield-check`／`ellipsis` |
| 派工／改派／分配服务站 | `user-round-plus`／`arrow-right-left`／`building-2` |
| 审核／驳回／异常 | `clipboard-check`／`circle-x`／`triangle-alert` |
| 提交完工／重新打开／接收 | `send`／`rotate-ccw`／`package-check` |
| 确认出库／确认入库／重置密码 | `package-minus`／`package-plus`／`key-round` |

设计取舍：单支铅笔在小尺寸下轮廓更清晰；行内 Tooltip 帮助确认纯图标含义，不增加常驻文字；菜单已有中文名称，去掉图标可减少视觉重复。本节为后续功能复用与复盘依据，覆盖早期预览中“业务操作图标加文字”的探索方案。当前 `detail` 隐藏规则继续遵循第 3 节。

### 6.2 新增／编辑弹窗规范（2026-09-11 确认）

- 新增／编辑默认使用常规居中弹窗，不使用全屏弹窗。“居中”同时指水平和垂直居中，由 `EsFormDialog` 统一启用 `align-center`；业务页不得通过顶部 `margin`、`top` 或自定义包装层把弹窗改为居上。简单单列表单、需要较宽输入区的单列表单和双列或复杂表单在标准桌面视口下分别使用 620px、760px、960px；宽屏按下表提高上限。只有业务流程明确需要沉浸式大面积操作时，才在对应 Spec 确认全屏形式。
- 弹窗尺寸按交互结构和内容密度分级，不由页面开发者任意选择；同一业务族、同一字段结构的新增／编辑弹窗必须使用同一尺寸档。默认同时满足“可编辑字段不超过 6 个、不含多 Tab、动态集合、大型选择器或宽表格”的少信息表单使用 `small` 单列布局；图片上传和长文本本身不构成升级双列的理由。单列布局需要更宽输入区时使用 `medium`；只有标签短、控件内容紧凑且在目标桌面视口完成视觉验证时，才允许双列使用 `medium`。采用 96～112px 横向标签的标准双列表单默认使用 `large`，无论是否包含 Tab；多 Tab、大型权限树、动态集合或宽表格等复杂内容同样使用 `large`。长文本、附件和图片在双列表单中仍占满整行。业务内容的可读性明显不适合默认档位时允许升级，但不得降级造成输入区局促，并须保持同一业务族内同类布局一致。
- 新增及实质修改的业务表单弹窗统一使用 `apps/after-sales/src/components/common/EsFormDialog`，不得在业务页面重复封装 `el-dialog` 的宽度、滚动区、错误区和底部操作。组件按浏览器视口统一切换以下宽度上限：

| 浏览器视口宽度 | `small` | `medium` | `large` |
| --- | ---: | ---: | ---: |
| `< 1600px` | 620px | 760px | 960px |
| `1600～1919px` | 680px | 840px | 1080px |
| `≥ 1920px` | 720px | 920px | 1200px |

实际宽度仍统一使用 `min(当前视口档位上限, 100vw - 32px)`，窗口较窄时自动收缩并始终保留左右各 16px 安全间距；窗口进入 1600px 或 1920px 宽屏档时主动放大。业务页不得覆盖这些断点或编写另一组宽度。内部 `es-form-dialog` 整体最高占视口 85%，标题区和底部操作区固定，仅内容区纵向滚动。业务页不得让整个弹窗超过视口，也不得把保存／取消按钮放入会被滚走的内容区。
- 内容可能超过一屏的多 Tab 表单使用 `EsFormDialog` 的 `sticky-tabs` 能力，由内部 `es-form-dialog--tabs` 固定 Tab 导航并保持不透明背景和正确层级；滚动长表单时用户应能随时切换分区。Tab 固定不改变字段草稿、校验、权限、提交白名单或未保存关闭确认。
- 弹窗内视觉层级统一为“弹窗标题 → Tab 导航 → 分段标题 → 辅助描述”，主要依靠字号、颜色、间距和选中指示建立层级，避免用明显的粗体跳变制造强调。弹窗标题使用 17px／500／主文字色；Tab 默认使用 14px／400／常规文字色，仅当前项使用 500 字重和主题色，并配 2px 主题色指示线；Tab 区与首个内容分段保留 20px 间距。分段标题使用 14px／500／常规文字色，辅助描述使用 13px／400／次要文字色。不得让全部 Tab 同时加粗，也不得在业务页面各自覆盖字号、颜色、指示线或间距；数量只是标题补充时与 Tab 文案同级，不使用强调 Badge，只有明确的待处理状态才可使用状态标识。
- 桌面端字段较多的新增／编辑表单优先使用高密度横向标签：标签与输入框、选择框同排，单个弹窗内标签宽度统一，建议在 96～112px 之间按最长常用标签确定并右对齐；不要因个别超长标签无限扩大标签列，必要时精简文案或为该字段单独换行。短小表单、窄容器或标签本身需要较长解释时可使用顶部标签，不要求所有场景强制横排。
- 基本信息按业务任务分组，不按接口对象机械分组。每组由简短标题和可选的一句辅助说明组成；桌面端说明可与组标题同排。表单分组统一使用 `gaoge-form-section` 和 `gaoge-form-section__header`：首组不画线，后续组在标题上方使用 20px 留白和一条浅色分隔线，分隔线属于组与组之间；标题与其下方字段保持连续，不在标题下方另画线。避免重复卡片、重色背景或多层边框。标准字段使用双列网格和 24px 列间距，长文本、富文本、附件及图片等需要连续空间的控件占满整行；已有单列响应式保护继续保留。
- 控件顺序遵循“身份／归属 → 规格 → 状态与业务属性 → 内容 → 附件或图片”的实际操作路径；必填项靠前。所有可编辑的 `el-input`（含文本域）、`el-select` 和 `el-date-picker` 必须显式提供占位符；文本输入默认使用“请输入……”、选择和日期控件默认使用“请选择……”。存在格式、示例、隐私或条件要求时，优先写成可直接指导操作的具体提示，不只复述字段标题；禁用只读或系统计算展示字段可不设置占位符。字段仍须保留可见标签，不能用占位符代替标签。格式、大小、数量、保存方式等关键限制应在操作发生前可见，不依赖报错后才告知。
- 同一表单网格内的 `el-input`、`el-select`、`el-tree-select`、`el-date-picker` 和 `el-input-number` 统一填满可用宽度，并使用通用表单控件高度；不得因 Element Plus 控件默认宽度差异造成日期框、树选择框比同列输入框短，也不在单个业务页用零散 `width` 或工具类逐项补齐。附件上传必须复用通用文件上传展示：标题通过 `el-form-item` 与其他字段共用标签列，上传入口、前置限制、文件名、大小、预览和移除状态保持一致。

#### 行政区与地图定位组件选择

新增地址类表单前，先确认业务只需要行政区层级，还是确实需要一个可计算、可导航的精确坐标。不得因为接口存在经纬度字段就默认接入地图，也不得在需要精确坐标时继续让用户手工输入经纬度。

| 使用场景 | 标准组件与交互 | 典型对象 |
| --- | --- | --- |
| 只用于行政归属、筛选、覆盖层级、统计或规则匹配，不消费单点距离与导航 | 使用 `views/network/shared/RegionFields.vue`。省／市／区县合并为一个可搜索、可清空并显示完整路径的 `el-cascader`，街道单独选择或录入，不接入单点地图 | 服务区域、区域筛选条件、覆盖范围配置 |
| 一个业务实体对应一个实际地点，后续需要导航、距离计算、地图展示、派单或现场到达 | 使用 `RegionFields.vue + MapLocationPicker.vue`。地图负责精确选点并回填地址层级和坐标，行政区、街道及详细地址保留为结果展示、降级录入和人工修正入口 | 代理商、门店、服务站、仓库或上门地址中已确认需要精确定位的场景 |
| 当前业务没有确认坐标用途，或对象表达一片覆盖范围而不是一个点 | 只使用行政区组件，不为视觉完整性增加地图。覆盖范围必须等待后端具备围栏几何模型、校验及展示契约后再接地图围栏 | 服务区域、销售区域、责任区域 |

行政区组件统一遵循以下约束：

- 不并排堆放省、市、区三个相互依赖的下拉框；表单模型仍按后端契约拆分保存各级名称。
- 行政区快照在控件首次展开时按需加载，不阻塞弹窗打开，也不将 `ADMIN_REGION` 字典作为省市区唯一数据源。
- 业务只要求精确到某一级时限制可选深度；允许不完整地址的主档可选择中间层级。
- 街道因变更频率和数据覆盖差异单独保留可搜索、可手工录入的控件，只有已选区县且首次展开街道时才请求街道数据。

精确地图选点统一遵循以下约束：

- 标准流程为“搜索地址／选择建议 → 地图定位 → 点击或拖动微调 → 确认”，确认后一次性回填省、市、区县、街道、详细地址、经度和纬度。地图结果允许人工修正行政区和地址，但经纬度只能由地图产生，不显示普通经纬度输入框。
- 父表单只在详细地址控件下方展示一行辅助状态：未定位时说明地图会回填哪些信息；已定位时展示“已完成地图定位”、坐标和“移除坐标”。两种状态使用相同高度，不再增加重复的位置预览区。
- “移除坐标”只清除经度和纬度，不联动删除行政区、街道或详细地址，避免误删仍可独立保存的业务地址。若业务确需清除完整地址，应提供名称明确的独立动作并按数据影响决定是否二次确认。
- 地图默认视角依次使用已有坐标、父表单行政区、IP 当前城市和城市级兜底；空表单不得以全国全景作为常规起点。已有坐标使用地点级缩放，行政区或当前城市使用城市级近景。
- 地图弹窗工具栏使用“地址搜索 + 重置”。重置恢复本次打开地图时的搜索内容、选点、标记和视角；不并列提供结果重复的“清空”。搜索框自身的清除只处理搜索关键词和建议，不删除已经选择的位置。
- 地图弹窗使用 `EsFormDialog` 的 `large` 尺寸和独立的地图高度规则，地图、已选位置摘要及固定底部操作必须在常见桌面视口内形成足够的选点空间；内容超高时仍只滚动正文区域。
- 地图 SDK 只在用户主动打开地图弹窗后按需加载，Key 与安全密钥从环境变量读取。地图未配置或加载失败时明确提示，父表单仍可手工录入行政区、街道和详细地址，坐标允许保持未设置；地图错误和加载状态不得锁定父表单。
- 集合或资源型 Tab 在名称后显示当前数量，内容区统一使用 `apps/after-sales/src/components/common/EsDialogTablePanel` 轻量外壳，不由业务页面重复拼接表格标题栏。外壳只负责 14px／500 的标题、13px 常规数量、按需说明、右上操作、提示区和弹窗内空状态高度，不得独立覆盖表头、行高、斑马纹、边框或圆角，也不持有业务数据、权限、请求、选择或提交状态。标题必须存在；只有名称不足以说明新增态暂存、编辑态即时保存、权限或操作影响时才增加一句说明，不为保持版式机械补文案。数量使用普通文本，不使用强调 Badge；操作区只放当前集合的主操作。标题信息块与右侧操作按钮按各自整体垂直居中，无论左侧只有一行标题还是包含第二行说明，都不得按首行顶部对齐。外壳内部按场景继续使用 `EsTable` 或 Element Plus `el-table`：只读展示及分页优先使用 `EsTable`，行内编辑、单选、多选等复杂表格保留 `el-table`，不得为了组件统一改变业务交互。两种实现必须共用 `es-table-surface` 基础视觉类，原生 `el-table` 还须显式启用 `stripe`；`EsTable` 在组件内部自动应用，两者保持相同的表头、行高、空状态文字和固定列基础样式。标准资源表格最大高度统一为 360px、空状态至少 220px，并由表格内部滚动；同一 Tab 中附属于长表单的次级紧凑表格可使用 220px 最大高度和 140px 空状态。独立选择弹窗不强制套用 Tab 表格外壳，但其中的表格仍须使用同一基础视觉类，可按其可用空间设置高度。新增态暂存、编辑态即时保存等提交差异必须在当前 Tab 或底部固定区明确提示，不允许用户猜测底部“保存”的作用范围。
- 点击新增／编辑后必须先建立本地表单模型并立即打开弹窗，不得在 `openCreate` / `openEdit` 中等待与首屏展示无关的字典、组织树、全量选项或未打开 Tab 的资源。选择项在用户首次展开对应控件时加载，Tab 专属资源在进入该 Tab 或发起具体操作时加载，同一弹窗周期内缓存并合并重复请求。编辑态为回显当前值所必需的选项允许在弹窗打开后后台预取；其 loading 只锁定对应选择控件或资源区，不得因非提交请求锁住整个弹窗。
- 只读状态使用文字或 Tag 展示并说明修改入口，不用禁用的 Switch、Checkbox 等交互控件伪装为只读信息。布尔编辑项可使用带“是／否”等可见语义的控件，但仍须保留可访问名称。
- 校验错误就近显示在字段下方；跨 Tab 提交失败时切回包含错误的 Tab，滚动到按视觉顺序排列的首个错误字段并把键盘焦点移入控件。固定 Tab 下的滚动目标必须预留偏移，不能把字段标签或所属分组标题遮住。接口或业务错误在弹窗顶部使用可读错误区展示，保留用户已填内容。
- 图片上传入口使用 Element Plus `picture-card` 的虚线加号卡片并提供 `aria-label`。卡片内部只保留加号；格式与单文件大小说明在整个方块外部下方另起一行，左侧与方块对齐，使用 12px 的次要文字颜色，常规宽度优先一行、空间不足时自然换行，不拼入字段标题、不放入方块内部，也不再使用信息图标 Tooltip。为保持高密度，不显示“点击 +”、`0 / 1` 等重复说明；业务数量上限仍由组件校验并在超限时明确提示。上传入口的可访问名称同时包含格式和大小限制；纯图标操作提供 Tooltip 和包含对象序号的 `aria-label`，图片提供可区分的替代文本；颜色、边框、圆角和交互状态沿用子系统主题 token，不为单个表单引入新的装饰风格。
- 底部操作统一按“取消／关闭在前、主要提交操作在后”排列，并在左侧提供必填说明或当前 Tab 的提交语义。桌面端按钮统一为 34px 高、至少 72px 宽、左右内边距 20px，按钮文案较长时允许自然扩宽；次要按钮使用 400 字重，主要按钮使用 500 字重，按钮之间保持真实 12px 间距，不得与 Element Plus 默认相邻外边距叠加。底部区域连同上下间距控制在约 64～68px，不为增强存在感额外加高。正文滚动区底部预留约 20px 视觉安全距离，底部区域保持纯净背景，不增加永久或动态阴影及渐变遮罩。滚动条使用稳定独立槽位并向弹窗右侧内边距移动约 8px，避免覆盖输入框、选择框或表格最右侧内容，业务页面不得自行添加另一层滚动容器。提交期间禁用关闭和重复提交，失败时保留输入与可读错误。嵌套编辑弹窗独立管理自己的关闭和提交状态，不随父弹窗内容滚动。
- 验收至少覆盖常见桌面视口下的左右留白、信息密度、标签和控件对齐、最大高度、内容区滚动、标题／Tab／底部操作持续可见、首个错误字段定位与焦点、Tab 数量和提交提示，以及新增／编辑切换后的数据不丢失。当前不做移动端／窄屏专项验收，已有响应式保护仍须保留。

### 6.3 通用表单组件与图片上传约束（2026-09-11 验证后确认）

- `EsFormDialog` 是统一交互壳，不是业务表单生成器。它只负责尺寸、视口约束、内容滚动、固定标题／Tab／底部操作、加载锁、顶部错误和通用按钮；调用方继续持有 Tab 类型和顺序、字段布局、校验、权限、提交白名单、脏数据确认及接口状态。复杂多 Tab 表单、标准双列表单与简单单列表单使用同一组件，通过 `large`／`small` 尺寸档和插槽组合内容，不复制另一套弹窗结构；`medium` 按第 6.2 节限定场景使用。
- `EsDialogTablePanel` 是弹窗 Tab 内集合／资源表格的统一结构外壳，不是另一套表格组件。标题、可选说明、数量、操作和提示通过明确属性或插槽传入，默认插槽继续承载现有 `EsTable` 或 `el-table`；外壳不得代理行事件、改写列配置、发起请求、推断权限或重新定义表格基础皮肤。表格基础视觉集中维护在全局 `es-table-surface` 类中，所有 `EsTable` 自动使用，业务中因行内编辑或选择而保留的原生 `el-table` 必须显式使用。普通列表页、独立选择弹窗以及不在 Tab 内的配置表格不强制套用该外壳，但也不得另建表格视觉体系。
- 现有业务新增／编辑及同构的一次性提交表单应迁移到 `EsFormDialog`，包括商品目录、服务网络、服务资源、客户预约与建单、投诉与知识库、沟通记录、会员标签、库存单据与仓库、用户与角色等模块。迁移不得改写业务字段、权限、校验或提交时机；横向标签为默认高密度布局，复杂内容按 `small`／`medium`／`large` 选择最小可用尺寸。关联商品等双栏选择器、纯详情／确认弹窗，以及表格内逐行独立保存的配置器不属于该壳层的强制范围，不得为了形式统一改变其操作模型。
- 新增标准表单弹窗时不得直接使用原生 `el-dialog`；若场景确实属于上述例外，应在代码评审中说明其交互模型为何不能使用一次性提交壳层。现有迁移清单及可编辑控件占位符约束由 `tests/form-components.test.ts` 固化，防止页面在后续修改中退回各自维护宽度、错误区和底部按钮，或再次出现无操作提示的空输入控件。
- 新增及实质修改的图片上传场景统一使用 `apps/after-sales/src/components/common/EsImageUpload`。组件以 Element Plus `el-upload` 承接文件选择和上传生命周期，通过业务方注入的 `upload(file, onProgress)` 完成真实上传并返回服务端规范 URL；通用组件不得推断接口、权限、目录或业务字段。既有旧上传组件不再作为售后新功能范例，随相关页面进入修改范围时再按本节迁移。
- 图片上传项默认占据表单整行，不放入双列网格的半列中压缩展示。格式与单文件大小统一由 `EsImageUpload` 内部的 `Hint.vue` 在上传卡片外部下方展示，调用方不得在字段标题、卡片内部或组件外自行拼接另一套说明；业务规则不同时只向上传组件传入参数，由内部提示同步展示。建议图片尺寸使用可选 `recommendation` 参数，显示在格式／大小之前；已有图片达到数量上限时仍常驻显示。
- 选择文件后立即显示本地预览和圆形百分比进度，不额外显示“上传中”文字；上传期间通过 `uploading-change` 通知弹窗合并为 loading，必须禁用重复选择、保存、取消、右上关闭和 Esc 关闭。上传成功后才把去重后的服务端规范 URL 写入业务模型，不得把 `blob:`、Base64 或本地路径写入提交载荷；临时对象 URL 在成功、移除或组件卸载时释放。
- 上传失败保留失败图片、文件对象和可读原因，恢复弹窗操作，并在图片卡片内提供“重试／移除”；重试重新进入上传锁，成功后收敛为正常图片。失败不得清空表单其他字段，不得出现无进度的全局静默等待，也不得因单次失败让弹窗永久处于 loading。
- 上传前同时校验格式、单文件大小和总数量，限制文案在选择前常驻展示；格式判断优先使用 MIME，并允许空 MIME 时按白名单扩展名兜底，不接受 MIME 与扩展名明显冲突的文件。默认图片规则为 JPG/JPEG/PNG/WebP、单张不超过 5MB、最多 10 张，业务规则不同时由调用方显式传入并在对应 Spec 记录。
- 成功图片卡片默认完整展示缩略图；桌面端鼠标移入后使用覆盖整张卡片的半透明蒙层，居中显示“预览／下载／删除”三个统一线性图标，不再常驻底部操作条。蒙层同时响应 `focus-within`，图标按钮可按视觉顺序通过键盘聚焦并保留可见焦点；不支持 hover 的设备直接显示操作层，不能把核心操作做成鼠标专属。只读或禁用态保留预览，隐藏会改变或导出数据的操作。纯图标按钮提供 Tooltip 和包含序号的 `aria-label`，图片提供可区分的替代文本，上传状态使用 `aria-live`，失败原因使用 `role="alert"`；图片预览使用统一查看器，蒙层过渡在减少动态效果模式下关闭。
- 验收除第 6.2 节内容外，至少覆盖进度从非零值更新到完成、上传期间全弹窗操作锁、成功回填、失败恢复、原文件重试、预览、移除、格式／大小／数量拒绝，以及简单弹窗和复杂多 Tab 弹窗两种组合。真实业务接口验证与本地模拟生命周期验证分开记录，模拟通过不得替代正式角色、对象存储和权限验收。

### 6.4 目录卡片视图（2026-09-11）

五个目录菜单保留表格并增加卡片，复用 `EsListViewToggle`、`EsRecordCard` 和 `EsTable` 卡片插槽；`EsListToolbar` 的 `tools` 插槽放置切换器。筛选、分页和请求状态共用，不在卡片中重复查询详情。分类采用当前层级与面包屑，商品／系列／配套品采用上图下文，配件采用左图右文。画廊图框 3:2、分类与配件 1:1，使用 `cover` 等比例居中铺满且无图片内边距；建议上传分别为 1200 × 800 px、800 × 800 px，并在新增／编辑位置常驻提示。商品相同编码与型号合并，空字段省略；配套品／配件品牌与型号同行，分类仅筛选时展示所属路径。图片有原图预览、无图及失败重试；背景、文字、边框和状态使用主题变量，兼容深色模式。操作和关联链接继续遵守第 5、6.1 节权限与图标规则。详见[字段、接口和验证记录](../specs/2026-09-11-商品目录卡片视图与深色模式.md)。

2026-09-12 起，所有支持表格／卡片切换的页面通过 `useListView` 共用一份 Pinia 显示偏好，按用户及登录信息中可获得的租户标识隔离，不再按菜单分别保存。偏好使用独立的本地缓存键，不覆盖导航模式或深浅色设置；刷新、同账号重新登录可恢复，同源浏览器标签页通过 `storage` 事件同步。共享缓存缺失或损坏时默认表格；旧菜单缓存没有最后选择时间，不猜测迁移，下一次明确切换写入新共享值。仅支持表格的页面继续使用组件默认表格，不读取或覆盖该偏好；切换不触发业务请求或改变筛选、分页和权限。实施与验证见 [OPT-20260912-01](../specs/2026-09-11-商品目录卡片视图与深色模式.md#opt-20260912-01)。

#### 6.4.1 渠道与网点主档卡片（2026-09-15）

代理商、门店、服务站和服务区域在保留表格的基础上增加卡片视图，继续复用 `EsListViewToggle`、`EsRecordCard`、`EsTable` 卡片插槽和 `useListView` 共享偏好。卡片与表格共用当前页数据、筛选、分页、定位、loading、错误和权限，不追加详情请求；没有读取权限时不显示切换器，只有读取权限但没有新增权限时仍允许切换视图。

这四类主档没有业务图片，统一使用无媒体区的 `master` 紧凑布局，不显示“暂无图片”占位，也不为不同实体增加装饰性色块。卡片按名称与状态、编码、单列关键字段、底部详情与业务操作建立层级；每个字段保持独立一行，标签使用统一宽度并与字段值横向排列，字段值使用剩余宽度，避免上下堆叠造成卡片过长。字段值确实超长时单行省略，标签和值均保留原生完整值提示，完整信息在详情中展开。名称、正文、边框、状态、焦点和明暗主题全部使用现有语义变量，卡片 hover 仅加强边框，不制造影响阅读的位移或动画。

字段按任务裁剪：代理商突出层级、上级、组织、所在地、下级代理商和关联门店；门店突出所属代理商、门店类型、营业状态、服务类型、所在地和组织；服务站突出行政区域、服务区域及优先级、服务项目、负责人、热线和师傅数量；服务区域突出行政区域、层级、关联服务站数量及带优先级的站点摘要。服务站信息较多且当前数据量有限，卡片网格使用最小 520px 的宽卡密度，正文按已确认的“业务分栏”原型分为左侧业务主列和右侧资源列。业务主列依次展示行政区域与行内定位状态、统一主色的服务项目标签，以及紧跟标题的服务区域数量和按真实优先级分项的区域块；区域块支持多项换行，不用顿号拼成单行摘要。资源列使用中性浅底和 Lucide 图标展示负责人、服务热线和师傅数量；正文按同排卡片等高拉伸，保证多行区域使单卡增高时其他卡片的分栏线仍延伸到正文底部。不在列表逐卡实例化在线地图，也不以固定标记位置伪装精确地图，真实地址和坐标仍来自业务数据。卡片底部保留显式 Eye 详情入口，编辑、配置、启停和删除继续复用表格操作契约、后端 `actions`、确认和重复提交保护；表格操作列仍遵守隐藏详情及最多两个图标槽位的规则。

四类主档详情统一沿用商品详情的信息层级，不再使用仅由旧式键值网格组成的详情：弹窗采用 1040px 桌面宽度和固定头尾，顶部以类型、名称、编码、状态及核心摘要建立身份区，正文按“概览／工商信息／关联资料／附件资料”实际可用内容显示页签。概览内使用 `EsDetailSection` 分组，服务站与服务区域的关联数据使用 `EsDialogTablePanel + EsTable`，代理商、门店和服务站的工商、附件资料完整展示；未提供的值显示 `—`，附件链接不可用时给出明确状态。详情与商品模块共用主题、滚动和信息层级，但不为无业务图片的网点补造图片占位。

### 6.5 目录详情阅读（2026-09-11）

五菜单卡片底部显式增加 Eye“查看详情”，Tooltip 与 aria-label 使用同一文案；图片点击继续预览原图，缺图也保留详情入口。卡片允许一个独立只读图标加原两个操作位置；表格仍遵守第 3、6.1 节隐藏 detail 和两个位置限制，不全局放开查看。

目录详情复用 `EsDetailDialog`，由 `EsDetailGallery`、`EsDetailSection` 组合图文摘要与分组资料；固定标题／关闭区，内部滚动，采用现有主题。概览、关联、已有故障／手册分开呈现；关联数量直接打开关联页签。详情原图完整包含，卡片封面等比裁切。分类复用已读行，其余详情按需读取并在弹窗内显示加载、错误和重试。字段、数量、价格零值和关联权限保持真实契约，不能为了美观隐藏业务必需信息。见[实现及验证](../specs/2026-09-11-商品目录卡片视图与深色模式.md)。

### 6.6 目录表格阅读与关联入口（2026-09-11）

五菜单首列复用 `EsRecordIdentity`，左固定，名称主信息、编码次信息；五菜单均展示已有缩略图，名称查详情，缩略图预览原图；分类／系列无图时保留同宽占位，分类树箭头位于图片前，缩进跟随整组资料。列顺序按身份、型号／归属、关联数量、价格／规格、状态、维护信息和操作组织；低频审计信息放详情，配套品／配件成本价按需显示。数量列提供只读关联入口，零值为文本；关联商品表将导航放在名称、分类和系列列，编码不再兼作链接。商品详情按精确 ID 延迟读取配套品／配件，展示对应必备数量并复用分页和请求隔离。链接继续要求目标读取权限、菜单可达及有效 ID；同模块定位也应关闭原详情。详见[列配置、契约与验证](../specs/2026-09-11-商品目录卡片视图与深色模式.md#表格阅读与双向关联优化2026-09-11)。

### 6.7 中英文支持（2026-09-12）

国际化统一遵循[国际化架构与迁移规范](12-售后子系统国际化架构与迁移规范.md)：单一语言状态、语义词条、响应式配置工厂，语言切换保留页面、筛选与表单现场。当前注册界面的公共框架、菜单、个人设置、通用反馈及各业务模块均已接入；完整迁移范围、验证结果和共享环境验收边界见[实施 Spec](../specs/2026-09-12-国际化基础与商品分类表单试点.md)。

业务原始名称、ID、枚举值、接口和权限不随语言改变；后续新增或尚未实现的界面仍须按本规范接入，不能只因工具栏提供语言入口就标记已支持英文。英文长标签按既有桌面布局规范验证，不复制另一套页面。筛选标签最多占字段宽度 40%，超长时自然换行，禁止以固定 6em 省略截断或仅 hover 提示替代完整名称。

## 7. 验证要求

- 新页面至少覆盖查询、筛选、重置、分页（如适用）、空状态、加载失败和重试。
- 写操作覆盖权限展示、校验、重复提交保护、失败保留、未保存确认及成功后刷新。
- 修改通用组件或 composable 时，运行其现有测试并回归商品分类及其他受影响页面。
- 新增表格关联跳转时，验证有权限与无权限、有 ID 与无 ID、字符串长整型 ID、目标直达与刷新、返回状态恢复、键盘及 Ctrl/Cmd 点击，以及 403、404 和加载失败；一次点击只导航一次。
- 按影响范围执行子系统定向测试、类型检查、生产构建和必要的桌面交互验证；标准列表页需同时检查有数据、空数据和加载状态下表格撑满剩余高度、内部滚动及底部分页位置。
- 隔离数据或构建通过不等于共享 MySQL、真实租户和正式角色验收完成，必须分开记录。
