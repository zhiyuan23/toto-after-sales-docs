## 查看原型

- 打开 [index.html](index.html) 可本地查看，不需要安装依赖或连接业务后端。
- 当前为消费者 v0.11 共 30 屏、服务人员 v0.8 共 28 屏，两端共 58 屏，各有 8 条核心流程。这是原型屏幕数，不是业务入口数量。
- 三个视图：单页走查、核心流程、页面总览。
- 右侧说明区记录页面目标和待确认规则，可切换“首次使用”“已登记产品”“申请已收到·等待联系”“服务进行中”“多项服务”五种消费者场景，以及加载失败等通用状态。
- 表单支持演示必填校验、会话内输入保留、登记结果回显和审核退回后的重提反馈。
- 页面使用虚构数据。非主流程入口仅提供说明性反馈；手机号授权、订单同步和扫码均为本地模拟，头像不上传服务器，拨号、定位、故障媒体上传和业务提交也未接真实能力。
- 刷新页面会清除演示会话。不要填写真实客户资料。

当前消费者产品服务流程建议从首页依次试用：切换两件产品 → 选择维修或使用指导 → 填写问题 → 联系与期望时间 → 核对提交 → 查看同一申请的进度。安装入口支持选择一件或多件产品；消费者安装开放条件仍待业务确认。右侧切换场景会清除消费者的演示数据，普通返回和产品切换会保留各自草稿。

## 服务人员 v0.8 当前服务与四分类怎么体验

- 首页按待处理／待补资料／审核中／历史任务四分类展示；底部仍为任务／配件／我的三个 Tab。
- 在陈女士任务中进入现场服务，点“定位签到”后返回首页，出现“正在服务”独立卡；也可通过无法定位的到达说明或远程指导的开始按钮进入。仅打开服务页不置顶。
- 当前服务卡显示客户、地址与填写进度，点“继续服务／继续填写完工资料”回到本单上次步骤；切换分类或搜索仍可见。下方列表不重复显示，但待处理计数包含置顶任务。
- 无服务中任务时显示简洁汇总；同时出现多张服务中任务时全部保留入口，不假设服务端已限制一单。完工提交、登记异常或改约后移出独立区域。
- 待补资料仅收录审核退回且未重提的任务，计数与地图筛选同步；取消待交单分类与独立交单页。
- 赵先生“补充资料”直达退回材料，审核中的黄先生只能查看进度。
- 在黄先生审核进度页，通过右侧“审核通过 → 服务中心回访”演示后台审核；工单进入历史任务 → 后续跟进，显示审核通过和待回访，无需再次提交。
- 孙女士是已审核通过的样例，可直接查看后续进度。审核通过不自动关闭；回访与后续办结仍由后台结果模拟。
- 未分配本人／未下发任务从列表、日程及地图统一排除，旧 `#w-handover` 链接转到审核进度，旧交单提交被阻止。

## 服务人员 v0.5 首页与快捷入口怎么体验

[打开任务首页](index.html#w-tasks) · [首页／日程／地图并排预览](worker-entry-overview.html) · [设计与验证](01-两端小程序设计说明.md#22-服务人员-v05--列表首页与日程地图快捷入口)

1. 任务首页默认展示列表，右上角保留“日程”“地图”图标和文字入口；底部仍为任务、配件、我的。取消列表／日程／地图三个平级视图 Tab。
2. 点“日程”进入独立日程页，继续上次查看的日期；点“今日预约”数字直接查看今天。日程页保留周历、月历、过去记录、未来预约和待安排入口。
3. 点“地图”按列表当前队列和筛选查看位置；日程内的地图／路线带入选定日期；工单详情“去这单”直接进入该单路线，地址无坐标时提示核实，远程任务不展示上门入口。
4. 日程和地图作为下级页面显示返回按钮；返回首页保留原队列、筛选、排序、已查询内容、未提交的搜索文字和列表滚动位置。条件变化后不复用旧位置，切企业、退出或重置清空上下文。

三种展示继续共用工单数据，各自按列表条件、确认预约日期或可标点位置展示，数量不要求相等。本版共 59 项自动检查、10,440 组模板组合；仍为本地业务模拟，正式接口和微信能力未接入。

以下 v0.2～v0.5 记录保留历史演进；平级视图 Tab、日程路由别名、交单操作和旧屏幕数已由后续版本替代，在线预览统一展示当前代码。

## 服务人员 v0.4 日程怎么体验（历史）

[打开日程](index.html#w-schedule) · [今天／未来／过去并排预览](worker-schedule-overview.html) · [规则与验证](01-两端小程序设计说明.md#21-服务人员-v04--日程与历史预约)

1. 任务页顶部切换“列表／日程／地图”；日程默认展示演示日 09-13 的时间轴，底部仍为三个 Tab。
2. 点周历日期或展开月历，查看过去和未来；可切周、切月、直接跳转日期和回到今天。09-14 有两张时间重叠的预约，09-11 有退回待补，09-12 可展开已完工待审核记录。
3. “待安排”集中展示未确认时间的任务；联系确认后自动进入相应日期。改约保留过往预约记录，不自动判定超时或修改任务处理状态。
4. “当日地图／安排当日路线”带入选定日期；远程任务只显示在日程，不加入上门路线。详情返回保留日期，切企业／退出清空上下文。

日程、列表和地图共用十一张虚构工单。新增日程 10 项自动检查，连同既有回归共 55 项；正式工单、预约历史接口及微信能力仍未接入。

## 服务人员 v0.3 地图与路线怎么体验

[打开任务地图](index.html#w-map) · [三种视图并排预览](worker-map-overview.html) · [接入设计与验证](01-两端小程序设计说明.md#20-服务人员-v03--任务标点与路线)

1. 选中时间／状态标点，底部工单同步；切列表可搜索，同址多单展开选择，待核地址与远程任务分开统计。
2. 点击“去这单 · 看路线”，选择当前位置或服务中心起点，切换驾车／步行并预览。打开微信位置页的交接浮层后可返回原路线，不自动签到。
3. 点击“今日路线”，按已确认预约安排多站，上移、移除或恢复顺序后重新预览；可导航到首站或点每站箭头。

地图、位置和路程均为虚构演示，未接真实地图或导航；当前已存在服务站经纬度，工单坐标、真实算路与小程序授权配置仍需补齐。新增地图 10 项状态测试，与现有回归合计 45 项；原型浏览器走查通过，不改变真实实现／验收计数。

## 服务人员 v0.2 怎么体验

打开[服务人员交互原型](index.html#w-tasks)，或先看[三个 Tab 并排预览](worker-overview.html)。本版按用户 2026-09-13 的方向，将底部导航收为 **任务、配件、我的**：技术资料和延保资料放进我的；领料、退料、调拨记录归配件；工单保留带产品、带任务的快捷入口。旧 `#w-apps` 自动转到我的。

- **任务**：顶部数字直接筛选今日预约、退回待补、等配件；四分类直接展示，支持按任务号／联系人／地址搜索和排序；正在服务独立置顶。卡片用时间侧栏、状态色和下一步提示显示处理重点。十一张虚构任务各自保留草稿和历史。
- **现场主线**：选陈女士 → 现场服务 → 签到（或无法定位说明）→ 检测处理 → 完工四步 → 待审核。图片默认添加示例材料；右侧选择“下一次添加材料：模拟上传失败”可走失败重试，其他草稿保留。
- **跨角色衔接（当前规则）**：右侧“模拟后台结果”用于审核通过／退回、库房处理和后续办结。审核通过直接待回访，师傅无需二次提交；手机内不提供审批或关闭按钮。
- **缺件与配件**：从周女士任务进入异常跟进、按任务领料；或直接从配件 Tab 备料。支持多项数量调整、空申请／超量校验、申请回显、拒绝／撤销、实物收件、退料和调拨接收。记录保留原任务，申请不立即增加库存，收件确认才更新演示个人库存。
- **退回与远程**：赵先生任务补充铭牌后生成新版本，旧版本保留；许先生远程指导跳过上门签到与现场照片。取消恢复先登记申请，保持取消状态等待服务中心确认，不擅自确定恢复目标。
- **我的**：技术资料支持品番／关键词／版本及类型检索，延保可查示例项目范围；反馈保留本次处理记录；切企业和退出清空企业上下文。密码页仅演示验证，勿填真实凭证。

任务分布目前是按当前筛选展示的地址列表，未接地理底图或路线。资料预览只展示元信息和内容位置，未提供真实维修内容或视频；照片、扫码、定位、电话、账号、反馈和后台处理均为本地模拟。草稿仅本次页面会话有效，刷新清除，不代表离线持久化已完成。全部 16 个业务入口都有原型归属，不能据此认定真实业务全流程已实现或验收。

原型状态模型、入口对照和验证记录见[设计说明第 19 节](01-两端小程序设计说明.md#19-服务人员-v02--三-tab-与流程联动原型)。

## 顶部文案与操作层级

v0.9 按用户确认的优化方向调整：个人信息直接展示绑定手机与字段；购买记录和我的产品保留数量摘要；服务页无活动单时去掉顶部标语，空态仍说明下一步。登记与服务表单统一以“第 N 步 / 共 3 步”表示进度，减少导航、步骤和大标题之间的重复；购买日期明确按购买凭证或订单填写，不能误填收货或安装日期。

## 头像与兴趣偏好怎么体验

v0.10.3 将[个人信息](index.html#c-profile)的绑定手机号置顶，按用户要求撤回横向表单调整，姓名和地址恢复上方标签、下方输入框；头像仍为缩略图和更换箭头的资料行。移除上传文案、格式大小提示、“选填”及默认头像说明；头像仍非必填，未选择时自然显示默认图。点击整行选择图片，保存后同步到“我的”；已移除“恢复默认”按钮，已选图片可直接更换。正式小程序使用微信原生能力，本 HTML 原型保留浏览器选图演示，不上传服务器，刷新或重置清除。

个人信息下方的[兴趣偏好](index.html#c-preferences)独立保存，含“关注的产品”7 个候选、“希望了解的内容”6 个候选；默认均未选，可取消单项或清空。蓝色边框、浅蓝底及勾选标记区分选中状态；返回后保留草稿，保存后入口显示数量摘要。不从已购买品类自动勾选、不触发营销订阅、不改变服务提醒；不影响个人资料未保存草稿。

本轮暂不加入生日、性别、家装需求或联系时段；品类映射、会员画像规则、通知投放和真实头像存储待正式功能契约落实。见[设计说明第 18 节](01-两端小程序设计说明.md#18-消费者-v010--选填头像与兴趣偏好)。

## 个人信息和购买记录怎么体验

从“我的”进入[个人信息](index.html#c-profile)或[购买记录](index.html#c-purchases)。

1. **个人信息**：修改姓名、常用地址及服务进度提醒，点击“保存个人信息”后返回“我的”核对回显。常用地址可留空，填写时地区与详细地址须完整；普通返回保留未保存草稿。
2. **更换手机号**：展开同页验证区，获取演示验证码。原号使用 `123456`，验证后填写不同的新号码，再获取并输入 `654321`。输错提示重试；获取验证码后修改新号码须重新获取。取消保留原号码；未发送短信或修改真实账户。
3. **购买记录**：已有示例为一条购买记录、两件商品；展示日期、门店、型号及数量，按需展开各产品既有安装码。点商品进入对应产品资料，返回保留展开状态。复制仅反馈，不写剪贴板。
4. **自行登记与空态**：首次使用显示无记录并引导登记；登记后显示自行填写的购买信息，缺失门店不补造、不生成安装码。右侧切换场景保留当前个人信息／购买记录页，演示数据仍重置。
5. **失败恢复**：右侧选择“加载失败与重试”，重新加载后保留个人信息草稿及购买记录展开状态。常用资料的修改不会改写历史购买资料或服务申请。

手机号的原号／新号验证方式与地址交互属于评审建议；微信订阅授权、真实本人数据隔离与资料接口未接入。完整范围与验证见[设计说明第 16 节](01-两端小程序设计说明.md#16-消费者-v08--个人信息与购买记录)。

## 服务页怎么体验

打开[服务页](index.html#c-service)，查看当前状态、产品小图、四阶段进度、服务安排和下一步；新申请通过轻量“申请新服务”回到产品选择。服务页已移除与首页重复的安装／维修／指导按钮。

1. 右侧选“申请已收到·等待联系”，应显示联系后确认安排；填写的期望时间不会被展示为已确认时间。
2. 切“服务进行中”，查看已确认时间及准备提示；切“多项服务”，直接在本页切换服务，完整进度跟随选中单。
3. “已登记产品”但无活动单时，显示正确空态并引导选产品申请；“首次使用”引导登记。即使首页当前产品没有工单，服务页也会汇总其他产品的活动单。
4. 同一多商品安装申请只计一项服务；历史服务与评价仍指向独立已完结示例。有活动单时只保留进度相关的客服联系动作，辅助区不重复放客服；客服只演示入口。

在服务页切换右侧评审场景会保留当前页面位置；场景切换仍会重置演示数据。范围与验证见[设计说明第 15 节](01-两端小程序设计说明.md#15-消费者-v07--服务跟进与多项服务切换)。

## 添加产品新流程怎么体验

右侧先切换“首次使用”，从[欢迎页](index.html#c-welcome)开始：

1. **手机号自动同步**：点击“授权手机号并同步产品”，模拟验证后自动出现一条购买记录、两件产品；重新同步不重复添加。
2. **一码通扫**：从[添加产品](index.html#c-register)进入扫一扫。`DEMO-SN-001` 和 `DEMO-TRACE-002` 直接定位具体产品，`DEMO-INSTALL-003` 回查购买产品；确认后加入“我的产品”，再次扫描同一码只提示已有。
3. **普通商品码**：输入 `DEMO-PRODUCT-001`，只能识别型号，需继续填写购买日期和必要使用信息；结果显示用户申报、实物待核验。
4. **无码兜底**：没有码或识别失败时，按分类 → 系列 → 产品 → 购买日期添加。该产品可以进入列表，但不会自动获得免费安装或保修权益。
5. **统一展示**：“我的产品”和“购买记录”区分手机号同步、扫码添加、用户申报；产品详情分别显示实物识别和用户关系状态。

原型不会访问真实微信手机号、订单或编码服务；页面里用字符串分流只是为了评审交互，正式版必须由服务端验码和查重。当前路径与边界见[设计说明第 26 节](01-两端小程序设计说明.md#26-消费者-v011--手机号自动同步与扫码优先添加)。

## 查找服务网点怎么体验

网点查询沿用 v0.6：从“服务 → 查找服务网点”或[网点查询入口](index.html#c-outlets)进入，以地图为主界面，保留查询、地区选择、详情 3 屏；电话与导航使用浮层。网点结构与 v0.6 验证见[设计说明第 14 节](01-两端小程序设计说明.md#14-消费者-v06--地图主界面与原生能力模拟)。

1. 顶部单行选择地区、输入关键词，再切换“授权门店／维修网点”；默认上海市为手选示例，不表示已定位。
2. 点击示意地图点位，底部摘要同步名称、地址及电话／导航动作；距离只在模拟定位成功后显示。展开列表与收起均在本页，选中一行回到地图查看该网点。
3. 进入详情查看营业时间、服务范围与到访信息，再返回保留查询上下文；点击定位可在评审面板选择成功、拒绝或失败，拒绝或失败后仍可手选地区。
4. 电话和导航打开浮层模拟原生能力；导航说明是“打开微信位置页”，不表示已经开始路线导航。旧电话／导航 hash 转到网点详情；空结果及加载失败仍可调整条件或重试。
5. “首次使用”尚无产品时也能查网点。维修网点详情可进入原维修申请路径，所浏览网点不自动成为承接站；登记要求、已有服务判断和后续联系仍沿用原流程。

本地 HTML 使用虚构示意地图，不接真实地图、拖拽、定位、电话或业务 API；机构、地址、热线、时间与距离均为示例。正式小程序拟使用 `map` 标记选点、按需 `getLocation`、`makePhoneCall` 与 `openLocation`，权限、隐私和原生样式须在真实开发时验证，不能以此稿认定真机能力已完成。

当前仍保留 v0.4 的手动登记、标签码辅助识别及安装码说明，不恢复安装码认领或手机号找回演示；本轮不改变业务接口、开放状态或验收计数，也不生成图片。
