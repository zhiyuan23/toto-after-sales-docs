## 查看原型

- 打开 [index.html](index.html) 可本地查看，不需要安装依赖或连接业务后端。
- 消费者 v0.13／v0.11 都是 32 屏，v0.14 在此基础上新增 5 个评审页面；服务人员页面数以当前工作台实时显示为准，切换消费者样式不改变服务人员页面和流程。
- 左侧可切换 v0.14、v0.13 与 v0.11；用 `?consumerVersion=0.14`、`?consumerVersion=0.13` 或 `?consumerVersion=0.11` 固定打开，无参数时默认为 v0.14。v0.14 可额外切换游客与尚未关联产品场景，登录仅模拟状态，不采集真实身份。
- 三个视图：单页走查、核心流程、页面总览。
- 右侧说明区记录页面目标和待确认规则，可切换“首次使用”“已登记产品”“申请已收到·等待联系”“服务进行中”“多项服务”五种消费者场景，以及加载失败等通用状态。
- 表单支持演示必填校验、会话内输入保留、登记结果回显和审核退回后的重提反馈。
- 页面使用虚构数据。非主流程入口仅提供说明性反馈；手机号授权、订单同步和扫码均为本地模拟，头像不上传服务器，拨号、定位、故障媒体上传和业务提交也未接真实能力。
- 刷新页面会清除演示会话。不要填写真实客户资料。

当前消费者 v0.11 产品服务流程建议从首页依次试用：选择当前产品 → 申请售后服务 → 说明问题 → 确认联系与期望时间 → 独立复核 → 提交 → 查看进度。首页的安装入口仍是原型探索；真实开发在业务范围确认前保持隐藏或不可用。右侧切换场景会清除消费者的演示数据，普通返回和产品切换会保留各自草稿。

## 消费者 v0.11 怎么体验

1. 在[新样式 v0.13](index.html?consumerVersion=0.13#c-home)右侧切到“首次使用”，先体验手机号自动同步，再对照扫码和无码手选兜底。
2. 添加产品按“添加入口 → 扫码／输入 → 识别结果”走查；无码手选按“选产品 → 购买日期 → 个人／使用信息 → 登记结果”走查。
3. 服务申请保留三步表达：问题与媒体 → 联系与期望时间 → 独立复核提交；提交后再进入回执和进度。
4. 用“我的产品”、产品资料和购买记录对照手机号同步、扫码添加和用户申报三类来源及核验状态。
5. 样式评审也直接在这套 32 屏原型中进行，关键检查首页、AI 智能售后、电话／微信客服、添加产品、服务申请与我的六类页面。

首页产品切换使用轻量胶囊 Tab：不设置整组底板或分隔线，当前产品使用透明背景、服务蓝文字和蓝色描边；无边框的“加号 + 添加”作为同行尾项。安装、维修、使用指导改为三个独立的圆形快捷入口：不设共同底板、矩形卡片或分隔线，圆形中只放统一蓝色图标，操作名称位于下方。这一形式与下方横向的服务状态卡分层，避免两组矩形组件相互竞争。“我的”页四行账户入口去掉卡片上下额外内边距，首末行与卡片边界共用行高节奏。

## AI 智能售后助手怎么体验

1. 从[首页](index.html?consumerVersion=0.13#c-home)点击右下角 52px 的“AI”悬浮按钮。首次使用且尚无产品时入口仍保留，可同步／添加产品，也可直接联系人工客服。
2. 助手默认带入当前产品；有多个产品时可切换。点击常见问题或输入故障描述，原型只在匹配当前品番的已发布知识中返回一轮建议，并展示知识标题、版本、发布日期和编号。
3. 若建议已解决问题，点击“已经解决”结束对话，不创建服务申请；若仍未解决，点击“还没解决”，查看助手整理的产品、问题、已尝试建议与判断结论。
4. 摘要中的“用户问题”和“希望获得的帮助”可修改。点击“带入维修申请”后，核对后的摘要预填到既有维修表单；点击“复制摘要并联系客服”会先复制文本，再在当前页打开 C09 底部抽屉。选电话客服直接调用拨号，选在线客服直接进入微信客服，不显示虚假的已转人工状态。
5. 首屏、回答页和服务失败状态均保留直接人工入口。当前产品没有适用品番知识时不套用其他型号建议；漏水、异常发热等风险问题先提示停止使用；已有活动服务单时阻止重复申请并引导查看进度。右侧“查看通用状态”可切换 AI 加载中与加载失败示例。

本功能仍是固定虚构知识和本地状态驱动的交互原型。C09 在线客服按钮使用微信小程序 `button open-type="contact"` 的正式设计语义；电话客服不写入占位号码，需后台提供有效配置后再调用拨号能力。后台 A23 服务知识库和 Web 统一工单是已有基础，但消费者安全查询、消费者维修申请提交、真实模型调用、客服配置及真机验证尚未实现。

## 日程与地图（当前原型）

任务页概览卡的“今日预约”进入当日已确认预约日程，显示时间、联系人和地址，可进入任务详情；“任务地图”进入本人待处理上门任务的位置示意与任务列表。远程指导不出现在地图上。地图图形仅用于交互评审，不表示真实坐标、路线、距离或导航能力；正式微信地图能力以实现和真机验证为准。

## 服务人员 v0.2 怎么体验

本节仅保留已失效决策背景。历史三个 Tab 并排预览已删除；当前实现只能以上文“唯一有效原型入口”为准。本版当时将底部导航收为 **任务、配件、我的**：技术资料放进我的；延保资料因当前管理后台、后端和真实小程序均无对应能力而暂时隐藏入口。当前仅将领料、退料记录归入配件，调拨入口暂不提供；工单保留带产品、带任务的快捷入口。旧 `#w-apps` 自动转到我的。

- **任务**：顶部数字直接筛选今日预约、退回待补、等配件；四分类直接展示，支持按任务号／联系人／地址搜索和排序；正在服务独立置顶。卡片用时间侧栏、状态色和下一步提示显示处理重点。十一张虚构任务各自保留草稿和历史。
- **现场主线**：选陈女士 → 处理任务 → 签到（或无法定位说明）→ 服务处理 → 证据与客户确认 → 核对提交 → 待审核。原“服务记录”和“完工资料”合并为一个三段页面，内容自动保存，不再提供手工暂存和重复核对勾选。图片上传失败可原位重试，其他草稿保留；旧 `#w-completion` 地址转到处理任务。
- **跨角色衔接（当前规则）**：右侧“模拟后台结果”用于审核通过／退回、服务站管理员处理和后续办结。审核通过直接待回访，师傅无需二次提交；手机内不提供审批或关闭按钮。
- **缺件与配件**：从周女士任务进入异常跟进、按任务领料；或直接从配件 Tab 备料。支持多项数量调整、空申请／超量校验、申请回显、拒绝／撤销和退料。记录保留原任务；领退料申请时库存不变，服务站管理员通过后直接完成并同步更新服务站与个人库存。当前原型不提供调拨入口、记录或收件确认。
- **退回与远程**：赵先生任务补充铭牌后生成新版本，旧版本保留；许先生远程指导跳过上门签到与现场照片。取消恢复先登记申请，保持取消状态等待服务中心确认，不擅自确定恢复目标。
- **我的**：技术资料支持品番／关键词／版本及类型检索；延保资料入口暂隐藏，仅保留直达评审页和 WAPP-019 需求追踪。反馈保留本次处理记录；切企业和退出清空企业上下文。密码页仅演示验证，勿填真实凭证。

任务分布目前是按当前筛选展示的地址列表，未接地理底图或路线。资料预览只展示元信息和内容位置，未提供真实维修内容或视频；照片、扫码、定位、电话、账号、反馈和后台处理均为本地模拟。草稿仅本次页面会话有效，刷新清除，不代表离线持久化已完成。业务入口均有原型归属，当前实际加载的 `worker.js` 定义 25 个评审屏幕；页数收敛不改变 W01～W16 需求追踪，也不能据此认定真实业务全流程已实现或验收。

原型状态模型、入口对照和验证记录见[设计说明第 19 节](01-两端小程序设计说明.md#19-服务人员-v02--三-tab-与流程联动原型)。

## 个人信息和购买记录怎么体验

从“我的”进入[个人信息](index.html#c-profile)或[购买记录](index.html#c-purchases)。

1. **个人信息**：姓名、所在地区和详细地址都可留空；修改输入项并离开控件，或改变地区选择后，该项单独更新。头像选择成功后独立更新，页面没有整页保存按钮。
2. **更换手机号**：点击后调起微信手机号授权弹窗；取消保留原号码，允许后用微信返回的号码更新。
3. **购买记录**：已有示例为一条购买记录、两件商品；卡片只展示日期、门店、来源、型号和数量，不再设详情展开。点商品进入对应产品资料，在同页展开“产品与购买信息”查看完整资料。
4. **自行登记与空态**：首次使用显示无记录并引导登记；登记后显示自行填写的购买信息，缺失门店不补造、不生成安装码。右侧切换场景保留当前个人信息／购买记录页，演示数据仍重置。
5. **原地同步**：已授权时点“同步购买记录”直接刷新当前页，不再进入独立同步页；未授权时先调起微信授权弹窗。

微信手机号授权、购买记录刷新与资料更新均为本地交互模拟；真实本人数据隔离与业务接口未接入。当前资料页交互见[设计说明第 29.5 节](01-两端小程序设计说明.md#295-账户与服务记录简约卡片)，初版范围留档见第 16 节。

## 服务页怎么体验（v0.11 原版）

打开[服务页](index.html#c-service)，查看当前状态、产品小图、四阶段进度、服务安排和下一步；新申请通过轻量“申请新服务”回到产品选择。服务页已移除与首页重复的安装／维修／指导按钮。

1. 右侧选“申请已收到·等待联系”，应显示联系后确认安排；填写的期望时间不会被展示为已确认时间。
2. 切“服务进行中”，查看已确认时间及准备提示；切“多项服务”，直接在本页切换服务，完整进度跟随选中单。
3. “已登记产品”但无活动单时，显示正确空态并引导选产品申请；“首次使用”引导登记。即使首页当前产品没有工单，服务页也会汇总其他产品的活动单。
4. 同一多商品安装申请只计一项服务；历史服务与评价仍指向独立已完结示例。有活动单时只保留进度相关的客服联系动作，辅助区不重复放客服；客服只演示入口。

在服务页切换右侧评审场景会保留当前页面位置；场景切换仍会重置演示数据。范围与验证见[设计说明第 15 节](01-两端小程序设计说明.md#15-消费者-v07--服务跟进与多项服务切换)。

## 添加产品流程怎么体验（v0.11 原版）

右侧先切换“首次使用”，从[欢迎页](index.html#c-welcome)开始：

1. **手机号自动同步**：点击“微信授权并同步产品”，在弹窗允许后自动出现一条购买记录、两件产品；重新同步不重复添加。
2. **一码通扫**：从[添加产品](index.html#c-register)进入扫一扫。`DEMO-SN-001` 和 `DEMO-TRACE-002` 直接定位具体产品，`DEMO-INSTALL-003` 回查购买产品；确认后加入“我的产品”，再次扫描同一码只提示已有。
3. **普通商品码**：输入 `DEMO-PRODUCT-001`，只能识别型号，需继续填写购买日期和必要使用信息；结果显示用户申报、实物待核验。
4. **无码兜底**：没有码或识别失败时，按分类 → 系列 → 产品 → 购买日期添加。该产品可以进入列表，但不会自动获得免费安装或保修权益。
5. **统一展示**：“我的产品”和“购买记录”区分手机号同步、扫码添加、用户申报；产品详情分别显示实物识别和用户关系状态。

原型不会访问真实微信手机号、订单或编码服务；页面里用字符串分流只是为了评审交互，正式版必须由服务端验码和查重。当前路径与边界见[设计说明第 26 节](01-两端小程序设计说明.md#26-消费者-v011--手机号自动同步与扫码优先添加)。

## 查找服务网点怎么体验（v0.11 原版）

网点查询沿用 v0.6：从“服务 → 查找服务网点”或[网点查询入口](index.html#c-outlets)进入，以地图为主界面，保留查询、地区选择、详情 3 屏；电话与导航使用浮层。网点结构与 v0.6 验证见[设计说明第 14 节](01-两端小程序设计说明.md#14-消费者-v06--地图主界面与原生能力模拟)。

1. 顶部只保留居中的“维修网点／授权门店”切换，不常驻搜索框和城市选择。默认上海市为手选示例，不表示已定位；只在定位失败或空结果时按需进入地区选择。
2. 点击示意地图点位，底部摘要同步名称、地址及电话／导航动作；距离只在模拟定位成功后显示。展开列表与收起均在本页，选中一行回到地图查看该网点。
3. 进入详情查看营业时间、服务范围与到访信息，再返回保留查询上下文；点击定位可在评审面板选择成功、拒绝或失败，拒绝或失败后仍可手选地区。
4. 电话和导航打开浮层模拟原生能力；导航说明是“打开微信位置页”，不表示已经开始路线导航。旧电话／导航 hash 转到网点详情；空结果及加载失败仍可调整条件或重试。
5. “首次使用”尚无产品时也能查网点。维修网点详情可进入原维修申请路径，所浏览网点不自动成为承接站；登记要求、已有服务判断和后续联系仍沿用原流程。

本地 HTML 使用虚构示意地图，不接真实地图、拖拽、定位、电话或业务 API；机构、地址、热线、时间与距离均为示例。正式小程序拟使用 `map` 标记选点、按需 `getLocation`、`makePhoneCall` 与 `openLocation`，权限、隐私和原生样式须在真实开发时验证，不能以此稿认定真机能力已完成。

当前仍保留 v0.4 的手动登记、标签码辅助识别及安装码说明，不恢复安装码认领或手机号找回演示；本轮不改变业务接口、开放状态或验收计数，也不生成图片。
