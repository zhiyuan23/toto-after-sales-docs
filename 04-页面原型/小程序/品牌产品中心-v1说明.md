## 定位与页面分工

以消费者已购产品为中心，提供使用资料、售后与适量品牌内容。首页体现品牌的生活审美和持续服务，不使用自动轮播、促销弹窗或商品瀑布流。

| 页面 | 第一版内容 |
| --- | --- |
| 首页 | 品牌场景、当前服务卡、本人产品摘要、固定服务快捷入口、使用照护、品牌故事及产品新知 |
| 我的产品 | 本人产品图片、品番、来源、核验状态；查看档案，单件服务状态直接进入进度 |
| 我的 | 个人信息下方固定“我的服务”；沿用购买记录及账户等原有入口 |
| 我的服务（二级） | 跨产品进行中服务列表、历史记录空态、申请服务及公共帮助 |
| 服务进度（二级） | 服务安排／服务处理／服务完成三阶段，确认预约与期望日期分开表达 |
| 产品内容（二级） | 使用指南、日常照护、品牌与生活、产品新知；内容到网点和客服可继续交互 |

首页服务卡只在有进行中服务时出现：一项直达该单，多项先进入汇总列表。无活动服务时不占空白卡片。首页、服务页和产品未关联页均可直接联系客服，公共内容不要求登录。

## 演示方式

直接打开 HTML 即可查看，无构建与依赖安装；也可在文档仓库启动 `python3 -m http.server 8768 --bind 127.0.0.1`，浏览 `/04-页面原型/小程序/brand-center-v1.html`。

默认是两件产品、一项已确认维修服务。右侧“消费者使用场景”可切换：

- 手机号已同步：有产品、没有服务，观察进度卡收起。
- 游客／首次使用／尚未关联产品：产品引导、公开内容、人工帮助及模拟登录。
- 申请已收到：等待联系，不承诺预约时间。
- 服务进行中：单项服务直接进入进度。
- 多项服务：维修与使用指导分属不同产品，汇总入口进入列表，选择后保持商品与服务对应关系。

“查看通用状态”保留加载、空态、失败重试等演示。单页、核心流程和页面总览均可使用。`?capture=c-home` 为 390 × 844 的纯手机预览；使用完整评审页切换场景。

## 素材与边界

- 沿用现有 TOTO 官方商品示意图与 AI 浴室场景图，来源见 [素材说明](assets/README.md)。AI 场景不代表正式 TOTO 商品或品牌发布素材。
- 首页、品牌故事文字是设计提案，未宣称已获品牌审核。产品新知演示未来新品推广的位置与详情路径，目前使用已有商品，不虚构上市时间、促销价格、产品性能或新款身份。
- 使用指南提供官方说明书中心外链；日常照护不虚构逐型号拆装、维修或清洁步骤。正式内容运营需要适用产品、发布和下架机制，本轮未实现后台。
- 产品归属与服务资格分开表达；沿用的扫码、授权、填写与提交均是本地模拟，不请求真实身份或业务 API。
- 历史记录首版演示空态，没有伪造已完成服务；原有评价页仅留在评审目录，不能视作当前演示账户的真实历史记录。
- 原有安装、评价、登记等下游页面继续作为历史原型复用。其旧探索说明不覆盖当前正式功能 Spec，本轮不据此重新确认业务规则。
- 仅修改原型导航文档，生产需求、应用进度与业务验收计数不变；未修改业务源码，已本地提交，未推送或发布。

## 文件与维护

新版独立入口、样式、页面覆盖层分别为 `brand-center-v1.html`、`brand-center-v1.css`、`brand-center-v1.js`。`brand-center-v1-app.js` 是 2026-09-27 原控制器的独立快照，仅调整本方案导航、场景、图标及核心流程；旧 `index.html`、`app.js`、`consumer-brand.*` 等实现保持不变。基础产品、账户、网点与服务表单仍引用已有只读原型模块。

保留独立控制器是为了避免这轮探索改变旧版行为；它不是新的生产应用架构。后续确认落地时应按正式端侧规范实现，不能直接把原型复制为生产代码。服务人员原型仍以原 `index.html?consumerVersion=0.13#w-tasks` 为唯一入口。

视觉采用现有品牌体系及原生 CSS，不引入新 UI 库：浅色画布、品牌蓝、胶囊操作按钮、无装饰边框的信息卡、统一进入箭头。设计强度为低变化／低动效／低密度（4／2／3）；本轮不扩展已有浅色评审原型的深色主题。
