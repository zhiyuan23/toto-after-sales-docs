# 系统管理员工作台设计说明

评审日期：2026-10-19。状态：第五版紧凑指标与数据构成原型已获用户授权落地；本次仅提交已完成原型，正式前后端实现及其实施记录按用户要求保留工作区、不纳入提交。原型数字仍为演示值，正式接口与权限遵循[系统管理契约](../../../specs/05-平台集成与公共能力/2026-10-15-系统管理视角与全部功能入口.md)，不代表共享发布或业务验收。

[打开交互原型](../当前原型/administrator.html) · [后台原型导航](../README.md)

## 设计结论

建议将管理员首页组织为“今日异常线索 → 配置缺项 → 管理入口”。使用蓝白后台外壳、紧凑数字摘要、可筛选的日志列表、三项服务状态及按需打开的详情抽屉，便于管理员从线索进入既有管理页面。

这是根据现有岗位职责、功能契约和源码作出的设计判断，尚未开展管理员访谈或使用频率统计。系统管理员与总部运营、服务站管理员、代理商管理员职责不同；管理员需要业务运营信息时，可进入原有岗位工作台。

## 管理员重点关注什么

| 优先级 | 到达首页时的问题 | 推荐表达 | 当前依据与边界 |
| --- | --- | --- | --- |
| 第一优先 | 今天有哪些失败记录，需要从哪里排查？ | 今日失败总数与分类构成＋最近六条列表；时间、事件／追踪编号、来源／业务对象、失败结果；详情展开完整错误码 | 现有管理员工作台已查今日 `FAILURE` 总数及最近六条。日志条数不是独立故障数，也不是影响用户数 |
| 第一优先 | 哪项已启用的外部服务配置缺失？ | AI、地图 Web、地图 JS 三行状态；缺项使用橙色与明确文字 | 已有配置返回启用与配置完整性。配置完整不证明连接正常，首页不自动连接测试 |
| 第二优先 | 谁能访问哪些功能，去哪里调整？ | 用户总数与启停分布、售后角色总数、售后页面数，点击进入对应管理入口 | 现有授权管理能力，首页不新增待授权审批、不编造高风险账号或权限异常统计 |
| 辅助 | 我刚发起的导入导出怎样了？ | 页头轻量入口，按需打开本人任务抽屉；首页不展示任务计数或最近任务 | 继续使用本人任务范围和独立权限，不转换为全系统后台任务监控 |
| 辅助 | 日志、配置、字典和模板在哪里？ | 日志、服务区直接下钻；字典与模板归入右侧管理区 | 来自当前账号已授权功能，不增加第二套业务菜单 |

## 为什么采用这个形式

- 顶部保留两个固定紧凑宽度的异常指标：今日失败记录、已启用服务配置待补齐项；右侧增加今日失败构成条形图，展示请求、外部调用、安全及其他记录的数量和占比。账号与权限区域展示售后范围的用户、角色和页面数量，用户另列启用／停用分布；各项可进入原管理页面。不计算综合健康分，个人导入导出不占常驻指标位置。
- 主工作区使用按时间倒序的横向日志列：时间、事件／追踪编号、来源／业务对象、失败结果。事件列优先分配宽度，类别通过线性图标和来源区分，追踪编号作为次级信息；HTTP 502、HTTP 200 但业务失败、登录校验失败和客户端请求异常在列表直接可辨，完整错误码等继续在详情展开。这样避免把来源和对象都挤在左侧，并利用宽桌面的横向空间。
- 服务配置是三项离散状态，使用状态列表即可比较；补充接口已有的凭证来源、加密配置、配置修订号和更新时间，不展示凭证内容、不使用可用率仪表盘。
- 查询详情采用右侧抽屉，保留首页上下文；真正的维护动作进入已有页面，由其承担权限、校验与提交保护。
- 颜色只用于已选导航和有明确语义的状态，红色表示失败记录，橙色表示配置缺项，绿色仅表示配置齐全。

首版不放工单量、满意度、服务站排行、全国地图等总部运营指标；也不放尚无可靠采集能力的 CPU、内存、在线人数、全量请求成功率、系统可用率和版本发布状态。后续如确需监控能力，应先单独确认来源、采集覆盖与口径。

## 原型布局与交互

顶部沿用已确认的系统管理、服务运营、基础资料、配件库存四模块顺序。工作台位于系统管理首项；切换顶部模块只更换侧栏，保留当前工作台。其他模块侧栏仅提供相关示例入口，不代替完整正式目录。

首页依次为紧凑页头、两个小型异常指标与今日失败构成、左侧失败日志与右侧配置／账号概览。主区域按可用桌面高度分配空间：标题、筛选、列头与统计底栏保持固定，仅日志内容内部滚动；账号权限增加用户启用／停用比例条，再以带数量和统计范围的纵向三行提供入口，字典与模板紧随其后。移除重复的全宽常用入口和顶部大面积口径说明，将统计边界保留在日志底栏。配置缺项排在服务列表首位；摘要、类别、服务、管理入口使用一致的线性图标，颜色同时配合状态文字。

账号概览：用户统计与售后用户管理列表一致，示例为 24 个用户、启用 22／停用 2；角色统计售后角色，示例为 7 个；页面统计售后菜单管理树的页面节点，示例为 48 个，不包含根节点、目录和操作权限。所有数字均为演示值；失败显示未知，无查看权限时不展示数量与管理入口。

导入导出仅保留页头入口，点击后按需查看本人任务；移除顶部任务统计和高桌面的最近任务面板。任务空状态和读取失败均在抽屉内呈现，无任务权限时隐藏入口。

1280×720、1440×900 是本轮桌面核对尺寸；正常桌面无整页纵向滚动。低于 620px 高时保留页面滚动兜底，嵌入预览窄于 1100px 时保留桌面最小阅读宽度，不以隐藏溢出代替可达性。未增加移动端适配范围。

可评审交互：

1. 日志按最近六条中的类别筛选，支持方向键切换。筛选结果明确标注“最近 6 条中 X 条”，顶部总数不随局部筛选变化。
2. 点击记录打开详情，查看业务失败与 HTTP 状态的区别；有追踪号时可复制并预览关联查询条件，缺失时不提供虚假的关联入口。
3. 查看日志继承今日、失败与当前类别；关联查询预览沿用今日、失败和所选追踪号。正式日志页如何默认过滤关联记录，可在实施时继续复核。
4. 配置缺项定位到服务区；配置及账号权限入口打开入口意图预览。原型没有保存、授权或供应商测试操作。
5. 页头本人导入导出入口按需打开虚构任务抽屉，关闭或 Esc 返回原工作台；模块与岗位原型可切换。
6. 页底评审场景可切换无失败记录、日志读取失败、部分来源不可用、无日志权限、配置读取失败、无配置权限、账号概览读取失败、无账号概览权限、本人暂无任务、任务读取失败及无任务权限。

## 状态与数据口径

| 场景 | 应呈现的状态 |
| --- | --- |
| 今日无失败记录 | 显示 0，说明“今日可查询范围内暂无失败记录”，不宣称系统全部正常 |
| 日志读取失败 | 数量显示未知，提供重试；配置区独立可用，不以旧值或零值替代 |
| 部分日志来源不可用 | 显式提示覆盖不完整，数量仅指当前可查询来源 |
| 无日志读取权限 | 不展示数量与记录，日志入口隐藏；正式接入时不得发送日志请求 |
| 配置读取失败 | 配置缺项数显示未知，独立提供重试，不保留误导的绿色状态 |
| 无配置查看权限 | 不展示配置状态或相关入口；正式接入时不得发送配置请求 |
| 账号概览读取失败 | 数量未知，提示重新读取，不显示零值正常 |
| 无账号概览查看权限 | 不展示用户／角色／页面数量及对应管理入口 |
| 本人暂无任务 | 点击页头入口后，抽屉显示本人暂无任务 |
| 本人任务读取失败 | 点击页头入口后，抽屉提示状态未知并可重试 |
| 无任务查看权限 | 隐藏页头本人任务入口 |
| 加载中 | 刷新按钮暂不可重复操作，展示示例加载占位 |

所有数据均写在原型脚本内，包含今日 18 条失败、最近 6 条记录及 1 项配置缺项；账号概览为 24 个用户（启用 22／停用 2）、7 个角色、48 个页面；本人任务仅在抽屉展示 1 项处理中、1 项已完成。这些值不来自真实系统。列表“全部类型”指当前六条示例记录，不能推导全量分类分布。新增今日失败构成使用另一份完整今日演示汇总：请求 7、外部调用 5、安全 4、其他 2，总计 18；部分来源场景为 5／3／2／2，总计 12。分类筛选最近记录不会修改今日构成；没有失败记录时各类为 0、比例条为空，读取失败显示未知，无权限隐藏图表。示例错误码用于展示排查层级，不声明正式枚举契约。

## 与现有实现的关系

现有管理员首页已具备今日失败聚合、最近六条、外部服务配置与常用入口；本次新增独立设计文件，保留当前正式实现。

正式实施可复用原首页聚合模型、日志接口、外部配置接口、授权解析和任务抽屉。分类筛选、打开日志详情、关联条件继承、账号数量／统计范围、今日分类汇总和表现层状态需进行接入与相应验证；原型中的入口预览不能作为这些功能已经落地的证据。顶部摘要中的配置缺项数可由已返回的启用／配置字段计算，不需要额外健康监控接口。

项目进度与业务验收计数不变，不新增正式 Spec 或修改原有权限契约。

### 第二版：桌面一屏与横向信息列

2026-10-19 根据用户反馈调整原型表现层：压缩页头、摘要、区块间距与常用入口高度，主工作区使用剩余视口；日志采用独立滚动区，账号权限入口改为带图标的横向三项。保留既有示例数据、分类、详情、查询预览与权限状态。

浏览器尺寸核对：1280×720 的页面高度为 720px，账号权限底部位于 620px，评审工具栏底部为 710px；日志可视区约 214px，内容 384px，可内部滚动。1440×900 的页面高度为 900px，账号权限底部位于 788px，日志可视区 352px、内容 408px。两种尺寸页面宽度与视口相同，未产生横向溢出。

1280×720 下默认及六项异常／权限场景逐项核对，页面高度始终为 720px、账号权限底部始终为 620px，配置区内容无溢出。键盘 End 将日志滚动至底部，最后一行底部与列表底部均为 586px，整页滚动位置保持 0。请求筛选返回两条，详情及追踪号仍可查看。脚本语法及知识文档 246 页校验通过；仅验证原型，正式实现与真实接口边界保持。


## 各原型共享标题与视角切换

2026-10-19 按用户反馈，将本页左上“蓝鲸数字｜售后服务＋当前视角下拉”应用到全部后台页面和两端小程序原型。一个下拉直接切换七个视角，专业页和历史小程序方案在“其他页面与方案”展开。统一预览不再另加应用切换栏，小程序侧栏仅保留页面与流程导航；原型独立打开也使用共享标题。各页业务布局与演示状态仍由原页面维护，统一入口切换时缓存保留。


### 第三版：失败结果直读与桌面空间利用

2026-10-19 本轮继续优化原型：将原顶部口径说明替换为本人任务摘要，移除重复的底部全宽入口，回收高度供日志使用。来源与业务对象合并一列，新增失败结果列；六条记录直接区分 HTTP 502、HTTP 200 业务失败、登录校验失败与客户端请求异常。配置缺项置顶，账号权限入口补充用途；字典与模板合并到管理区。高桌面增加同一任务集合的最近任务预览，不新增系统级监控指标。页面标题仍与侧栏／页签统一为“工作台”。

本轮仅维护原型和本说明，不更新正式功能进度或验收计数；没有修改业务源码、数据库、部署或提交 Git。

本轮验证结果：
