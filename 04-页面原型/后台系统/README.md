## 运行与验证

从上级 `04-页面原型/` 启动静态服务，打开 `index.html`。所有页面使用虚构数据；没有真实登录、授权变更或业务提交。统一入口没有额外切换工具栏；视角下拉直接置于各页自身顶栏。原型的独立 HTML 也使用相同标题与下拉，可直接查看。

2026-10-19 验证：本地资源／入口链接、视角路由及后台回归 56 项通过。浏览器实测七个主视角均只有一套共享左上标题，1280×720 下顶栏高度 64px、品牌左距 22px、顶栏无横向溢出；小程序已隐藏重复应用和版本切换。管理员筛选与消费者当前页在视角往返后保留；专业页入口、配件页签与服务站卡片方案重绘后的共享标题、键盘 Esc 和浏览器前进／后退通过。1440×900 下复核小程序及专业页，文档 246 页校验与差异空白检查通过。截图只保留在已忽略的 `.local/verification-artifacts/20261019-native-perspective/`。验证限于原型，不代表真实接口与权限验收。

## 切换与刷新修复（2026-10-19）

直接打开本地 HTML 时，原先父页面读取子页面 DOM 的导航方式会受不透明来源限制，顶层地址无法随视角切换而更新。当前下拉改为带 `target="_top"` 的原生链接，点击不再依赖消息通信；消息辅助同步内部页面和原页面中的非链接跳转，父页仍校验消息来源与已装载窗口，不读取子页 DOM。统一地址记录当前视角、小程序内部页面及配件页签，刷新后按地址恢复；普通切换继续复用本次页面状态。仅保存页面定位，刷新仍会初始化临时表单与示例业务数据。

验证：63 项入口／路由／后台回归通过，包含拒绝父子 DOM 访问的 HTTP／file 模拟回归、消息来源校验及小程序选页事件。HTTP 浏览器实测七视角点击后刷新均保留；消费者“探索产品”、人员端“日程”刷新恢复，两端往返及浏览器前进／后退通过。浏览器工具禁止访问 file URL，因此未直接操作 Chrome 的本地文件页；file 场景以消息与导航回归验证。文档及脚本语法检查通过。本轮仅修复原型导航，正式业务进度与验收状态不变。

2026-10-19 续轮修复：下拉、品牌返回与“其他页面与方案”全部采用原生顶层链接；共享点击处理不取消这些链接的默认跳转。内部定位消息兼容 file 来源的 `null` 与 `file://` 两种序列化，且保留窗口来源校验；HTTP 仍精确匹配来源。浏览器实现中的 file 来源差异见 [Chromium 记录](https://chromium.googlesource.com/chromium/src/+/1005cd9df17b6c0b8ad25bb79b49c4efb7e9186b)。旧页延迟发来的状态不覆盖已请求的新视角地址。

本轮 67 项检查通过，增加原生链接不取消默认行为、本地来源序列化与来源限制回归。HTTP 浏览器逐一点击七个视角并刷新确认；两端内部页面刷新定位继续保留。本地 file 页仍受浏览器工具访问限制，未直接实测，不将模拟回归写为浏览器验证。

提交前复核（2026-10-19）：入口／路由／后台原型 67 项全部通过。小程序测试夹具补齐浏览器 `Event` 与事件派发，并将共享导航交由专用夹具验证；全部原型检查共 192 项，185 项通过、7 项失败。以提交前 `HEAD` 导出原小程序原型后重跑，其 125 项中同样有 7 项失败，名称逐项一致，无新增失败；现有断言涉及消费者首页按钮外观和人员端旧任务数量／时间结构，不在本轮导航整理中改写。原始输出保留本地临时目录；此次不把全量原型回归记录为全部通过，也不提交正式管理员工作台实现。

## 当前可评审内容

- Gaia 售后子系统外壳，包含顶栏、视角切换、一级导航和分组侧栏。
- 总部地图版以全国省级地图为主画布，支持工单态势、服务站网络、服务质量与已配置服务区域四个图层，点击省份联动区域报表、服务网络和质量日事实；四类图层收进地图标题栏下拉菜单。“全部工单”由右侧当前区域主数字统一承载，全国待办区收敛为六节点轻量状态河，其中待分配服务站和待完工保持线性待办下钻。异常关注独立展示可下钻的缺件工单；审核退回和超时工单只保留待接入位，不伪造数字。右栏保留全国近 30 天工单趋势，服务质量增加评价率、满意度、审核退回率和取消率的全国汇总接入位，未接入前不从单条日事实或当前分页推算。
- 地图与右侧运营信息采用自适应主次分栏：右栏以主内容区 29% 为目标比例，并限定在 400-620px 的可读范围内；1280px 及以下收敛为 390px 右栏。这样常规宽屏下地图仍是主视觉，超宽屏下右栏也不会退化为过窄的固定侧条。数字按“区域主数／全国待办与服务网络／质量事实”建立三级层级，用字号、字重和等宽数字强化扫读，而不依赖更多颜色或装饰。
- 总部服务质量新版按“全国汇总指标—30 天量效趋势—对象横向比较—重点关注—明细下钻”组织，补充可由现有分子分母安全计算的评价覆盖率和投诉率；旧版日汇总事实页完整保留，两版标题区可直接切换。
- 总部运营报表新版以工单时间趋势和单维度结构为核心，关闭、取消、投诉采用独立序列和并列数值，避免误表达为互斥构成；旧版分组报表完整保留，两版标题区可直接切换。
- 客服首页将下一项待办、按团队／个人分组的数据摘要和四个高频操作收进首屏行动带；工单状态用图标、连接线和岗位标签表达。客服可办理受理与分配服务站，“服务站处理中”只提供跟进／提醒／按权限转站，完工审核标记为需审核权限，投诉作为异常分支。建单和其他办理在待办＋办理双栏完成，服务上下文按需从右侧展开；不在客服视角选择服务人员。
- 服务站今日安排与配件版将工作台办理范围收敛为两类：分配服务人员、领退料审批。顶部三张待办卡依次对应“全部待办／待分配／领退料审批”，点击卡片与页签同步切换；全部待办卡以略大的数字和浅色底突出主信息，当前视图只用细线与描边提示。旁边的今日期望工单、缺件工单和可用人员只读展示，不切换待办。左侧保留“全部待办／待分配／领退料审批”三个页签，跨两类单据按创建时间混排、固定高度内部滚动；中间可完成候选人选择、超容量原因核对以及领退料通过／拒绝，右侧库存独立展示。页面主色跟随客服工作台的蓝色基线；底部按 08:00～20:00 的两小时时段展示人员与期望工单关联，空格仅表示没有关联工单，不代表可接单。现有程序的工单状态队列与更多 workflow 动作仍在相应专业流程中，本页不把它们当作服务站工作台的待办。页面数字均为演示数据；正式跨工单／单据的全部待办需分别读取并校验权限。
- 服务站管理卡片样式的隔离评审页：从信息层级重新设计结构名片、业务分栏和清爽横排三个可切换方向；已确认的业务分栏样式已同步到正式程序卡片模式，其他方向继续只用于原型评审。
- 配件管理专业页的入库单查询、新增／编辑／提交／物理删除，服务站库存查询，领料／退料列表、详情、通过和必填原因拒绝；审核通过会在会话内联动双方库存。
- 门店工作台采用“左侧办理、右侧数据”上下骨架：顶部左侧为加高的购买登记主卡，背景改用总部工作台主卡的主题蓝渐变和环形装饰，不再显示“主要工作 · 购买发生时”眉题。“消费者 → 购买记录 → 商品实例”去掉整块边框与背景，三个节点改为自然宽度并紧密排列，只保留语义图标、文字和短连接线；登记主按钮独立收口在右下角，放大为 196px 宽的高对比白底按钮，用明显阴影和实色蓝色箭头建立操作层级。右侧保留四张独立指标卡，每张按“图标与名称—主数值—趋势状态与统计口径”三层排版；主数值居中突出，趋势以图标、色彩和轻状态底直观表达，口径弱化到底部，卡内不使用横向分隔线。下半区左侧是两行摘要式购买记录；右侧严格上下 1:1 分区，上半为近 30 日登记趋势，下半并列热销商品排行和由手机号历史购买关系得到的新客／复购结构。完整资料通过“查看”弹层呈现，服务工单仅在侧栏按需查询。登记弹层只保留取消和确认登记，商品行只填写商品与数量。所有数字均为原型示例；当前无金额字段，不展示销售额、利润或客单价，环比与客户结构正式实施时需由授权门店汇总接口提供。
- 指标联动、搜索、侧滑办理、数据／加载／空／失败／无权限五种列表状态、快捷搜索、菜单收起、刷新、深浅主题和全屏。

原型中的工单、购买记录、顾客、服务站、排班、数量、趋势和及时率都是页面内演示数据。原型不代表功能已验收或相关报表口径已全部确认。

地图版的数据边界：省份颜色对应现有运营报表 `PROVINCE` 维度；服务站点位、启停、服务项目、配置日上限、人员数量和关联区域来自服务站档案可承载字段；质量只展示一个对象的一条日汇总事实；覆盖层只表达“已配置服务区域”。当前不展示原始工单地址点、人员实时位置、服务盲区、实际产能或利用率。

服务站候选以行政辖区匹配层级和配置优先级为当前可靠依据；距离为需要候选接口补充字段后的增强展示。服务人员候选以本站归属、服务技能、期望日期可用性、当天已分配数／日容量和冲突原因为依据，当前不展示缺少可靠数据来源的人员距离。
