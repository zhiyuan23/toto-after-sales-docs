## 新增计划

1. 新建 `YYYY-MM-DD-计划主题/` 目录；同日多份计划可在主题后加 `-02` 等编号。计划编号使用 `PLAN-YYYYMMDD-两位序号`。
2. 复制[通用模板](../摘要汇报模板/index.html)为该目录的 `index.html`。修改浏览器标题、项目／计划标题、日期、阶段目标、预计用时、四项重点和底部共同要求，同时修改源码中的 PNG／HTML 下载文件名，避免混淆。工具栏文字与导出逻辑不需要调整。
3. 新建 `README.md`，参考已有计划填写：编号、整理日期、目标、预计周期、演示对象、材料状态、来源、工作重点、范围及验证。未明确的日期或安排保留待确认，不自行换算成承诺工期。
4. 在本页目录表最上方加入链接。后续新阶段使用新目录；同一计划的小幅更正可以原位修订并同步说明，范围、目标或周期有实质变化时在说明中标注变更日期及依据。
5. 浏览器核对文字和版式，再导出 PNG 检查实际图片。点「保存 HTML」得到的下载文件不会自动写回仓库；将确认后的内容更新到本期 HTML 后再提交。

## 模板和历史计划怎么维护

- 通用模板只放占位内容和可复用的版式／工具，不作为任何一期的正式计划。每份计划保持单文件、可离线使用，便于发送和长期查看。
- 每份计划是独立材料。模板后续优化用于新计划，不自动改写已有计划；需要修复某份历史计划的展示或导出时再定向更新，并复核导出的图片。
- 已发送材料需要固定版本时，注明发送日期及版本；后续修订保留变更说明，不把旧计划改写成新阶段。
- Git 维护 HTML、计划说明和索引。PNG 默认按需导出发送，验证截图和临时下载不重复入库；需要正式留存发送版时按[证据与材料留存规范](../../03-开发管理/08-团队文档协作与提交同步规范.md#evidence-retention)处理。
- 业务需求、实施契约、开发进度和验收结果继续在原有目录维护，本目录只负责阶段计划的汇报表达。
